# History retrieval / 历史检索

Status: implementation contract, 2026-09-23. / 状态：实现契约，2026-09-23。

Agents retrieve recorded project evidence through a read-only interface, then inspect only the context needed for the task. This improves access to requirements, rejected alternatives, attempts and validation without asserting that a historical completion statement proves a merge or remains valid today. / Agent 通过只读接口检索已记录项目证据，再按需查看上下文，以更容易找回要求、被拒方案、尝试及验证；历史完成声明不证明已经合并或至今仍有效。

## Scope / 范围

- Operations: `history status`, `history search`, `history context`, `history read`, `history open`, plus Codex-only `history observe`. An explicitly started `history serve` instance fixes one project and one source, independently of ordinary browser state. / 操作包括 `history status`、`history search`、`history context`、`history read`、`history open`，以及仅支持 Codex 的 `history observe`。明确启动的 `history serve` 实例固定单个项目和来源，与普通浏览器状态独立。
- Event candidates use existing case-insensitive, whitespace-tolerant literal search and structured filters. They are not natural-language answers or automatically identified decisions. Main is the default Event Layer; disclosure depth is independent of Event Layer. / 事件候选复用忽略大小写、容忍空白变化的字面搜索及结构化筛选，不是自然语言答案或自动识别的决定。默认事件层为 Main；披露深度独立于事件层。
- Selected sessions are materialized for context and evidence reads; suspected retrieval-artifact sessions may also be materialized to classify real calls. Repeated CLI calls reuse the explicit service rather than rebuilding an index each time. / 为选定会话物化上下文和证据详情；疑似含检索工件的会话也可能被物化，以核验真实调用。连续 CLI 调用复用明确启动的服务，不逐次重建索引。
- Semantic search, automatic decision cards, mixed-source indexing, permanent archives and system service installation are outside this increment. / 本轮不包括语义搜索、自动决策卡、混合来源索引、永久归档或系统服务安装。

For Codex artifact classification, a session needs both the existing `session-analyzer` text hint and an indexed `response_item` / `function_call` for a supported command tool before source materialization is attempted. The hints may occur in different Raw Records; they do not establish an artifact without strict materialization and structured classification. Existing unsupported forms, including `custom_tool_call`, remain searchable. This gate does not expand classification coverage or change context/read/open source verification. / Codex 工件分类在尝试来源物化前，要求会话同时具有既有 `session-analyzer` 文本提示，以及已索引、工具属于受支持命令工具的 `response_item`／`function_call`。两类提示可位于不同 Raw Record；它们不能代替严格物化与结构化分类来确认工件。现有未支持形式（含 `custom_tool_call`）仍可搜索。此门禁不扩大分类覆盖，也不改变 context／read／open 来源核验。

Search may therefore succeed on the fixed projection of a changed or deleted source when the session has no supported classification call, instead of failing during an otherwise fruitless classification materialization. Search success does not verify source validity; selecting that evidence through context/read/open still strictly rejects incompatible source changes. / 因此，当会话没有受支持的分类调用时，即使来源已改写或删除，搜索仍可基于固定投影成功，不再因原本无果的分类物化而失败。搜索成功不证明来源仍有效；通过 context／read／open 选读该依据时，仍严格拒绝不兼容的来源变化。

## Source observation / 来源观察

`history observe` (`POST /api/history/observe`) explicitly compares physical Codex candidate/dependency metadata against a startup baseline. `status.capabilities.sourceObservation` advertises support; other sources return `UNSUPPORTED_SOURCE`. Ordinary status/search/context/read do not perform this check. Observation does not refresh the index, validate content or advance a baseline. Keep old evidence validity separate from the question of later historical coverage. / `history observe`（`POST /api/history/observe`）显式比较 Codex 物理候选／依赖的 metadata 与启动基线。`status.capabilities.sourceObservation` 声明支持情况，其他来源返回 `UNSUPPORTED_SOURCE`。普通 status／search／context／read 不执行此检查。观察不刷新索引、不核验内容、不推进基线；旧证据是否有效与是否覆盖后续历史须分开表达。

Accept only `callerSessionId`, `maxFiles`, `limit`, `maxBytes`, `presentation`, `contextRef`. Defaults/ranges are 10000/1–100000 files, 8/1–100 detail items, and 24000/4096–1048576 serialized UTF-8 bytes. The report names observation/baseline/indexing intervals, scope, unchecked controls, limits, gaps and partial work. `counts` are mutually exclusive measured file classifications: metadata unchanged, size increased/decreased, metadata/identity changed, missing, unreadable, unobserved, new candidate or prior existence unknown. Unchanged metadata is not proof of unchanged content; growth is not proof of append-only history. Missing paths are distinct from failed inspection. Candidate membership in this project remains unchecked unless already an indexed dependency. / 仅接受上述六个字段。文件数、详情项数及序列化 UTF-8 字节的默认值／范围分别为 10000／1–100000、8／1–100、24000／4096–1048576。报告列出观察／基线／索引时段、范围、未检查的控制来源、限制、缺口及部分工作。`counts` 是互斥的已量测文件分类：metadata 未变、大小增长／缩小、metadata／身份改变、缺失、不可读、未观察、新候选或原先存在性未知。metadata 未变不证明内容未变；增长不证明历史仅追加。路径缺失与检查失败分开；除已索引依赖外，不检查候选是否属于此项目。

`callerSessionId` is an optional caller assertion, not authenticated actor identity. Match only exact indexed session IDs; accept an absent ID and return `caller.indexedSessionMatched:false`. Do not infer identity from names or recency. `caller.counts` and `other.counts` partition physical files, with shared indexed owners retained in details. `unattributed` changes may belong to the caller or another project. Continuous caller growth is normal; it is neither excluded nor automatically labelled a retrieval echo or a refresh requirement. / `callerSessionId` 是可选的调用方声明，不是经认证的主体身份。只精确匹配索引会话 ID；接受尚未索引的 ID，并返回 `caller.indexedSessionMatched:false`。不得根据名称或时间推断身份。`caller.counts` 与 `other.counts` 按物理文件分组，详情保留共享的索引归属。`unattributed` 变化可能属于调用方或其他项目。调用方持续增长是正常情形；不排除这些变化，不自动将其标为检索回声或要求刷新。

Details are bounded by both `limit` and `maxBytes`, with `itemsOmitted` and per-group `detailsOmitted`; counts include omitted details. `partial` describes incomplete observation/baseline work, while `truncated` describes omitted details. There is no pagination (`hasMore:false`, `nextCursor:null`); repeating the operation starts another observation against the original baseline. Increasing bounds cannot repair an incomplete baseline. Keep a task evidence cutoff, then explicitly create a new service snapshot only if later evidence is needed. A separate port can preserve the old reader; never silently retarget old refs, cursors or Web URLs. / 详情同时受 `limit` 与 `maxBytes` 限制，返回 `itemsOmitted` 及各组 `detailsOmitted`；计数仍包含省略详情。`partial` 描述观察／基线未完成，`truncated` 描述详情省略。不分页（`hasMore:false`、`nextCursor:null`），重复操作会再次对原基线观察。提高上限不能修复不完整基线。保持本轮证据截止点，只有需要后续依据时才显式创建新服务快照。另一端口可保留旧阅读服务，不得静默重定向旧引用、游标或 Web URL。

## Open evidence for a user / 为用户打开证据

An Agent can explicitly hand one verifiable historical event to the user for inspection and continued reading in Session Analyzer. `history open --endpoint <original endpoint> --ref <returned reference>` validates the original scope, source snapshot and event identity, prepares a Web entry point and requests the local browser to open it. `--no-browser` prepares the same URL for a citation without invoking the browser. Search/context/read never open pages automatically. / Agent 可以显式把一条可核验历史事件交给用户，在 Session Analyzer 中核对并继续阅读。上述命令核验原范围、来源快照和事件身份，准备 Web 入口并请求本机浏览器打开；`--no-browser` 准备相同 URL 供引用，不调用浏览器。Search／context／read 不自动打开页面。

Accept exactly one event `evidenceRef` (a full result's `ref`) or one `hr1` handle with its original `--context`. Resolve compact handles server-side and export a durable evidenceRef before creating the URL; reject ranges instead of guessing a target. The original history service lazily starts and reuses a loopback Web listener bound to the same fixed index. Its project/source/root cannot change, while the user may browse other sessions within that scope. An ordinary Web instance remains independent. / 仅接受一个事件 evidenceRef（完整结果的 ref），或携带原 `--context` 的 hr1 句柄；服务端解析短句柄并导出持久 evidenceRef 后生成 URL，拒绝范围引用而不猜目标。原检索实例按需启动并复用绑定同一固定索引的回环 Web 服务，项目／来源／根固定，允许浏览范围内其他会话；普通 Web 实例保持独立。

The response distinguishes `targetVerified`, `viewerReady` and `browserOpenRequested`, and includes the verified `target`, `evidenceRef` and ready `url`. CLI `browser.status` is `skipped`, `requested` or `failed`; a failed opener returns a nonzero exit status but preserves the ready URL and verification result. Neither invocation nor listener readiness confirms that a page finished locating the record. URLs belong to the service's machine/environment; remote/container localhost is not automatically reachable from the user's browser. / 响应分别报告三个布尔状态，并包含已核验 target、evidenceRef 和就绪 url。CLI 的 browser.status 为 skipped／requested／failed；浏览器启动失败返回非零退出状态，但保留 URL 和核验结果。启动调用及服务就绪均不等于页面已完成定位。URL 属于服务所在机器／环境，远端或容器的 localhost 不会自动映射到用户浏览器。

Browser invocation succeeds when the platform launcher acknowledges the launch request, independently of the browser application's lifetime. Linux invocation requires `gio` (GLib) and a registered default HTTP browser; missing launchers or handlers and explicit launch failures retain the failure result and ready URL. `--no-browser` does not require a launcher. / 平台启动器确认启动请求后，浏览器调用即成功，与浏览器应用的运行时长无关。Linux 调用要求 `gio`（GLib）及已注册的默认 HTTP 浏览器；启动器或处理程序缺失及明确启动失败，仍返回失败结果并保留就绪 URL。`--no-browser` 不要求启动器。

The fragment carries the durable reference (`/#ref=...`); refresh and later opens reverify the source. Scope mismatch, expired compact context, changed/deleted source, incompatible snapshot and unavailable target produce explicit errors. A separate action to browse the current session must not be reported as successful evidence location. EvidenceRef lifetime is independent of Web URL reachability: stopping the history instance closes its viewer, and a restarted instance can revalidate unchanged source evidence but may choose another port. / Fragment 携带持久引用；刷新及再次打开重新核验来源。范围不匹配、短句柄 context 过期、来源改写／删除、快照不兼容及目标不可用明确报错；独立的浏览当前会话动作不能被报告为证据定位成功。EvidenceRef 的生命周期与 URL 可达性独立：停止检索实例会关闭查看页服务，重启后可以重新核验未改变的证据，但端口可能变化。

Landing guarantees the original session/layer/event and readable content. A temporary Timeline presentation preserves saved preferences. The linked record opens expanded with a small identity marker; nearby records appear as ordinary summary cards in source order and expand in place with shared selection/Inspector, keeping the Events surface on mobile. Initial navigation scrolls to the linked record, not the first nearby card. Internal gaps show exact omitted-event counts; outer boundaries identify earlier/later unloaded records only when present. There is no permanent top evidence panel. / 落地保证原会话／层／事件及可读内容；临时 Timeline 呈现保留持久偏好。链接指向的记录展开并带小型身份标记，附近记录按来源顺序显示为普通摘要卡片，可原地展开，共用选中状态／Inspector，手机端保持在事件界面。初始滚动定位引用记录，不定位第一张附近卡片。内部间隔显示准确省略事件数；确有更早／更晚未加载记录时才显示外侧边界。不再设置常驻顶部证据面板。

For Main, “Continue in session” sits after the excerpt group and explicitly loads the existing prefix with progress/cancel/retry. The group stays mounted while loading; once all group event IDs are available, it switches to the continuous timeline without duplicates, preserving selection, expansion and Inspector state while bringing the selected record (the linked record by default) into view. Inserted gap content must not displace it off screen. Scrolling excerpts never loads the prefix. “Back to linked record” restores the original reference and readable target position after nearby selection or continuation, waiting for target detail height and yielding to newer input. Protocol/Raw use “View Main timeline”, a change of reading layer rather than same-event continuation. Gap markers explain omissions, not range-loading controls. Later user intent supersedes old navigation requests. Opening a new reference retires the previous selected detail immediately; its late response must not cancel the new reference while resolution is pending. Bidirectional windows, universal character mapping, tab control, multi-evidence comparison and remote recovery remain separate milestones. / Main 的“在会话中继续阅读”位于节选组之后，显式加载既有前缀，提供进度／取消／重试。加载期间保留原卡片，组内全部事件 ID 可用后切换至连续时间线，不重复事件，并保持选中、展开及 Inspector 状态，把选中记录（默认为定位记录）带入视口；补入间隔内容不能把它推到屏幕之外。滚动节选不加载前缀。选中附近记录或续读后，“返回定位记录”恢复原引用及可读目标位置，等待目标详情高度，并服从后续用户输入。Protocol／Raw 使用“查看主时间线”，表示切换阅读层而非原事件续读。省略标记仅作说明，不是区间加载控件。后续用户意图使旧导航请求失效。打开新引用时立即退役先前选中详情；其迟到响应不得在新引用解析期间取消新导航。双向窗口、通用字符映射、标签页控制、多证据对照及远端恢复仍另立里程碑。

Following an event reference within the same session and layer selects an excerpt member in place. A target outside the excerpt opens its exact card through ordinary reading navigation after saving the excerpt return position; it is not added beside excerpt records as if they were adjacent. On mobile Main + Timeline, the target is visible in Events. Back to reading position restores the original excerpt, selection, local folds and reading surface. A later event selection takes precedence over a delayed reference response. / 沿同会话、同层事件引用跳转时，摘录内的目标原地选中。摘录外的目标先保存摘录返回位置，再通过普通阅读导航打开准确卡片，不将其追加在摘录记录旁并暗示连续相邻。移动端 Main + Timeline 的目标显示在事件界面。“返回刚才的位置”恢复原摘录、选中状态、临时折叠及阅读界面。后续事件选择优先于延迟的引用响应。

Return and Continue immediately show a small in-button progress indicator while keeping the action label and width. Busy actions ignore repeated activation, remain available to assistive technology as busy/disabled, and keep Cancel and navigation usable. Completion, failure or cancellation removes the indicator; reduced-motion preference uses a static indicator. Return retains its dock through resolution instead of disappearing during the wait. / 返回及续读立即在原按钮内显示小型等待标记，保持操作文字及宽度。忙碌操作忽略重复触发，通过无障碍属性表达忙碌／禁用，并保留取消及导航。完成、失败或取消时移除标记；减少动态效果偏好下使用静态标记。返回在解析期间保持原吸底操作区，不因等待而消失。

After explicit continuation, only the return action stays in a small sticky footer within the reading pane so a long, growing timeline cannot push it out of reach. The initial excerpt group uses a normal footer, and leaving the reference context removes sticky positioning. / 显式续读后，仅返回操作保留在阅读区的轻量吸底栏中，避免不断加载的长时间线使其难以到达。初始节选组使用普通组后操作区，离开引用上下文后取消吸底。

After detail loads, hide the search excerpt and preview when the exact target body's readable content contains the hit line. Otherwise offer “View match not shown in the record” and a short actual-match preview. Failed detail keeps this fallback; loading detail is undecided. Only expanded Timeline body content establishes coverage, excluding Inspector, nearby summaries, hidden/clipped sections and closed disclosures. Scrolling does not change coverage; ambiguous rendering retains the excerpt. Nearby cards use localized roles/timestamps and never repeat the anchor. Language changes preserve the reference without prefix loading. Reading return from a related session restores the excerpt group, selection, expansion and viewport; failures remain retryable. / 详情加载后，若准确目标的可读正文已包含命中行，则隐藏搜索片段及预览；否则提供“查看正文未展示的命中片段”及简短实际命中预览。详情失败时保留补充入口，加载中暂不判断。仅展开的 Timeline 正文参与覆盖判断，排除 Inspector、附近摘要、隐藏／裁剪区及未打开的折叠内容。滚动不改变覆盖判断；渲染对应关系不明时保留摘录。附近卡片显示本地化角色与时间，不重复锚点。语言切换保持引用，不加载前缀。从关联会话返回时恢复节选组、选中、展开状态及视口；失败可重试。

Switching from excerpts to Trajectory first loads the referenced records in the session; failure or cancellation keeps the excerpts readable. Re-selecting Timeline keeps the current excerpt group. Ordinary session reading restores remaining-page controls and Turns/Messages/Issues/Files/Protocol/Plans metrics; a failed summary can be retried without losing the record. Changing the search query or scope exits excerpt mode, while Back to linked record remains available explicitly. / 从摘录切到 Trajectory 时，先加载引用记录所属会话；失败或取消仍保留可读摘录。重选 Timeline 保持当前摘录组。普通会话阅读恢复剩余分页控件及轮次／消息／问题／文件／Protocol／计划指标；概况失败可重试而不丢失记录。改变搜索词或范围退出摘录模式，同时保留显式“返回链接记录”入口。

## Result contract / 结果契约

An expanded search supplement shows a muted “Search text · Lines 128–132 · Match on line 130” row above its excerpt when reliable search-projection coordinates exist. Single-line excerpts show only the match line. A tooltip identifies these as this event's search-text lines; they do not locate transcript-file or rendered-body lines. Missing or inconsistent coordinates leave the row absent. Ordinary manual-search snippets currently carry no line coordinates and receive no inferred position or field labels. Position labels do not participate in search highlighting. / 展开的搜索补充在具备可靠搜索投影坐标时，于摘录上方弱化显示“搜索文本 · 第 128–132 行 · 命中第 130 行”；单行摘录只显示命中行。提示说明这些属于该事件的搜索文本，不定位转录文件或页面正文行。坐标缺失或不一致时省略位置行。普通手动搜索片段目前不携带行坐标，不推算位置或字段标签。位置文字不参与搜索高亮。

Conditional search excerpts and previews follow primary content inside the expanded Timeline card, before footer actions. Manual-search excerpts follow primary Trajectory Detail and precede supplemental detail/metadata. Nearby context uses timeline cards; continuation, return, progress and errors use a modest footer after the group. These reading aids add no panel at the top of the timeline. / 按需搜索片段及预览位于展开的 Timeline 卡片主体之后、底部操作之前。手动搜索摘录位于 Trajectory 主体 Detail 之后、补充详情／元数据之前。附近上下文使用时间线卡片；续读、返回、进度及错误使用节选组之后的轻量操作区。这些阅读辅助均不在时间线顶部增加面板。

Search excerpts expose `hitLine` as a one-based line in the search projection, alongside `startLine`/`endLine` and UTF-16 `hitOffset`. The viewer can highlight that excerpt row and initially bring it into the excerpt's own viewport, including on narrow screens. These coordinates do not map to rendered Markdown, detail fields or physical source lines. / 搜索摘录在 startLine／endLine 及 UTF-16 hitOffset 之外，提供从 1 开始的搜索投影行号 hitLine。查看页可标出摘录中的命中行，并在首次展示时使其进入摘录自身视口，包括窄屏。坐标不映射到 Markdown 渲染、详情字段或来源物理行。

Query-storage spill does not change search results: short records migrated to disk, phrases spanning blocks, excluded terms, grouped queries and retrieval-artifact policies retain their semantics. `match.terms` reports the matched original query strings; excerpt `hitOffset` remains an original projection UTF-16 offset and line coordinates refer to that projection, independent of chunk boundaries. Long lines and omitted surrounding lines explicitly set `truncated`. / 查询存储落盘不改变搜索结果：迁移到磁盘的短记录、跨块短语、排除词、分组查询及检索工件策略保持原语义。`match.terms` 报告已命中的原始查询字符串；摘录 `hitOffset` 仍为原始投影的 UTF-16 偏移，行坐标也指向该投影，不受块边界影响。长行与省略的周边行明确设置 `truncated`。

JSON responses identify `producer`, `operation`, `schemaVersion` and `contextRef`, and report coverage, warnings and truncation separately from returned items. Coverage describes the fixed repository/source and indexed snapshot, diagnostics and known omissions. Source coverage gaps, unfinished scanning, pagination and byte-budget omission must remain distinguishable. Zero matches never establish that no history exists. / JSON 响应包含 `producer`、`operation`、`schemaVersion`、`contextRef`，在结果之外分别报告覆盖、警告和截断。覆盖描述固定仓库／来源及索引快照、诊断和已知缺口。来源覆盖缺口、扫描未完成、分页和字节预算省略必须可区分。零命中永不证明不存在历史。

An evidence reference identifies the source, session and event against verified source-version information. It must not silently retarget after source changes or resolve outside the instance's admitted project/source. Source verification allows reads after a restart when the source is unchanged; ephemeral context and navigation cursors may expire. References are locators, not authentication credentials or permanent archives. / 证据引用根据经核验的来源版本标识来源、会话和事件。来源变化后不能悄悄重定位，也不能解析到实例准入项目／来源以外。来源不变时允许重启后核验读取；临时上下文和导航游标可以过期。引用是定位符，不是认证凭据或永久归档。

## Candidate diversity and scope / 候选会话覆盖与范围

Search defaults to `order=diverse`: return each matching session's first eligible event before their second events, then continue by the same rule. Sessions are ordered by latest update (ID breaks ties); eligible events keep their session order. Artifact exclusion precedes the ordering. `order=session` retains the earlier grouped session order. These are deterministic discovery orders, not claims about decision importance or semantic relevance. / 搜索默认 `order=diverse`：先返回每个匹配会话首个合格事件，再返回各会话第二个，依此类推。会话按最近更新排序（ID 打破平局）；合格事件保留会话内顺序。工件排除先于排序。`order=session` 保留此前按会话分组的顺序。这些是确定性发现顺序，不表示决定重要性或语义相关性。

`session=<sessionId>` restricts candidates to a known indexed Session without narrowing subsequent context to search matches; an unknown Session returns `UNKNOWN_SESSION`. Coverage still describes the instance's fixed project/source, while `scan.scopedSessions`, `scan.matchedSessions` and `scan.order` describe this query. All eligible events remain reachable: pagination binds the order and scope, and changing page size or byte budget continues after the last returned rank without repeats or omissions. / `session=<sessionId>` 将候选限定到已索引会话，但后续上下文仍不受命中条件过滤；未知会话返回 `UNKNOWN_SESSION`。Coverage 仍描述实例固定项目／来源，`scan.scopedSessions`、`scan.matchedSessions`、`scan.order` 则描述本次查询。全部合格事件仍可读取：分页绑定排序及范围，改变页大小或字节预算后从最后返回的排序位置继续，不重复、不遗漏。

## Hit context window / 命中上下文窗口

Context keeps navigable recorded parent/fork/supersession targets in `relatedSessions`, with Main range references. `unavailableRelatedSessions` separately reports recorded targets without a navigable Main range: `target_not_indexed` means absent from this snapshot's admitted sessions, and `target_has_no_main_events` means indexed but without Main records. Each entry preserves `relation` and `sessionId`, explains recovery in `message`, and contains no fabricated ref. An absent target may be outside scope or missing from available sources; the response does not assert deletion or global nonexistence. Inferred review parents remain excluded from both lists. Full, compact and viewer context preserve these distinctions; returned refs still require strict source verification when followed. / Context 在 `relatedSessions` 中保留可导航的已记录父级／fork／替代目标及其 Main 范围引用。`unavailableRelatedSessions` 单独报告没有可导航 Main 范围的已记录目标：`target_not_indexed` 表示未纳入当前快照的会话集合，`target_has_no_main_events` 表示已索引但没有 Main 记录。每项保留 `relation`、`sessionId`，通过 `message` 说明恢复方法，不编造 ref。未纳入目标可能在范围外或可用来源中缺失；响应不据此断言已删除或全局不存在。推断的 review 父关系仍不进入这两个列表。完整、紧凑及查看入口上下文均保留这些区别；沿返回引用读取时仍须严格核验来源。

The message-anchor template applies to Main. Protocol and Raw return a local window of at most two neighboring events on each side with `boundaries.mode=layer_local`; message anchors are unavailable on those layers. / 消息锚点模板适用于 Main。Protocol 和 Raw 返回前后各最多两个邻近事件的局部窗口，标明 `boundaries.mode=layer_local`；这些层没有消息锚点。

Use the session's unfiltered event order: nearest preceding user message (`U−`), nearest assistant message after that user and before the hit (`A−`, if any), hit (`H`), nearest following assistant message before the next user (`A+`, if any), and next user (`U+`, if any). Deduplicate anchors when the hit is itself a message. Assistant anchors are nearby statements; the next user is a boundary, not an acceptance signal. / 使用会话未受搜索条件过滤的事件顺序：最近前置用户消息（`U−`）、其后且命中之前最近助手消息（`A−`，如有）、命中（`H`）、下一用户之前最近后置助手消息（`A+`，如有）、下一用户（`U+`，如有）。命中本身是消息时去重。助手锚点只是邻近发言；下一用户是边界，不是验收信号。

Context events include zero-based timelineIndex in their layer's unfiltered event order. Each gap includes beforeEventId and afterEventId identifying its returned endpoints, alongside the exact count and readable range reference. Full, compact and viewer context preserve these fields; clients never decode references to infer positions. Outward navigation uses readable references/cursors. Missing and budget-omitted anchors are distinct. Windows stay within one Session without inventing causality. Projection line numbers are not transcript physical lines. / Context 事件携带层内未过滤事件顺序中从 0 开始的 timelineIndex。每个间隔携带标识所返回两端记录的 beforeEventId／afterEventId、准确数量及可读取范围引用。完整、紧凑及查看入口上下文均保留这些字段；客户端不拆引用猜位置。向外导航使用可读取引用／游标。不存在的锚点与预算省略的锚点不同。窗口不跨会话、不编造因果。投影行号不是转录物理行号。

## Evidence, budgets and retrieval artifacts / 证据、预算与检索工件

Batch `read` supports explicit parts such as messages, requests, results and Raw evidence. Byte limits bound serialized responses; omitted content remains reachable by references and continuation. Budgets do not silently turn an incomplete excerpt into full evidence. No exact tokenizer budget is promised. / 批量 `read` 支持明确选择消息、请求、结果和 Raw 证据等部分。字节限制约束序列化响应；省略内容仍可经引用及续读访问。预算不能将不完整摘录悄悄呈现为完整证据。不承诺精确 tokenizer 预算。

Parts are selectors: duplicate names are normalized in first-occurrence order before continuation offsets and cursor identity are interpreted. Literal CLI query/filter values retain leading hyphens; help is recognized only in option positions. / Parts 是选择器：解释续读偏移及游标身份前，重复名称按首次出现顺序归一化。CLI 的字面查询／筛选值保留前置连字符；仅在选项位置识别帮助请求。

Invalid repeated CLI options, incompatible context length, unsupported open fields and insufficient output budgets include operation-appropriate recovery guidance in `error.message`, retaining existing error codes and envelopes. Distinguish content that does not fit from metadata that alone exceeds the budget. Guidance does not trigger automatic retries, raise the caller's budget or certify incomplete excerpts as complete evidence; changing cursor-bound request fields requires restarting that request without the old cursor. / CLI 非法重复参数、不兼容的 context length、open 不支持的字段及输出预算不足，会在 `error.message` 中给出适用于当前操作的恢复建议，保留既有错误码与响应结构。区分内容无法容纳与仅元数据便超过预算；提示不触发自动重试、不提高调用方预算，也不将不完整摘录认作完整依据。修改游标绑定的请求字段时，须去掉旧游标重新发起该请求。

Explicit `read aroundHit:{before,after}` reads around each reference's stored search hit. Both counts are required nonnegative safe integers; `before+after+1` is at most 100000. It selects `parts:["projection"]` automatically; an explicit parts selector must normalize to exactly that list. It cannot be combined with `source`, `offset`, `length` or `textFormat`. Ordinary reads keep their existing defaults. Missing stored hit offsets return `HIT_OFFSET_UNAVAILABLE`, with ordinary read/context still available; the service never guesses a position. / 显式 `read aroundHit:{before,after}` 围绕各引用已保存的搜索命中读取。两个计数均为必填的非负安全整数，`before+after+1` 最多为 100000。自动选择 `parts:["projection"]`；显式 parts 必须归一化为该列表。不可与 `source`、`offset`、`length` 或 `textFormat` 组合。普通读取保留既有默认值。未保存命中偏移时返回 `HIT_OFFSET_UNAVAILABLE`，仍可使用普通 read/context；服务不猜测位置。

The returned projection part exposes original UTF-16 code-unit `hitOffset`, inclusive `offset`, exclusive `endOffset`, `totalLength`, and bounded `text`. The exact range is `[max(0,hitOffset-before), min(totalLength,hitOffset+after+1))`; it includes one code unit at the hit, without claiming a match length. `previous` and `next` are adjacent `{offset,length}` ranges or null at the respective boundary. Continue with the same ref and `parts:["projection"]`, spreading one returned range into an ordinary read; do not resend aroundHit. Each continuation is at most the requested window width. Existing `nextOffset` and batch `nextCursor` retain their distinct text/item meanings. These coordinates do not map to detail, Raw or rendered text. Source validation, compact durable exports and serialized byte budgets apply unchanged. / 返回的投影 part 提供原始 UTF-16 码元坐标 `hitOffset`、包含起点 `offset`、不含终点 `endOffset`、`totalLength` 及有界 `text`。准确范围为上述公式；包含命中处一个码元，不声称匹配长度。`previous`、`next` 为相邻的 `{offset,length}` 范围，到达相应边界时为 null。以同一 ref、`parts:["projection"]` 和返回范围发起普通读取来续读，不再发送 aroundHit。每段续读不超过请求窗口宽度。既有 `nextOffset`、批量 `nextCursor` 分别保留文本／结果项分页含义。坐标不映射到详情、Raw 或渲染文本。继续执行既有来源核验、紧凑持久引用导出及序列化字节预算。

`--retrieval-artifacts exclude|include|only` controls reliably identified pure retrieval calls/results, defaulting to `exclude`. Filtering happens before top-K selection and reports excluded counts. Plain documentation, copied JSON, ambiguous shell wrappers and mixed tool operations are not excluded by text resemblance alone. Indirect assistant paraphrases remain searchable. / `--retrieval-artifacts exclude|include|only` 控制可可靠识别的纯检索调用／结果，默认 `exclude`。过滤先于 top-K 选择并报告排除数量。普通文档、复制 JSON、歧义 shell 包装和混合工具操作不因文本相似被排除。助手的间接转述仍可搜索。

Direct `history observe` invocations and their explicitly paired outputs follow this same policy when a later snapshot includes them. This does not classify all caller-associated file growth as retrieval artifacts. / 后续快照包含直接 `history observe` 调用及其明确配对输出时，也按此策略处理；这不表示将调用方关联文件的全部增长分类为检索工件。

Historical content is data, not authorization for current actions. Read access is confined to admitted source evidence; a reference cannot request arbitrary files. The service does not upload history, but passing its output to a hosted agent can transmit that output. This increment does not add a general redaction engine: choose source roots and disclosure scope accordingly. / 历史内容是数据，不是当前操作授权。读取限于准入来源证据；引用不能请求任意文件。服务不上传历史，但将输出交给托管 agent 可能传输该输出。本轮不增加通用脱敏引擎，应据此选择来源根及披露范围。

The running snapshot verifies its accepted source prefix: later append-only records may leave old evidence readable but are outside that snapshot. Changing indexed bytes or removing an admitted source fails verification. A restart indexes the new snapshot and may invalidate previous refs. DeepSeek compact Raw storage currently lacks reliable retrieval-artifact classification and reports that gap. / 运行中快照核验已接受来源前缀：后续仅追加记录可能不影响旧证据读取，但不属于该快照。修改已索引字节或删除准入来源会导致核验失败。重启索引新快照，可能使旧引用失效。DeepSeek 紧凑 Raw 存储当前缺少可靠检索工件分类，会报告该缺口。

## Acceptance / 验收

### Efficient disclosure / 高效披露

Default `presentation=full` retains the existing envelope. Opt-in `compact` returns service-context-bound short handles; reading one exports a durable `evidenceRef`. Handles cannot be rebound after restart or used without their context. A compact response with an explicitly supplied current context may replace unchanged coverage/warnings with `coverageRef`; status always supplies the full declaration. / 默认 `presentation=full` 保留原外层契约。可选 `compact` 返回绑定服务上下文的短句柄；精读时导出持久 `evidenceRef`。句柄不能在重启后重新绑定，也不能脱离所属 context 使用。显式传入当前 context 的紧凑响应可用 `coverageRef` 代替未变化的覆盖／警告；status 始终提供完整声明。

Compact context uses a shared top-level `events` table, with per-window `eventIndexes` and `anchorIndexes`. Identical displayed event bodies are shared, while different events, excerpts, boundaries and navigable gaps remain distinct. `view=full` begins at the referenced session's first event and pages within `limit`; range refs continue their admitted range. Its event projection text is bounded by `length`, with explicit `nextOffset`. This view is not a promise that the whole session or every event body fits in one response. / 紧凑上下文采用顶层共享 `events` 表，各窗口以 `eventIndexes`、`anchorIndexes` 定位。相同展示正文共享，不同事件、摘录、边界和可导航间隙保持区分。`view=full` 从引用会话的首事件开始，按 `limit` 分页；范围引用继续其准入范围。事件投影文本受 `length` 约束，并明确提供 `nextOffset`；此视图不承诺完整会话或全部正文都能放进单次响应。

`read textFormat=text` exposes a readable detail projection without repeated identical renderer payloads within one event. Unsupported renderers remain structured JSON. Neither this mode nor projection text is claimed to be original source text; Raw remains available. Byte budgets measure the selected serialized presentation, including shared tables and durable exports. / `read textFormat=text` 提供可读详情投影，去除同一事件内相同 renderer 载荷重复；未支持 renderer 保留结构化 JSON。不将此模式或搜索投影称为来源原文，仍可读取 Raw。字节预算测量所选序列化呈现，包含共享表和持久引用导出。

Deterministic checks cover project isolation, reference invalidation, budgets and continuation, anchor/gap navigation, literal search, echo counterexamples and legacy CLI/package compatibility. Independent agent tasks assess evidence quality and uncertainty, separately from adapter tests. Do not claim multi-model acceptance until the recorded workers actually use distinct models. / 确定性检查覆盖项目隔离、引用失效、预算与续读、锚点／间隙导航、字面搜索、回声反例和旧 CLI／安装包兼容性。独立 agent 任务评估证据质量及不确定性，与 adapter 测试分开。不在实际记录 worker 使用不同模型之前声称通过多模型验收。

## Independent query groups and indexed locators / 独立查询组与已索引定位

`search.groups` contains 1–8 independent query objects, each with a unique 1–64 character `id` (letters, digits, underscore or hyphen), literal query/queries and its own filters, limit, maxBytes and cursor. Defaults per group are four candidates and 8,000 bytes; existing single-search defaults and ordering are unchanged. Only groups, contextRef, presentation and maxBytes are accepted at the top level in grouped mode. A query-shaped phrase containing uppercase spaced `OR` still executes literally and adds `queryWarnings`, including in compact mode. / `search.groups` 包含 1–8 个独立查询对象，各有唯一的 1–64 字符 `id`（字母、数字、下划线或连字符）、字面 query/queries 及自己的筛选、limit、maxBytes、cursor。各组默认四个候选和 8,000 字节；既有单查询默认值与排序不变。分组模式顶层只接受 groups、contextRef、presentation、maxBytes。包含两侧空白的大写 OR 的词组仍按字面执行，并增加 `queryWarnings`，紧凑模式也保留。

The response has `groups` with queryIdentity, scan counts, items and per-group continuation. `state=complete` means the group executed and fitted this response, not that every candidate was returned; follow its nextCursor when hasMore. `results_omitted` means scanning finished but the batch output budget excluded its items; counts remain available, nextCursor is null, and resumeCursor is the original input cursor (null means retry without a cursor). `not_executed` has scan.complete=false, unknown counts and hasMore=null; retry the original query. Outer scan.complete only describes execution coverage, outer hasMore/truncated aggregate group states, and outer nextCursor stays null. Do not merge independent queries or infer zero hits from omitted/unexecuted groups. / 响应 groups 带 queryIdentity、扫描计数、items 和组内续读。complete 表示组已执行且本次响应可容纳，不表示全部候选已返回；hasMore 时沿其 nextCursor 续读。results_omitted 表示已扫描但整批输出预算未容纳候选；计数可用，nextCursor 为 null，resumeCursor 是原输入游标（null 表示重试时省略游标）。not_executed 的 scan.complete=false，计数未知、hasMore=null，应重试原查询。外层 scan.complete 仅描述执行覆盖，hasMore/truncated 汇总组状态，nextCursor 恒为 null。不合并独立查询，不从未执行／省略推断零命中。

Grouped continuation must retain the original group `id`, query and filters. To retry one group, submit a one-element `groups` array, for example `{"groups":[{"id":"sha","query":"abc123","cursor":"<resumeCursor>"}]}`; omit cursor when resumeCursor is null. Do not transfer a group cursor to flat single-search input. The same rule applies to nextCursor. / 分组续读必须保留原组的 `id`、查询和筛选。单独重试时仍提交仅含该组的 `groups` 数组，如上述 JSON；resumeCursor 为 null 时省略 cursor。不得将组游标用于平面的单查询输入，nextCursor 同样遵循此规则。

`read.source` accepts exactly one `sourceRef` or `sourcePath`, plus `locator:{type:"jsonl-line",line:N}` (physical JSONL line, one-based). Initial support is admitted uncompressed Codex primary transcripts; unsupported sources/locators are rejected. Historical dependencies can contribute searchable events without admitting their old source positions through this entrypoint. sourcePath must exactly match indexed relative metadata or its index-derived absolute alias; no arbitrary filesystem path is read. Default parts become raw. The response source object contains persistent sourceRef, canonical relative sourcePath, locator, matchedRawRecords, verification and warnings. Items contain Raw evidence and explicit logicalRefs (zero or more, no guessed ownership). `limit` bounds both returned Raw items and each association list; repeat with source.logicalOffset set to logicalRefsNextOffset to continue associations. Text continuation still uses top-level offset/length. / `read.source` 接受 sourceRef 或 sourcePath 二选一，加上述 locator（从 1 开始的 JSONL 物理行）。首版支持准入的未压缩 Codex 主转录，拒绝未支持来源／定位类型。历史依赖可以贡献可搜索事件，但其旧来源位置未必被此入口准入。sourcePath 必须精确匹配索引相对路径或由索引推导的绝对别名，不读取任意文件系统路径。默认 parts 改为 raw。响应 source 对象含持久 sourceRef、规范相对 sourcePath、locator、matchedRawRecords、verification、warnings。items 含 Raw 证据与明确 logicalRefs（零个或多个，不猜归属）。limit 同时限制返回 Raw 项数及各关联列表；以 source.logicalOffset=logicalRefsNextOffset 续读关联，文本仍用顶层 offset/length 续读。

Legacy path+line yields `unverified_legacy_locator`: membership in the current index does not prove what an old note pointed to. Save the returned SourceRef for future snapshot-bound reads; this does not retroactively validate the legacy note. Versioned input yields source_snapshot_verified only after source validation. Accepted-prefix append semantics remain: indexed bytes are verified, later appended records are absent until restart, and incompatible indexed-byte changes fail. / 旧路径／行号返回 unverified_legacy_locator：当前索引归属不证明旧笔记所指内容。保存返回 SourceRef 可用于后续绑定快照读取，但不追认旧笔记。版本化输入通过来源核验后才返回 source_snapshot_verified。沿用已接受前缀语义：核验索引字节，重启前不包含新追加记录，不兼容索引字节变更会失败。

Locator admission follows the indexed source identity, not its canonical filename suffix. A compressed primary may be indexed under a `.jsonl` path but returns `UNSUPPORTED_SOURCE` through this entrypoint. A historical dependency or archived ancestor not separately admitted as a primary returns `UNKNOWN_SOURCE`; its accepted records can still participate in indexing, search and Raw evidence reads. Those capabilities do not admit an old path/line locator or guarantee a Logical Event association: only recorded `rawRefs` establish the latter. / 定位准入依据索引来源身份，不依据规范文件名后缀。压缩主来源可能以 `.jsonl` 路径索引，但经此入口返回 `UNSUPPORTED_SOURCE`。未另以主来源准入的历史依赖或归档祖先返回 `UNKNOWN_SOURCE`，其已接纳记录仍可参与索引、搜索及 Raw 证据读取。这些能力不准入旧路径／行号定位，也不保证逻辑事件关联；后者只由已记录的 `rawRefs` 建立。
