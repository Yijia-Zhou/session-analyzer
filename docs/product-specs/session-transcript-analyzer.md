## Summary / 摘要

Session Transcript Analyzer is a local web tool for reviewing Codex session transcripts for a specific repository. It helps a single developer move from raw transcript dumps to usable history: searchable sessions, layered timelines, tool-call analysis, and drill-down into the original JSONL when needed. The product is optimized for long sessions, repeated iterations, and mixed protocol noise inside Codex transcripts.

Session Transcript Analyzer 是一个本地 Web 工具，用于查看特定仓库的 Codex 会话转录。它帮助单个开发者把原始转录转储转化为可用历史：可搜索的会话、分层时间线、工具调用分析，以及在需要时下钻到原始 JSONL。该产品针对长会话、反复迭代，以及 Codex 转录中混杂的协议噪声进行了优化。

## Problem / 问题

- Raw Codex transcripts are long, repetitive, and hard to review after many sessions. / 原始 Codex 转录又长又重复，在许多会话之后很难回顾。
- The same user or assistant content may appear through multiple channels, which makes naive viewers noisy. / 同一用户或助手内容可能通过多个通道出现，这会让朴素查看器产生大量噪声。
- Tool activity, protocol injections, and proposed plans are useful for debugging but should not dominate normal reading. / 工具活动、协议注入和 proposed plan 对调试有用，但不应主导正常阅读。
- Without a local review tool, repository-specific engineering history becomes hard to search and hard to trust. / 如果没有本地查看工具，特定仓库的工程历史会变得难以搜索，也难以信任。

## Target users / 目标用户

- Primary users: individual developers using Codex across many sessions in the same repository / 主要用户：在同一仓库中跨多个会话使用 Codex 的个人开发者
- Secondary users: maintainers debugging transcript format changes or viewer behavior / 次要用户：调试转录格式变化或查看器行为的维护者
- Non-target users: multi-user hosted analytics or cloud reporting consumers / 非目标用户：多用户托管分析或云报告消费者

## Goals / 目标

- Make repository-scoped session history readable without opening raw JSONL files by hand. / 让仓库范围内的会话历史可读，而不需要手动打开原始 JSONL 文件。
- Support fast search across messages, tool calls, files, and outputs. / 支持跨消息、工具调用、文件和输出的快速搜索。
- Provide a main timeline that reflects logical work rather than raw duplicated transcript rows. / 提供反映逻辑工作的主时间线，而不是原始重复转录行。
- Preserve access to protocol and raw transcript detail for debugging and verification. / 保留对协议和原始转录细节的访问，以便调试和验证。

## Non-goals / 非目标

- Cloud sync, shared collaboration, or hosted dashboards / 云同步、共享协作或托管仪表板
- LLM-based summarization or semantic clustering / 基于 LLM 的摘要或语义聚类
- Editing or mutating Codex transcript files / 编辑或变更 Codex 转录文件
- Supporting every historical Codex transcript variant perfectly on day one / 在第一天就完美支持每一种历史 Codex 转录变体

## User stories / 用户故事

- As a developer, I want to list only sessions that touched my current repository, so that unrelated Codex history stays out of the way. / 作为开发者，我希望只列出触及当前仓库的会话，以便排除无关的 Codex 历史。
- As a developer, I want to search for a file path, command, or error string, so that I can jump back to the relevant work quickly. / 作为开发者，我希望搜索文件路径、命令或错误字符串，以便快速跳回相关工作。
- As a developer, I want the default timeline to collapse protocol noise and duplicate message channels, so that I can follow the real flow of work. / 作为开发者，我希望默认时间线折叠协议噪声和重复消息通道，以便跟随真实的工作流程。
- As a maintainer, I want a protocol layer and a raw layer, so that I can verify how the logical timeline was derived. / 作为维护者，我希望有协议层和原始层，以便验证逻辑时间线是如何派生的。
- As a maintainer, I want tool operations grouped by logical call, so that shell runs, patch applications, and MCP calls are easier to inspect. / 作为维护者，我希望按逻辑调用对工具操作分组，以便更容易检查 shell 运行、补丁应用和 MCP 调用。

## User-facing behavior / 面向用户的行为

1. The user starts the local server through the `session-analyzer` CLI, commonly via `npx session-analyzer`, with an optional repository root; if omitted, the browser can show configured Codex workspaces immediately, then update project activity after transcript scanning discovers session working directories. / 用户通过 `session-analyzer` CLI 启动本地服务器，常见方式是 `npx session-analyzer`，并可传入可选的仓库根目录；如果省略，浏览器可以先立即显示已配置的 Codex 工作区，然后在转录扫描发现会话工作目录后更新项目活动信息。
1. Invalid CLI values fail before the HTTP server starts: `--port` must be an integer from `1` to `65535`, `--host` must not be empty, unknown options and positional arguments are rejected, a small set of common option spelling variants such as `--repos` and `--codexhome` are accepted as aliases, the CLI prints a user-facing error plus usage/help, and the process exits non-zero. / 无效的 CLI 参数会在 HTTP 服务器启动前直接失败：`--port` 必须是 `1` 到 `65535` 的整数，`--host` 不能为空，未知 option 和位置参数会被拒绝，少量常见 option 拼写变体（如 `--repos` 和 `--codexhome`）会作为别名接受；CLI 会打印面向用户的错误信息和 usage/help，并以非零状态退出。
1. When a project is already selected, opening the idle project chooser keeps a return path: clicking the project switch control again exits the chooser and restores the currently indexed project. While a replacement project is indexing, the top bar is hidden and the chooser's cancel control remains the cancellation path. / 当已经选择了项目时，打开空闲的项目选择器仍保留返回路径：再次点击项目切换控件会退出选择器并恢复当前已索引项目。替换项目正在索引时，顶部栏会隐藏，项目选择器内的取消控件仍是取消入口。
2. The application scans the local Codex home and shows only sessions matching the selected repository. / 应用扫描本地 Codex 主目录，并只显示与所选仓库匹配的会话。
3. The user sees a session list with counts, sizes, timestamps, and failure indicators; long rows are height-limited by default and reveal their full content on hover or keyboard focus. Forked subagent and review sessions remain selectable but render as visually secondary derived sessions with their source session title when available, and hovering or focusing a derived session lightly highlights its visible parent. Plain user-created `/fork` sessions remain normal primary rows but show a `Fork · from ...` relationship tag when the source session is known. / 用户看到包含计数、大小、时间戳和失败指示器的会话列表；较长的条目默认限制高度，并在鼠标悬停或键盘聚焦时显示完整内容。fork 出来的子 agent 和 review 会话仍可选择，但会以视觉上次级的派生会话呈现，并在可用时显示来源会话标题；悬停或聚焦派生会话时，会轻量高亮当前可见的父会话。普通用户发起的 `/fork` 会话仍作为普通主会话行展示，但在已知来源会话时显示 `Fork · from ...` 关系标签。
4. Opening a session shows the main timeline by default, including visible review start/completion lifecycle markers when the transcript records review mode. / 打开会话时默认显示主时间线；当转录记录了 review mode 时，主时间线会显示 review 开始和完成的生命周期标记。
5. The user may switch between `Main timeline`, `Protocol layer`, and `Raw records`. / 用户可以在 `Main timeline`、`Protocol layer` 和 `Raw records` 之间切换。
6. The user may search from the top search bar, use `file:`, `kind:`, `status:`, and `layer:` operators for structured narrowing, choose common analyzed-project files from suggestions, choose current-layer event kinds from dynamic suggestions, inspect grouped tool operations, and see free-text matches highlighted in the currently rendered session list, timeline, and detail panel. / 用户可以从顶部搜索栏搜索，使用 `file:`、`kind:`、`status:` 和 `layer:` 操作符进行结构化收窄，从候选中选择常见的被分析项目文件，从动态候选中选择当前事件层的事件类型，检查分组后的工具操作，并在当前已渲染的会话列表、时间线和详情面板中看到自由文本命中高亮。
7. Expanding a timeline card through folding strategy, event selection, or the small spine control replaces the preview with structured timeline body content: markdown messages, visually distinct `update_plan` status badges and user-input option cards, goal status summaries, image-inspection summaries, structured collaboration cards, readable fallback summaries for unknown tool families, unmodeled text responses retained alongside specialized cards, command run regions for command/stdout/stderr, patch changes, notices, and other primary work output. Timeline cards and inspector chips omit redundant layer labels because the active layer is already visible in the surrounding controls; inspector chips also omit the generic `protocol` kind, empty chip containers are not rendered, and Raw refs subtitles use the event label without repeating layer or kind values. Selected user-input options are highlighted, and plan, goal, or collaboration statuses use distinct styling. Data URLs are omitted from logical timeline summaries, logical detail payload copies, and cached logical previews while remaining available through raw drill-down. Supported embedded raster image payloads are externalized before long-lived indexing. Inspector previews use same-origin URLs that fetch validated bytes only when the browser needs them, are deduplicated, and are capped at eight descriptors per event; additional images remain available through Raw refs. Expanded cards also render a compact bottom collapse icon control. When a card that naturally belongs in summary mode is manually expanded, the small spine control or bottom collapse control returns it to summary mode instead of the more compact collapsed mode. / 通过折叠策略、事件选择或小型脊柱控件展开时间线卡片时，会以内联结构化 timeline 正文替换预览：Markdown 消息、视觉上区分明确的 `update_plan` 状态标记和用户输入选项卡片、goal 状态摘要、图片检查摘要、结构化协作卡片、未知工具族的可读兜底摘要、与专用卡片一同保留的未建模文本响应、command 的命令/stdout/stderr 执行区域、patch 变更、通知以及其他主要工作输出。时间线卡片和检查器 chip 会省略冗余的层级标签，因为当前层已经由周边控件明确展示；检查器 chip 还会省略泛化的 `protocol` 类型，不会渲染空 chip 容器，Raw refs 副标题也只使用事件 label，不再重复层级或类型值。已选择的用户输入选项会高亮，计划、goal 或协作状态会使用不同样式。data URL 会从 logical timeline 摘要、logical detail 载荷副本和缓存的 logical 预览中省略，但仍可通过原始下钻查看。受支持的内嵌 raster 图片 payload 会在长期索引保留前外置。Inspector 预览使用同源 URL，仅在浏览器需要时获取经过验证的字节；预览会去重，并且每个事件最多保留八个 descriptor，更多图片仍可通过 Raw refs 查看。展开卡片底部也会渲染紧凑的收起图标控件。当一个自然属于摘要模式的卡片被手动展开后，小型脊柱控件或底部收起控件会把它恢复到摘要模式，而不是更紧凑的折叠模式。
8. Raw JSON fallback, metadata tables, structured payloads, and other supplemental sections live in the selected-event inspector instead of duplicating the timeline body. / 原始 JSON 回退、元数据表、结构化 payload 以及其他补充区段位于选中事件检查器中，而不重复 timeline 正文。
9. Clicking a timeline event selects it, expands it when needed, and shows a selected-event inspector in the right-side panel with summary only when it adds context, compact metadata, source context, raw refs, and supplemental details named by purpose such as Files, Result, Run context, Arguments, Request, and Response. / 点击时间线事件会选中该事件，在需要时展开它，并在右侧面板显示选中事件检查器；只有概要能补充上下文时才显示概要，同时展示紧凑元数据、来源上下文、原始引用，以及按用途命名的补充详情，例如 Files、Result、Run context、Arguments、Request 和 Response。
10. Clicking the selected-event inspector's `Raw refs` control shows all underlying raw JSONL rows for verification in the right-side panel, with a return path back to the selected-event inspector. / 点击选中事件检查器中的 `Raw refs` 控件会在右侧面板显示所有底层原始 JSONL 行以供验证，并提供返回选中事件检查器的入口。
11. The UI reports filtered session and event result counts while structured filters are active. Free-text search is a find-in-timeline aid rather than an event filter: it treats the remaining `q` text as one case-insensitive contiguous phrase, with each query whitespace run matching one or more whitespace characters, highlights full phrase matches inside the current session and layer, reports the current position against the currently rendered or materialized jump targets, and keeps the backend full-text hit count visible as secondary context. Previous/next controls and Enter/Shift+Enter can materialize additional jump targets by loading later timeline pages or temporarily expanding a matching event whose detail has not been rendered yet; these search-triggered expansions are not saved as folding overrides and clear when the search target changes or the user manually overrides that event. Detail panes opened only by search navigation are transient: they return to the folding strategy panel when free text is cleared or the refreshed query no longer hits the selected event. Detail panes the user explicitly opened through timeline selection, Raw refs/Inspect toggles, selected-event navigation, or navigation-category changes stay open across free-text changes while the selected event remains in the current structured result and layer. Navigating to an inspector match opens its closed supplemental `<details>` ancestors and scrolls the concrete match into view; ordinary highlight refresh does not open them. If a manual fold makes a previously registered body target temporarily unavailable, navigation keeps the stable denominator and skips that target for the current transition instead of becoming stuck. From a selected event in a filtered or non-main view, the user can choose `Read from here` to clear event filters, return to `Main timeline`, and keep reading from the selected event's position or the nearest visible main event. / 当结构化筛选生效时，界面会显示过滤后的会话和事件结果数量。自由文本搜索是时间线内查找辅助，而不是事件筛选器：它会把剩余的 `q` 文本视为一个忽略大小写的连续短语，查询中的每段空白匹配一个或多个空白字符，在当前 session 和事件层中高亮完整短语命中，显示当前位于已渲染或已物化跳转目标中的位置，并把后端全文命中数作为次级上下文保留。上一个/下一个控件以及 Enter/Shift+Enter 可以通过加载后续时间线分页，或临时展开详情尚未渲染的命中事件，来物化更多跳转目标；这些由搜索触发的展开不会保存为折叠覆盖，并会在搜索目标变化或用户手动覆盖同一事件时清除。仅由搜索导航打开的详情面板是临时的：当自由文本被清空，或刷新后的查询不再命中所选事件时，它会回到折叠策略面板。用户通过时间线选择、Raw refs/Inspect 切换、选中事件导航或导航类别变更明确打开的详情，会在自由文本变化时保持打开，只要所选事件仍在当前结构化结果和事件层中。导航到 Inspector 命中时，会展开其关闭的补充 `<details>` 祖先并将具体命中滚动到视口内；普通高亮刷新不会展开这些区段。如果手动折叠使已注册的正文目标暂时不可呈现，导航会保留稳定分母，并在当前转换中跳过该目标，而不会卡住。在筛选后视图或非主时间线视图中选中事件后，用户可以选择 `Read from here` 清除事件筛选、回到 `Main timeline`，并从选中事件的位置或最近的可见主时间线事件继续阅读。
12. Session analysis metrics use a compact display and provide reading-view shortcuts where the metric maps to a useful mode: on Main timeline, nonzero message, issue, file-change, and plan metrics toggle conversation, error-focus, change-review, and planning folding strategies respectively and can return to the previous strategy; on protocol and raw layers, those folding-strategy shortcuts are disabled because profiles are not active there. The Issues metric counts Main-timeline events whose status is `failed` or whose severity is not `normal`. The narrative strategy keeps ordinary high-frequency tool activity compact while expanding goals, developer messages, and review markers. The change-review strategy expands patches, summarizes review commands, and collapses proposed plans, touched-file events, and failed events. The conversation strategy expands message-continuity anchors including proposed plans, goals, compactions, plan updates, `update_plan`, and `request_user_input`, summarizes readable reasoning entries, and keeps unrelated tool internals hidden. The error-focus strategy hides ordinary events by default, while the planning strategy expands only proposed plans, goals, and `update_plan` anchors and collapses other known Main-timeline event kinds. Search focus expands search hits and collapses other important events. The plan metric includes proposed plans and `update_plan` calls. Nonzero protocol metrics toggle the protocol layer and can return to the previous layer. Zero-value metrics remain informational only. / Session 分析指标使用紧凑显示，并在指标能映射到有用模式时提供阅读视角快捷入口：在 Main timeline 上，非零的消息、问题、文件改动和计划指标会分别切换到对话阅读、错误聚焦、改动审查和计划阅读折叠策略，并可返回之前的策略；在 protocol 和 raw layer 上，这些折叠策略快捷入口会禁用，因为 profile 在这些层不生效。Issues 指标统计状态为 `failed` 或 severity 不是 `normal` 的 Main timeline 事件。叙事时间线策略会保持普通高频工具活动紧凑，同时展开 goal、developer message 和 review 标记。改动审查策略会展开 patch、摘要显示 review command，并折叠 proposed plan、触达文件事件和失败事件。对话阅读策略会展开保持消息连续性所需的锚点，包括 proposed plan、goal、compaction、plan update、`update_plan` 和 `request_user_input`，摘要显示可读 reasoning 条目，并隐藏无关工具内部细节。错误聚焦策略默认隐藏普通事件；计划阅读策略只展开 proposed plan、goal 和 `update_plan` 锚点，并折叠其它已知 Main timeline 事件类型。搜索聚焦会展开搜索命中，并折叠其它重要事件。计划指标包含 proposed plan 和 `update_plan` 调用。非零协议指标会切换协议层，并可返回之前的事件层。零值指标仅作为信息展示。

Changing the folding strategy reapplies that strategy's defaults for the selected session instead of keeping stale manual fold overrides, and the reset-folds control only appears after the user manually expands or collapses a timeline card. When a selected event exists, folding-strategy and layer switches keep focus on that event if it remains visible, or move focus to the nearest visible event in the new timeline order; when no event is selected, switches focus the first naturally expanded event if one exists. / 切换折叠策略时，会对当前选中 session 重新应用该策略的默认展开规则，而不是保留过时的手动折叠覆盖；重置展开状态控件只会在用户手动展开或折叠时间线卡片后出现。当存在选中事件时，折叠策略和事件层切换会在该事件仍可见时保持焦点，否则把焦点移到新时间线顺序中最近的可见事件；当未选中事件时，切换后会在存在自然展开事件时聚焦第一个自然展开事件。
16. When no event is selected on Main timeline, the right-side detail panel shows the active folding strategy as editable rule groups for Main timeline event kinds only, with familiar event-kind groups such as conversation, common work, and issues shown before lower-frequency tool and lifecycle kinds; schema-only low-frequency kinds such as `hook` and `subagent` remain governed by built-in rules but are hidden from the editor until they appear in the selected session or a custom strategy changes them. Unsaved edits preview immediately, and Save stores a browser-local custom strategy while Cancel restores the saved strategy. For saved built-in strategies with no unsaved preview, the visible folding-strategy picker provides a nearby info control that opens a hover/focus comparison of all strategy names and descriptions; that single info control follows the active picker between the right-side strategy panel and the topbar. On protocol and raw layers, the profile picker is disabled and the panel explains the layer's fixed display rules with a path back to Main timeline. / 在 Main timeline 上未选中事件时，右侧详情面板会以只适用于 Main timeline 事件类型的可编辑规则组显示当前折叠策略，并把对话、常见工作、问题等熟悉的事件类型分组显示在低频工具和生命周期类型之前；`hook`、`subagent` 等只由 schema 保留的低频 kind 仍受内置规则控制，但会在当前选中 session 出现或自定义策略修改它们之前从编辑器中隐藏。未保存修改会立即预览，Save 会保存为浏览器本地自定义策略，Cancel 会恢复已保存策略。对于没有未保存预览的已保存内置策略，当前可见的折叠策略选择器旁会提供一个说明控件，通过 hover/focus 对比展示所有策略名称和说明；该单一说明控件会在右侧策略面板和顶部栏之间跟随当前生效的选择器。自定义策略和未保存预览状态下会隐藏该说明控件。在 protocol 和 raw layer 上，profile 选择器会禁用，面板会说明该层的固定显示规则，并提供回到 Main timeline 的入口。

## Edge cases / 边界情况

- Sessions with no `session_index.jsonl` entry / 没有 `session_index.jsonl` 条目的会话
- Sessions with partial or malformed JSONL rows / 包含部分或格式错误 JSONL 行的会话
- Old transcripts that only expose tool call plus output without an `event_msg:*_end` row / 只暴露工具调用及输出、但没有 `event_msg:*_end` 行的旧转录
- Empty reasoning records / 空推理记录
- Sessions that contain user-side protocol wrappers such as `<turn_aborted>` and user-initiated shell wrappers such as `<user_shell_command>` / 包含 `<turn_aborted>` 等用户侧协议包装器，以及 `<user_shell_command>` 等用户发起的 shell 包装的会话
- Forked subagent sessions that start with child `session_meta` and then embed parent `session_meta` from forked context / fork 出来的子 agent 会话以子会话 `session_meta` 开头，随后又因 fork 上下文嵌入父会话 `session_meta`

## Metrics / 指标

- Adoption: number of repository sessions loaded and revisited locally / 采用度：本地加载和再次访问的仓库会话数量
- Success: time to locate a prior session or relevant command/file path / 成功指标：定位先前会话或相关命令/文件路径所需时间
- Failure: duplicate content still visible in main timeline, or important protocol data impossible to recover / 失败指标：主时间线中仍可见重复内容，或重要协议数据无法恢复
- Guardrail: raw row drill-down always remains available / 护栏：原始行下钻始终保持可用
