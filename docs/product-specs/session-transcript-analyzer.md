## Summary / 摘要

Session Transcript Analyzer is a local web tool for reviewing Codex session transcripts for a specific repository. It helps a single developer move from raw transcript dumps to usable history: searchable sessions, layered timelines, tool-call analysis, and drill-down into the original JSONL when needed. The product is optimized for long sessions, repeated iterations, and mixed protocol noise inside Codex transcripts.

Session Transcript Analyzer 是一个本地 Web 工具，用于查看特定仓库的 Codex 会话转录。它帮助单个开发者把原始转录转储转化为可用历史：可搜索的会话、分层时间线、工具调用分析，以及在需要时下钻到原始 JSONL。该产品针对长会话、反复迭代，以及 Codex 转录中混杂的协议噪声进行了优化。

## Problem / 问题

- Raw Codex transcripts are long, repetitive, and hard to review after many sessions. / 原始 Codex 转录又长又重复，在许多会话之后很难回顾。
- The same user or assistant content may appear through multiple channels, which makes naive viewers noisy. / 同一用户或助手内容可能通过多个通道出现，这会让朴素查看器产生大量噪声。
- Tool activity, protocol injections, and proposed plans are useful for debugging but should not dominate normal reading. / 工具活动、协议注入和 proposed plan 对调试有用，但不应主导正常阅读。
- Without a local review tool, repository-specific engineering history becomes hard to search and hard to trust. / 如果没有本地查看工具，特定仓库的工程历史会变得难以搜索，也难以信任。

## Target users / 目标用户

- Primary users: individual developers using Codex across many sessions in the same repository / 主要用户：在同一仓库中跨多个会话使用 Codex 的个人开发者
- Secondary users: maintainers debugging transcript format changes or viewer behavior / 次要用户：调试转录格式变化或查看器行为的维护者
- Non-target users: multi-user hosted analytics or cloud reporting consumers / 非目标用户：多用户托管分析或云报告消费者

## Goals / 目标

- Make repository-scoped session history readable without opening raw JSONL files by hand. / 让仓库范围内的会话历史可读，而不需要手动打开原始 JSONL 文件。
- Support fast search across messages, tool calls, files, and outputs. / 支持跨消息、工具调用、文件和输出的快速搜索。
- Provide a main timeline that reflects logical work rather than raw duplicated transcript rows. / 提供反映逻辑工作的主时间线，而不是原始重复转录行。
- Preserve access to protocol and raw transcript detail for debugging and verification. / 保留对协议和原始转录细节的访问，以便调试和验证。

## Non-goals / 非目标

- Cloud sync, shared collaboration, or hosted dashboards / 云同步、共享协作或托管仪表板
- LLM-based summarization or semantic clustering / 基于 LLM 的摘要或语义聚类
- Editing or mutating Codex transcript files / 编辑或变更 Codex 转录文件
- Supporting every historical Codex transcript variant perfectly on day one / 在第一天就完美支持每一种历史 Codex 转录变体

## User stories / 用户故事

- As a developer, I want to list only sessions that touched my current repository, so that unrelated Codex history stays out of the way. / 作为开发者，我希望只列出触及当前仓库的会话，以便排除无关的 Codex 历史。
- As a developer, I want to search for a file path, command, or error string, so that I can jump back to the relevant work quickly. / 作为开发者，我希望搜索文件路径、命令或错误字符串，以便快速跳回相关工作。
- As a developer, I want the default timeline to collapse protocol noise and duplicate message channels, so that I can follow the real flow of work. / 作为开发者，我希望默认时间线折叠协议噪声和重复消息通道，以便跟随真实的工作流程。
- As a maintainer, I want a protocol layer and a raw layer, so that I can verify how the logical timeline was derived. / 作为维护者，我希望有协议层和原始层，以便验证逻辑时间线是如何派生的。
- As a maintainer, I want tool operations grouped by logical call, so that shell runs, patch applications, and MCP calls are easier to inspect. / 作为维护者，我希望按逻辑调用对工具操作分组，以便更容易检查 shell 运行、补丁应用和 MCP 调用。

## User-facing behavior / 面向用户的行为

1. The user starts the local server through the `session-analyzer` CLI, commonly via `npx session-analyzer`, with an optional repository root; if omitted, the browser can show configured Codex workspaces immediately, then update project activity after transcript scanning discovers session working directories. / 用户通过 `session-analyzer` CLI 启动本地服务器，常见方式是 `npx session-analyzer`，并可传入可选的仓库根目录；如果省略，浏览器可以先立即显示已配置的 Codex 工作区，然后在转录扫描发现会话工作目录后更新项目活动信息。
1. Invalid CLI values fail before the HTTP server starts: `--port` must be an integer from `1` to `65535`, `--host` must not be empty, unknown options and positional arguments are rejected, a small set of common option spelling variants such as `--repos` and `--codexhome` are accepted as aliases, the CLI prints a user-facing error plus usage/help, and the process exits non-zero. / 无效的 CLI 参数会在 HTTP 服务器启动前直接失败：`--port` 必须是 `1` 到 `65535` 的整数，`--host` 不能为空，未知 option 和位置参数会被拒绝，少量常见 option 拼写变体（如 `--repos` 和 `--codexhome`）会作为别名接受；CLI 会打印面向用户的错误信息和 usage/help，并以非零状态退出。
1. When a project is already selected, opening the idle project chooser keeps a return path: clicking the project switch control again exits the chooser and restores the currently indexed project. While a replacement project is indexing, the top bar is hidden and the chooser's cancel control remains the cancellation path. / 当已经选择了项目时，打开空闲的项目选择器仍保留返回路径：再次点击项目切换控件会退出选择器并恢复当前已索引项目。替换项目正在索引时，顶部栏会隐藏，项目选择器内的取消控件仍是取消入口。
2. The application scans the local Codex home and shows only sessions matching the selected repository. / 应用扫描本地 Codex 主目录，并只显示与所选仓库匹配的会话。
3. The user sees a session list with counts, sizes, timestamps, and failure indicators; long rows are height-limited by default and reveal their full content on hover or keyboard focus. Forked subagent and review sessions remain selectable but render as visually secondary derived sessions with their source session title when available, and hovering or focusing a derived session lightly highlights its visible parent. Plain user-created `/fork` sessions remain normal primary rows but show a `Fork · from ...` relationship tag when the source session is known. / 用户看到包含计数、大小、时间戳和失败指示器的会话列表；较长的条目默认限制高度，并在鼠标悬停或键盘聚焦时显示完整内容。fork 出来的子 agent 和 review 会话仍可选择，但会以视觉上次级的派生会话呈现，并在可用时显示来源会话标题；悬停或聚焦派生会话时，会轻量高亮当前可见的父会话。普通用户发起的 `/fork` 会话仍作为普通主会话行展示，但在已知来源会话时显示 `Fork · from ...` 关系标签。
4. Opening a session shows the main timeline by default, including visible review start/completion lifecycle markers when the transcript records review mode. / 打开会话时默认显示主时间线；当转录记录了 review mode 时，主时间线会显示 review 开始和完成的生命周期标记。
5. The user may switch between `Main timeline`, `Protocol layer`, and `Raw records`. / 用户可以在 `Main timeline`、`Protocol layer` 和 `Raw records` 之间切换。
6. The top search HUD stays on one line and continuously shows the current scope, active-filter count, free-text input, and compact scope metrics; session scope also exposes previous/next navigation. The canonical global Layer selector remains immediately beside the search field and is not duplicated inside the HUD. The input holds only free text, so operator-like text such as `status:failed` is searched literally. The Scope and Filters pills open the non-modal search-options popover at their corresponding controls; Filters focuses an always-visible quick-filter grid: Kind and Status share the first row, and the `Touched file` display control backed by the stable `file` field spans the second row. Each cross-layer control's `Any…` value is its inactive and clear state, so adding or removing one of the three cross-layer filters requires no intermediate field-management action. Focusing or typing in an active free-text search shows only a compact result popover. Idle parameter state hides result breakdown, navigation guidance, and `Clear all`; those regions appear only when the current expression makes them meaningful. The Layer row links to the adjacent global Layer selector rather than creating a second Layer state. Filter suggestions use the active scope plus current Layer: the selected session in current-session scope, or all indexed project sessions in project scope. The touched-file combobox keeps its suggestion surface visible with a clear empty-state message when that context has no files or the typed fragment has no matches. `Clear all` removes free text and structured filters while preserving scope and Layer. When a project-scope expression changes, old result cards and counts disappear immediately and remain in a searching state until the new request context commits. / 顶部搜索 HUD 始终保持单行，并持续显示当前范围、生效筛选数、自由文本输入和紧凑的范围计数；session 范围还提供上一个/下一个导航。唯一的全局层级选择器紧邻搜索框保留，不在 HUD 内重复展示。输入框只保存自由文本，因此 `status:failed` 等类似操作符的文本会按字面搜索。范围与筛选胶囊会在非模态搜索选项弹层中打开并聚焦各自控件；筛选会聚焦始终可见的快速筛选网格：类型与状态位于第一行，由稳定 `file` 字段支持的“涉及文件”展示控件独占第二行。每个跨层控件的“任意……”值同时表示未启用和清除状态，因此启用或移除这三个跨层筛选之一不需要中间的字段管理动作。聚焦或输入已有自由文本搜索时，只显示紧凑结果弹层。空闲参数状态会隐藏结果明细、导航提示和“全部清除”；仅在当前表达式使这些区域有意义时才显示。层级行链接到相邻的全局层级选择器，不创建第二份层级状态。筛选候选使用当前范围加当前层级：当前 session 范围使用所选 session，项目范围使用已索引项目中的所有 session。当该上下文没有文件，或输入片段没有匹配项时，涉及文件组合框仍保持候选表面可见，并显示明确的空状态提示。`全部清除` 会移除自由文本和结构化筛选，同时保留范围与层级。项目范围表达式变化时，旧结果卡和旧计数会立即消失，并保持搜索中状态，直到新的请求 context 提交。

On Main timeline only, the same filter surface adds the independent `Code Mode request / Code Mode 请求` control. Its exact stable value is `codeModeRequest=<tool-name>`; the localized option catalog counts matching Code Mode operations rather than calls or executions. It is distinct from Event type, composes with free text, Kind, Status, and Touched file on the same parent event, and is cleared when the user switches to Protocol or Raw so no invisible constraint survives. Current-session and entire-project scopes both support it, and the active chip retains the full provenance label, for example `Code Mode request: Shell command / Code Mode 请求：Shell command`. / 仅在 Main timeline 中，同一筛选表面还会增加独立的 `Code Mode request / Code Mode 请求` 控件。它的精确稳定值为 `codeModeRequest=<tool-name>`；本地化选项目录按匹配的 Code Mode operation 计数，而不是按调用或执行计数。它与 Event type 相互独立，与自由文本、Kind、Status 和 Touched file 在同一个父事件上组合，并会在用户切换到 Protocol 或 Raw 时清除，避免保留不可见约束。当前 session 与整个项目范围都支持它；生效 chip 保留完整来源标签，例如 `Code Mode request: Shell command / Code Mode 请求：Shell command`。
7. Expanding a timeline card through folding strategy, event selection, or the small spine control replaces the preview with structured timeline body content: markdown messages, visually distinct `update_plan` status badges and user-input option cards, goal status summaries, image-inspection summaries, structured collaboration cards, readable fallback summaries for unknown tool families, unmodeled text responses retained alongside specialized cards, command run regions for command/stdout/stderr, patch changes, notices, and other primary work output. Timeline headers omit protocol channels and Raw-ref counts for every event kind and layer; those provenance facts remain in inspector metadata and the Raw refs action. Timeline cards and inspector chips also omit redundant layer labels because the active layer is already visible in the surrounding controls; inspector chips omit the generic `protocol` kind, empty chip containers are not rendered, and Raw refs subtitles use the event label without repeating layer or kind values. Selected user-input options are highlighted, and plan, goal, or collaboration statuses use distinct styling. Data URLs are omitted from logical timeline summaries, logical detail payload copies, and cached logical previews while remaining available through raw drill-down. Supported embedded raster image payloads are externalized before long-lived indexing. Inspector previews use same-origin URLs that fetch validated bytes only when the browser needs them, are deduplicated, and are capped at eight descriptors per event; additional images remain available through Raw refs. Expanded cards also render a compact bottom collapse icon control. When a card that naturally belongs in summary mode is manually expanded, the small spine control or bottom collapse control returns it to summary mode instead of the more compact collapsed mode. / 通过折叠策略、事件选择或小型脊柱控件展开时间线卡片时，会以内联结构化 timeline 正文替换预览：Markdown 消息、视觉上区分明确的 `update_plan` 状态标记和用户输入选项卡片、goal 状态摘要、图片检查摘要、结构化协作卡片、未知工具族的可读兜底摘要、与专用卡片一同保留的未建模文本响应、command 的命令/stdout/stderr 执行区域、patch 变更、通知以及其他主要工作输出。所有事件类型和层级的时间线 header 都省略协议 channel 与 Raw-ref 数量；这些来源事实继续保留在 inspector metadata 与 Raw refs 动作中。时间线卡片和检查器 chip 也会省略冗余的层级标签，因为当前层已经由周边控件明确展示；检查器 chip 还会省略泛化的 `protocol` 类型，不会渲染空 chip 容器，Raw refs 副标题也只使用事件 label，不再重复层级或类型值。已选择的用户输入选项会高亮，计划、goal 或协作状态会使用不同样式。data URL 会从 logical timeline 摘要、logical detail 载荷副本和缓存的 logical 预览中省略，但仍可通过原始下钻查看。受支持的内嵌 raster 图片 payload 会在长期索引保留前外置。Inspector 预览使用同源 URL，仅在浏览器需要时获取经过验证的字节；预览会去重，并且每个事件最多保留八个 descriptor，更多图片仍可通过 Raw refs 查看。展开卡片底部也会渲染紧凑的收起图标控件。当一个自然属于摘要模式的卡片被手动展开后，小型脊柱控件或底部收起控件会把它恢复到摘要模式，而不是更紧凑的折叠模式。
For non-base64 data URLs embedded in logical text, explicit `%HH`, uppercase, or symbol/numeric-only continuation tokens across newline/tab boundaries remain redacted. Ordinary lowercase prose after that boundary remains visible and searchable even when it contains path separators, snake_case, URL punctuation, `+`, or `=`. / 对嵌入逻辑文本的非 base64 data URL，跨换行/tab 边界的明确 `%HH`、全大写或仅符号/数字 continuation token 仍会被脱敏。边界后的普通小写正文即使包含路径分隔符、snake_case、URL 标点、`+` 或 `=`，仍然可见且可搜索。

8. Raw JSON fallback, metadata tables, structured payloads, and other supplemental sections live in the selected-event inspector instead of duplicating the timeline body. / 原始 JSON 回退、元数据表、结构化 payload 以及其他补充区段位于选中事件检查器中，而不重复 timeline 正文。
8. A Code Mode outer `exec`, its pending cell, and matching `wait` chain appear as one neutral tool operation rather than independent poll events. Every Code Mode operation shows a `Code Mode` source chip and omits the outer `exec` tool chip. When safe structured projections are unavailable, its expanded body prioritizes the outer JavaScript command and final observed output under the `Script operation` title; while collapsed or summarized, it shows one sanitized `Source` preview chosen from the outer JavaScript, not a partial declaration or execution claim. Exactly one safe declared request uses that tool's ordinary structured body without a projection wrapper; its compact header keeps the native tool presentation, while folded states show a compact request-only `Request` summary without repeating the tool title. Every safely projected tool type must produce this summary: specialized request fields are preferred and a sanitized scalar or localized no-argument marker is the bounded fallback. A final observed operation output that does not meet the supported result-output shape remains in a separate `Operation output` section; it receives no header warning and is not presented as the declared tool's result. Two or more safe declarations retain the composite projection cards under the `Multiple operations` title with a compact tool count; while collapsed or summarized, they show a bounded, source-ordered `Declared sequence` preview using tool labels and key request content only. Neither compact preview uses results, waits, or nested lifecycle records as execution evidence. Request evidence, machine tool name, result-association detail, protocol channel, Raw-ref count, outer source, operation metadata, and wait trace remain available in the inspector instead of competing for header space. / Code Mode 的 outer `exec`、pending cell 与匹配的 `wait` 链会显示为一个中性工具操作，而不是相互独立的 poll 事件。所有 Code Mode operation 都显示一个“代码模式”来源 chip，并省略 outer `exec` 工具 chip。无法安全生成结构化投影时，展开正文以“脚本操作”为标题，优先展示 outer JavaScript 命令和最终已观测输出；在折叠或摘要态则显示从 outer JavaScript 选出的、已脱敏的“源码”预览，它不是局部声明列表，也不表示已执行。恰好一个安全声明 request 时，使用该工具的普通结构化正文而不增加投影 wrapper；紧凑 header 保留原生工具呈现，折叠状态则显示不重复工具标题、仅来自 request 的紧凑“请求”摘要。每一种可安全投影的工具类型都必须生成该摘要：优先使用专用 request 字段，并以脱敏后的标量或本地化“无参数”标记作为有界兜底。不满足受支持结果输出形态的最终已观测操作输出会保留在独立的“操作输出”区域；它不显示 header 警示，也不会被呈现为声明工具的结果。两个及以上安全声明继续使用复合投影卡片，标题为“多个操作”并显示紧凑工具数量；在折叠或摘要态会显示一个有上限、按源码顺序排列的“声明顺序”预览，其中仅包含工具展示名和关键 request 内容。两种紧凑预览都不会使用结果、wait 或嵌套 lifecycle 记录作为执行证据。Request evidence、机器工具名、result association 详情、协议 channel、Raw-ref 数量、outer source、operation metadata 与 wait trace 继续位于 inspector，不与 header 的主要信息竞争空间。

The request names that pass whole-program eligibility are additionally recorded as an independent, name-only presentation fact, not as a canonical field or execution record. A lightweight timeline DTO may expose `presentationFacts.codeModeDeclaredRequests` with `toolNames` and `requestEvidence: 'declared_source'`; full arguments, AST nodes, outer source, result association, and all observed outcome evidence remain detail or Raw-reference data. Dynamic arguments or dispatch, unsupported bindings, branches, loops, concurrency, unknown tools, syntax errors, and source/call/literal budget failures contribute no fact. The fact does not create or alter event IDs, kinds, subtypes, tool names, status, severity, touched files, metrics, search ownership, Raw refs, escalation, results, outcomes, or independently visible Observed Nested Activity. / 通过整段程序资格检查的 request 名称还会记录为独立、仅名称的呈现事实，而不是 canonical 字段或执行记录。轻量 timeline DTO 可以通过 `presentationFacts.codeModeDeclaredRequests` 暴露带有 `toolNames` 和 `requestEvidence: 'declared_source'` 的数据；完整 arguments、AST 节点、outer source、result association 以及所有已观测 outcome 证据仍属于 detail 或 Raw-reference 数据。动态参数或分派、不受支持的 binding、分支、循环、并发、未知工具、语法错误以及 source/call/literal 预算失败都不贡献事实。该事实不会创建或改变 event ID、kind、subtype、tool name、status、severity、touched files、指标、搜索 ownership、Raw refs、提权、result、outcome 或独立可见的 Observed Nested Activity。

For a raw `Script operation`, the collapsed `Source` preview remains one sanitized source line, with the whole source sanitized before excerpt-line selection. LF, CRLF, lone CR, U+2028, and U+2029 each delimit logical source lines. Its frameless summary row may show up to two source-ordered sanitized logical lines, but each logical line occupies one independently truncated visual row; a single source line is not enlarged merely to fill summary space. The short source label is visually secondary to the preview text. ## Edge cases / 边界情况

- Sessions with no `session_index.jsonl` entry / 没有 `session_index.jsonl` 条目的会话
- Sessions with partial or malformed JSONL rows / 包含部分或格式错误 JSONL 行的会话
- Old transcripts that only expose tool call plus output without an `event_msg:*_end` row / 只暴露工具调用及输出、但没有 `event_msg:*_end` 行的旧转录
- Empty reasoning records / 空推理记录
- Sessions that contain user-side protocol wrappers such as `<turn_aborted>` and user-initiated shell wrappers such as `<user_shell_command>` / 包含 `<turn_aborted>` 等用户侧协议包装器，以及 `<user_shell_command>` 等用户发起的 shell 包装的会话
- Forked subagent sessions that start with child `session_meta` and then embed parent `session_meta` from forked context / fork 出来的子 agent 会话以子会话 `session_meta` 开头，随后又因 fork 上下文嵌入父会话 `session_meta`
- Code Mode JavaScript with branches, loops, concurrency, dynamic tool selection, or ambiguous output ordering; Nested Tool Projections must use `none` or raw fallback rather than a bounded result association. / 包含分支、循环、并发、动态工具选择或歧义输出顺序的 Code Mode JavaScript；嵌套工具投影必须使用 `none` 或 raw fallback，不得使用 bounded 结果关联。

## Metrics / 指标

- Adoption: number of repository sessions loaded and revisited locally / 采用度：本地加载和再次访问的仓库会话数量
- Success: time to locate a prior session or relevant command/file path / 成功指标：定位先前会话或相关命令/文件路径所需时间
- Failure: duplicate content still visible in main timeline, or important protocol data impossible to recover / 失败指标：主时间线中仍可见重复内容，或重要协议数据无法恢复
- Guardrail: raw row drill-down always remains available / 护栏：原始行下钻始终保持可用
