## Identity and statistics conventions / 身份与统计约定

Branch grouping, native-entry bookmarks and readable recorded-state/image evidence are implemented in the [history workflow design](pi-history-navigation.md). Deduplicated native/project totals and full recorded-context projection remain deferred. / 分支分组、原生 entry 书签及可读状态／图片依据按所列设计实现；去重原生／项目总量及完整记录上下文投影继续延后。

1. Group visible branches by `(sourceKind, sourceSessionId)` within the admitted source root, retaining artifact provenance separately. `sourceSessionId` is the native session ID; `sourceDerivedId` is the leaf entry ID. Canonical `pi:<encoded-session-id>:<encoded-leaf-id>` identifies a root-to-leaf snapshot; appending a child replaces that leaf Session ID. Last persisted entry / “latest” describes persisted evidence, not the current interactive cursor: navigation without persistence can move the cursor. [Grouping fixtures](../../test/pi-branches.test.js), [native branches](../../test/pi.test.js). / 在准入根内按所列身份分组可见分支，另保留工件来源；sourceSessionId 为原生会话 ID，sourceDerivedId 为叶 entry ID。canonical ID 标识根到叶快照；追加子节点会替换叶 Session ID。最后持久化 entry／“latest”仅描述持久化依据，不代表当前交互游标；未持久化导航也可移动游标。
2. Canonical event/Raw IDs still include the leaf. Separate `pi-entry-v1` bookmarks contain admitted root/project scope, artifact/native/entry identity, exact entry digest and optional logical projection. Append/reindex can resolve the same entry on new descendant leaves; shared entries require branch choice. Changed evidence is unavailable; old snapshot-bound references are unchanged. Same-branch Detail refs coexist with verified cross-branch summary/label actions. [Navigation fixtures](../../test/pi-navigation.test.js). / canonical event／Raw ID 仍含叶；独立书签包含准入根／项目范围、工件／原生／entry 身份、精确 entry 摘要及可选逻辑投影。追加重建可解析到新后代叶中的同一 entry，共享 entry 需选择分支；改变依据不可用，旧绑定快照引用不变。同分支详情引用与已核验跨分支摘要／标签操作并存。
3. Label counts as selected root-to-leaf path statistics **including shared prefixes**. Rendered event counts can differ from native message/request counts; one outer call remains one tool count despite nested receipts. `bytes`/`lineCount` describe the artifact, not branch-owned bytes/lines. Never obtain whole-native totals by summing leaf analyses. Future aggregation must deduplicate physical entries and derived contributors. A shared call can complete differently on descendant branches: identify calls by call-entry/block, results by physical result entry, retaining sibling outcomes separately. [Branch ownership](../../test/pi.test.js), [nested ownership](../../test/pi-reading-evidence.test.js), [shared file-call outcomes](../../test/pi-file-accounting.test.js). / 计数标为所选根到叶路径统计，**包含共享前缀**；展示事件数可不同于原生消息／请求数，嵌套回执不增加外层工具计数。bytes／lineCount 描述工件，不代表分支拥有的字节／行；不可累加叶分析得到完整原生总量。未来聚合须按物理 entry 及派生贡献项去重；共享调用可在不同后代有不同结果，分别按调用 entry／block、物理结果 entry 标识并保留兄弟结果。
4. **File activity is recorded request/path evidence; confirmed patch statistics require admitted result evidence.** Reads/writes/searches and failed/incomplete edits may appear in file activity through valid recorded paths. `counts.patches` counts successful admitted edit operations; `analysis.patchedFiles` records their per-path occurrence counts, and the Files metric counts those distinct patched paths; write content, replacement requests, invalid patches and generic tools add no confirmed patch. Additions/deletions count complete admitted hunks even when Detail is truncated; they do not measure final file contents or unique lines changed across a branch. Shared-prefix file activity appears on each containing branch; no deduplicated whole-native file total is exposed. [Native fixtures](../../test/pi-native-tools.test.js), [branch accounting](../../test/pi-file-accounting.test.js), [Files browser fixture](../../e2e/pi-native-tools.test.js). / **文件活动是记录的请求／路径依据；确认的 patch 统计要求准入的结果依据。** read／write／搜索及失败／不完整 edit 可通过有效记录路径进入文件活动。counts.patches 计成功且准入的 edit 操作，analysis.patchedFiles 记录逐路径出现次数，Files 指标计这些不同的 patch 路径；write 内容、替换请求、无效 patch 及通用工具不增加确认 patch。增删数按完整准入 hunk 统计，即使 Detail 已截断；不代表最终文件内容或分支内去重变更行。共享前缀活动会出现在每个包含它的分支，不提供去重的完整原生文件总量。
5. Branch Detail separates assistant work, toolResult nested model work, standalone usage (any kind), compaction and branch-summary partial sums, with eligible/missing-receipt/field coverage. Explicit zero, missing/invalid fields and overflow remain distinct. `reasoning` is included in output; `cacheWrite1h` is a subset of cacheWrite. Preserve recorded cost without tariff/billing/cache inference or double counting main/nested work.
