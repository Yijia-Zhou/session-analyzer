# Background terminal requests / 后台终端请求

## Scope / 范围

Phase A interprets durable Codex `response_item/function_call(name=write_stdin)` arguments as request evidence. Phase B adds a bounded, fail-closed presentation relation to an originating direct `exec_command`. Each call remains its existing Logical Event. Canonical `exec_command` classification is unchanged. / A 阶段将 durable Codex `response_item/function_call(name=write_stdin)` 的 arguments 解释为请求证据。B 阶段新增有界、fail-closed 的 presentation relation，指向起始 direct `exec_command`。每次调用保留原有 Logical Event，canonical `exec_command` 分类不变。

## Facts and ownership / 事实与归属

- Exactly one durable function request must belong to the event. Missing `chars` or an empty string means `poll`; every nonempty string means `input`, including whitespace, newline, Ctrl-C and escape sequences. Invalid JSON, non-object arguments and non-string explicit `chars` fall back to generic presentation. / Event 必须拥有恰好一条 durable function request。缺失 `chars` 或空字符串表示 `poll`；所有非空字符串均表示 `input`，包括空白、换行、Ctrl-C 和转义序列。无效 JSON、非对象参数和显式非字符串 `chars` 回退到通用展示。
- `session.presentationIndexes.backgroundTerminalRequests` maps existing event IDs to `{action, processId?}`. `processId` is admitted only for a JSON integer in the source i32 range; invalid IDs do not erase independently valid action evidence. This number identifies the requested runtime process, not the Analyzer Session or a permanent process identity. / 该索引将既有 event ID 映射到 `{action, processId?}`。仅接受源 i32 范围内的 JSON 整数 ID；无效 ID 不抹去独立有效的 action 证据。该数字是请求中的 runtime process ID，不是 Analyzer Session 标识或永久 process identity。
- Facts are rebuilt during materialized-session finalization from existing raw arguments. They are not added to the durable project-query store or canonical Logical Event. No canonical schema version change is needed; server restart discards old in-memory materializations. / 在 materialized session finalization 中从既有 raw arguments 重建事实，不加入持久 project-query store 或 canonical Logical Event。无需修改 canonical schema version；服务重启丢弃旧的内存 materialization。
- Request facts contain no stdin, output, command text, origin ID or Raw References. Separate `backgroundTerminalOrigins` stores only `{processId, commandPreview}` per referenced origin (at most 160 Unicode code points, no control characters); `backgroundTerminalContinuations` stores `{originEventId}` per admitted W. No input/output payload is copied. Existing generic search storage is unchanged; this is not a global stdin-redaction change. / Request facts 不包含 stdin、output、command text、origin ID 或 Raw References。独立的 `backgroundTerminalOrigins` 对被引用 origin 仅保存 `{processId, commandPreview}`（最多 160 个 Unicode code point，移除控制字符）；`backgroundTerminalContinuations` 对准入 W 保存 `{originEventId}`。不复制输入／输出 payload。既有 generic 搜索存储不变，本次并非全局 stdin 脱敏。

Contract validation is bidirectional: every continuation references an owned matching origin, and every stored origin has at least one continuation. Empty maps and multiple continuations sharing one origin are valid; orphan origins and dangling references are rejected. / Contract 双向校验：每条 continuation 引用所属的匹配 origin，每个保存的 origin 至少被一条 continuation 引用。空映射及多条 continuation 共享 origin 合法；拒绝 orphan origin 与悬空引用。

Native and single-tool Code Mode Detail compose request and response metadata into one untitled KV panel. An identical response process ID appears only once; a different response ID is explicitly labeled `Response Process ID`, and a missing request ID remains unknown. Composition uses display copies without mutating request/result sections or their evidence ownership. Input and literal stdout (including JSON-looking stdout) remain separate and intact. / Native 与 single-tool Code Mode Detail 将请求／响应 metadata 组合为一个无标题 KV 面板。响应进程 ID 相同时只显示一次；不同时明确标为“响应进程 ID”，请求 ID 缺失时仍保持未知。组合只使用展示副本，不修改请求／响应 section 及其证据归属。输入及原样 stdout（包括看似 JSON 的 stdout）仍独立保留。

## Strict format admission / 严格格式准入

The user explicitly selected format admission rather than a guessed release range. `native-local-direct-v1` is based on commit `624ccf794703e2d84e748fc3ef547d6191a8c0a4`; its Cargo version is `0.0.0`, so no semver range is asserted. Required leading metadata: `session_meta` at physical line 1; nonempty `id`; `session_id === id`; `originator === "codex_cli_rs"`; a syntactically valid `cli_version`; `source` is `cli` or `exec`; history mode is absent/null or `legacy`; no parent/fork/history-base/inherited ordinal and no dynamic tools. Paginated/ordinal-bearing records, namespaced calls, other producers and exports lacking this shape fall back to Phase A. This trusts normally produced supported Codex history, not external modification-proof authenticity. / 用户明确选择按格式准入，不猜 release 范围。Profile 基于上述 commit，其 Cargo 版本为 `0.0.0`，故不声明 semver 范围。首条 metadata 要求：物理行 1 的 `session_meta`、非空 `id`、`session_id === id`、`originator === "codex_cli_rs"`、语法有效的 `cli_version`、`source` 为 `cli` 或 `exec`、history mode 缺失／null 或 `legacy`，没有 parent／fork／history-base／继承 ordinal 或 dynamic tools。Paginated／带 ordinal 记录、namespaced calls、其他 producer 和不符合形态的 export 均降级至 A。这里信任正常产生的受支持 Codex history，不证明其未被外部篡改。

Only direct terminal requests/results and passive messages, reasoning, turn context, world state, token accounting, and recognized turn/message events are admitted. Initial `thread_settings_applied` before any tool is allowed; later settings are a conservative runtime boundary. Any unsupported record or opaque tool taints the remaining source segment; completing an outer tool does not clear that taint. Blank/malformed skipped lines mark the next real Raw Record as a barrier, without inventing a Raw Record or reference. Compact raw state retains only the optional `terminalSourceEvidence` scalar (`native-local-direct-v1` or `barrier`). / 仅准入 direct terminal request／result 与被动消息、reasoning、turn context、world state、token accounting 和已识别的 turn／message events。工具前的初始 `thread_settings_applied` 放行，后续 settings 保守视为 runtime 边界。任何不支持记录或不透明工具都会阻断该 source segment 的剩余部分，外层工具返回不解除阻断。被跳过的空行／坏行使下一条真实 Raw Record 带 barrier 标记，不制造 Raw Record 或引用。Compact raw 仅增加可选 `terminalSourceEvidence` 标量（profile 或 barrier）。

Full physical order is paired before a linear sweep. Every exec request advances the creation generation and invalidates older candidates; a new receipt opens an epoch only if no prior creator overlaps it. Same-ID W spans that overlap are rejected. The origin snapshot captured at W.request must still be current at W.output. This tests the closed interval through the result, including later same-cycle creation, without a permanent process-ID map. A terminal or unrecognized W response closes eligibility for that ID until a new origin. / 先按完整物理顺序配对，再线性扫描。每次 exec request 递增创建代数并使旧候选失效；仅无此前 creator 重叠时，新 receipt 才开启 epoch。拒绝重叠的同 ID W span。W.request 时捕获的 origin 到 W.output 时必须仍为当前候选，因此覆盖闭区间及同 cycle 后续创建，不使用永久 process-ID map。W 的 terminal 或无法识别 response 使该 ID 失去准入资格，直到新 origin。

Receipt grammar is the direct formatter's LF prefix: optional `Chunk ID`, mandatory four-decimal `Wall time`, exactly one running-ID or exit-code line, optional original-token count, and `Output:` followed by LF. IDs/codes must be i32. Body text, arbitrary JSON results, old headers and conflicting fields never establish access. A nonzero exit receipt proves process access but does not change canonical status or prove stdin success. / Receipt grammar 是 direct formatter 的 LF 前缀：可选 `Chunk ID`、四位小数的 `Wall time`、恰好一条 running-ID 或 exit-code、可选 original-token count，以及后接 LF 的 `Output:`；ID／code 须为 i32。正文、任意 JSON result、旧 header 或冲突字段不能建立访问证据。非零退出 receipt 可证明访问 process，但不改变 canonical status 或证明 stdin 成功。
