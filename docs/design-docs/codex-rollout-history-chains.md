# Codex rollout history chains / Codex rollout 历史链

Status: accepted; automated and real-project acceptance evidence is maintained in the [completed execution plan](../exec-plans/completed/2026-10-14-codex-rollout-history-chains.md). / 状态：已接纳；自动及真实项目验收依据记录于[已完成计划](../exec-plans/completed/2026-10-14-codex-rollout-history-chains.md)。

## Source authority / 来源依据

Pinned Codex `rust-v0.162.1` [revert writer](https://github.com/openai/codex/blob/rust-v0.162.1/codex-rs/thread-store/src/local/revert_thread.rs) preserves the logical thread ID, writes a new physical rollout, then atomically replaces SQLite's current rollout pointer. A written file alone is not proof that cutover succeeded. [Filename parsing](https://github.com/openai/codex/blob/rust-v0.162.1/codex-rs/rollout/src/rollout_file_name.rs) distinguishes the logical thread ID from the optional suffixed RolloutId. [HistoryPosition](https://github.com/openai/codex/blob/rust-v0.162.1/codex-rs/protocol/src/protocol.rs) names that physical ID through its legacy `thread_id` field. / 固定版本的回退 writer 保留逻辑线程 ID，先写新物理 rollout，再原子替换 SQLite 当前文件指针；文件已写入不证明切换成功。文件名解析区分逻辑线程 ID 与可选后缀 RolloutId；HistoryPosition 通过旧字段 thread_id 引用物理 ID。

[Lineage resolution](https://github.com/openai/codex/blob/rust-v0.162.1/codex-rs/thread-store/src/local/rollout_lineage.rs) follows explicit prefixes in ancestor-to-head order. Byte boundaries address decoded JSONL, including for Zstd artifacts. The [ordinal writer](https://github.com/openai/codex/blob/rust-v0.162.1/codex-rs/rollout/src/ordinal.rs) starts each file at its inherited exclusive ordinal (zero without a base); its initial metadata consumes one ordinal. [Model-context replay](https://github.com/openai/codex/blob/rust-v0.162.1/codex-rs/thread-store/src/local/model_context.rs) omits each segment's metadata and uses the selected head's canonical metadata. Analyzer uses these storage facts without claiming to reconstruct the model's exact input. / 谱系解析按祖先至当前文件顺序跟随显式前缀。字节边界针对解码后的 JSONL，Zstd 亦同。每份文件从继承前缀的排他序号开始，无基底时为零；首条 metadata 占一个序号。上游模型上下文回放略过各分段 metadata，使用所选当前文件的规范 metadata。Analyzer 使用这些存储事实，不声称还原模型的精确输入。

## Admission and selection / 准入与选择

Project matching identifies candidate logical Sessions before archive dependency traversal. Traversal starts from every discovered active artifact belonging to those Sessions, including artifacts whose recorded cwd differs from the requested project, so head selection and dependency discovery use the same scope. An archived artifact can supply a retained prefix but cannot become a standalone Session head. If the only resolved head is archived, exclude that standalone Session with a diagnostic while retaining valid dependent and unrelated Sessions; do not silently fall back to its older active artifact. / 项目匹配先确定候选逻辑会话，再遍历归档依赖。遍历从这些会话的全部已发现活动工件出发，包含记录 cwd 与所选项目不同的工件，使链头选择与依赖发现范围一致。归档工件可以提供保留前缀，但不能成为独立会话链头。若唯一解析出的链头已归档，则诊断并排除该独立会话，同时保留有效依赖会话及无关会话；不能静默回退到它较早的活动工件。

Discovery keeps physical artifact identity separate from Session identity. An affected logical Session reads only its requested `threads.id` / `threads.rollout_path` rows from the known `state_5.sqlite` in the selected Codex home. The database is opened read-only, never created or migrated, and is not a history-content source. Committed WAL rows are visible. Canonical path resolution supports directory aliases and Windows namespace paths while rejecting escapes from the selected sessions root. The chosen path must match a discovered artifact and its header owner. / 发现阶段分开物理工件身份与会话身份。受影响会话只读取所选 Codex home 中已知 state_5.sqlite 的所需 id／rollout_path 行。数据库以只读方式打开，不创建或迁移，也不提供历史正文；可读已提交 WAL 行。规范路径解析支持目录别名与 Windows namespace 路径，同时拒绝越出所选 sessions 根的指针。所选路径必须对应已发现工件及其头部归属。

A valid pointer may choose an ancestor or one branch while newer unselected artifacts remain on disk. Without a usable pointer, only a unique connected filesystem head is readable, accompanied by `CODEX_HISTORY_HEAD_INFERRED`; this is not a claim about Codex's active state. Explicitly invalid pointers, ambiguous heads, missing bases, cycles, owner conflicts and invalid boundaries exclude the affected Session with source diagnostics. Other valid Sessions remain readable. No newest-mtime rule, fabricated Session ID, silent tail merge or source modification is used. / 有效指针可以选择祖先或某分支，其他较新工件仍留在磁盘。没有可用指针时，仅唯一且连通的文件系统链尾可读，同时报告所列推断诊断，不宣称这是 Codex 当前活动状态。明确无效指针、歧义链尾、缺失基底、循环、归属冲突及无效边界会排除受影响会话并报告来源诊断；其他有效会话仍可读。不根据最新修改时间选择，不虚构会话 ID、不静默拼入尾部、不改来源。

The accepted chain has at most 4096 artifacts. Every selected segment requires paginated metadata, complete nonblank JSONL records, contiguous recorded top-level ordinals and matching exclusive byte/ordinal bounds. Unsupported or incomplete inputs produce diagnostics instead of guessed history. Explicitly referenced ancestors may be resolved in the selected Codex home's `archived_sessions` sibling; they remain dependencies rather than standalone candidate Sessions. Only the exact `../archived_sessions/` source prefix is permitted, with canonical home/archive containment and symlink-escape checks. Custom Codex SQLite-home configuration and other state database versions are not discovered automatically. / 已接纳历史链最多 4096 个工件。每段要求 paginated metadata、完整非空 JSONL 记录、连续的顶层 ordinal，以及相符的排他字节／序号边界。不支持或不完整的输入报告诊断，不猜测历史。显式引用的祖先可从所选 Codex home 的 archived_sessions 同级目录解析；它们仅为依赖，不作为独立候选会话。仅允许精确的 ../archived_sessions/ 来源前缀，校验规范 home／archive 范围并拒绝链接逃逸。不自动发现自定义 Codex SQLite-home 配置或其他 state 数据库版本。

## Representation and lifecycle / 表示与生命周期

Unselected artifact paths retained as selection evidence use the same restricted history-path policy as selected segments, including explicitly admitted archive dependencies. This evidence does not add unselected records to any transcript layer. Shell context is derived in accepted source order from non-inherited environment-context records, preserving the parser's first nonempty shell and size-bound semantics. Removed tails and unselected or inherited environments cannot supply it. / 作为选择依据保留的未选工件路径，与所选分段使用相同的受限历史路径规则，包含显式接纳的归档依赖。这些依据不会将未选记录加入任何转录层。Shell 上下文按已接纳来源顺序从非继承的环境上下文记录推导，保持解析器首个非空 shell 及大小限制语义；已移除尾部、未选分支或继承环境不能提供该上下文。

Composition preserves inherited-context flags already validated by a segment's subagent ordinal boundary, even when the physical artifact belongs to the same child Session. Retained same-owner segment headers remain `fork_metadata`, identified by the selected snapshot, owner and physical line 1; they neither become inherited parent content nor start the child's continuation. The ordinary inherited-prefix invariant still applies to content records. / 组合保留分段子 agent 序号边界已验证的继承上下文标记，即使物理工件属于同一子会话。保留的同归属分段头部通过所选快照、归属及物理第一行识别，仍为 fork_metadata，既不视为继承父级内容，也不开启子会话 continuation；普通继承前缀不变量仍约束内容记录。

One logical Session composes retained ancestor prefixes plus selected head content. Only the head's metadata drives Protocol/session identity; all physical headers remain inspectable in Raw. Reverted tails and unselected branches remain in their original files but are outside this Session's Main, Protocol, Raw and search projection. Explicit cross-thread inherited context remains Raw-only under existing fork ownership rules. / 一个逻辑会话由保留的祖先前缀及所选当前文件内容组成。仅当前文件 metadata 驱动 Protocol／会话身份；所有物理头部仍可在 Raw 检查。被回退尾部与未选分支仍保留原文件，但不属于此会话 Main、Protocol、Raw 或搜索投影。显式跨线程继承上下文按既有分叉归属规则仅保留 Raw。

Raw source locators retain physical file and line. Non-root artifact Raw IDs include physical RolloutId so reused ordinals cannot alias old records; retained original-artifact identities stay stable. Logical event construction runs once across the accepted content, allowing a request and result to span artifacts. Code Mode may correlate verified chain intervals while keeping physical endpoint references. Snapshot-bound history references still become stale after index cutover even when retained event IDs survive. / Raw 来源定位保留物理文件与行号。非原始工件 Raw ID 包含物理 RolloutId，防止复用序号误指旧记录；保留的原始工件身份保持稳定。逻辑事件对接纳内容统一构建，允许调用与结果跨文件。Code Mode 可在已验证链区间内关联，同时保留物理端点引用。索引切换后，即使保留事件 ID 未变，绑定快照的历史引用仍按既有规则失效。

The source-specific `rollout-history-v1` materialization payload captures selected segments, physical identity, accepted-prefix digests, byte counts and pointer selection evidence. Every segment is a dependency. Materialization and hydration revalidate the accepted bytes, not mutable SQLite history. A concurrent pointer cutover does not rewrite the accepted historical snapshot; a new index rereads selection. Chains rebuild on reindex rather than reusing single-file fast paths. Existing single-file and other-source behavior remains subject to its original contracts. / 来源专属 rollout-history-v1 物化 payload 捕获所选分段、物理身份、已接纳前缀 digest、字节数和指针选择依据。每段都是依赖。物化及 hydration 重新校验已接纳字节，不读取可变 SQLite 历史。并发指针切换不会改写已接纳历史快照；新索引重新读取选择。历史链重建索引时重新构建，不套用单文件快速复用；既有单文件及其他来源仍遵守原契约。

The source adapter's optional synchronous `legacyRawSessionFacts` hook supplies bounded per-file accepted-byte facts. Shared admission guards input immutability, copies only admitted fields and charges retained facts to the existing workspace budget. The v2 legacy Raw range encoding remains unchanged; physical addresses shared by parent/child histories remain ambiguous rather than choosing an owner. / 来源 adapter 可选同步 legacyRawSessionFacts hook 提供有界的逐文件已接纳字节事实。共享准入保护输入不被修改，只复制准入字段，并计入既有工作空间预算。v2 旧式 Raw 区间编码不变；父子历史共用物理地址时仍保持歧义，不擅选归属。

The distinct physical candidate count is calculated after history selection and reused by progress and final totals. Source-backed admission refreshes it only when failed histories change the selected candidate set. Per-file progress does not rescan or normalize the whole candidate collection. / 去重后的物理候选计数在历史选择结束后计算，供进度与最终统计复用；来源支持准入仅在失败历史改变候选集合时刷新。逐文件进度不重新扫描或规范化整个候选集合。
