# Codex turn relationships / Codex turn 关系

## Scope and identity / 范围与身份

2A adds read-only inspection in existing Main/Protocol event details, in both languages and both Main Presentations. Session parentage and collaboration navigation remain independent. There is no child directory, ancestor graph, configuration interval, token aggregation, cost estimate or new discovery setting. / 2A 在现有 Main／Protocol 事件详情中增加只读检查，覆盖双语及两种 Main Presentation。Session 父子关系和协作导航保持独立；不增加子级目录、祖先图、配置区间、token 汇总、金额估算或存储发现设置。

A turn identity is `(source/project index, Session ID, turn ID)`. A recorded parent/root ID resolves only when exactly one owned turn in that index has that ID. Duplicate identities stay ambiguous; names, paths, timestamps, spawn and Session relationships cannot disambiguate them. Root=self is valid and has no redundant action. / turn 身份为所列三元组。已记录父／根 ID 仅在当前索引中存在唯一自有 turn 时解析；重复身份保持歧义，不以昵称、路径、时间、spawn 或 Session 关系消歧。根等于自身合法，不提供重复跳转。

## Admission, storage and query / 准入、存储与查询

`src/codex-turn-lineage.js` admits parent only from start attribution with matching inner/outer turn IDs. Outer lifecycle/context roots remain independent of invalid attribution. Root evidence comes only from start, matching attribution, complete/abort and `turn_context`. Missing IDs on lifecycle/context roots need unique existing Raw→turn ownership; missing fields do not synthesize self. Token usage attribution and compaction checkpoints stay Raw. / 该模块仅从内外 turn ID 一致的开始 attribution 接纳父级；外层生命周期／上下文根不受无效 attribution 影响。根依据只来自开始、匹配 attribution、完成／中断和 turn_context；生命周期／上下文根缺少 ID 时须有唯一的现有 Raw→turn 归属。缺字段不补成自身；token usage 归属和压缩 checkpoint 保持 Raw。

The parser retains a closed `turnLineageFact` projection, never an arbitrary payload. After accepted-history composition and inherited-ownership filtering, the index builder reuses `buildRawTurnOwnershipIndex` and `turnOwnershipForEvent` with representative event IDs disabled. Every referenced Raw Record must have explicit, consistent ownership. Conflicts, unknown owners and cross-turn groups suppress the section. / parser 仅保留封闭 turnLineageFact 投影，不保留任意 payload。已接纳历史组合及继承归属过滤后，索引构建复用现有 Raw→turn 函数，不采用事件代表 ID。全部原始引用须有明确且一致的归属；冲突、未知归属及跨 turn 分组不显示关系 section。

The adapter's frozen `index.codexTurnLineage` stores per-session turns/event ownership and a turn-ID destination directory. It is constructed during indexing, reused only with a compatible unchanged index, and replaced with the index revision. It contains no complete event graph or arbitrary source payload. Detail lookup touches the selected identity and exact targets, never scans/materializes all Sessions. Materialization does not rebuild a second global lineage index. / adapter 的冻结索引保存逐会话 turn／事件归属及 turn ID 目标目录；随索引构建，仅在兼容且不变时复用，随索引版本替换，不保留完整事件图或任意来源 payload。详情只查询当前身份及精确目标，不扫描／物化全部会话；物化不重建另一套全局关系索引。

Parent and root accumulate distinct values independently; there is no last-write-wins rule. Parent self-reference and uniquely provable parent cycles are invalid. Relations cap distinct displayed values at 16 and physical references at 32, marking reference truncation; excess distinct values cannot become a navigable singleton. Identifiers over 512 characters are not admitted. / 父根分别累积不同值，不使用最后一条优先。自指父级及唯一身份能证明的父级循环无效。各关系最多展示 16 个不同值、32 条物理引用，并标记引用截断；超额不同值不能变成可导航单值。超过 512 字符的标识不准入。

The optional Supplemental Detail `turn_lineage` section has a strict closed DTO: current turn, independent parent/root values/status/evidence, optional display name and resolved target. Statuses are `unrecorded`, `conflict`, `invalid`, `self`, `missing`, `ambiguous`, `no_anchor`, `resolved`. Raw layer retains original evidence. Event IDs, counts, search projections and token totals are unchanged. / 可选 Supplemental Detail section 使用严格封闭 DTO，包含当前 turn、独立父根值／状态／依据，以及可选标题和已解析目标。状态如上；Raw 层保留原始依据，不改变事件 ID、计数、搜索投影或 token 汇总。

## Navigation and restoration / 导航与返回

Each resolved target contains source/project/revision, Session ID, turn ID, event ID and layer. Prefer its first owned Main event, then first owned Protocol event (explicitly labeled); otherwise report no anchor. Root navigation is independent of intermediate parents and never claims a full ancestry chain. / 已解析目标包含来源／项目／版本、Session／turn／事件 ID 及层。优先首个自有 Main 事件，其次明确标注的首个 Protocol 事件，否则报告无锚点。根跳转不依赖中间父级，不声称完整祖先链。

The click endpoint re-resolves the relation under an index-revision lease, materializes at most the two participating Sessions and checks their accepted physical sources plus relation evidence, including after cache hits. A missing dependency, changed source, wrong scope or retired revision fails without substituting a session start. Newer selection/search/presentation/navigation intent wins over pending responses. Existing reading history restores filters, queries, presentation, expansion, selection, viewport and the exact original action focus. / 点击接口在索引版本 lease 下重新解析关系，最多物化参与的两个会话，并检查其已接纳物理来源及关系依据，包括缓存命中路径。缺依赖、来源改变、作用域不符或版本退役时失败，不替换为会话起点。较新选择／搜索／呈现／导航意图优先于未完成响应；现有阅读历史恢复筛选、查询、呈现、展开、选择、视口及原操作焦点。

Snapshot verification hashes the entire accepted prefix of every physical transcript dependency of those participating Sessions, for both plain and Zstd storage, including dependencies without retained Raw rows. Checking only the first row and anchor cannot detect an in-place rewrite of a lifecycle record that established turn ownership. Appends beyond the accepted prefix remain allowed. This click-time verification streams bytes proportional to the participating accepted prefixes under the existing hydration coordinator; it neither scans other Sessions nor changes ordinary detail hydration's early-stop behavior. / 快照验证对参与会话的每个物理转录依赖核对完整已接纳前缀摘要，覆盖普通及 Zstd 存储，也覆盖没有保留 Raw 行的依赖。只检查首行和锚点无法发现确定 turn 归属的生命周期记录被原位改写。已接纳前缀之外的追加仍被允许。点击时验证复用既有 hydration 调度器，流式读取量与参与会话的已接纳前缀大小成正比；不扫描其他会话，不改变普通详情 hydration 的提前停止行为。

Writer-entry coverage remains open in the [follow-up handoff](../exec-plans/active/2026-10-14-codex-followups-handoff.md); 2B/2C and storage discovery are not closed by 2A. / writer 入口覆盖仍在整体交接中保持开放；2A 不关闭 2B／2C 或存储发现工作。

## Local observation and validation / 本地观察与验证

A bounded read-only sample of five project artifacts dated 2026-10-15 found start attribution/root fields in all five, direct parents in three and self roots in two. Their creation metadata reports `cli_version: 0.162.1`; this does not prove the producer version of every appended record or identify a client entry point. Two isolated local copies reproduced actual root/child HTTP details. No real transcript was added to committed fixtures, and no dedicated writer workflow was run. Client/flag/mode combinations in the matrix remain open. / 对 2026-10-15 当天五个本项目工件作有界只读抽样，五个均有开始 attribution／根字段，其中三个有直接父级、两个根为自身。创建 metadata 报告 cli_version 为 0.162.1，但不证明每条追加记录的 producer 版本，也不能识别客户端入口。两个隔离本地副本复现了真实根／子级 HTTP 详情；未将真实转录加入提交用 fixture，未运行专门 writer 工作流。矩阵中的客户端／开关／模式组合仍保持开放。

Real-corpus acceptance exposed and fixed a Windows-only validation mismatch: physical Raw Reference paths may contain backslashes while canonical JSONL locators normalize to slashes. The DTO compares those path spellings under the existing locator normalization, preserving the physical reference itself. Nested-directory synthetic fixtures and an explicit cross-platform separator test protect this case. / 真实语料验收发现并修复了 Windows 校验差异：物理原始引用可能使用反斜杠，而规范 JSONL locator 统一使用正斜杠。DTO 按既有 locator 规范化比较路径写法，同时保留物理引用本身；嵌套目录合成 fixture 及显式跨平台分隔符测试覆盖此案例。
