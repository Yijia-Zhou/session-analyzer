## Decision summary / 决策摘要

The committed Index will retain `IndexedSession` objects, not complete canonical Sessions. An `IndexedSession` contains stable identity, list metadata, relationship/navigation facts, bounded summary facts, an opaque source-owned materialization descriptor, and a key into one shared source-neutral project-query store. It must not retain `rawEvents`, `logicalEvents`, full `analysis`, presentation maps, parsed source records, or hidden alternate event projections. / 已提交的 Index 将常驻 `IndexedSession` object，而不是完整 canonical Session。`IndexedSession` 包含稳定 identity、列表 metadata、关系／导航事实、有界摘要事实、opaque 且由来源拥有的物化描述符，以及指向统一来源中立项目查询存储的 key。它不得常驻 `rawEvents`、`logicalEvents`、完整 `analysis`、presentation map、已解析来源记录或隐藏的替代事件投影。

A `MaterializedSession` is a complete canonical Session reconstructed on demand by the owning source adapter. It contains the Raw Records, Logical Events, analysis, and presentation indexes required by timeline, event, analysis, detail, Raw, and image-preview behavior. One runtime owner coalesces and caches materialization per committed Index revision. Materialization never mutates an Index or `IndexedSession`. / `MaterializedSession` 是由所属来源 adapter 按需重建的完整 canonical Session。它包含时间线、事件、分析、详情、Raw 与图片预览行为所需的 Raw Record、Logical Event、analysis 与 presentation index。一个 runtime owner 在每个已提交 Index revision 内合并并缓存物化。物化绝不修改 Index 或 `IndexedSession`。

The design keeps list, project filtering, project search, project file suggestions, and global catalogs resident-only. It does so through one shared packed query-store schema rather than through adapter-specific query DTOs or complete per-event objects. Timeline and detail surfaces explicitly cross the materialization boundary. / 该设计让列表、项目级过滤、项目级搜索、项目文件建议与全局目录只依赖常驻数据。实现方式是一套共享的紧凑查询存储 schema，而不是 adapter 专属查询 DTO 或完整逐事件 object。时间线与详情 surface 会显式跨越物化边界。

## M0 evidence and stop condition / M0 证据与停止条件

### Baseline and consumer audit / 基线与 consumer 审计

The baseline full Node suite passed 528 of 528 tests on Node `v24.18.1` and npm `12.0.2`. The audit traced every committed `Session` consumer through `server.js`, `src/session-query.js`, the source-adapter boundary, both source implementations, relationship inference, analysis, detail, Raw readback, image preview, and browser navigation. / 基线全量 Node 测试在 Node `v24.18.1` 与 npm `12.0.2` 下通过 528／528。审计追踪了 `server.js`、`src/session-query.js`、来源 adapter 边界、两种来源实现、关系推断、analysis、detail、Raw 回读、图片预览与浏览器导航中的每个已提交 `Session` consumer。

The ordinary Session card needs only compact metadata and bounded summaries. The current project query path does not: it scans every retained Raw or Logical Event for structural filters, free text, file suggestions, catalogs, result identity, and navigation. Timeline paging is not a retention boundary because it scans complete event arrays and Raw paging currently creates DTOs before slicing. Codex retains compact Raw and complete Logical projections plus relationship/presentation derivations; Claude retains parsed Raw graphs as well as Logical projections. / 普通 Session card 只需要紧凑 metadata 与有界摘要；当前项目查询路径并非如此：它会扫描每条常驻 Raw 或 Logical Event，以完成结构过滤、自由文本、文件建议、目录、结果 identity 与导航。时间线分页不是常驻边界，因为它会扫描完整事件数组，而且 Raw 分页当前在切片前先创建 DTO。Codex 常驻紧凑 Raw、完整 Logical 投影及关系／presentation 派生；Claude 还会同时常驻已解析 Raw 图与 Logical 投影。

### Profiling methodology and reproducibility limit / Profiling 方法与可复现性限制

The real-corpus run used a separate `node --expose-gc` process, the production `buildIndex` path, one forced GC after commit, and aggregate counters from the resulting object graph. The first run used the default heap and failed naturally; the diagnostic retry alone added `--max-old-space-size=4096`. The naive projection phase copied the exact current query-consumed event fields into ordinary per-event objects, severed complete Raw/Logical bodies, forced GC, and sampled `process.memoryUsage()`. The packed experiment length-framed UTF-8 `preview`/`searchText`, dictionary/column metadata, and level-1 gzip blocks; the absent phrase was scanned once per layer in the same environment. Temporary measurement scripts were removed because they referenced local discovery setup, so these are single-run directional measurements rather than a reproducible benchmark artifact. M3 must add a committed, aggregate-only profiling script that records exact command/options, repeat count, median/range, Node/V8 version, corpus aggregate counts, heap/RSS/external/ArrayBuffer, and transient decode peak without content or paths. / 真实语料运行使用独立 `node --expose-gc` 进程、生产 `buildIndex` 路径、提交后一次强制 GC，以及结果 object 图的聚合 counter。首次运行使用默认 heap 并自然失败；只有诊断性重试增加 `--max-old-space-size=4096`。朴素投影阶段把当前查询消费的精确 event 字段复制到普通逐 event object，断开完整 Raw／Logical body，强制 GC 后采样 `process.memoryUsage()`。紧凑实验对 UTF-8 `preview`／`searchText` 做长度分帧，构建 dictionary／column metadata 与 level-1 gzip block；同环境中每个 layer 对不存在短语扫描一次。临时量测脚本因引用本地 discovery setup 而移除，因此这些是单次方向性量测，不是可复现 benchmark artifact。M3 必须新增已提交、仅聚合 profiling script，记录精确 command／option、repeat count、median／range、Node／V8 版本、语料聚合 count、heap／RSS／external／ArrayBuffer 与瞬态 decode peak，且不记录内容或 path。

### Semantic invariants / 语义不变量

- `preview` and `searchText` remain separate frames. The phrase is trimmed, split on whitespace, regex-escaped, joined with flexible `\s+`, and matched case-insensitively. An event occurrence count is `max(count(preview), count(searchText))`; snippet selection tries preview first, then search text, with the current 80-character leading and 180-character window rules. / `preview` 与 `searchText` 保持独立 frame。短语 trim 后按空白拆分、regex escape、用灵活 `\s+` 连接，并执行大小写不敏感匹配。Event 出现次数是 `max(count(preview), count(searchText))`；snippet 先尝试 preview，再尝试 search text，并保持当前前置 80 字符与 180 字符窗口规则。
- Project expression activation remains exact: trimmed `q`, `file`, `kind`, `status`, or an active presentation filter enters `searchMatch` mode; `tool` alone and `layer` alone stay on the ordinary-result path. A layer-only request does not require the Session to contain that layer. Date filtering always uses `updatedAt || startedAt`. / 项目 expression activation 保持精确：trim 后的 `q`、`file`、`kind`、`status` 或 active presentation filter 会进入 `searchMatch` mode；单独 `tool` 与单独 `layer` 继续走 ordinary-result path。只有 layer 的请求不要求 Session 包含该 layer。日期过滤始终使用 `updatedAt || startedAt`。
- All structural predicates conjoin on the same row. `kind` matches exact `kind` or `subtype`; `status` is exact; `tool` is a case-insensitive substring. ## Runtime materialization owner / Runtime 物化 owner

The full owner contract is fixed by M1 and implemented in M6, after both source-backed adapter migrations. M2 compatibility materialization has no revision changes because current event routes remain synchronous around the already-resident object. M3 introduces a smaller `IndexRevisionLease` for every committed legacy or strict Index: `{ index, indexRevision, retirementController }`, with no cache, waiter group, queue, or scheduler. Every asynchronous project query and every explicit event-level materialization captures that lease, joins the caller signal with its retirement signal, and performs a post-await `lease === state.revisionLease && !lease.signal.aborted` check before response. M4/M5 use this lease while reparsing a cold Session per request. M6 extends—not replaces—the lease semantics with reuse/coalescing. / 完整 owner 契约由 M1 固定，并在两个来源回读 adapter 迁移后的 M6 实现。M2 兼容物化没有 revision 变化，因为当前 event route 围绕已常驻 object 保持同步。M3 为每个已提交 legacy 或 strict Index 引入更小的 `IndexRevisionLease`：`{ index, indexRevision, retirementController }`，没有 cache、waiter group、queue 或 scheduler。每个异步项目查询与每个显式 event-level 物化都捕获该 lease，把 caller signal 与 retirement signal 合并，并在 response 前执行 post-await `lease === state.revisionLease && !lease.signal.aborted` 检查。M4／M5 在每次 cold Session request 重解析时使用该 lease。M6 扩展而非替换 lease 语义，加入复用／合并。

The first installed Index lease uses process-local revision 1; every successful Index install increments once. Clearing state for a source/project identity reset also increments once and retires the prior lease, so no old response can match the empty/new state; a later install increments again. Failed/cancelled replacement does not increment. Retirement aborts the lease before the synchronous commit transition yields. An open request retired before response fails HTTP 409 `INDEX_REVISION_RETIRED`; a disconnected caller remains an internal `AbortError` with no response. / 首个已安装 Index lease 使用进程内 revision 1；每次成功 Index install 恰好递增一次。因来源／项目 identity reset 清空状态时也恰好递增一次并 retire 之前的 lease，因此旧 response 无法与空／新状态匹配；后续 install 再递增一次。失败／取消替换不递增。Retirement 会在同步 commit transition yield 前中止 lease。Response 前被 retire 的开放 request 以 HTTP 409 `INDEX_REVISION_RETIRED` 失败；已断开 caller 继续是无 response 的内部 `AbortError`。

The M6 first version intentionally had no eviction; the weighted-cache follow-up changes only successful-value retention. Concurrent callers for the same Session/revision still share one underlying materialization. ## Freshness and failure semantics / Freshness 与失败语义

Materialization is snapshot reconstruction, not “parse whatever is currently on disk.” Each descriptor and interned dependency set records the closed accepted source snapshot, including positive files, negative/absent inputs, accepted directory membership, and copied metadata. The adapter builds into local variables, validates or deliberately ignores later data according to each dependency policy, and returns only after the complete canonical result matches the Indexed Session. / 物化是 snapshot 重建，而不是“解析磁盘上的当前内容”。每个 descriptor 与 intern dependency set 记录封闭的已接受来源 snapshot，包括正向文件、负向／缺失输入、已接受 directory membership 与 copied metadata。Adapter 在局部变量中构建，按每个 dependency policy 校验或有意忽略后续数据，并且只有完整 canonical 结果与 Indexed Session 匹配后才返回。

For Codex JSONL, the dependency set records the accepted byte prefix/length, line count, stable identity, and prefix digest. Append-only growth materializes only that accepted prefix; rewrite, truncation, identity drift, or prefix mismatch fails `INDEXED_SOURCE_STALE`. `session_index.jsonl` title/updated-time values use `copied_value`: they are immutable Indexed facts for this revision and are reconsidered only by reindex, not a materialization freshness dependency. / 对 Codex JSONL，dependency set 记录已接受 byte prefix／length、line count、稳定 identity 与 prefix digest。仅 append 的增长只物化该已接受 prefix；rewrite、truncate、identity drift 或 prefix mismatch 以 `INDEXED_SOURCE_STALE` 失败。`session_index.jsonl` 的 title／updated-time 使用 `copied_value`：它们是本 revision 的不可变 Indexed fact，只在 reindex 时重新考虑，不属于物化 freshness dependency。

For Claude, immutable request-time dependency sets are interned at Index scope and referenced by ID. Each current Session has exactly one `accepted_prefix` entry for the selected transcript that is reread to reconstruct its body. Append-only growth remains outside the old snapshot; rewrite, truncation, removal, identity drift, or prefix mismatch fails `INDEXED_SOURCE_STALE`. Duplicate/conflict membership, pointer/UUID ancestry, parent Agent/Workflow evidence, optional sidecars, manifests/journals, sibling membership, and directory/tree state are source-tree evidence used to decide the next Index revision. Their resulting relationship and ownership facts are copied into the Indexed Session; an already committed revision neither rereads those unrelated files nor treats them as request-time freshness dependencies. Thus a sibling or sidecar change triggers changed reindex evidence but cannot make an unrelated old-revision body stale. / 对 Claude，不可变 request-time dependency set 在 Index scope intern 并以 ID 引用。当前每个 Session 精确包含一条 `accepted_prefix` entry，指向重建其 body 时会重读的所选 transcript。Append-only 增长继续位于旧 snapshot 之外；rewrite、truncate、remove、identity drift 或 prefix mismatch 会以 `INDEXED_SOURCE_STALE` 失败。Duplicate／conflict membership、pointer／UUID ancestry、parent Agent／Workflow 证据、optional sidecar、manifest／journal、sibling membership 与 directory／tree 状态属于决定下一 Index revision 的 source-tree evidence。其关系与 ownership 结果会复制到 Indexed Session；已经提交的 revision 既不重读这些无关文件，也不把它们当作 request-time freshness dependency。因此 sibling 或 sidecar 变化会让 reindex evidence 发生变化，但不能使无关旧 revision body stale。

## Source migration sketches / 来源迁移草图

### Codex / Codex

Codex parsing and finalization are factored into a reusable complete-Session builder. During indexing, one candidate complete Session is built transiently and reduced to a provisional query shard, summary draft, materialization dependencies, and compact fork/review evidence before the complete arrays are released. The final Index never commits Raw/Logical arrays. Because relationship discovery may happen after the child is first parsed, the provisional shard carries a source-owned `segmentTag` per row until Codex finalization; that tag is consumed and removed before the closed shared query-store validator runs. An implementation may instead choose a second accepted-prefix reparse before compression, but it may not retain ordinary events between passes. / Codex 解析与 finalize 会拆出可复用的完整 Session builder。索引期间，一次瞬态构建一个候选完整 Session，并在释放完整 array 前把它缩减为 provisional query shard、summary draft、物化依赖与紧凑 fork／review 证据。最终 Index 绝不提交 Raw／Logical array。由于关系发现可能发生在 child 初次解析后，provisional shard 在 Codex finalize 前为每个 row 携带来源拥有的 `segmentTag`；在封闭共享查询存储 validator 运行前，该 tag 会被消费并移除。实现也可选择在压缩前对已接受 prefix 做第二次 reparse，但不得在两次 pass 之间常驻普通 event。

The source-owned Codex fork projection descriptor is normative: it records parent/child IDs; accepted physical Raw boundary ordinals; copied-prefix digest/count; ancestry/review-parent evidence; a Raw-ID-to-segment classifier represented as compact ordinal ranges for exactly `fork_metadata`, `inherited_context`, and `continuation`; bounded inherited-context previews/counts; unique-child, parent-inactivity, no-cycle, continuation-present, and temporal-review facts needed by earlier-branch supersession; and committed relationship/storage/evidence values. A Logical Event is valid only when it has at least one ordered `rawRef`, every reference resolves, and every reference belongs to the same one of those three segments. Missing or multi-segment references fail closed. Public Logical ownership drops only `inherited_context`; both `fork_metadata` and `continuation` remain public. / 来源拥有的 Codex fork projection descriptor 是规范要求：它记录 parent／child ID；已接受物理 Raw boundary ordinal；copied-prefix digest／count；ancestry／review-parent 证据；用紧凑 ordinal range 表示且精确覆盖 `fork_metadata`、`inherited_context` 与 `continuation` 的 Raw-ID-to-segment classifier；有界 inherited-context preview／count；earlier-branch supersession 所需的 unique-child、parent-inactivity、no-cycle、continuation-present 与 temporal-review fact；以及已提交 relationship／storage／evidence 值。Logical Event 只有在至少有一个有序 `rawRef`、每个 reference 都可解析、且每个 reference 都属于三个 segment 中同一个 segment 时才有效。缺失或跨多个 segment 的 reference 会 fail closed。Public Logical ownership 只删除 `inherited_context`；`fork_metadata` 与 `continuation` 都继续 public。

The M4 candidate implements the permitted two-pass form. Pass A parses one candidate at a time, then releases the complete graph while retaining only canonical digest strings, scalar Raw-boundary tuples, numeric Logical ownership ranges, review markers, and closed aggregate temporal/continuation facts. It retains no Raw/Logical event-shaped object and no preview or search text. After global physical-fork/review/earlier-branch inference, pass B processes acyclic parents before materialized children and applies the parent's own committed relationship projection before deriving each child's exact inherited-context counts and at most 12 preview rows. A materialized relationship cycle has no topological first parent, so only its members receive a sequential accepted-prefix preflight inside pass B: each transient graph is projected, its child context is derived, and it is released before the next member; normal finalization remains one Session at a time. Each final child reparse applies the committed ordinal boundary and fails closed on unresolved or cross-segment Logical references. The declarative strict boundary avoids an O(total Index) immutability fingerprint on every event request for every adapter, not only repository-known sources. `materializationContextFields` selects bounded source-owned root strings; shared code copies them beside `sourceKind` and `repoRoot` into a request-owned context. Final query-projection admission is asynchronous, bounded, and signal-aware in both production paths. Index replacement first performs the closed synchronous structural contract, then yields before streaming stored-shard rows through the canonical digest; it checks the project job signal between bounded row/text chunks and again immediately before installing the revision. Strict materialization fingerprints the complete selected Materialized Session with bounded byte/graph chunks, streams its canonical projection without constructing a full layer-sized row array, rechecks the guarded graph, and performs a final abort check before returning to the revision owner. The owner can therefore admit neither a cancelled replacement nor a Session whose last waiter cancelled during verification. Cancellation queued while synchronous structural validation is running may be observed only at the mandatory handoff, but it still precedes admission. Fingerprint capture/recheck exceptions, including revoked Proxy graphs, are normalized to `MATERIALIZATION_CONTRACT_VIOLATION`; when rejection and mutation/unverifiability coincide, mutation remains dominant and retains the adapter rejection as `cause`. / 两条生产路径的最终 query-projection admission 都是异步、有界且 signal-aware。Index replacement 先执行封闭的同步结构契约，再在流式读取 stored-shard row 计算 canonical digest 前让出 event loop；它会在有界 row／text chunk 之间检查 project job signal，并在安装 revision 前立即再次检查。严格物化以有界 byte／graph chunk fingerprint 完整的所选 Materialized Session，在不构造完整 layer-sized row array 的情况下流式计算其 canonical projection，重新检查受保护 graph，并在返回 revision owner 前执行最后 abort check。因此 owner 不会接纳已取消的 replacement，也不会接纳 verification 期间最后 waiter 已取消的 Session。在同步结构校验运行期间排队的取消可能只能在强制 handoff 处被观测，但仍早于 admission。Fingerprint capture／recheck 异常（包括 revoked Proxy graph）会统一为 `MATERIALIZATION_CONTRACT_VIOLATION`；rejection 与 mutation／unverifiability 同时发生时，mutation 继续优先，并把 adapter rejection 保留为 `cause`。

## Weighted Materialized Session working set / 加权 Materialized Session working set

The 2026-08-22 follow-up replaces revision-long unbounded complete-Session retention with one deterministic source-neutral weighted LRU. Ordinary cache state obeys both `maxEstimatedMaterializedBytes = 256 MiB` and `maxCachedSessions = 12`. Each admitted entry owns its complete Materialized Session, the existing estimated weight, a monotonic access sequence, and current `foreground` or `speculative` origin. The small entry cap makes an O(N) victim scan simpler than a custom linked list. These values are initial engineering defaults, not permanent product contracts. / 2026-08-22 的后续用一个确定性、来源中立的加权 LRU 取代 complete Session 在整个 revision 生命周期内的无界保留。普通 cache state 同时遵守 `maxEstimatedMaterializedBytes = 256 MiB` 与 `maxCachedSessions = 12`。每个已准入 entry 拥有完整 Materialized Session、既有估算 weight、单调 access sequence，以及当前 `foreground` 或 `speculative` origin。较小的 entry 上限使 O(N) victim scan 比自定义 linked list 更简单。这些值是初始工程默认值，不是永久产品 contract。

A foreground hit touches the entry as MRU. If the entry originated from prewarm, that same hit atomically promotes its current origin to foreground; the existing prewarm-cache-hit metric records the prediction once rather than leaving a stale historical marker. Foreground admission evicts least-recently-used speculative entries before least-recently-used foreground entries. Speculative admission is planned atomically and may evict only speculative entries: if the new value still cannot fit without a foreground eviction, no existing entry is removed and the speculative value is not retained. / Foreground hit 会把 entry touch 为 MRU。若该 entry 来源于 prewarm，同一次 hit 会把它的当前 origin 原子 promote 为 foreground；既有 prewarm-cache-hit metric 只记录一次预测，而不会留下 stale 历史 marker。Foreground admission 会先淘汰 least-recently-used speculative entry，再淘汰 least-recently-used foreground entry。Speculative admission 会原子规划且只能淘汰 speculative entry：若新 value 仍需淘汰 foreground 才能容纳，则不移除任何既有 entry，且不保留该 speculative value。

One exception keeps a very large foreground Session usable and warm: a foreground estimate above the entire byte budget evicts all residents and becomes the sole cached entry even though its weight exceeds 256 MiB. A later foreground admission treats that oversize entry as an ordinary victim. Speculative materialization never receives this exception. Therefore the invariant is either an ordinary cache within both limits or exactly one oversize foreground resident. / 一个例外让非常大的 foreground Session 保持可用且 warm：若 foreground estimate 超过整个 byte budget，它会淘汰全部 resident，并在自身 weight 超过 256 MiB 的情况下成为唯一 cached entry。后续 foreground admission 把该 oversize entry 当作普通 victim。Speculative materialization绝不享有此例外。因此不变量是：普通 cache 同时位于两项限制内，或恰好只有一个 oversize foreground resident。

The budget bounds deterministic retained cache weight, not V8 heap, RSS, transient parsing memory, ProjectQueryStore external memory, temporary fingerprint/projection allocations, or total object reachability. If request A already obtained a Materialized Session and a later admission evicts A from the owner, A's ordinary local JavaScript reference remains valid until that request finishes. No pin, reference count, or acquire/release lease is added. Browser timeline pagination remains independent: it bounds response DTOs but does not make the cached server Session partial. / Budget 限制的是确定性 retained cache weight，不是 V8 heap、RSS、瞬时解析内存、ProjectQueryStore external memory、临时 fingerprint／projection 分配或 object 总可达性。若 request A 已取得 Materialized Session，而后续 admission 从 owner 淘汰 A，则 A 的普通局部 JavaScript reference 在该 request 完成前仍有效。不增加 pin、reference count 或 acquire／release lease。Browser timeline pagination 保持独立：它限制 response DTO，但不会让 server cached Session 变为局部对象。

In stable recent order, entry 13 triggered the count candidate at 170,305,110 estimated bytes; the byte candidate first triggered at entry 21. Opening 16 distinct recent Sessions retained all 16 and 208,072,531 estimated bytes, adding 257,002,064 forced-GC heap bytes and 297,172,992 RSS bytes relative to the committed Index sample. This confirms 256 MiB／12 without treating estimator-to-heap or GC/RSS deltas as exact conversion or reclamation accounting. / M0 在 501 个真实 Codex Session 上量测当前无界 baseline，未输出内容或 path。按稳定近期顺序，第 13 个 entry 在 170,305,110 estimated bytes 时触发 count candidate；byte candidate 到第 21 个才首次触发。打开 16 个不同近期 Session 后全部保留，共 208,072,531 estimated bytes；相对 committed Index sample 增加 257,002,064 forced-GC heap bytes 与 297,172,992 RSS bytes。Retirement 后 heap 回到该 sample 的 8,642,864 bytes 范围内，而 RSS 保持在接近 allocator high-water mark 的位置。该结果确认 256 MiB／12，同时不把 estimator-to-heap 或 GC／RSS delta 当作精确转换／回收 accounting。

The final post-policy run opened 24 distinct recent foreground Sessions. Cache count never exceeded 12, peak retained estimate was 261,213,143 bytes, and admission saw 11 count-pressure cases versus two byte-pressure cases; count was dominant and both byte cases also had count pressure.
