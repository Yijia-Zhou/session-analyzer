## Decision summary / 决策摘要

The committed Index will retain `IndexedSession` objects, not complete canonical Sessions. An `IndexedSession` contains stable identity, list metadata, relationship/navigation facts, bounded summary facts, an opaque source-owned materialization descriptor, and a key into one shared source-neutral project-query store. It must not retain `rawEvents`, `logicalEvents`, full `analysis`, presentation maps, parsed source records, or hidden alternate event projections. / 已提交的 Index 将常驻 `IndexedSession` object，而不是完整 canonical Session。`IndexedSession` 包含稳定 identity、列表 metadata、关系／导航事实、有界摘要事实、opaque 且由来源拥有的物化描述符，以及指向统一来源中立项目查询存储的 key。它不得常驻 `rawEvents`、`logicalEvents`、完整 `analysis`、presentation map、已解析来源记录或隐藏的替代事件投影。

A `MaterializedSession` is a complete canonical Session reconstructed on demand by the owning source adapter. It contains the Raw Records, Logical Events, analysis, and presentation indexes required by timeline, event, analysis, detail, Raw, and image-preview behavior. One runtime owner coalesces and caches materialization per committed Index revision. Materialization never mutates an Index or `IndexedSession`. / `MaterializedSession` 是由所属来源 adapter 按需重建的完整 canonical Session。它包含时间线、事件、分析、详情、Raw 与图片预览行为所需的 Raw Record、Logical Event、analysis 与 presentation index。一个 runtime owner 在每个已提交 Index revision 内合并并缓存物化。物化绝不修改 Index 或 `IndexedSession`。

The design keeps list, project filtering, project search, project file suggestions, and global catalogs resident-only. It does so through one shared packed query-store schema rather than through adapter-specific query DTOs or complete per-event objects. Timeline and detail surfaces explicitly cross the materialization boundary. / 该设计让列表、项目级过滤、项目级搜索、项目文件建议与全局目录只依赖常驻数据。实现方式是一套共享的紧凑查询存储 schema，而不是 adapter 专属查询 DTO 或完整逐事件 object。时间线与详情 surface 会显式跨越物化边界。

### Profiling methodology and reproducibility limit / Profiling 方法与可复现性限制

The real-corpus run used a separate `node --expose-gc` process, the production `buildIndex` path, one forced GC after commit, and aggregate counters from the resulting object graph. The first run used the default heap and failed naturally; the diagnostic retry alone added `--max-old-space-size=4096`. The naive projection phase copied the exact current query-consumed event fields into ordinary per-event objects, severed complete Raw/Logical bodies, forced GC, and sampled `process.memoryUsage()`. The packed experiment length-framed UTF-8 `preview`/`searchText`, dictionary/column metadata, and level-1 gzip blocks; the absent phrase was scanned once per layer in the same environment. Temporary measurement scripts were removed because they referenced local discovery setup, so these are single-run directional measurements rather than a reproducible benchmark artifact. M3 must add a committed, aggregate-only profiling script that records exact command/options, repeat count, median/range, Node/V8 version, corpus aggregate counts, heap/RSS/external/ArrayBuffer, and transient decode peak without content or paths. / 真实语料运行使用独立 `node --expose-gc` 进程、生产 `buildIndex` 路径、提交后一次强制 GC，以及结果 object 图的聚合 counter。首次运行使用默认 heap 并自然失败；只有诊断性重试增加 `--max-old-space-size=4096`。朴素投影阶段把当前查询消费的精确 event 字段复制到普通逐 event object，断开完整 Raw／Logical body，强制 GC 后采样 `process.memoryUsage()`。紧凑实验对 UTF-8 `preview`／`searchText` 做长度分帧，构建 dictionary／column metadata 与 level-1 gzip block；同环境中每个 layer 对不存在短语扫描一次。临时量测脚本因引用本地 discovery setup 而移除，因此这些是单次方向性量测，不是可复现 benchmark artifact。M3 必须新增已提交、仅聚合 profiling script，记录精确 command／option、repeat count、median／range、Node／V8 版本、语料聚合 count、heap／RSS／external／ArrayBuffer 与瞬态 decode peak，且不记录内容或 path。

## Canonical contracts / Canonical 契约

### Transitional capability and commit point / 过渡 capability 与切换点

M2 adds a discriminated adapter lifecycle seam. A descriptor declares exactly one `sessionLifecycle`: `resident-complete-v1` or `indexed-materialized-v1`. `materializeSession` is required in both modes. During M2 both production adapters remain `resident-complete-v1`: the current canonical Session validator stays active, `buildIndex` keeps complete Sessions resident, and the compatibility `materializeSession` returns the exact already-built complete Session from the captured Index after ownership/cancellation validation. It must be asynchronous, non-mutating, and pass the Materialized Session validator, so conformance traverses the future lifecycle even though memory behavior is unchanged. / M2 增加判别式 adapter 生命周期 seam。Descriptor 必须声明且只能声明一个 `sessionLifecycle`：`resident-complete-v1` 或 `indexed-materialized-v1`。两种 mode 都要求 `materializeSession`。M2 期间两个生产 adapter 都保持 `resident-complete-v1`：继续使用当前 canonical Session validator，`buildIndex` 继续常驻完整 Session，兼容 `materializeSession` 在 ownership／cancellation 校验后从捕获的 Index 返回精确的已构建完整 Session。该 operation 必须异步、不可 mutate，并通过 Materialized Session validator，使 conformance 即使在内存行为不变时也穿过未来生命周期。

The M2 compatibility form is deliberately explicit rather than pretending to satisfy the future compact field table. In `resident-complete-v1`, `validateCanonicalIndexedSessionShape(session, { allowResidentComplete: true })` applies **exactly the existing canonical complete-Session requirements**: non-empty `id`, exact `sourceKind`, Array `rawEvents` and `logicalEvents`, and finite non-negative `counts.messages`, `counts.toolCalls`, and `counts.failedCommands`, plus the current exact Index collection identity/key/set rules. It permits `cwdSet` as the builder currently owns it (`Set` or fixture Array); permits missing source/list/relationship fields whose current list DTO supplies `''`, `null`, or computed defaults; derives no `rawEventCount`, `logicalEventCount`, or `summary`; and requires no descriptor, dependency/query store, or snapshot field. `validateCanonicalMaterializedSessionShape` in this mode re-applies the current complete Session/event/Raw-reference ownership checks and requires `materializedSession === indexedSession === index.sessionsById.get(id)`. It performs no Indexed deep-equality or snapshot comparison because object identity is stronger and the current object has no snapshot field. M2 does not normalize or mutate either production Session shape. / M2 兼容 form 是显式过渡，不伪装满足未来紧凑字段表。在 `resident-complete-v1` 中，`validateCanonicalIndexedSessionShape(session, { allowResidentComplete: true })` **精确应用既有 canonical 完整 Session 要求**：非空 `id`、精确 `sourceKind`、Array `rawEvents` 与 `logicalEvents`、有限非负 `counts.messages`、`counts.toolCalls` 与 `counts.failedCommands`，以及当前精确 Index collection identity／key／set 规则。它允许 builder 当前拥有的 `cwdSet`（Set 或 fixture Array）；允许缺失当前列表 DTO 以 `''`、`null` 或计算值补齐的来源／列表／关系字段；不派生 `rawEventCount`、`logicalEventCount` 或 `summary`；也不要求 descriptor、dependency／query store 或 snapshot 字段。该 mode 下 `validateCanonicalMaterializedSessionShape` 重新应用当前完整 Session／event／Raw-reference ownership 校验，并要求 `materializedSession === indexedSession === index.sessionsById.get(id)`。由于 object identity 更强且当前 object 没有 snapshot 字段，不执行 Indexed deep-equality 或 snapshot 比较。M2 不 normalize 或 mutate 任一生产 Session shape。

In `indexed-materialized-v1`, `allowResidentComplete` is forbidden. The strict future field/default/forbidden-retainer/descriptor/dependency/query/snapshot rules below all apply; `cwdSet` is an Array, every required default is owned explicitly, counts/summary are resident, and materialization returns a separately constructed complete object validated by deep equality plus `materializationSnapshotId`. This whole strict branch is exercised with synthetic contract fixtures in M2, adopted by production Codex in M4, and adopted by Claude in M5. / 在 `indexed-materialized-v1` 中禁止 `allowResidentComplete`。下方严格未来字段／default／禁止 retainer／descriptor／dependency／query／snapshot 规则全部适用；`cwdSet` 是 Array，每个必需 default 被显式拥有，count／summary 常驻，物化返回独立构建的完整 object，并以 deep equality 加 `materializationSnapshotId` 校验。该严格分支在 M2 由合成契约 fixture 覆盖，在 M4 由生产 Codex 采用，在 M5 由 Claude 采用。

M3 builds and adopts the shared `ProjectQueryStore` for both legacy production adapters, removes complete-event dependencies from list/project query behavior, and makes event APIs explicitly consume the result of `materializeSession`; the legacy compatibility operation still returns the resident complete object. It also introduces the source-neutral `IndexRevisionLease` described below: no cache or scheduler, only revision identity, retirement cancellation, request capture, and post-await validation for asynchronous project queries and direct materialization. M3 does **not** switch either source to source-backed Session materialization and does not claim the full-corpus default-heap memory gate. It stops for the mandatory hidden-dependency implementation review. / M3 为两个 legacy 生产 adapter 构建并采用共享 `ProjectQueryStore`，从列表／项目查询行为中移除完整事件依赖，并让 event API 显式消费 `materializeSession` 的结果；legacy 兼容 operation 仍返回常驻完整 object。它还引入下述来源中立 `IndexRevisionLease`：没有 cache 或 scheduler，只包含 revision identity、retirement cancellation、request capture，以及异步项目查询／直接物化的 post-await validation。M3 **不会**把任何来源切换为来源回读 Session 物化，也不声称通过全语料默认 heap 内存门槛；完成后停在强制隐藏依赖实现评审。

After the M3 checkpoint is accepted, M4 switches Codex `buildIndex` to `indexed-materialized-v1` and runs the Codex structural/default-heap gates; M5 independently switches Claude and runs its source-semantic gates. Their uncached direct materializations are protected by the M3 lease before and after await, so replacement can never emit or cache an old-revision result. M6 then extends each lease into the already-specified `MaterializedSessionOwner` with cache/coalescing/global scheduling and completes warm reuse. Only after M5 do both production adapters have no legacy resident-complete mode. / M3 检查点接受后，M4 把 Codex `buildIndex` 切换到 `indexed-materialized-v1` 并运行 Codex 结构／默认 heap 门槛；M5 独立切换 Claude 并运行其来源语义门槛。它们的无 cache 直接物化在 await 前后都受 M3 lease 保护，因此替换绝不发送或 cache 旧 revision 结果。M6 再把每个 lease 扩展为已经指定的 `MaterializedSessionOwner`，加入 cache／合并／全局 scheduling 并完成 warm reuse。只有 M5 完成后，两个生产 adapter 才都不再处于 legacy resident-complete mode。

### Normative Index and Indexed Session fields / 规范 Index 与 Indexed Session 字段

The table below is the strict `indexed-materialized-v1` committed shape. M2's `resident-complete-v1` compatibility mode applies only the exact legacy complete-Session rules above; M3 adds the query store to that legacy Index without claiming strict compactness. Text scan processes one bounded chunk at a time, uses async inflate, checks abort before/after inflate and at least every 4,096 rows, yields to the event loop after every chunk with `setImmediate`, and releases decoded buffers before reading the next chunk. It never fills the materialization cache or a decoded-text cache. / Indexed mode 下 `filterSessions` 与项目文件建议是异步的，server 在两种 mode 都始终 `await` query interface。正文扫描一次处理一个有界 chunk，使用 async inflate，在 inflate 前后及至少每 4,096 rows 检查 abort，每个 chunk 后以 `setImmediate` 让出 event loop，并在读取下一个 chunk 前释放解码 buffer。它绝不填充物化 cache 或解码正文 cache。
- Query-store construction is shared. Adapters submit canonical query facts while a complete Session is transiently available. Session-scoped timeline/query remains a Materialized Session operation; the store is project-scope data, not a second event model. / 查询存储由共享代码构建。完整 Session 瞬态可用时，adapter 提交 canonical 查询 fact。Session 级 timeline／query 继续属于 Materialized Session operation；该 store 是项目级数据，不是第二套 event model。

M3 must compare Main, Protocol, and Raw project-search latency and retained memory with M0. Its gate requires exact oracle parity, abort observation within 100 ms under the cancellation fixture, no cold layer above 2 seconds or 2× its M0 baseline, and event-loop yielding at every bounded chunk. If the initial codec fails, M3 changes the shared codec before review; it must not restore event objects or source-specific search branches. / M3 必须把 Main、Protocol、Raw 项目搜索 latency 与常驻内存同 M0 比较。门槛要求精确 oracle 等价、cancellation fixture 中 100 ms 内观测 abort、任何冷 layer 不超过 2 秒或其 M0 基线的 2×，并在每个有界 chunk 让出 event loop。若初始 codec 失败，M3 必须在评审前改变共享 codec；不得恢复 event object 或来源专属搜索分支。

## Runtime materialization owner / Runtime 物化 owner

The full owner contract is fixed by M1 and implemented in M6, after both source-backed adapter migrations. M2 compatibility materialization has no revision changes because current event routes remain synchronous around the already-resident object. M3 introduces a smaller `IndexRevisionLease` for every committed legacy or strict Index: `{ index, indexRevision, retirementController }`, with no cache, waiter group, queue, or scheduler. Every asynchronous project query and every explicit event-level materialization captures that lease, joins the caller signal with its retirement signal, and performs a post-await `lease === state.revisionLease && !lease.signal.aborted` check before response. M4/M5 use this lease while reparsing a cold Session per request. M6 extends—not replaces—the lease semantics with reuse/coalescing. / 完整 owner 契约由 M1 固定，并在两个来源回读 adapter 迁移后的 M6 实现。M2 兼容物化没有 revision 变化，因为当前 event route 围绕已常驻 object 保持同步。M3 为每个已提交 legacy 或 strict Index 引入更小的 `IndexRevisionLease`：`{ index, indexRevision, retirementController }`，没有 cache、waiter group、queue 或 scheduler。每个异步项目查询与每个显式 event-level 物化都捕获该 lease，把 caller signal 与 retirement signal 合并，并在 response 前执行 post-await `lease === state.revisionLease && !lease.signal.aborted` 检查。M4／M5 在每次 cold Session request 重解析时使用该 lease。M6 扩展而非替换 lease 语义，加入复用／合并。

The first installed Index lease uses process-local revision 1; every successful Index install increments once. Clearing state for a source/project identity reset also increments once and retires the prior lease, so no old response can match the empty/new state; a later install increments again. Failed/cancelled replacement does not increment. Retirement aborts the lease before the synchronous commit transition yields. An open request retired before response fails HTTP 409 `INDEX_REVISION_RETIRED`; a disconnected caller remains an internal `AbortError` with no response. / 首个已安装 Index lease 使用进程内 revision 1；每次成功 Index install 恰好递增一次。因来源／项目 identity reset 清空状态时也恰好递增一次并 retire 之前的 lease，因此旧 response 无法与空／新状态匹配；后续 install 再递增一次。失败／取消替换不递增。Retirement 会在同步 commit transition yield 前中止 lease。Response 前被 retire 的开放 request 以 HTTP 409 `INDEX_REVISION_RETIRED` 失败；已断开 caller 继续是无 response 的内部 `AbortError`。

In M6, each lease gains a `MaterializedSessionOwner` holding only that revision's cache, waiter groups, queued jobs, active jobs, and the same retirement controller. The cache key is canonical Session ID because revision is part of owner identity. Cache state is never stored on or written into the Index. / 在 M6，每个 lease 获得一个 `MaterializedSessionOwner`，只持有该 revision 的 cache、waiter group、queued job、active job 与同一个 retirement controller。由于 revision 属于 owner identity，cache key 只需 canonical Session ID。Cache 状态绝不存入 Index，也不写入 Index。

The runtime has one source-neutral global materialization semaphore with `MAX_ACTIVE_MATERIALIZATIONS = 1`; every owner also has a FIFO queue with `MAX_QUEUED_MATERIALIZATIONS = 32`. Coalescing happens before queue admission, so all callers for one Session occupy one job. A thirty-third distinct queued Session fails immediately with HTTP 503 `MATERIALIZATION_BUSY` and `Retry-After: 1`. The global semaphore spans old and new owners, so an abort-ignoring old adapter cannot overlap a new full parse; its eventual value is discarded. / Runtime 有一个来源中立全局物化 semaphore，`MAX_ACTIVE_MATERIALIZATIONS = 1`；每个 owner 另有 `MAX_QUEUED_MATERIALIZATIONS = 32` 的 FIFO queue。Queue admission 前先执行合并，因此同一 Session 的所有 caller 只占一个 job。第 33 个不同 Session queued job 立即以 HTTP 503 `MATERIALIZATION_BUSY` 与 `Retry-After: 1` 失败。全局 semaphore 横跨新旧 owner，因此忽略 abort 的旧 adapter 不会与新的完整 parse 重叠；旧 adapter 最终返回值会被丢弃。

```text
HTTP request
  -> capture { index, indexRevision, revisionLease, owner? }
  -> resident route? -------- yes -> use IndexedSession / ProjectQueryStore
  -> no
  -> M3-M5: adapter.materializeSession(..., combinedLeaseSignal)
       -> validate -> post-await lease check -> MaterializedSession
  -> M6: owner.get(sessionId, callerSignal)
       -> cache hit -> validate revision -> MaterializedSession
       -> in flight -> join waiter set
       -> cold -> adapter.materializeSession(..., ownerSignal)
                    -> source snapshot/freshness validation
                    -> complete canonical construction
                    -> Indexed/Materialized equality validation
                    -> commit to this owner cache only
  -> existing timeline/detail/raw/image behavior

successful reindex/source identity replacement (lease from M3; owner from M6)
  -> one synchronous transition retires the old lease/optional owner and installs
     { new index, new revision, new lease, new owner? } before yielding
  -> abort old async work; from M6 also release the old cache

failed or cancelled replacement
  -> keep old { index, revision, lease, owner? } unchanged
```

The first version intentionally has no eviction. Concurrent callers for the same Session/revision share one underlying materialization. Each caller has an independent waiter: cancelling one rejects only that waiter while another live waiter keeps the job. The last waiter cancellation removes a queued job or aborts an active job. Failed, cancelled, stale, retired, busy, or validation-failed values are never cached. A successful value is cached only after a post-await check proves the owner is not retired, the captured Index/revision still match, the job still has a live waiter, and both shared and adapter validations pass. / 首版有意不实现 eviction。同一 Session／revision 的并发 caller 共享一次底层物化。每个 caller 有独立 waiter：取消一个只拒绝该 waiter，只要还有活 waiter，job 就继续。最后一个 waiter 取消会移除 queued job 或中止 active job。失败、取消、stale、retired、busy 或 validation 失败的值绝不 cache。成功值只有在 post-await 检查证明 owner 未 retire、捕获 Index／revision 仍匹配、job 仍有活 waiter、且共享与 adapter validation 全部通过后才进入 cache。

A request captures Index, revision, and lease together before asynchronous work and never refetches `state.index` midway; from M6 it captures the owner in the same snapshot. Materialization, asynchronous resident project search, and project suggestions all join the lease retirement signal, which becomes the owner's retirement signal in M6. A successful replacement performs one synchronous, non-yielding commit transition that retires the old lease/optional owner, installs the new state snapshot, and aborts old search/materialization work; M6 additionally removes queued work and releases the old cache. No request can observe an intermediate ordering. A failed or cancelled replacement leaves the old snapshot and optional cache unchanged. Old-revision async work never returns a successful old snapshot after retirement; it fails with HTTP 409 `INDEX_REVISION_RETIRED`, and the browser reloads state. Caller socket disconnect remains an internal `AbortError` with no response body, not a 409. / Request 会在异步工作前一起捕获 Index、revision 与 lease，过程中绝不重新读取 `state.index`；从 M6 起还会在同一 snapshot 中捕获 owner。物化、异步常驻项目搜索与项目建议都加入 lease retirement signal；M6 中该 signal 同时成为 owner retirement signal。成功替换执行一次同步、不 yield 的 commit transition：retire 旧 lease／可选 owner、安装新 state snapshot，并中止旧 search／materialization work；M6 还会移除 queued work与释放旧 cache。任何 request 都无法观察中间顺序。失败或取消的替换保持旧 snapshot 与可选 cache 不变。旧 revision 异步工作在 retire 后绝不成功返回旧 snapshot，而是以 HTTP 409 `INDEX_REVISION_RETIRED` 失败，浏览器随后重载 state。Caller socket disconnect 继续是无 response body 的内部 `AbortError`，不是 409。

## Freshness and failure semantics / Freshness 与失败语义

Materialization is snapshot reconstruction, not “parse whatever is currently on disk.” Each descriptor and interned dependency set records the closed accepted source snapshot, including positive files, negative/absent inputs, accepted directory membership, and copied metadata. The adapter builds into local variables, validates or deliberately ignores later data according to each dependency policy, and returns only after the complete canonical result matches the Indexed Session. / 物化是 snapshot 重建，而不是“解析磁盘上的当前内容”。每个 descriptor 与 intern dependency set 记录封闭的已接受来源 snapshot，包括正向文件、负向／缺失输入、已接受 directory membership 与 copied metadata。Adapter 在局部变量中构建，按每个 dependency policy 校验或有意忽略后续数据，并且只有完整 canonical 结果与 Indexed Session 匹配后才返回。

For Codex JSONL, the dependency set records the accepted byte prefix/length, line count, stable identity, and prefix digest. Append-only growth materializes only that accepted prefix; rewrite, truncation, identity drift, or prefix mismatch fails `INDEXED_SOURCE_STALE`. `session_index.jsonl` title/updated-time values use `copied_value`: they are immutable Indexed facts for this revision and are reconsidered only by reindex, not a materialization freshness dependency. / 对 Codex JSONL，dependency set 记录已接受 byte prefix／length、line count、稳定 identity 与 prefix digest。仅 append 的增长只物化该已接受 prefix；rewrite、truncate、identity drift 或 prefix mismatch 以 `INDEXED_SOURCE_STALE` 失败。`session_index.jsonl` 的 title／updated-time 使用 `copied_value`：它们是本 revision 的不可变 Indexed fact，只在 reindex 时重新考虑，不属于物化 freshness dependency。

For Claude, immutable dependency sets are interned at Index scope and referenced by ID. They include primary and derived transcript prefixes; duplicate/conflict candidate membership; pointer ancestry and command/output/container evidence; UUID-overlap evidence; parent Agent/Workflow rows; optional sidecar presence **and absence**; metadata, forked-skill markers, workflow manifests and journals; sibling/directory membership; and every accepted child transcript. Primary/derived JSONL use `accepted_prefix`, so append-only active Sessions remain materializable as the indexed snapshot. Present semantic sidecars use `exact`; absent sidecars stay logically absent even if later created; directory snapshots read only accepted members and ignore later additions. Accepted dependency disappearance/rewrite fails stale. Relationship facts themselves are copied from `IndexedSession`; materialization validates the evidence set and reconstructs the owned body, but never recomputes a newer global relationship. / 对 Claude，不可变 dependency set 在 Index scope intern 并以 ID 引用。它们包含 primary 与 derived transcript prefix；duplicate／conflict candidate membership；pointer ancestry 与 command／output／container 证据；UUID overlap 证据；parent Agent／Workflow row；optional sidecar 的存在**与缺失**；metadata、forked-skill marker、workflow manifest 与 journal；sibling／directory membership；以及每个已接受 child transcript。Primary／derived JSONL 使用 `accepted_prefix`，因此仅 append 的活跃 Session 仍可作为已索引 snapshot 物化。已存在语义 sidecar 使用 `exact`；缺失 sidecar 即使后来创建也在旧 snapshot 中保持逻辑缺失；directory snapshot 只读取已接受 member 并忽略后续新增。已接受依赖消失／rewrite 会 stale 失败。关系 fact 本身从 `IndexedSession` 复制；物化校验证据集合并重建自有 body，但绝不重算更新的全局关系。

## Source migration sketches / 来源迁移草图

### Codex / Codex

Codex parsing and finalization are factored into a reusable complete-Session builder. During indexing, one candidate complete Session is built transiently and reduced to a provisional query shard, summary draft, materialization dependencies, and compact fork/review evidence before the complete arrays are released. The final Index never commits Raw/Logical arrays. Because relationship discovery may happen after the child is first parsed, the provisional shard carries a source-owned `segmentTag` per row until Codex finalization; that tag is consumed and removed before the closed shared query-store validator runs. An implementation may instead choose a second accepted-prefix reparse before compression, but it may not retain ordinary events between passes. / Codex 解析与 finalize 会拆出可复用的完整 Session builder。索引期间，一次瞬态构建一个候选完整 Session，并在释放完整 array 前把它缩减为 provisional query shard、summary draft、物化依赖与紧凑 fork／review 证据。最终 Index 绝不提交 Raw／Logical array。由于关系发现可能发生在 child 初次解析后，provisional shard 在 Codex finalize 前为每个 row 携带来源拥有的 `segmentTag`；在封闭共享查询存储 validator 运行前，该 tag 会被消费并移除。实现也可选择在压缩前对已接受 prefix 做第二次 reparse，但不得在两次 pass 之间常驻普通 event。

The source-owned Codex fork projection descriptor is normative: it records parent/child IDs; accepted physical Raw boundary ordinals; copied-prefix digest/count; ancestry/review-parent evidence; a Raw-ID-to-segment classifier represented as compact ordinal ranges for exactly `fork_metadata`, `inherited_context`, and `continuation`; bounded inherited-context previews/counts; unique-child, parent-inactivity, no-cycle, continuation-present, and temporal-review facts needed by earlier-branch supersession; and committed relationship/storage/evidence values. A Logical Event is valid only when it has at least one ordered `rawRef`, every reference resolves, and every reference belongs to the same one of those three segments. Missing or multi-segment references fail closed. Public Logical ownership drops only `inherited_context`; both `fork_metadata` and `continuation` remain public. / 来源拥有的 Codex fork projection descriptor 是规范要求：它记录 parent／child ID；已接受物理 Raw boundary ordinal；copied-prefix digest／count；ancestry／review-parent 证据；用紧凑 ordinal range 表示且精确覆盖 `fork_metadata`、`inherited_context` 与 `continuation` 的 Raw-ID-to-segment classifier；有界 inherited-context preview／count；earlier-branch supersession 所需的 unique-child、parent-inactivity、no-cycle、continuation-present 与 temporal-review fact；以及已提交 relationship／storage／evidence 值。Logical Event 只有在至少有一个有序 `rawRef`、每个 reference 都可解析、且每个 reference 都属于三个 segment 中同一个 segment 时才有效。缺失或跨多个 segment 的 reference 会 fail closed。Public Logical ownership 只删除 `inherited_context`；`fork_metadata` 与 `continuation` 都继续 public。

After cross-session inference, Codex uses the provisional `segmentTag` only to remove inherited Logical query rows; it does not store any segment column or presentation fact in `ProjectQueryStore`. All physical Raw query rows remain because project search does not consume `forkSegment`. Codex then recomputes exact public counts/summary/catalogs and freezes/compresses the shared shard. Materialization reparses the accepted child prefix, applies exactly the same three-segment membership predicate, keeps fork-metadata plus continuation Logical events, and reconstructs `_forkSegmentsByRawId` only in the Materialized Session for Raw timeline presentation. It does not materialize the parent or retain `_logicalEvents`. `session_index.jsonl` title/time metadata is copied immutable Index data as specified above. / 跨 Session 推断后，Codex 只用 provisional `segmentTag` 移除 inherited Logical 查询 row；不会在 `ProjectQueryStore` 中存储任何 segment column 或 presentation fact。所有物理 Raw 查询 row 都保留，因为项目搜索不消费 `forkSegment`。随后 Codex 重算精确 public count／summary／catalog，并 freeze／compress 共享 shard。物化重解析已接受 child prefix，应用完全相同的三 segment membership predicate，保留 fork-metadata 加 continuation Logical event，并且只在 Materialized Session 内重建 `_forkSegmentsByRawId`，供 Raw timeline presentation 使用。它不会物化 parent，也不会保留 `_logicalEvents`。`session_index.jsonl` title／time metadata按前述规则作为 copied immutable Index data。

Unchanged reindex reuse reuses only Indexed metadata, query shards, and adapter-owned compact evidence when fingerprints and relationship dependencies are unchanged. It never shares a Materialized Session across revisions. Existing bounded source-row hydration, FIFO/two-operation coordination, image externalization, digest checks, and detail equivalence remain after materialization. / 未变化 reindex 只有在 fingerprint 与关系依赖未变化时才复用 Indexed metadata、query shard 与 adapter 拥有的紧凑证据；绝不跨 revision 共享 Materialized Session。物化完成后，既有有界来源行 hydration、FIFO／双 operation 协调、图片外置、digest 校验与 detail 等价性全部保留。

### Claude / Claude

Claude indexing is split into candidate/directory inspection, transient complete parsing, compact relationship-evidence collection, global primary identity conflict resolution, derived/pointer/materialized-fork resolution, dependency-set interning, and Indexed/query finalization. Parsed Raw records, content blocks, tool calls/results, usage objects, plan/lifecycle snapshots, and Logical arrays are released after the candidate's query facts and compact evidence are extracted. Candidate admission records both the full accepted top-level candidate membership and negative optional-input facts, so later materialization cannot accidentally observe a different source graph. / Claude 索引拆分为候选／directory inspection、瞬态完整解析、紧凑关系证据收集、全局 primary identity conflict 解析、derived／pointer／materialized-fork 解析、dependency-set intern，以及 Indexed／query finalize。提取候选 query fact 与紧凑证据后，会释放 parsed Raw record、content block、tool call／result、usage object、plan／lifecycle snapshot 与 Logical array。候选 admission 同时记录完整已接受顶层候选 membership 与负向 optional-input fact，因此后续物化不会意外观察到不同来源图。
