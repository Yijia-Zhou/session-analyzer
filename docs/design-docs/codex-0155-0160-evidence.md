- [Default change #47900](https://github.com/openai/codex/pull/47900) makes `LocalThreadStore` default to Paginated while retaining explicit Legacy selection. Identity proofs are type-specific: [command/file producers](https://github.com/openai/codex/blob/rust-v0.160.0/codex-rs/core/src/tools/events.rs#L590) assign `id = ctx.call_id`; [dynamic producer](https://github.com/openai/codex/blob/rust-v0.160.0/codex-rs/core/src/tools/handlers/dynamic.rs#L219) assigns `id = call_id`; [MCP completion](https://github.com/openai/codex/blob/rust-v0.160.0/codex-rs/core/src/mcp_tool_call.rs#L1077) does likewise. `UserMessage::new` and `ContextCompaction::new` create UUIDs. This does not authorize merging duplicate IDs across threads, turns, forks or conflicting items. / 身份证明按类型限定：上述工具生产端使用 call ID；用户消息与压缩构造器生成 UUID。不能据此合并跨线程、跨 turn、fork 或冲突的重复 ID。

[Message mapping](https://github.com/openai/codex/blob/rust-v0.160.0/codex-rs/core/src/event_mapping.rs#L149) copies a present response-item ID to `AgentMessage`; absent IDs generate UUIDs. `Reasoning` copies a present response ID, otherwise an empty string. User messages deliberately generate a new ID instead of copying the response ID. The [user prompt producer](https://github.com/openai/codex/blob/rust-v0.160.0/codex-rs/core/src/session/mod.rs#L4963) persists prepared response items before emitting the typed user message; image preparation can produce additional messages. Equal text or an assumed shared ID is therefore insufficient for user-message mirror merging. / 消息映射将已有 response ID 传给 AgentMessage，缺省则生成 UUID；Reasoning 传已有 ID，缺省为空；UserMessage 刻意生成新 ID。用户 prompt 先持久化准备后的 response items 再发 typed 消息，图片准备还可能增加其他消息。因此同文本或假定共享 ID 不足以合并用户镜像。

[Collaboration spawn](https://github.com/openai/codex/blob/rust-v0.160.0/codex-rs/core/src/tools/handlers/multi_agents/spawn.rs#L181) uses the tool call ID. Sub-agent activities have mixed origins: [message activity](https://github.com/openai/codex/blob/rust-v0.160.0/codex-rs/core/src/tools/handlers/multi_agents_v2/message_tool.rs#L89) uses a call ID, but [completion activity](https://github.com/openai/codex/blob/rust-v0.160.0/codex-rs/core/src/agent/control/completion.rs#L73) uses `subagent-completed-{turn_id}`. A generic activity-to-call mapping is invalid. / 协作 spawn 使用 call ID；子 agent 活动身份来源混合：message 活动可用 call ID，但 completion 用带 turn_id 的专用身份，不能统一映射成调用。

The same call-ID assignment is verified for collaboration [send_input](https://github.com/openai/codex/blob/rust-v0.160.0/codex-rs/core/src/tools/handlers/multi_agents/send_input.rs#L113), [resume_agent](https://github.com/openai/codex/blob/rust-v0.160.0/codex-rs/core/src/tools/handlers/multi_agents/resume_agent.rs#L111), [wait](https://github.com/openai/codex/blob/rust-v0.160.0/codex-rs/core/src/tools/handlers/multi_agents/wait.rs#L224) and [close_agent](https://github.com/openai/codex/blob/rust-v0.160.0/codex-rs/core/src/tools/handlers/multi_agents/close_agent.rs#L80). Extension [sleep](https://github.com/openai/codex/blob/rust-v0.160.0/codex-rs/core/src/tools/handlers/sleep.rs#L103), [image generation](https://github.com/openai/codex/blob/rust-v0.160.0/codex-rs/ext/image-generation/src/tool.rs#L235) and [web search](https://github.com/openai/codex/blob/rust-v0.160.0/codex-rs/ext/web-search/src/tool.rs#L176) also assign the invocation call ID. Sleep's typed `durationMs` is requested duration, not measured elapsed time or proof it was uninterrupted. Extension web action tags are `openPage` / `findInPage`; the core action tags are `open_page` / `find_in_page`. / 所列其他协作工具及 sleep、图片生成、web search 均已核验调用 ID 赋值。Sleep 的 typed durationMs 是请求时长，不是实测耗时或未中断证明。扩展 web action 的 tag 与 core 大小写不同。

[External output producer](https://github.com/openai/codex/blob/rust-v0.160.0/codex-rs/core/src/hook_runtime.rs#L755) copies response-item `id`, `name`, `namespace` and `output.body` into `FunctionCallOutput`; this does not establish a tool call ID. [UserInput image](https://github.com/openai/codex/blob/rust-v0.160.0/codex-rs/protocol/src/user_input.rs#L15) flattens image references, so `{type:"image",file_id:"..."}` becomes `{type:"input_image",file_id:"..."}` at the semantic boundary. Uploaded local images can be rewritten to file references before typed completion. / 外部输出复制 response 身份及正文，不证明工具 call ID；用户图片引用是扁平字段，语义转换保留 file_id；上传的本地图片可在 typed completion 前重写成文件引用。

Command `sandbox_type` and `model_context` have `serde(skip)` and are not durable fields. `duration` is Rust `std::time::Duration` serialization, not the TypeScript annotation's suggested string. [Extension schemas](https://github.com/openai/codex/tree/rust-v0.160.0/codex-rs/ext/items/src) use their own field naming: sleep has `durationMs`; image generation has `revisedPrompt`, `transparentBackground`, `savedPath`, `failure`; nested analytics request/generation IDs are skipped. / 命令 sandbox_type、model_context 不序列化；duration 使用 Rust Duration 序列化，不应依 TS 注解猜字符串；扩展使用自身字段命名，内部 analytics 身份不落盘。

Correction to the handoff's timestamp exclusion: [ItemCompletedEvent](https://github.com/openai/codex/blob/rust-v0.160.0/codex-rs/protocol/src/protocol.rs#L1948) itself contains optional `started_at_ms` and `completed_at_ms` (default zero for old missing values). These can persist; they still do not replace top-level rollout `timestamp` or prove the same timing interval as command duration. / 修正交接中的时间戳排除：ItemCompletedEvent 本身已有可持久化的上述字段，旧值缺省零；仍不能替换顶层 timestamp，也不能假定与命令 duration 为同一计时间隔。

### Accepted implementation boundary / 接纳实现边界

External-output/provenance review repair: FunctionCallOutput mirrors require complete output equality and untruncated name/namespace agreement; matching display prefixes or equal media placeholders are insufficient. Logical `channels` now use original Raw reference record types after mirror grouping. Synthetic conflict, long-output search, typed-only/mixed provenance, append and cache tests pass within the final 1552-test Node suite. / 外部输出／来源审查修复：FunctionCallOutput 镜像要求完整输出相等及未截断 name／namespace 一致，展示前缀或媒体占位符相同不足以合并。Logical channels 在镜像分组后使用原 Raw 引用的记录类型；合成冲突、长输出搜索、纯 typed／混合来源、追加与缓存回归通过最终 1552 项 Node 套件。

Dynamic outcome review repair: a completed typed DynamicToolCall retains `completed` when success is missing, null or nonboolean. Boolean true permits `success` only without explicit failure evidence; false, error or failed status remains `failed`. A generic end record or accompanying textual response is not affirmative typed success evidence. Synthetic typed-only/mixed regressions cover three representations, Detail/status filters, Raw, append and warm reuse; 57 affected tests pass. / 动态结果审查修复：已完成 typed DynamicToolCall 在 success 缺失、null 或非布尔时保持 completed；布尔 true 仅在无明确失败证据时允许 success，false、error 或 failed 状态仍为 failed。通用 end 记录或伴随文本回复不构成 typed 成功证据。合成纯 typed／混合回归覆盖三种表示、详情／状态筛选、Raw、追加及缓存复用；相关 57 项测试通过。
