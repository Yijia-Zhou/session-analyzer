## Decision and scope / 决策与范围

The first slice should inspect **recorded configuration**, not reconstruct actual per-request model consumption. The pinned implementation can update active step settings independently of the initial TurnContext. Its command analytics model labels are not serialized, and reroute notifications are not normally persisted. A continuous effective-model timeline cannot be proven from these records alone. / 首版应检查**已记录配置**，不还原实际逐请求模型消费。固定实现可独立更新运行中 step 的设置，TurnContext 仍保留初始设置；命令分析用模型标签不序列化，重路由通知也不常规落盘。仅凭这些记录不能证明连续的实际模型时间线。

Keep four distinct evidence categories: requested spawn arguments; recorded child startup settings; thread settings snapshots; turn-context snapshots and trusted effort-update instructions. Values from different categories can differ without being corrupt. Never silently replace one category with another. / 分开保留四类依据：spawn 请求参数、已记录子级启动设置、线程设置快照、turn 上下文快照及可信 effort 更新指令。不同类别的值可以合法不同，不应直接当作数据损坏，也不得相互静默替代。

No new Main events, configuration editor, independent overview, token aggregation or monetary estimate. Do not change Session relationships, turn lineage, search text, existing counts or cache/token accounting. 2C remains gated on independent accounting evidence. / 不增加 Main 事件、配置编辑器、独立概览、token 汇总或金额估算；不改变 Session 关系、turn 谱系、搜索文本、既有计数及 cache／token 核算。2C 仍需独立核算依据。

## Interval semantics / 区间语义

1. Identity uses the selected source/project/index revision, logical Session, owned turn and accepted logical Raw order. Physical file/line remains evidence, never the cross-file sort key. Exclude inherited context, removed tails and unselected replacements before attribution; reuse existing Raw-to-turn ownership and accepted history composition. / 身份采用来源／项目／索引版本、逻辑会话、自有 turn 及已接纳 Raw 逻辑顺序。物理文件／行号仅作依据，不作为跨文件排序键；先排除继承上下文、移除尾部及未选替换，再复用既有 Raw→turn 归属与历史组合。
2. A thread snapshot describes recorded thread defaults only. Its inspection range is from its own record to the next owned thread snapshot or accepted-history end, labeled “last recorded thread settings”. A malformed/unowned snapshot cannot authorize carry-forward into a turn. Do not use it to fill missing turn-context fields. / 线程快照仅描述已记录线程默认设置；检查范围从本记录到下一自有线程快照或已接纳历史末尾，标为“最近记录的线程设置”。畸形／归属不明快照不能授权填入 turn，也不用于补 turn-context 缺失字段。
3. A turn-context observation starts at its actual record, not the preceding task start or message. Bound it by the next context snapshot, compaction boundary, lifecycle end/restart, ownership discontinuity or snapshot end. A resumed occurrence of the same turn ID is a separate observation span. “Snapshot end” means observation stopped, not task completed. / turn-context 观测从实际记录开始，不回填前面的 task start 或消息；由下一上下文、压缩边界、生命周期结束／重启、归属中断或快照末尾界定。同 turn ID 恢复产生独立观测段；快照末尾只表示观测停止，不表示任务完成。
4. A trusted effort instruction starts a separate instruction-evidence span at its record. A later trusted instruction is an ordered update, not a contradiction. Stop at compaction, turn boundary or uncertain ownership; do not infer carry-over across turns/windows from absence of another update. A repeated turn-context snapshot never resets this instruction track. These spans express retained evidence, not proven backend application. / 可信 effort 指令从本记录开启独立指令依据段；后续可信指令是有序更新，不是矛盾。压缩、turn 边界或归属不确定时停止，不因无后续更新而推断跨 turn／窗口延续；重复 turn-context 不重置指令轨道。区段仅表达保留依据，不证明后端已应用。
5. Keep `missing`, explicit `null`, bounded string and malformed field states distinguishable. A new full snapshot with an omitted field does not inherit the prior value. Do not resolve defaults from today's model catalog. Sparse effort instructions never modify the model or provider. Nested collaboration settings remain separately labeled unless equality is verified; conflicting duplicate evidence at one logical position stays unresolved. / 区分缺失、显式 null、有界字符串及畸形字段；新完整快照缺字段不继承旧值，不从当前模型目录补历史默认值。稀疏 effort 指令不修改模型／provider；嵌套协作配置保持单独标注，除非核对相等；同一逻辑位置的重复矛盾依据保持未解析。
6. Distinct sequential snapshots remain distinct observations, even when the turn ID is unchanged. Differing request/startup/thread/context values are a comparison, not one precedence chain. Old rows without a unique owned turn remain inspectable in Raw/Protocol without guessed association. Grouped events spanning several observations show the multiple observations or an explicit mixed state; never pick their first Raw Reference arbitrarily. / 即使 turn ID 不变，顺序不同的快照仍是不同观测。请求／启动／线程／上下文值不同是比较关系，不是一条优先级链；旧记录无唯一自有 turn 时保留 Raw／Protocol 检查，不猜归属。跨多个观测的分组事件展示多项或明确混合状态，不任取首条引用。

## Detail and index design / 详情与索引设计

Use a compact “Recorded configuration / 已记录配置” Supplemental Detail section beside existing turn relationships, in Main/Protocol and both Timeline/Trajectory/locales. Show recorded turn-context model/effort, observation boundary and Raw References; list trusted effort instructions separately. Requested/started spawn settings keep their existing call-local presentation. Optional thread-default context must be explicitly labeled and never masquerade as current-turn configuration. No continuous effective-model chart is proposed. / 在既有 Turn 关系旁增加紧凑“已记录配置”补充详情，覆盖 Main／Protocol、双呈现及双语。显示 turn-context 模型／effort、观测边界及 Raw Reference，可信 effort 指令单列；spawn 请求／启动设置维持既有调用局部呈现。可选线程默认上下文须明确标注，不能伪装成当前 turn 配置；不提出连续实际模型图。

`src/codex-configuration.js` reuses canonical turn ownership and source-backed hydration. Closed `configurationFact` values capture admitted fields and explicit trust; a frozen `codexConfiguration` index is built and invalidated with the Session lifecycle. Event lookup uses indexed observation references, without scanning or materializing the project. The optional `recorded_configuration` section has a strict shared DTO and compact/package contracts. / 所列模块复用规范 turn 归属及来源 hydration；封闭 configurationFact 保存准入字段与显式可信依据，冻结 codexConfiguration 索引随会话生命周期构建及失效。事件通过索引引用查询观测，不扫描或物化项目；可选 section 有严格共享 DTO、紧凑化及打包契约。

Each section contains at most eight observations, with an explicit truncation flag and `recorded`/`mixed` status. Each observation distinguishes its category, field states, start/end Raw References and boundary reason. Strings are bounded to 512 characters; missing, null and invalid states carry no guessed value. The private index also retains ownership/boundary evidence references, never arbitrary payloads. Ordinary detail verifies relevant evidence rows. Plain JSONL stops after the last requested line; Zstd retains the existing full accepted-stream decode and digest check for each opened artifact. Unlike lineage navigation, ordinary detail does not request complete-prefix verification of every transcript dependency. Evidence navigation reuses stale-source recovery and reading history. / 每个 section 至多包含八个观测，明确截断标记及 recorded／mixed 状态；每个观测区分类别、字段状态、起止 Raw Reference 与边界原因。字符串上限 512 字符；缺失、null、无效状态不填猜测值。私有索引还保留归属／边界依据引用，不保留任意 payload；普通详情校验相关依据行；普通 JSONL 在最后所需行停止，Zstd 对每个打开的工件保留既有完整已接纳流解码及摘要校验。与谱系导航不同，普通详情不会请求对所有转录依赖执行完整前缀校验。依据导航复用来源失效恢复与阅读历史。

The section is collapsed by default: a short model/effort summary, with “Context effort” and “Effort update instruction” distinguishing the initial context snapshot from a recorded update. Thread and collaboration settings retain their own scope labels. Expanding reveals category rows, boundaries and short Raw buttons; paths stay in tooltips, and explanations stay inside the disclosure. Mixed observations never choose one model for the summary. Native disclosure keyboard behavior and 390px layouts are covered alongside both locales and Main Presentations. / 区域默认折叠，仅显示简短模型／effort 摘要，以“上下文推理强度”和“推理强度更新指令”区分初始上下文快照及已记录更新；线程和协作设置保留各自作用域标注；展开后显示分类行、边界及简短 Raw 按钮，路径置于提示，说明保留在折叠内容内。混合观测不任取一个模型作摘要；原生键盘展开、390px 布局、双语及两种 Main Presentation 均有覆盖。

For limits, reuse the 2A maximum ID/value length and bounded evidence lists where applicable; report truncated evidence explicitly. Do not retain arbitrary settings, model catalogs, prompts or payloads. Resident/source-backed, cold/warm, materialized/hydrated and plain/Zstd paths must produce equal inspection results. / 长度与依据数量限制尽量复用 2A，省略依据须明确标注；不保留任意设置、模型目录、提示词或 payload。驻留／来源支持、冷热、物化／hydration 及普通／Zstd 路径须输出等价检查结果。
