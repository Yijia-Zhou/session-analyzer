# Project path interpretation / 项目路径解释

Local acceptance reference: cross-platform execution completed on 2026-11-13 for candidate `e09575700cf5191fbdc4fc613173650a9a54e2f7`, based on `64f5b3ab351c3be6840396ddb1e8194ab102b4dc`. / 本地验收参考：基于所列基线的候选已于 2026-11-13 完成双平台本地执行。

## Contract / 契约

Project identity and lexical directory containment share one interpreted descriptor. Filesystem resolution and source-read authorization remain independent. A project key never becomes an `open` path or a Raw owner key. Existing `fs-path` and scheduled-origin helpers retain their separate responsibilities. / 项目身份与词法目录包含共用解释后的描述；文件系统解析及来源读取授权独立。项目 key 不作为 open 路径或 Raw 归属 key。既有 fs-path 与定时来源 helper 保持各自职责。

Version 1 keys encode namespace, complete volume root, normalized components and comparison policy. Evidence (`syntax`, `producer`, `user`, `legacy`) is separate from identity. POSIX preserves case and literal backslashes; Windows retains the existing lowercase logical comparison convention, without promising physical case insensitivity. Ordinary UNC requires server plus share, including the share root itself. Component containment cannot cross a server/share/drive root or confuse `project` and `project-2`. / 第 1 版 key 编码 namespace、完整卷根、规范组件及比较策略；依据与身份分开。POSIX 保留大小写和字面反斜杠；Windows 沿用小写逻辑比较约定，不承诺物理文件系统不区分大小写。普通 UNC 必须包含 server 与 share，共享根本身合法；组件包含不跨 server／share／drive 根，不混淆相邻前缀。

Exactly two leading forward slashes lack universal historical-platform evidence. Existing JSONL admission therefore defaults to POSIX compatibility, preserves raw cwd and reports `PROJECT_PATH_LEGACY_ASSUMPTION`. Explicit physical artifact/container rules can choose ordinary UNC or POSIX for otherwise unknown double-slash records. Three or more forward slashes remain POSIX. Source kind, selected project, Analyzer OS and local existence never determine historical semantics. Reliable conflicting source semantics return conflict rather than fallback; no generic producer-platform field is invented. / 恰好双前导正斜杠缺少通用历史平台依据。既有 JSONL 准入默认保留 POSIX 兼容解释、原始 cwd 并报告兼容假设；明确物理工件／容器规则可选择普通 UNC 或 POSIX。三个以上正斜杠仍按 POSIX。来源类型、选定项目、Analyzer OS 及本机存在性不决定历史语义；可靠来源证据冲突时报告冲突，不回退，也不虚构通用平台字段。

NUL, empty or wrongly typed paths, historical relative paths, drive-relative/root-relative Windows forms, and malformed UNC roots have no ordinary project identity. Device/extended namespaces remain unsupported by the ordinary interpreter. Existing native-backslash namespace spellings use an opt-in, separate compatibility identity at the Node input boundary so existing history remains readable; the prefix stays intact, there is no ordinary-path alias, and `PROJECT_PATH_NAMESPACE_COMPATIBILITY` records that limit. This does not authorize device I/O or expand a source reader's admission. Physical source-root readers keep their existing namespace handling. Mapped drives, host aliases and WSL mounts are not merged. Exact file-activity paths retain their own treatment of `..`. / NUL、空值、错误类型、历史相对路径、Windows 盘符相对／根相对形式及不完整 UNC 根不具有普通项目身份。普通解释器仍不支持设备／extended namespace；Node 输入边界对既有原生反斜杠写法显式采用独立兼容身份，以保留历史阅读能力。前缀完整保留，不产生普通路径别名，并以 PROJECT_PATH_NAMESPACE_COMPATIBILITY 记录其限制；这不授权设备 I/O，也不扩大来源 reader 准入。物理来源根 reader 保持现有 namespace 处理。不合并映射盘、主机别名或 WSL 挂载；精确文件活动路径独立处理 ..。

## Configuration and scope / 配置与范围

Analyzer reading configuration is a source-config map. Rules bind `sourceKind`, local `sourceHome` and physical locators, never cwd or interpreted keys. Rule scopes are `artifact` (one exact locator) or `container` (directory components, including new descendants). Paths are relative to sourceHome or explicit absolute paths inside it. Overlapping disagreeing rules are rejected; no scan-order precedence or per-row editor is provided. Choosing container `.` explicitly affects all relevant unknown records in that source root. Source bytes, producer configuration and desktop databases are never rewritten. / Analyzer 读取配置按来源存储。规则绑定来源类型、本机来源根及物理 locator，不依据 cwd 或解释后 key；artifact 指精确工件，container 指目录组件范围并包含新后代。路径相对来源根或为根内绝对路径；重叠冲突规则拒绝，不按扫描顺序取胜，也不提供逐行编辑器。明确选择容器 . 将影响同根全部相关未知记录；不改写来源字节、producer 配置或桌面数据库。

Local scope identity uses the host path API after resolving configuration input once. Windows scope serialization folds case for sourceHome and rule locators; POSIX preserves case and literal backslashes. The context's physical `sourceHome` keeps its configured spelling for readers; `sourceHomeIdentity` is separate comparison data. Namespace prefixes and configured symlink aliases remain distinct; this does not use realpath or authorize reads. Equivalent home edits retain the existing configured spelling and inherit omitted rules; an explicit empty rule set still clears them. Captured serialization, policy digests, history scope and pi navigation scope use the same native identity, so equivalent spelling preserves current/running work and reference scope. Legacy pre-policy history migration retains its existing narrow gate. / 本机范围身份在配置输入一次解析后使用宿主 path API。Windows 对序列化上下文中的 sourceHome 与规则 locator 统一大小写；POSIX 保留大小写及字面反斜杠。上下文的物理 sourceHome 保留配置拼写供 reader 使用，sourceHomeIdentity 单独用于比较。namespace 前缀与配置的 symlink 别名仍区分，不使用 realpath，也不授权读取。等价 home 编辑保留既有配置拼写并继承省略的规则；显式空集仍清除规则。捕获序列化、策略摘要、history scope 与 pi 导航 scope 使用相同本机身份，因此等价拼写保留当前／在途工作及引用范围。策略引入前的旧 history 引用迁移继续保留既有窄门槛。

```json
{
  "workbuddy": {
    "home": "/synthetic/buddy",
    "projectPathRules": [
      { "scope": "container", "path": "projects/explicit-container", "interpretation": "unc" }
    ]
  }
}
```

`--path-config <file>` supplies the same JSON to normal startup and `history serve`; relative home entries are resolved against the config file directory once. `--project-path-semantics windows|posix` interprets only the selected project input, allowing an explicitly UNC `//server/share/project` without changing any record's meaning. A selected historical project need not exist locally. Local relative project inputs resolve once at the local input boundary; historical relative cwd never borrows Analyzer cwd. / 普通启动及 history serve 使用同一配置文件入口；相对 home 按配置文件目录一次解析。项目输入语义选项仅解释所选项目，允许明确 UNC 的正斜杠写法而不改变记录含义。历史项目无需本机存在；本机相对项目输入仅在入口一次解析，历史相对 cwd 不借用 Analyzer cwd。

## Lifecycle and adapters / 生命周期与来源

Each scan/job captures a canonical versioned context and digest. Discovery keys, configuration/transcript list merging, candidate membership, final `matchesRepo`, index reuse and materialization use that context. Policy changes cancel/retire old active state, invalidate discovery caches and reject stale responses. Strict materialization captures and rechecks the serialized context. History and pi references include project identity and context; old references cannot redirect under a different policy. Browser saved entries/bookmarks are retained; ambiguous or cross-policy entries pause automatic restoration with a notice. / 每次扫描／作业捕获规范的版本化上下文及摘要；发现、配置／转录列表合并、候选归属、最终 matchesRepo、索引复用及物化统一使用。策略变化取消／退役旧状态、失效发现缓存并拒绝旧响应；严格物化捕获及回验序列化上下文。历史与 pi 引用包含项目身份及上下文，不跨策略重定向；保存项／书签保留，歧义或跨策略时暂停自动恢复并提示。

Claude clusters retain unsupported/conflicting cwd evidence as inference blockers. Under explicit UNC, two directly associated slash variants plus one metadata-only session may form one cluster and admit three Sessions, with the third remaining `container-inferred`. Distinct POSIX projects stay distinct. Existing pointer/fork/subagent gates remain. pi counts branches; DeepSeek uses the initial header; WorkBuddy scheduled-origin uses its own evidence; OpenCode retains host-path admission and the worktree/directory OR filter. / Claude 聚类保留不支持／冲突 cwd 作为推断阻断证据。明确 UNC 下，两条直接归属变体加一条无 cwd 可形成唯一 cluster 并接纳三条，第三条仍为 container-inferred；不同 POSIX 项目保持分离。指针／分叉／subagent 门槛不变。pi 按分支计数，DeepSeek 使用初始 header，WorkBuddy 定时来源证据独立，OpenCode 保留宿主路径准入及 OR 筛选。

Discovery and indexing read the decoded `cwd` from Codex project metadata, including JSON-escaped keys. When a native Windows Codex scan finds an existing configured extended drive directory, it uses the bounded, cancellable rollout reader to validate each logical record's UTF-8 bytes before decoding and check the decoded JSON. Invalid UTF-8, undecodable JSON, an invalid explicit `cwd`, or an unreadable artifact makes the scan incomplete. Discovery continues collecting readable sibling evidence. Configuration diagnostics remain visible and transcript diagnostics determine transcript coverage. / 发现和索引从已解码的 Codex 项目元数据读取 `cwd`，支持 JSON 转义键。Windows 原生 Codex 扫描遇到存在的扩展盘符配置目录时，使用有界、可取消的 rollout 读取器在解码前逐条验证 UTF-8 字节，并检查解码后的 JSON。UTF-8 无效、JSON 无法解码、显式 `cwd` 无效或工件不可读时，扫描覆盖不完整。发现仍收集同工件中可读的依据。配置诊断继续显示，转录诊断决定转录覆盖状态。

Full discovery and cached summaries apply the same visibility rule. For a configuration-only extended drive root, a completed scan must find an ordinary drive row with history and no recorded `cwd` at or below the extended root according to `projectPathContains`. Both spellings must have native directory stats with matching nonzero device and file IDs. Coverage applies to the artifacts observed in that scan. Summaries read the current configuration and reuse cached statistics for matching entries. When `config.toml` is temporarily unreadable, known configuration-only choices from the same scope remain selectable with unverified activity. A successful read or an absent file establishes the current configured choices. A failed current full scan revokes the cached coverage. Late responses and abandoned requests cannot overwrite or revoke the results of a newer settled scan. / 完整发现和缓存快速列表采用同一显示规则。对于仅来自配置的扩展盘符根，完整扫描须找到有历史的普通盘符条目，并通过 `projectPathContains` 确认扩展根及其子目录未记录 `cwd`。两种写法的本机目录设备标识和文件标识须分别相等且均非零。覆盖仅适用于当次扫描观察到的工件。快速列表读取当前配置并对匹配项复用缓存统计。`config.toml` 暂时不可读时，同一范围下此前已知的纯配置入口仍可选择，活动标为未核实。成功读到配置或确认文件缺失时，以当前配置为准。当前完整扫描失败时撤销缓存覆盖依据。迟到响应和已放弃的请求不能覆盖或撤销更新且已经得出结果的扫描。

Each verified configuration read, including an absent file observed by a summary, updates the same-scope configuration snapshot independently of transcript statistics. An I/O failure, invalid UTF-8, or a malformed project header leaves the last verified snapshot available for provisional choices. Well-formed declarations from the latest partial read can also supply provisional choices. Discovery tracks the latest configuration read outcome separately and uses it when assembling the response. A newer failed or partial read keeps configuration-only rows visible and pauses their automatic restoration, including in a full response whose transcript scan started earlier. / 每次核实配置都会独立于转录统计更新同一范围的配置快照，快速列表确认文件缺失时也会更新。读取失败、UTF-8 无效或项目声明头损坏时，保留最近一次已核实的快照以提供待核实入口。最近一次部分读取中格式完整的声明也可提供待核实入口。发现单独记录最近一次配置读取的结果，并在组装响应时使用它。更新的失败或部分读取会保留纯配置入口的可见性并暂停自动恢复，包括转录扫描较早启动的完整响应。

Only project table headers outside TOML values participate in discovery. Quoted keys use [TOML string escaping](https://toml.io/en/v1.1.0#string). Invalid table brackets or whitespace, duplicate project table declarations, and incomplete multiline values make the configuration provisional. A late verified configuration snapshot displaces older choices, while valid partial declarations augment that snapshot only when observed later. / 发现只采用 TOML 值之外的项目表头。引号键遵循 [TOML 字符串转义规则](https://toml.io/en/v1.1.0#string)。表头括号或空白不合法、项目表重复声明，或多行值不完整时，配置保持待核实状态。迟到的已核实快照会取代更早的入口，符合格式的部分声明只有在该快照之后观察到时才用于补充。

A full request superseded by a successful newer full scan uses the winning transcript candidates and diagnostics. A newer full failure prevents an older request from authorizing automatic restoration. If a competing request completes during directory identity checks, discovery reassesses changes to the effective evidence. An equivalent configuration can reuse those checks. / 较新的完整扫描成功后，已被取代的较早完整请求采用胜出的转录候选和诊断。较新的完整扫描失败后，较早请求无法作为自动恢复的依据。如果核验目录身份时另一请求完成，发现会重新评估有效依据是否变化。配置等价时可以复用已做的核验。

The chooser can report a decoded non-object record as incomplete coverage. Verified enumeration checks that observed rollout directories retain their identity and modification time through traversal. Disappearance, replacement, or a change to a directory's entries makes coverage incomplete. Verification reads each plain rollout from one open handle and compares its identity, size, and modification time before and after reading, including the final pathname. A changed artifact contributes no cwd evidence, and the chooser continues using other readable artifacts. Single-file indexing still observes the first decoded object, including an array, before testing project metadata. A later `session_meta` can provide cwd membership while the first decoded object determines which record can declare the file's history base. / 选择器可以将解码后不符合对象记录格式的内容计为覆盖不完整。核验遍历会检查已观察到的转录目录在遍历期间的身份和修改时间。目录消失、被替换或条目变化时，覆盖不完整。核验普通转录时从同一个打开的句柄读取，并对比读取前后及最终路径的工件身份、大小和修改时间。变化的工件不提供 cwd 依据，选择器继续使用其他可读工件。单文件索引在检查项目元数据前仍按既有规则观察首个解码对象，数组也计入。后续的 `session_meta` 可以提供 cwd 归属，而首个解码对象决定哪条记录有资格声明文件的历史基点。

Compressed rollout snapshots fingerprint the byte stream from a verified open file handle. Before publishing a snapshot, the reader checks that the exact compressed bytes consumed by the decoder match the fingerprint and that the source still matches. In verified discovery, the physical identity and metadata observed by the chooser must also match the handle used by snapshot acquisition, including when it can reuse an existing snapshot. / 压缩转录快照从经过核验的打开句柄读取字节并计算指纹。发布快照前，读取器核对解码器实际消费的压缩字节是否匹配指纹，并复核来源。用于核验的发现还会检查选择器观察到的物理身份和元数据是否匹配获取快照时使用的句柄，复用已有快照时也要核对。

The discovery response lists visible rows in `projects` and suppressed rows in `hiddenProjects`. When a current full refresh fails, the browser can temporarily re-expose the hidden choices from its most recent accepted response for the same source and policy, with activity marked unverified. Reopening the chooser shows those choices while the next refresh is pending, including when its summary fails. Activity for a newly eligible extended path remains unverified when the cached scan lacked complete coverage. Edits to inactive sources leave the active discovery running. Only successful full discovery can hide provisional choices again or authorize automatic restoration. Restoration checks both lists for a verified candidate with the saved lexical key under the saved source home and policy. Indexing uses that same key. / 发现响应的 `projects` 提供可见条目，`hiddenProjects` 提供隐藏条目。当前完整刷新失败时，浏览器可恢复同一来源和路径策略下最近一次接受的响应中的隐藏入口，并将活动标为未核实。重新打开选择器时，即使下一次快速列表失败，这些入口仍会在刷新等待期间显示。若缓存扫描的覆盖不完整，刚符合隐藏条件的扩展路径仍标为活动未核实。编辑非活跃来源时，活跃来源的发现可以继续运行。只有成功完成的完整发现可以再次隐藏待核实入口，或触发自动恢复。自动恢复在两份列表中按保存的词法 key 查找已核实的候选，并核对保存的来源根和策略。索引使用同一 key。

When a current discovery response reports that another client changed the active scope, the browser discards its old rows, applies the authoritative scope, and retries discovery once. Discovery responses also report the committed project selection and the identity of any current failed job. The browser updates Return and source-switch confirmation from the committed selection, and keeps a displayed retry only while its failed job is current. Both checks apply even if the policy digest is unchanged. Automatic restoration yields to a project committed by another client during discovery. While retrying within the same scope, a previously re-exposed project remains provisional by its original key if the next accepted response still reports its activity pending. Responses from a locally superseded request are ignored. An explicit change to the authority of the active source's rules, such as saving an empty set for the first time, also retires pending discovery without changing the project key. / 当当前发现的响应报告另一个客户端已改变活跃范围时，浏览器会清除旧条目、采用权威范围，并重试发现一次。发现响应还报告已提交的项目选中状态及当前失败任务的身份。浏览器根据已提交的项目更新「返回项目」和来源切换确认，并仅在对应失败任务仍为当前任务时保留「重试」。即使路径策略摘要相同，也执行这两项核验。如果其他客户端在发现期间提交了项目，自动恢复会保留该项目。同一范围重试时，如果下一次接受的响应仍将此前恢复的项目标为活动待核实，就会按原 key 保留其待核实状态。本地已被取代的请求响应会被忽略。活跃来源规则的权威性发生显式变化时，例如首次保存空规则，也会使进行中的发现失效，项目 key 仍保留。

## Evidence and limits / 依据与限制

All regression inputs are synthetic. Pure lexical tests do not establish physical filesystem behavior. Linux acceptance separately creates case-distinct paths, literal-backslash names and symlink boundaries; Windows acceptance must use a complete candidate checkout with native localhost UNC and junctions. Remote SMB/DFS/NAS, Windows symlinks and case-sensitive Windows directories are not newly promised. / 回归输入全部为合成数据；纯词法测试不证明物理文件系统行为。Linux 单独创建大小写不同路径、字面反斜杠名称及 symlink 边界；Windows 需完整候选 checkout 上的原生 localhost UNC 与 junction 实测。不新增远端 SMB／DFS／NAS、Windows symlink 及大小写敏感 Windows 目录的支持承诺。

The [completed plan](../exec-plans/completed/2026-11-12-project-path-interpretation.md) records failed target assertions, implementation, independent reviews, final same-candidate native evidence and support limits. / [已完成计划](../exec-plans/completed/2026-11-12-project-path-interpretation.md)记录失败目标断言、实施、独立审查、最终同候选原生依据及支持边界。
