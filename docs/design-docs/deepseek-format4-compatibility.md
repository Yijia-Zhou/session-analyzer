## Source authority and supported generations / 来源依据与支持代际

This compatibility line reads native DSH formats **0 and 4**. The format-0 reference is DSH `0.1.1-rc.2`, commit `b150a551b8d465e31e418e1b2eaf5e79bbb7d28e`; the format-4 target is DSH `0.1.7-rc.2`, tag `dsh-v0.1.7-rc.2`, commit `477b4f420553e8a52c2fbccc464d7561b239c443`. These are source pins, independent of npm's moving distribution tags. The reference checkouts under ignored `tmp/deepseek-harness-current/` and `tmp/deepseek-harness-0.1.7-rc.2/` are inspection aids, not runtime dependencies. / 本兼容线读取 DSH 原生 **format 0 与 4**。Format 0 的参考版本为 DSH `0.1.1-rc.2`、上述 `b150a551…` commit；format 4 的目标为 DSH `0.1.7-rc.2`、tag `dsh-v0.1.7-rc.2`、上述 `477b4f42…` commit。这些固定源码版本独立于 npm 浮动分发标签。忽略目录 `tmp` 中的两个参考 checkout 仅用于检查，不是运行依赖。

The pinned [Session types](https://github.com/deepseek-ai/deepseek-harness/blob/477b4f420553e8a52c2fbccc464d7561b239c443/packages/core/session/src/types.ts) define format 4. Its writer/type declarations take precedence over the same checkout's older format-status prose. [Message types](https://github.com/deepseek-ai/deepseek-harness/blob/477b4f420553e8a52c2fbccc464d7561b239c443/packages/llm/llm/src/message.ts), [assistant stream representation](https://github.com/deepseek-ai/deepseek-harness/blob/477b4f420553e8a52c2fbccc464d7561b239c443/packages/llm/llm/src/assistant-stream.ts), [PTC producer](https://github.com/deepseek-ai/deepseek-harness/blob/477b4f420553e8a52c2fbccc464d7561b239c443/packages/core/tools/src/ptc.ts), and the persistence codec are structural authorities. Minimized synthetic fixtures exercise the adapter's interpretation; local writer observations supply complementary acceptance evidence. / 固定版本的 Session 类型定义 format 4，其 writer／类型声明优先于同 checkout 中较旧的格式状态文字。消息类型、assistant 流表示、PTC 生产者及持久化 codec 是结构依据。最小合成 fixture 检验 adapter 的解释；本地真实 writer 观察提供补充验收证据。

Formats 1–3 and unknown future formats are explicitly unsupported. Analyzer does not run DSH migrations, create successor generations, or reinterpret an unsupported header as format 0 or 4. An unsupported selected generation produces `DEEPSEEK_FORMAT_VERSION_UNSUPPORTED`. / Format 1–3 与未知未来格式明确不受支持。Analyzer 不运行 DSH 迁移、不创建后继代际，也不把不支持的 header 当作 format 0 或 4。选中的代际不受支持时报告 `DEEPSEEK_FORMAT_VERSION_UNSUPPORTED`。

## Artifact selection and stable reads / 工件选择与稳定读取

Canonical names are `session.jsonl[.zstd]` for generation 0 and `session.vN.jsonl[.zstd]` for a positive safe-integer generation without leading zeroes. Temporary suffixes and noncanonical spellings do not become candidates. Within each session directory, select the highest canonical generation before attempting header or body decoding. A valid predecessor never substitutes for an unsupported, corrupt, or header-mismatched successor. Only the selected generation contributes an Indexed Session. / 第 0 代的规范文件名为 `session.jsonl[.zstd]`；正安全整数代际使用不带前导零的 `session.vN.jsonl[.zstd]`。临时后缀及非规范拼写不成为候选。在每个会话目录内，先选最高规范代际，再解码 header 或正文。不支持、损坏或 header 不匹配的后继均不能被有效前代替代；只有选中的代际能形成索引会话。

Both encodings at the highest generation are an ambiguity, reported as `DEEPSEEK_STORAGE_INVALID`; neither encoding wins by timestamp or size. A header must agree with its filename generation. Excluded predecessor files are counted as excluded candidates, not duplicated Sessions. / 最高代同时存在两种编码构成歧义，报告 `DEEPSEEK_STORAGE_INVALID`；不按修改时间或大小选择编码。Header 必须与文件名代际一致。被排除的前代文件计入排除候选数，不重复生成会话。

Existing committed-prefix and accepted-snapshot rules remain authoritative. Materialization, Detail, and Raw reads validate file identity, accepted bytes, and their digest, and revalidate generation selection. Publishing a successor or creating a selected-generation encoding collision can invalidate a snapshot even when the predecessor bytes are unchanged. Such reads report `INDEXED_SOURCE_STALE`; they must not return stale content under an old accepted selection. / 既有已提交前缀与已接受快照规则继续生效。物化、详情及 Raw 读取验证文件身份、已接受字节和摘要，并重新核验代际选择。即使前代字节不变，发布后继或在选中代际制造编码冲突也会使快照失效。此类读取报告 `INDEXED_SOURCE_STALE`，不得沿用旧选择返回陈旧内容。

Plain files retain the existing newline-terminated prefix rule; compressed files retain complete-frame validation and the existing torn-tail boundary. Format support does not authorize salvaging invalid committed records or silently skipping sequence gaps. / 普通文件沿用以换行终止的前缀规则；压缩文件沿用完整帧验证及既有未完整写入尾部边界。格式支持不允许挽救无效已提交记录，也不允许静默跳过序号缺口。

## Native event interpretation / 原生事件解释

| Concern / 关注点 | Contract / 契约 |
| --- | --- |
| Physical event / 物理事件 | A v4 event owns one physical row and its original `seq` and `time`. Inclusive `sourceEventSeqs` ranges are expanded only in interpretation; Raw retains the compact representation. / 每个 v4 事件拥有一条物理行及其原始 `seq`、`time`。`sourceEventSeqs` 的闭区间只在解释时展开；Raw 保留紧凑表示。 |
| Committed assistant message / 已提交助手消息 | `assistant/message.data.message` supplies Main text and reasoning. `interrupted:true` marks the delivered committed prefix as interrupted. Embedded stream fragments do not create extra Main messages or calls. / `data.message` 提供 Main 正文与推理；`interrupted:true` 将已交付且已提交的前缀标为中断。嵌入流片段不额外生成 Main 消息或调用。 |
| Attempt without a message / 未提交消息的尝试 | `assistant/attempt` remains explicit Protocol with bounded readable text/reasoning and stream facts. It commits no surface message. Its presence alone does not prove failure, cancellation, a retry, or tool execution. / `assistant/attempt` 保持为明确的 Protocol，显示有界文本／推理和流事实。它未提交模型可见消息；仅凭其存在不能判定失败、取消、重试或工具执行。 |
| Stream timing / 流时间 | `time0` is the first compact member's time; successive `dt` values accumulate within that run. A raw `chunk` uses its own `time`. The Logical Event uses settlement `event.time`; exact fragment timing stays in Raw. No latency or cancellation duration is inferred. / `time0` 是紧凑段首成员时间，后续 `dt` 在该段内累加；原生 `chunk` 使用自身 `time`。逻辑事件使用结算时的 `event.time`；精确片段时间留在 Raw，不推断延迟或取消耗时。 |
| Terminal outcome / 终止结果 | V4 `turn/end` keeps Protocol ownership and maps explicit `error`, `interrupted`, and `aborted` reasons to failed, interrupted, and aborted statuses. Error termination is an issue with readable error text/code; user cancellation has normal severity. This does not assign an outcome to preceding attempts. / V4 `turn/end` 保持 Protocol 归属，将明确的 error、interrupted、aborted 原因映射为 failed、interrupted、aborted 状态。错误终止计入问题并显示错误正文／代码；用户取消保持普通严重性。这不会给之前的 attempt 推断结果。 |
| Tool result / 工具结果 | V4 uses `message.role:'tool'`, direct `message.content`, `message.isError`, and `message.toolCallId`; v0 keeps its nested `tool-result` block. Pair only through durable call identity. / V4 使用工具角色、直接内容、消息级错误标记和调用 ID；v0 保持嵌套 `tool-result` 块。仅按持久化调用身份配对。 |
| Shell and approval / Shell 与审批 | Native `pwsh` and `bash` operations map to commands, including PTC dispatches and incomplete calls. Direct PowerShell requests use their recorded command text and language. Paired approval lifecycles sort at their source position before turn endings and retain exact request/call identity. / 原生 `pwsh` 与 `bash` 操作映射为命令，涵盖 PTC 派发和未完成调用。直接 PowerShell 请求使用实际记录的命令正文和语言。配对审批生命周期按来源位置排列在回合结束之前，保留精确请求／调用身份。 |
| PTC / 程序化工具调用 | V4 retains outer `run_code` and native `tool/ptc-dispatch[-start]`; v0 retains `tool/code-dispatch[-start]`. Topology uses exact `rootCallId`, `parentCallId`, and `subCallId`; nested and outer Raw ownership stays distinct. / V4 保持外层 `run_code` 和原生 PTC 事件名；v0 保持原事件名。拓扑只依据三个精确 ID，内外层 Raw 归属保持独立。 |
| Code language / 代码语言 | V4 runtime supports different program languages, while each call only records source text and description. Detail does not assert JavaScript from the `run_code` name. / V4 运行时支持不同编程语言，但每次调用仅记录代码文本和说明。详情不由 `run_code` 名称断言 JavaScript。 |
| Context and configuration / 上下文与配置 | System/developer messages are readable Protocol. Direct human source remains `kind:'user'`; other producer kinds retain runtime-context provenance. `request/header.header.config` supplies provider/model; system text belongs to `system/message`, and `startsSeries` is independent of header reason. / System／developer 消息显示为可读 Protocol。直接人类来源仍是 `kind:'user'`；其他生产者保留运行上下文来源。Request header 的 config 提供 provider／model，system 正文属于独立消息，`startsSeries` 独立于 header reason。 |
| Surface replacement / 模型可见历史替换 | V4 replacement bounds are `startSeq/endSeq`; v0 uses `start/end`. Prune `shadowedRange` remains `start/end`. Historical original results remain Main evidence; exact validated replacement chains supply provenance without a second execution. / V4 替换边界为 `startSeq/endSeq`，v0 为 `start/end`；prune 的 `shadowedRange` 仍为 `start/end`。历史原结果仍属于 Main，精确验证的替换链提供来源关系，不产生第二次执行。 |

The known-event vocabulary is the union of the two pinned sources. Known but unmodeled additions, such as subagent catalog/policy, workspace changes, deliverables, image offload, and feedback edits, retain Protocol/Raw evidence rather than gaining unverified domain behavior. Unknown source types remain explicit fallback evidence within a supported decodable generation. Approval, command, retry, Goal, and Todo reuse existing semantic rules only where their exact source shapes match. / 已知事件词汇取两个固定来源的并集。子代理目录／策略、工作区变更、交付物、图片外置及反馈修改等已知但未建模新增类型保留 Protocol／Raw 证据，不赋予未经核验的领域行为。在支持且可解码的代际内，未知类型也保持明确回退证据。审批、命令、重试、Goal、Todo 仅在来源精确结构吻合时复用既有语义规则。

The pinned default PTC transport excludes `run_code` from its program-facing `tools` bindings (`packages/core/tools/src/ptc.ts`); direct `tools.run_code` recursion is not a supported native scenario. Parent PTC → subagent → child PTC is observed across distinct Sessions. Deeper same-Session topology fixtures are structural tests, not claims that the default writer exposes recursive programs. / 固定版本的默认 PTC transport 从程序可见的 `tools` 绑定中排除 `run_code`；直接 `tools.run_code` 递归不是受支持的原生场景。已观察到父 PTC → 子代理 → 子 PTC 的跨会话调用。更深的同会话拓扑 fixture 属于结构测试，不代表默认 writer 暴露递归程序。

## Fork and subagent boundaries / 分叉与子代理边界

Format 0 continues to derive inherited ownership from `SessionHeader.seedLength`. Format 4 replaces that field with `isSeeded` and uses the **last** `session/end-seed` whose `data.inherited === true` as the current inherited-prefix cut. Untagged restore/resume markers do not move that cut; ancestor tagged markers do not override the latest one. The tagged marker and synthetic closers after it belong to the child. `isSeeded` must agree with the presence of this marker; inconsistent input is invalid. / Format 0 继续从 `SessionHeader.seedLength` 推导继承归属。Format 4 用 `isSeeded` 替代此字段，并以 **最后一个** `data.inherited === true` 的 `session/end-seed` 作为当前继承前缀截止位置。无标签 restore／resume 标记不会移动边界；祖先带标签标记也不会覆盖最后一个。带标签标记及之后的合成闭合事件属于子会话。`isSeeded` 必须与标记是否存在一致，否则输入无效。

Parent lineage and subagent origin remain separate facts. Descriptor versions 2 and 3 are recognized; v3 adds optional `agentReasoningEffort` for continuable children. A parent-owned `subagent/catalog` record remains source evidence and does not manufacture a child Session or replace the child's header/descriptor. / 父会话谱系与子代理来源保持为独立事实。识别 descriptor 版本 2、3；v3 为可继续子会话增加可选 `agentReasoningEffort`。父会话拥有的 `subagent/catalog` 记录保持来源证据，不制造子会话，也不替代子会话 header／descriptor。

Fork repair results after the cut retain their own child Protocol/Raw evidence and never pair across the inherited boundary. A `TOOL_NOT_STARTED` result proves no execution; `TOOL_OUTCOME_UNKNOWN` leaves a recorded child operation incomplete. A child-owned `turn/end` with reason `forked` and no child-owned `turn/start` is repair evidence and does not add a child turn to the count; its original turn ID and Raw remain inspectable. Native PTC projections retain source chronology before step/turn endings. / 边界之后的 fork 恢复结果保留独立的子会话 Protocol／Raw 证据，不跨继承边界配对。`TOOL_NOT_STARTED` 不证明执行发生；`TOOL_OUTCOME_UNKNOWN` 将已记录的子会话操作保持为 incomplete。子会话拥有、原因为 forked 且没有子会话自有 turn/start 的 turn/end 属于修复证据，不增加子会话回合数；原始 turn ID 与 Raw 仍可检查。原生 PTC 投影按来源顺序排列在 step／turn 结束之前。

## Replacement bounds and completed stream blocks / 替换边界与完整流块

Replacement endpoints identify positions in the current surface. Each endpoint must reference an earlier event, but sequence numbers need not ascend: a previous replacement can leave surface `[5, 2]`, for which `startSeq:5, endSeq:2` is valid. Both formats resolve order through current surface positions. Numeric `sourceEventSeqs` ranges still require ascending endpoints. / 替换端点标识当前 surface 中的位置。两个端点均须引用更早的事件，但序号不必递增：前次替换可以形成 `[5, 2]`，此时 `startSeq:5, endSeq:2` 有效。两种格式均按当前 surface 位置确定顺序；数值型 `sourceEventSeqs` 区间仍要求端点递增。

`src/deepseek-harness-stream.js` shares attempt extraction between indexing and Detail. It groups fragments by block index in first-seen order. The first `block-end` supplies authoritative completed content; prior deltas are replaced and later fragments for that closed block are ignored. Open blocks retain accumulated deltas. Text, reasoning, and search projections stay bounded without consuming the budget on superseded partial content. Tool blocks do not create executions or Main messages, and original streams remain unchanged in Raw. / `src/deepseek-harness-stream.js` 在索引与详情之间共享 attempt 提取逻辑，按块索引归组并保持首次出现顺序。首个 `block-end` 提供权威完整内容，替换之前的增量并忽略该块闭合后的片段；未闭合块保留累积增量。正文、推理和搜索投影保持有界，被完整块替代的部分内容不占最终预算。工具块不生成执行或 Main 消息，Raw 中的原始流保持不变。

## Raw identity, alternatives, and acceptance boundary / Raw 身份、备选方案与验收边界

The physical record at ordinal zero is the session header. Raw Detail preserves that header and its locator, while event extraction excludes it before decoding or checking workflow ownership. Header fields are never subjected to event-envelope requirements; ordinary event validation remains strict. / 第零条物理记录是 session header。Raw 详情保留 header 及其 locator，事件提取在解码或检查 workflow 归属前排除该记录。Header 不接受事件 envelope 的字段要求，普通事件仍执行严格校验。

No migration or legacy-shape rewriting occurs in Analyzer. Raw IDs remain based on source Session identity and physical record ordinal. Plain-text line references and compressed-record locators retain their original representation. Assistant embedded streams do not become fabricated physical chunk records. Detail decodes with the physical header version rather than adding a new public canonical format field. / Analyzer 不做迁移或旧结构改写。Raw ID 仍基于来源会话身份与物理记录序号。普通文本行引用与压缩记录 locator 保持原始表示；assistant 嵌入流不会变成虚构的物理 chunk 行。详情依据物理 header 版本解码，不新增公开 canonical 格式字段。

Merely raising a version ceiling was rejected because header ownership, streams, surface references, and tool results changed independently. Running upstream migration code was rejected because it would add source writes and change physical evidence. Falling back to a readable predecessor was rejected because it can silently present stale history. Supporting intermediate generations is a separate compatibility decision requiring their own frozen contracts and fixtures. / 仅提高版本上限不可取，因为 header 归属、流、surface 引用及工具结果分别发生了变化。运行上游迁移不可取，因为它会写入来源并改变物理证据。回退到可读前代不可取，因为它可能静默展示陈旧历史。支持中间代际属于独立兼容决策，需要各自固定契约与 fixture。

Acceptance must distinguish synthetic structural coverage from actual current-writer coverage. Focused tests should cover generation precedence/collisions, unsupported and corrupt successors, header/filename agreement, source ranges, committed tails, embedded attempts/interruption, native PTC/results, seed ownership, and stale snapshot reads. Replay must compare Indexed/Materialized counts and queries, inspect Logical Detail and exact Raw, and report diagnostics rather than treating HTTP readiness as success. / 验收必须区分合成结构覆盖与真实当前 writer 覆盖。聚焦测试应覆盖代际优先级／冲突、不支持及损坏后继、header／文件名一致性、来源区间、已提交尾部、嵌入尝试／中断、原生 PTC／结果、种子归属及快照失效读取。重放必须比较索引／物化计数和查询、检查逻辑详情与精确 Raw，并报告诊断；不能将 HTTP 就绪当作成功。

This design does not claim exhaustive current-writer coverage of approval interactions, failures/retries, forks, subagents, compaction, or every provider/tool. The execution plan records observed cases, unrun checks, and limitations. Real transcripts and unsanitized exports remain local ignored evidence; committed fixtures must be minimized synthetic or sanitized data. / 本设计不宣称已穷尽当前 writer 的审批交互、失败／重试、分叉、子代理、压缩或所有 provider／工具覆盖。实际观察、未运行检查与限制由执行计划记录。真实转录及未脱敏导出保持为本地忽略证据；提交的 fixture 必须是最小合成或脱敏数据。
