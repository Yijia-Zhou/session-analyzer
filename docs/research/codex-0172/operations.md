## 执行与缺口

### 真实文件的 Code Mode 归属核验

运行 `node scripts/audit-codex-0172-cell-witness.js`。该脚本在活动 sessions 目录按修改时间选择近 21 天、至多 12 MiB 的普通 JSONL，最多读取 40 个候选、合计 96 MiB。此次定向读取 9 个候选，选中 1 个首条 metadata 无 fork 标记、全文件 metadata 均无非空 `history_base` 的文件。读取固定初始字节数并核对文件身份、长度、mtime，随后仅把选中的稳定内容复制到私有临时目录。脚本从该目录建立 source-backed 冷索引、物化 session，再按物理行读回 Raw，结束时清理目录。控制台只输出聚合计数。[定向核验脚本](../../../scripts/audit-codex-0172-cell-witness.js)

同一显式 turn 边界内，脚本找到 **3 条**可唯一连接的 wait。每条都有顺序明确的 exec、含完整 `gN:M` 的 pending 回执、携带同值的 wait 及其输出，输入和输出按各自 call ID 配对。**3/3** 的 exec 与回执归于状态 `unknown` 的 Main Code Mode operation，wait 与输出归于单独的 Main `other_tool_call`，共同 owner 为 **0/3**。这 3 条链上的 **12/12** 次 Raw 行回读均与原物理行的子型、call ID 相符。该项将同文件匹配推进到了真实 reader 的事件归属，补充上述合成路径测试。样本按该缺口定向选择，仅覆盖一个文件的 source-backed 冷读取，不能估算其他会话发生率。
