# History state resolution evaluation / 历史状态判定评估

These three tasks test whether a worker can resolve changing state across synthetic Codex sessions. All source records are invented. The project identifier is `/synthetic/history-state-resolution`; five sessions live under `test/fixtures/history-state-resolution/codex/sessions/`. `tasks.json` is the worker-facing prompt set. `answer-key.json` is coordinator-only and must stay out of worker context. The answer key identifies source session IDs and one-based JSONL record lines, not service-generated evidence refs. / 这三项任务检验 worker 能否跨合成 Codex 会话判定变化中的状态。所有来源记录均为虚构。项目标识为 `/synthetic/history-state-resolution`；五个会话位于 `test/fixtures/history-state-resolution/codex/sessions/`。`tasks.json` 是面向 worker 的题目；`answer-key.json` 仅供协调者使用，不能进入 worker 上下文。答案键标明来源会话 ID 和从 1 开始的 JSONL 记录行，不是服务生成的证据引用。

S1 has an earlier unmerged observation and a later successful merge with an ancestry check. S2 has an earlier unmerged observation and a later unverified merge claim after a failed fetch; its latest state is uncertain. S3 has a late record quoting the earlier unmerged report after the verified merge; score the time the quoted state described separately from the time the quote was recorded. A latest timestamp alone cannot determine current state. / S1 包含较早的未合并观察以及随后成功的合并和祖先关系检查。S2 包含较早的未合并观察以及 fetch 失败后的较晚未核实合并说法；其最新状态不确定。S3 在核实合并后出现一条较晚记录，引用较早的未合并报告；评分时须区分引文所描述状态的时间和引文被记录的时间。仅凭最新时间戳不能判定当前状态。

Prepare each trial from a fresh copy of `test/fixtures/history-state-resolution/codex/` outside live Codex transcript roots. Create an empty target project directory, rewrite **only** `session_meta.payload.cwd` from `/synthetic/history-state-resolution` to that directory in the copied JSONL files, and hash the resulting snapshot in a manifest. Keep the original fixture immutable. The existing `prepare-history-eval.js` is specific to the older `history-retrieval-eval` corpus; for this corpus the coordinator should use a dedicated copy/rewrite script or a reviewed one-time copy. Run the same frozen snapshot and project scope for every condition. Never index trial logs, answer keys, or worker outputs. / 每次试验从 `test/fixtures/history-state-resolution/codex/` 全新复制到真实 Codex 转录根之外。创建空的目标项目目录，仅在复制后的 JSONL 中将 `session_meta.payload.cwd` 从 `/synthetic/history-state-resolution` 改为该目录，并在 manifest 中记录所得快照哈希。原始 fixture 保持不变。现有 `prepare-history-eval.js` 专用于旧的 `history-retrieval-eval` 语料；本语料应由协调者使用专门的复制／改写脚本或经审查的一次性复制操作。每种条件均使用相同的冻结快照和项目范围。不要索引试验日志、答案键或 worker 输出。

The planned comparison is raw-history baseline, then skill-only, then API-assisted follow-up. Freeze the raw baseline before exposing the new guide or API to that worker. Keep task wording, corpus hash, actual model/version, harness, retrieval-call and output budgets, and result contract fixed across comparable conditions; record any change as a separate variable. The full target is 3 tasks × 2 models × 2 independent trials × 3 conditions = 36 trials. The older 12-task retrieval matrix is 96 trials across two conditions and has **not** been run for this new corpus. No evaluation result or improvement claim is implied by this plan. / 计划依次比较原始历史基线、仅使用 skill、使用 API 的后续条件。向原始基线 worker 暴露新指南或 API 之前须冻结基线。在可比较的条件间固定题目表述、语料哈希、实际模型／版本、harness、检索调用与输出预算以及结果格式；任何变化都作为独立变量记录。完整目标为 3 题 × 2 模型 × 2 次独立试验 × 3 条件 = 36 次。本新语料**未运行**旧的 12 题、两条件、96 次检索矩阵。此计划不代表已有评估结果或改进结论。

Workers report a conclusion, supporting physical records or resolvable evidence refs, explicit uncertainty, unsuccessful searches, and errors. The coordinator scores final-state correctness, later evidence use, quote/state-time distinction, and citation support by reviewing the answer key and source records. Correct answers can require no `read` call if the returned search or context evidence is sufficient; read counts are diagnostics, never correctness scores. / Worker 报告结论、支持它的物理记录或可解析证据引用、明确的不确定性、未成功的检索及错误。协调者对照答案键和来源记录评判最终状态、较晚证据使用、引文时间与状态时间区分及引用支持。若 search 或 context 返回的证据已充分，正确答案可以无需 `read` 调用；读取次数只是诊断指标，绝非正确性分数。

`node scripts/measure-history-convergence.js [--annotations tmp/annotations.json] [--report tmp/convergence.json] <recorder-log.jsonl>...` reads the existing recorder format without modifying it. The optional annotation file maps `condition/trial` to `{ "provenance": "human review reference", "answerSupported": true, "evidenceUsed": true, "laterStateResolved": true }`; each verdict may also be `false` or `null`. Without a provenance-bearing annotation, those fields remain `null`. A `--report` path must be a new git-ignored file below this checkout's `tmp/`; stdout should also remain private. / 该命令读取现有 recorder 格式，不改写 recorder。可选 annotation 文件按 `condition/trial` 映射至带 `provenance` 的人工结论，三个判断字段可为 `true`、`false` 或 `null`；没有注明来源的人工标注时均保持 `null`。`--report` 必须指向本 checkout 的 `tmp/` 下新的、被 Git 忽略的文件；标准输出也应保持私密。

The analyzer reports search requests and independent grouped queries separately, including queries whose results were omitted or were never executed. It counts only returned group items as hits. It also reports searches before the first observed read, search hits versus unique events, exact known hit positions, observed excerpt bytes and byte-identical repeats, incomplete excerpts, and conservatively resolved search-to-read conversion. Distinct excerpts from one event remain distinct hits. Overlapping excerpts are not treated as saved bytes. Compact handles count only when their event identity or returned durable evidence ref resolves them; unknowns and failed, refused, truncated, unparseable, or unclassifiable calls remain visible. No `MatchRef`, model context, token savings, or answer support is inferred from an excerpt or a reference count. / 分析器分别报告搜索请求与分组中的独立查询，包括结果被省略或根本未执行的查询。只有实际返回的分组条目才计作命中。分析器还报告首次观察到读取前的搜索次数、搜索命中与唯一事件、已知精确命中位置、实际返回的摘录字节及逐字节相同的重复、未完整摘录，以及保守解析的搜索到读取转化。来自同一事件的不同摘录仍是不同命中。重叠摘录不算节省的字节。简短 handle 只有在事件身份或返回的持久证据引用能够解析时才计入；未知项以及失败、拒绝、截断、无法解析或无法分类的调用均保留。不能从摘录或引用数量推断 `MatchRef`、模型上下文、token 节省或答案支持。

`firstReadStep` means the first executed `read` with exit code 0 and a valid, error-free read envelope. `readAttempts`, `executedReadRequests`, and `successfulReadRequests` remain separate. `searchRequests` includes denied attempts; `searchesBeforeFirstRead` counts executed search requests before that successful read. If no successful read exists, `searchesBeforeFirstRead` is `null` and `searchesWithoutObservedRead` gives the executed search count. These are workflow diagnostics, not answer scores. / `firstReadStep` 指首次实际执行、退出码为 0、并返回有效且无错误的 read 响应的步骤。`readAttempts`、`executedReadRequests` 和 `successfulReadRequests` 分别记录。`searchRequests` 包含被拒绝的尝试；`searchesBeforeFirstRead` 统计首次成功读取前实际执行的搜索请求。若没有成功读取，`searchesBeforeFirstRead` 为 `null`，`searchesWithoutObservedRead` 给出已执行搜索数。这些是流程诊断，不是答案评分。
