# State-resolution pilot / 后续状态核验试跑

The three scenarios pass in all six complete-guide trials, including the frozen baseline. This establishes a small regression set, **not an accuracy improvement or an end-to-end efficiency advantage**. The API additions work; on these short, clue-rich histories, grouped queries did not consistently reduce the cost of answering. / 三个场景在六次完整指南试跑中均通过，包括冻结基线。这建立了一组小型回归保护，**不证明正确率提升或端到端效率优势**。新增接口可用，但在这些短且线索明确的历史上，分组查询没有一致降低回答成本。

## Method / 方法

Five synthetic Codex Sessions describe an earlier unmerged state, later verified merge, later unverified merge claim with failed checking, and a late quotation of an older report. Three related questions were answered together by each worker; S1 and S3 share evidence. Each condition used fresh `gpt-6-sol` (default effort) and `gpt-6-luna` (max) workers, without inherited development context or answer keys: six trials and eighteen task answers, one trial per model/condition. / 五个合成 Codex 会话覆盖早期未合并、后续已核验合并、后续未核实合并陈述及核验失败、较晚引用旧报告。每个 worker 一起回答三个相关问题，S1 与 S3 共享证据。各条件使用全新 Sol（默认 effort）和 Luna（max），不继承开发上下文或答案键：共六次试跑、十八个任务回答，每模型／条件仅一次。

The baseline runtime and guide were frozen from `d589d56`; the guide-only condition used the same baseline service with precise-first query guidance and bounded later-evidence checking. The API condition used the updated service plus its corresponding guide. Only fixture metadata cwd was rewritten before freezing. Corpus SHA-256: `8bda267b4fa088b1acff206d9a2553c2a0c35db9d5e0d6be472a14446c550ea7`. Recorder, guide and runtime hashes, exact calls and reports are retained in ignored local `tmp/state-eval/` and `tmp/history-eval-results/`. / 基线运行时及指南冻结自 d589d56；仅指南条件使用同一基线服务，增加具体线索优先及有界后续核验；API 条件使用新服务及对应指南。冻结前仅改写 fixture metadata 的 cwd。语料 SHA-256 如上。记录器、指南和运行时 hash、精确调用及报告保留在本地忽略目录。

Each worker had twelve retrieval calls for the entire three-question bundle, including failures/status, and 12,000 combined forwarded bytes per call. Guide reading was split into setup chunks of at most 3,500 characters so the whole guide could be read. Help and question reads are setup when labeled as such; a help invocation never counts as an evidence search in convergence analysis. There was no mandatory search/context/read sequence and no direct filesystem evidence fallback in these trials. / 每个 worker 三题合计十二次检索，含失败及 status；每次最多转发 12,000 字节。指南按不超过 3,500 字符分段在 setup 读取，确保读全。被标为 setup 的 help／题目读取单独计量；收敛分析始终不把 help 算作证据搜索。本轮不强制 search/context/read 顺序，也不允许直接文件系统证据回退。

Four earlier calibration trials had truncated setup guides, including omission of the new rule in guide-only workers. They remain saved and are excluded from the complete-guide comparison. Fresh workers reran both conditions after the setup procedure was corrected; the recorder and retrieval budget were unchanged. This failure demonstrates why guide exposure must be checked from captured/forwarded records rather than assumed from a read call. / 更早四次校准的 setup 指南被截断，包括仅指南组没有读到新增规则；记录全部保留，不纳入完整指南比较。修正 setup 流程后用全新 worker 重跑两个条件，记录器及检索预算不变。该失败说明，必须从捕获／转发记录核对指南暴露，不能仅凭一次读取调用假定已读全。

## Provided-locator probe / 已提供定位的试用

After finishing its state answers, the API Sol worker received a separate legacy path plus physical-line locator. In three calls it read the Raw Record, reused the returned SourceRef, and followed an explicit Logical Event reference: 7,179 returned bytes / 2,356 reference tokens, no errors/truncation. It correctly explained that `unverified_legacy_locator` does not authenticate an old note, and `source_snapshot_verified` verifies accepted stored bytes, not the truth of the contained merge claim. / 状态题完成后，API Sol worker 另收到旧路径及物理行定位。三次调用读取 Raw、复用 SourceRef、沿明确逻辑事件引用读取：返回 7,179 字节／2,356 参考 token，无错误／截断。它正确解释，unverified_legacy_locator 不认证旧笔记，source_snapshot_verified 核验已接受存储字节，不证明其中的合并陈述真实。

The locator was supplied, the worker context was reused, and no discovery comparison is claimed. Source-change invalidation, outside-path rejection, unsupported storage, blank lines, multiple associations and continuation are deterministic tests rather than model-trial claims. / 定位由协调者提供，复用同一 worker 上下文，不作发现能力对比。来源变更失效、越界路径、未支持存储、空行、多关联及续读属于确定性测试，不冒充模型试跑结论。

## Implementation acceptance and limits / 实现验收与局限

Full Node suite passed 1,300/1,300 before the final group-prevalidation/analytics refinements. Runtime/transport/source/metrics/package focused checks passed 66/66 after group prevalidation; the final CLI-help and durable-reference analytics regressions passed 9/9 in their affected suite. Installed-package smoke passed all three sources' existing UI/history paths and independent groups, plus Codex source-locator bootstrap and snapshot reuse. Browser sources/assets did not change; no full browser interaction rerun. Python skill validation was unavailable locally; Node frontmatter/reference checks were used. / 最后分组预校验／统计修正前完整 Node 1,300/1,300；分组预校验后运行时／传输／来源／统计／打包聚焦检查 66/66；最终 CLI help 及持久引用统计回归在受影响套件中 9/9。安装包验收覆盖三来源既有 UI/history 与独立分组，以及 Codex 定位首次读取和快照复用。浏览器源码／资产未改，未重跑完整交互套件。本地 Python skill 校验不可用，以 Node 检查 frontmatter／引用。

Independent Astra reviews found and repaired blank-line reads bypassing validation, denied reads being counted as reading, semantic validation skipped for groups omitted by the batch budget, and read conversion missing events whose evidence-reference hit offsets changed. Follow-up reviews found no remaining actionable issue; multi-owner pagination and help-shaped literal clues have regression coverage. This is an implementation increment with bounded usability evidence, not the full 96-trial matrix or full-branch merge acceptance. / 独立 Astra 审查发现并修复空行读取绕过校验、拒绝 read 被计为读取、整批预算省略组跳过语义校验，以及证据引用命中偏移变化导致漏计候选读取。复审无剩余可执行问题，多关联分页及形似 help 的字面查询有回归覆盖。本轮是实现增量与有界可用性证据，不是完整 96 次矩阵或整个分支合并验收。
