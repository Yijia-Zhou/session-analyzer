# Real development decision evaluation / 真实开发决策评估

Freeze the baseline runtime revision before implementation; lock six to eight selected real development questions and their private reference key before their trials. Record these as separate boundaries when task preparation overlaps implementation. Cover weak user clues that require stronger historical terms, evidence in the middle or tail of long events, parent/child or explicitly superseding decisions, and original evidence handed to a human for continued reading. Keep questions separate from coordinator-only facts, physical source records and scoring notes. Real transcripts, answers, source paths and private captures remain in ignored local `tmp/`; do not add them to repository fixtures. / 实现前冻结基线运行时版本，各项试验前锁定六至八项真实开发问题及私有参考答案；准备题目与实现并行时，分别记录这两个边界。覆盖弱线索逐步收敛为历史强线索、长事件中后部依据、父子会话或明确取代旧结论的决策，以及向人交付原始依据并继续阅读。题目与协调者专用事实、物理来源记录和评分说明分开；真实转录、回答、来源路径及私有捕获保留于本地忽略的 `tmp/`，不加入仓库 fixture。

The three [state-resolution scenarios](../history-state-resolution/README.md) are fixed regression cases. Their saturated baseline does not measure general task success, token savings or memory benefit. A selected real-task pilot also cannot establish representative project recall; report shared work episodes and source gaps. / 三项[状态判定场景](../history-state-resolution/README.md)是固定回归，已饱和的基线不量测普遍任务成功率、token 节省或记忆收益。精选真实题目的试跑同样不能代表项目召回率，需说明共用历史任务及来源缺口。

Freeze runtime commit/tree, source artifact hashes, task wording, environment, requested and independently verified model configuration, harness, budgets and guide exposure. Record the exact guide bytes forwarded and whether the worker received them completely. Compare independent fresh workers on the same task/corpus/model/environment; label an API-plus-instruction bundle honestly when both changed. Do not reuse a worker that has seen the answer key or a previous condition. Recheck corpus hashes without repairing a source midway through a pair. / 冻结运行时 commit/tree、来源工件 hash、题目、环境、请求及独立核实的模型配置、harness、预算及指南暴露。记录实际转发的指南字节，以及 worker 是否完整收到。同题／语料／模型／环境采用独立全新 worker；API 和指令同时变化时明确称为组合干预。不复用看过答案或另一条件的 worker；重新核对语料 hash，不在配对中途修复来源。

Use the existing [recorder](README.md#payload-and-frozen-corpus-tooling--载荷与冻结语料工具) for actual calls. Setup and deterministic reference checks are preparation, not model trials. A running command's session ID must be polled to completion before another call uses the same trial lock; preserve errors rather than deleting a live lock. Keep outer tool delivery large enough for the recorder byte cap, and record any additional truncation. Missing actual input/output/cache/reasoning/cost usage stays explicitly unavailable; payload bytes, reference token counts and passing tests cannot establish total-token or memory savings. / 实际调用使用现有[记录器](README.md#payload-and-frozen-corpus-tooling--载荷与冻结语料工具)。Setup 和确定性引用检查属于准备，不是模型试验。命令返回 session ID 时应轮询完成后再复用同一试验锁，保留错误，不删除活跃锁。外层工具需能完整容纳记录器字节上限，额外截断须记录。实际输入／输出／缓存／推理／费用缺失时明确为不可得；载荷字节、参考 token 与测试通过不能证明总 token 或记忆收益。

Score each layer separately using `true`, `false`, or `null` (unassessed), with review provenance. Distinguish physical inclusion from service admission and actual worker delivery. A nonprimary historical source locator rejection does not prove its canonical event is absent: check canonical search/read and Raw mapping first. An incomplete corpus is an evaluation limitation, not automatically a worker error. / 每层独立评分，使用 `true`、`false` 或 `null`（未评估）并记录审查依据；区分物理语料包含、服务准入与实际交付给 worker。非主历史文件的 locator 被拒绝不证明规范事件缺失，应先查规范搜索／读取及 Raw 映射。不完整语料是评估限制，不自动算作 worker 错误。

`node scripts/assess-history-decision-eval.js <private-annotation.json> <new-tmp-report.json> [recorder-log.jsonl ...]` validates explicit assessments and immutable trial identity, including the harness and enforced budgets actually recorded on every log row. It does not infer correctness or model reading from call counts. Its exported `pair()` requires independent trial identities, completed assessments, retrieval logs, hashed answers and verified recorder configuration; it rejects task/model/harness/environment/budget mismatches and records a changed guide as an intervention. Missing legacy recorder configuration stays unverified and cannot certify a pair. A completed trial needs a real retrieval log and an existing private answer file whose hash is recorded; preparation remains `prepared`. / 此命令校验显式评分及固定试验身份，包括每条日志实际记录的 harness 与执行预算，不从调用数推断正确性或模型阅读。导出的 `pair()` 要求独立试验身份、已完成评分、检索日志、回答 hash 及已核验记录器配置，拒绝题目／模型／harness／环境／预算不匹配，将指南变化记为干预。旧日志缺失记录器配置时保持未核验，不能认证配对。完成的试验需要实际检索日志及确实存在的私有回答文件，并记录其 hash；准备状态仍为 `prepared`。

Passing human handoff requires checking the returned URL/ref against the actual target, supporting original content and continued reading, retaining private verification evidence. `targetVerified`, `viewerReady`, and `browserOpenRequested` are separate API receipts; none proves rendering or reading. Mark handoff `null` when UI verification is unavailable. Browser captures against real sources stay private and must not use the synthetic-only `e2e/browser-diagnostics.js` helper. / 人的交接通过需要核对返回 URL/ref 的实际目标、支撑原文及继续阅读，保留私有验证依据。上述三项是分别的 API 回执，均不能证明渲染或阅读；UI 无法核验时交接评分为 `null`。真实来源浏览器捕获保持私密，不使用仅供合成来源的 `e2e/browser-diagnostics.js`。
