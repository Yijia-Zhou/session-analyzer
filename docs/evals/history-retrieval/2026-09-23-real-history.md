# Retrieval efficiency and real-history pilot / 检索效率与真实历史试跑

The compact presentation reduces repeated protocol payload, but this pilot does **not** establish lower end-to-end cost or better recall than raw search. Both first-round hybrid workers incorrectly replaced a later merge with an older unmerged status. A fresh guided follow-up recovered the later evidence, using raw-source fallback. / 紧凑呈现减少了重复协议载荷，但本次试跑**没有**证明端到端成本或召回优于原始搜索。首轮两个混合组都错误地用较早的未合并状态覆盖了后续合并；更新指南后的独立复测找回后续证据，使用了原始来源回退。

## Scope and method / 范围与方法

Four explicitly selected real Codex Sessions, 17,979,541 bytes, ended before 2026-09-22 and were frozen without rewriting. SHA-256 corpus identity: `03904b830b6508652f68615253d9fe9566075fddada0c09313bc0f6d5998977f`. Sources, questions, private evidence keys, model outputs and exact captures remain in ignored local `tmp/`; no real transcript is included in this report. This is a retrospective task, using the last relevant evidence within the frozen snapshot, not a simulation of what was knowable before the historical work. / 明确选择 4 个真实 Codex 会话，共 17,979,541 字节，均在 2026-09-22 前结束，未经改写冻结。语料 SHA-256 如上。来源、问题、私有证据键、模型回答和精确输出留在被忽略的本地 `tmp/`，本报告不包含真实转录。这是回顾任务，以冻结快照内最后相关证据为准，不模拟历史工作发生前能知道什么。

- **R1:** reconstruct a performance optimization's rationale, changed measurements, sample limitations, stop/close decision and reopening conditions. / 重建性能优化理由、前后测量变化、样本限制、停止／关闭决定及重开条件。
- **R2:** recover a compressed-input boundary failure, validation gap, repair and red/green sequence, then distinguish local acceptance, CI and a merge recorded in a later Session. / 找回压缩输入边界错误、验证缺口、修复及红绿过程，再区分本地验收、CI 与后续会话中的合并证据。

The first-round matrix comprises two named models (`gpt-6-sol`, default effort; `gpt-6-luna`, max), four conditions, and one independent worker per cell answering both questions: eight trials / sixteen task answers. Each received the same questions and snapshot, a 12-call retrieval budget for both tasks combined, and a 24,000-byte output limit per call. Structured/hybrid workers could use raw fallback; neither first-round structured worker did. A separate answer-blind builder produced the same generic memory for summary/hybrid workers without receiving the questions. Older Astra/Luna attempts hit provider limits; their partial artifacts are retained separately and excluded from this matrix. / 首轮矩阵包含两个明确模型（Sol 默认 effort、Luna max）、四个条件，每格一个独立 worker 回答两题，共 8 次试验／16 个任务回答。问题和快照相同，两题合计预算为 12 次检索、每次输出 24,000 字节。结构化／混合组可回退原始检索；首轮两个结构化 worker 均未使用。独立记忆构建者不接收题目，为摘要／混合组生成同一份通用记忆。较早 Astra／Luna 尝试遇到 provider 限额，其部分产物另行保留，不计入本矩阵。

## Memory cost and interpretation / 记忆成本与解释

The generic builder made 11 calls, receiving 108,893 bytes / **29,250 reference tokens** and producing a 20,185-byte memory. Its actual generation, reasoning and maintenance cost is unknown. Sol's first summary-assisted use therefore accounts for at least 29,250 + 5,554 = **34,804 measured incoming payload tokens**, before generation and other unmeasured model costs. Reuse can amortize construction, but this pilot does not measure that lifecycle. / 通用构建者调用 11 次，接收 108,893 字节／**29,250 个参考 token**，产出 20,185 字节记忆。实际生成、推理及维护成本未知。因此 Sol 首次使用摘要，已量测的传入载荷至少为 29,250 + 5,554 = **34,804 token**，尚未计生成等模型成本。重复使用可摊薄构建成本，但本试跑没有量测该生命周期。

The summary-only workers recovered important distinctions cheaply at query time because the builder had already selected them. The hybrid failures show that opening an original source improves provenance but does not automatically improve recency or correctness. Their citations resolved to real records; the conclusions were still stale. / 摘要组查询时以较低载荷恢复了重要区别，因为构建者已事先选中这些信息。混合组失败说明读取原始来源提高溯源能力，却不会自动提高时效性和正确性。其引用可以解析到真实记录，结论仍然过期。

These summary/hybrid conditions are architectural proxies, **not benchmarks of native Codex, Claude Code, Copilot, Cursor or third-party memory products**. The relevant tradeoff remains write-time selection and amortized reuse versus read-time evidence recovery. Neither guarantees complete historical recall or current-code validity. No product ranking or dollar-cost comparison follows from this experiment. / 摘要／混合条件只是架构代理，**不是 Codex、Claude Code、Copilot、Cursor 或第三方记忆产品的原生基准**。相关取舍仍是写入时选择与摊销复用，对比读取时恢复证据；两者均不保证历史全召回或当前代码有效性。本试验不能推出产品排名或美元成本对比。

## Repair and independent follow-up / 修正与独立复测

The first-round guide was frozen before adding a rule to compare timestamps across Sessions and preserve later unresolved leads instead of replacing them with older verified status. A fresh Sol hybrid worker then used the updated guide plus enforced recorder budgets. It answered both tasks with supporting physical-record citations, distinguishing the earlier unmerged state from the later squash merge. / 首轮指南在修改前已冻结。新增规则要求跨会话比较时间，并保留后续未核实线索，不能用较早已核实状态覆盖。之后全新 Sol 混合 worker 使用新版指南和强制记录器预算，凭物理记录引用回答两题，区分较早未合并与后续 squash 合并。

The follow-up used **12 retrieval calls, 84,239 bytes / 24,435 stdout reference tokens**, plus one setup read of 2,854 tokens; no recorded failed or truncated calls. It used raw-source fallback after memory/search, so this is evidence that the combined workflow can succeed, not proof that structured navigation alone improved. Guide and budget enforcement both changed, there was only one follow-up, and no causal effectiveness claim is made. Both original failures remain part of the result. / 复测使用 **12 次检索、84,239 字节／24,435 个 stdout 参考 token**，另有一次 setup 的 2,854 token，无被记录的失败或截断。它在摘要／搜索后回退原始来源，因此证明的是组合工作流可以成功，不能证明单独结构化导航改善。指南和预算执行同时改变，且仅一次复测，不作因果效果声明；两个首轮失败均保留。

The recorder now refuses over-budget retrieval before execution and separately stores exact captured versus forwarded bytes. Truncation emits a visible notice within the byte cap and preserves valid UTF-8 boundaries. Missing provider/harness usage remains null. Final log paths are validated against ignored private output scope and reject existing or dangling symlinks. / 记录器现已在执行前拒绝超预算检索，分别保存精确捕获与转发字节。截断会在字节上限内输出可见提示，保留有效 UTF-8 边界。缺失 provider/harness usage 保持 null。最终日志路径校验私有忽略目录边界，并拒绝既有或悬空符号链接。

## Presentation change and validation / 呈现变更与验证

Opt-in compact responses add context-bound short handles, durable evidence export, shared context event bodies and coverage reuse. Bounded full-session context and readable details reduce unnecessary navigation and UI-renderer duplication; default full responses remain compatible. / 可选紧凑响应增加上下文绑定短句柄、持久证据导出、共享上下文事件正文和覆盖信息复用。有界完整会话上下文及可读详情减少不必要的导航和 UI renderer 重复，默认完整响应保持兼容。

A deterministic replay of the previous six-call synthetic paths, keeping event identity/order and requested parts equal, measured full→compact stdout tokens: **6,788→4,699 (31%)** and **10,708→5,741 (46%)**. These are implementation payload savings on fixed paths, not fresh model trials, total-token savings, or the older pilot's original response counts. / 对此前两条六次调用合成轨迹进行确定性重放，保持事件身份／顺序及所读 parts 相同，完整→紧凑 stdout token 为 **6,788→4,699（31%）**、**10,708→5,741（46%）**。这是固定路径的实现载荷节省，不是新模型试验、总 token 节省或旧试跑原始响应计数。

Full Node validation passed **1,274/1,274** before the final eval-harness repairs. Installed-package UI and history smoke passed Codex, Claude Code and DeepSeek. Runtime Astra review found and repaired lost stream/title labels in readable detail, then returned clean. Eval-harness review additionally caught invisible truncation and final-log symlink containment; final focused runtime/transport/package/eval tests passed 59/59 and repeated Astra review returned clean. Browser sources/assets were unchanged; the full browser interaction suite was not rerun. The Python skill validator was unavailable locally; Node frontmatter/scaffold checks were used. / 最终评估工具修正前，完整 Node 验证 **1,274/1,274** 通过；安装包 UI 和 history smoke 覆盖 Codex、Claude Code、DeepSeek。运行时 Astra 审查发现并修复可读详情丢失流／标题标签，之后复审通过。评估工具审查另发现不可见截断及最终日志符号链接边界，最终运行时／传输／打包／评估聚焦测试 59/59 通过，反复 Astra 复审无剩余问题。浏览器源码／资产未变，未重跑完整浏览器交互套件。本地 Python skill 校验器不可用，以 Node 检查 frontmatter／基本结构。

Citation addressability and answer support were assessed separately: all 31 durable references extracted from first-round named-model reports resolved against the unchanged snapshot; key status/sample claims were checked against the private evidence key. Raw physical citations and memory-carried citations do not become independently verified merely because no durable-ref error occurred. / 引用可解析性与答案支撑分别检查：首轮明确模型报告提取的 31 个持久引用均可在未变化快照上解析；关键状态／样本主张对照私有证据键检查。原始物理引用和摘要携带引用不会因没有持久引用错误就自动成为独立核验。

This selected, clue-rich two-task pilot is not the planned full 96-trial synthetic matrix, an unbiased sample of project questions, or production recall measurement. Further work should test discovery without supplied clues, later contradictory decisions, source gaps, and end-to-end usage with a harness that exposes it. The current results justify keeping evidence recovery and summary memory complementary, and prioritizing chronology and navigation quality over claims of automatic memory correctness. / 本次精挑且提供线索的两题试跑不等于计划中的完整 96 次合成矩阵、项目问题无偏样本或生产召回量测。后续应测试无预置线索发现、后续矛盾决策、来源缺口，并使用暴露 usage 的 harness 测量端到端成本。当前结果支持将证据恢复与摘要记忆互补，并优先改善时间顺序核对和导航质量，而不宣称记忆自动正确。
