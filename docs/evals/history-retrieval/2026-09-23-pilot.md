# Retrieval MVP pilot, 2026-09-23 / 检索 MVP 试跑

This is a functional and usability pilot, not a completed recall/token-efficiency benchmark. The read-only implementation passed its deterministic and installed-package checks. Independent trials found useful evidence and also exposed avoidable reference and disclosure costs, which prompted repairs. / 这是功能与可用性试跑，不是已完成的召回率／token 效率基准。只读实现通过确定性及安装包检查。独立试验找回了有用证据，也暴露了引用及披露开销，并据此进行了修正。

## Corpus and method / 语料与方法

- Baseline checkout: `5c20e60`; worktree branch: `feat/history-retrieval`. Only synthetic transcripts were used. Prepared corpus: seven source files, six target-project sessions and one excluded project. SHA-256: `b55122cf85f1ad5e8b5233dbb93e0ddc1e8a6b5c9b49a95ce9289dd1907f78ae`. / 基线 checkout：`5c20e60`；worktree 分支：`feat/history-retrieval`。仅使用合成转录。准备后语料含七个来源文件、六个目标项目会话及一个排除项目；SHA-256 如上。
- Named configurations were explicitly selected through `collaboration.spawn_agent`: `gpt-6-astra` (default effort) and `gpt-5.6-luna` (`max`). Workers started with `fork_turns=none`, without answers, development history or other worker results. / 通过 `collaboration.spawn_agent` 明确指定 `gpt-6-astra`（默认 effort）及 `gpt-5.6-luna`（`max`）。Worker 均以 `fork_turns=none` 启动，不提供答案、开发历史或其他 worker 结果。
- Each initial trial bundled T03 (changed cache restriction), T06 (hidden operations and missing rerun) and T05 (commit attribution and absent SHA). Baselines used raw transcripts and normal search/JSON tools; enhanced trials used the shipped CLI and packaged guide. Enhanced workers did not use raw fallback. / 每次初始试验组合 T03（缓存限制变化）、T06（省略操作及缺失重跑）、T05（commit 归属与缺失 SHA）。对照组使用原始转录及普通搜索／JSON 工具；增强组使用随包 CLI 与指南，未回退原始文件。
- The pilot budgets were at most 12 shell tool calls for baseline workers and 12 retrieval calls for enhanced workers; enhanced helper commands were not counted as retrieval calls. These counts are not equivalent measures of model effort. A future comparative matrix must use one shared harness and budget rule. / 试跑上限为对照组 12 次 shell 工具调用、增强组 12 次检索调用；增强组辅助命令不计作检索调用。因此调用数不是等价的模型工作量指标；后续对照矩阵必须采用统一 harness 和预算规则。
- The source remained fixed; trial reports and traces were stored outside its root. Exact CLI outputs, errors and elapsed request time were captured by `scripts/record-history-eval.js`. Model tokens, total agent elapsed time and cold indexing time were not measured. / 来源保持固定；试验报告及轨迹保存在来源根之外。`scripts/record-history-eval.js` 记录完整 CLI 输出、错误及请求耗时。未量测模型 token、agent 总耗时或冷索引耗时。

## Repairs and verification / 修正与核验

- Real source-backed tests exposed that compact Codex Raw Records omit `parsed`; artifact classification now uses their preserved structured call fields and request arguments. Actual Codex and Claude indexing/materialization tests protect classification, pairing and counterexamples. / 实际来源测试发现紧凑 Codex Raw 记录省略 `parsed`；工件分类已改用保留的结构化调用字段及请求参数。真实 Codex／Claude 索引与物化路径测试保护分类、配对及反例。
- Reducing the limit while navigating backward could skip the unread part of a range. Range refs now preserve direction, and a complete backward traversal with a shrinking limit is tested. / 向前翻页时减小 limit 曾可能跳过范围未读部分。范围引用现在保留方向，测试覆盖缩小 limit 后完整反向遍历。
- Compact persistent `er2` refs replace long encoded locators; old `er1` refs remain readable. All 77 distinct refs collected from the three initial enhanced reports resolved successfully after restarting with the final implementation (31 inherited, 11 Luna, 35 Astra). / 紧凑持久 `er2` 引用替代长编码定位符；旧 `er1` 仍可读取。三个初始增强报告中的 77 个不同引用在最终实现重启后全部成功解析（继承配置 31、Luna 11、Astra 35）。
- The guide now explains batching, gap counts, increasing the range limit, and programmatic reference reuse. Excerpts also expose `hitOffset` for a precise projection read. / 指南补充批量读取、间隙数量、增大范围 limit 及程序化复用引用。摘录还提供 `hitOffset`，用于精确读取搜索投影。

Final post-repair T06 trials used fresh independent workers. Both recovered the operation sequence, case 5 failure, actual patch and explicit rerun request, while retaining uncertainty about validation. Astra used six calls, 21,091 output bytes and 3,873 ms of CLI time; Luna max used six calls, 31,743 bytes and 4,138 ms. Neither had a call error. All returned refs checked successfully: Astra 16/16, Luna 17/17. Their six-call budget covers one task, unlike the initial three-task trials; this is not a controlled efficiency comparison. / 修复后 T06 试验使用全新独立 worker。两者均找回操作序列、case 5 失败、实际 patch 及明确重跑要求，并对验证状态保留不确定性。Astra 使用六次调用、21,091 输出字节及 3,873 ms CLI 时间；Luna max 使用六次、31,743 字节及 4,138 ms。均无调用错误。所返回引用全部核验通过：Astra 16/16，Luna 17/17。六次预算覆盖单题，不同于初始三题试验；这不是受控效率对比。

## Limits and next evaluation / 局限与后续评估

The pilot does **not** demonstrate lower total tokens, latency or model cost than raw search. This small readable corpus favors direct inspection; structured disclosure still costs requests and repeated metadata. DeepSeek direct-echo classification, mixed wrappers, semantic recall, cross-source aggregation and current-code validity remain outside the verified promise. / 试跑**没有**证明相较原始搜索更低的总 token、时延或模型成本。小型可读语料有利于直接检查；结构化披露仍有调用与重复 metadata 开销。DeepSeek 直接回声分类、混合包装、语义召回、跨来源聚合及当前代码有效性仍不属于已核验承诺。

The full 12-task × 2-model × 2-trial × 2-condition matrix (96 trials), larger sanitized corpora, uniform budget accounting and total-token instrumentation remain future evaluation work. All unsuccessful attempts are retained in ignored local `tmp/history-eval-results/`; this portable report records the findings without committing agent transcripts. / 完整的 12 题 × 2 模型 × 2 次 × 2 条件矩阵（96 次）、更大脱敏语料、统一预算核算和总 token 量测仍是后续评估工作。所有失败尝试均保留于本地忽略目录 `tmp/history-eval-results/`；本可迁移报告记录发现，不提交 agent 转录。
