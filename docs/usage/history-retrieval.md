# Agent history retrieval / Agent 历史检索

This guide describes the new source-checkout interface, not the already published `0.2.0` CLI. Check `node server.js history --help` (or the installed binary's equivalent) before using it. The ordinary browser startup remains unchanged. / 本指南描述源码 checkout 的新接口，不代表已发布 `0.2.0` CLI 已具备这些命令。使用前检查 `node server.js history --help`（或安装后二进制的对应命令）。普通浏览器启动方式不变。

Compact JSON is the default; use `--presentation full` for the full structure. Read `status` once and reuse its `--context`: subsequent compact replies may return `coverageRef` instead of repeating coverage/warnings. `hr1` handles need that same context; `read` returns durable `evidenceRef` for saved citations. Compact context keeps event bodies in top-level `events`, referenced by each window's `eventIndexes` and `anchorIndexes`. At the 50,000-handle cap, the service may return a full response on the same snapshot if it fits the budget; otherwise it fails explicitly. Existing handles are never silently rebound or evicted. / 默认使用紧凑 JSON；完整结构可选 `--presentation full`。先读一次 `status`，后续复用其 `--context`：紧凑响应可返回 `coverageRef`，不重复覆盖／警告。`hr1` 句柄必须带相同 context；`read` 返回用于保存引用的持久 `evidenceRef`。紧凑上下文的正文位于顶层 `events`，各窗口以 `eventIndexes`、`anchorIndexes` 引用。达到 50,000 个句柄上限时，若预算可容纳，服务可在同一快照返回完整响应；否则明确失败。已有句柄不被静默重新绑定或淘汰。

For small sessions, use `context --view full --limit 20 --length 2000` to read from the session start in bounded event pages. Follow `next` using `view=full`; long event projections have `nextOffset` for `read --parts projection`. `read --text-format text` avoids identical repeated code/terminal/JSON sections; unsupported section types remain JSON. These representations remain projections, not verbatim source. / 小会话可用 `context --view full --limit 20 --length 2000` 从会话开头有界分页读取。保持 `view=full` 沿 `next` 续页；长事件投影的 `nextOffset` 用于 `read --parts projection`。`read --text-format text` 避免代码／终端／JSON 区段完全相同的重复；未支持区段类型保留 JSON。这些仍是投影，不是来源原文。

Start a dedicated service with the intended repository and source. It binds to localhost and defaults to port `17891`; custom source roots use the existing `--codex-home`, `--claude-home`, `--dsh-home` or `--pi-home` option. The example service stays in the foreground; manage its lifetime explicitly. / 用预期仓库及来源启动独立服务。它绑定 localhost，默认端口 `17891`；自定义来源根沿用 `--codex-home`、`--claude-home`、`--dsh-home` 或 `--pi-home`。示例服务前台运行，需明确管理生命周期。

For native pi session v3 in this checkout, use `node server.js history serve --repo /path/to/project --source pi --pi-home /path/to/pi/agent`. The pi root contains `sessions/`. Every root-to-leaf branch is a separate Session: shared-prefix hits can appear in several Sessions, and extending a branch changes its ID after restarting/reindexing. Use returned evidence references within their snapshot; changed evidence requires a new search. / 此 checkout 的原生 pi session v3 使用所列命令；pi 根包含 sessions/。每条根到叶分支是独立 Session，共享前缀可在多个会话命中；延长分支并重启／重建后会改变其 ID。返回的依据引用只适用于对应快照，依据变化后需重新搜索。

```powershell
node server.js history serve --repo 'C:\projects\target' --source codex --port 17891
```

From another terminal, reuse that instance. Inspect the status and search results, then use a hit's `ref` as the handle. The example selects the first hit. Save the read result's `evidenceRef` for a durable citation (the item's `ref` is already durable in a full response). / 从另一终端复用该实例。查看状态和搜索结果后，以某个命中项的 `ref` 用作句柄。示例选取首个命中。保存读取结果的 `evidenceRef` 用作持久引用（完整响应中该项的 `ref` 已是持久引用）。

```powershell
$endpoint = 'http://127.0.0.1:17891'
$status = node server.js history status --endpoint $endpoint | ConvertFrom-Json
$status.coverage
$hits = node server.js history search --endpoint $endpoint --context $status.contextRef --query 'eventHasSearchHit' --limit 8 | ConvertFrom-Json
$hits.items
if (-not $hits.items) { throw 'No hit returned. Search with another literal clue.' }
$hitHandle = $hits.items[0].ref
node server.js history context --endpoint $endpoint --context $hits.contextRef --ref $hitHandle
$read = node server.js history read --endpoint $endpoint --context $hits.contextRef --ref $hitHandle --parts message,request,result --max-bytes 12000 | ConvertFrom-Json
$read.items
$evidenceRef = $read.items[0].evidenceRef
if (-not $evidenceRef) { $evidenceRef = $read.items[0].ref }
$evidenceRef
```

Metadata equality does not prove complete current history or valid content. If later evidence is needed, deliberately start a new service, using another port to preserve the old reader when needed. See the packaged [source observation reference](../../skills/history-retrieval/references/source-observation.md). / 身份未知时省略 `--caller-session`；已知 ID 不在旧索引中时接受并标为未关联。结合范围及采样时段阅读上述计数、分组、部分完成、缺口及省略字段。增长仅是 metadata 线索，调用方写日志是正常情形；保持本轮证据截止点，不反复检查／重建直至日志停止。观察无游标，重试仍比较原基线。metadata 相同不证明当前历史完整或内容有效。需要后续依据时明确启动新服务，必要时用另一端口保留旧阅读服务。详见随包[来源观察参考](../../skills/history-retrieval/references/source-observation.md)。

Use `read --context '<contextRef>' --ref '<returned-hit-ref>' --around-hit-before 500 --around-hit-after 1499` to read around a stored hit. JSON uses `aroundHit:{before:500,after:1499}`. Ordinary reads still default to content; the explicit candidate `--mode auto` chooses that hit window only when parts or a text range have not already selected the read, and falls back to content for an ordinary event reference without a hit. Invalid offsets are never reused. Read-part `previous`/`next` are complete input objects, distinct from context navigation refs; submit them unchanged. See [reading and continuation](../../skills/history-retrieval/references/reading.md) for conflicts and exact coordinates. / 使用上述普通 flags 围绕已存命中读取，JSON 使用 `aroundHit:{before:500,after:1499}`。普通读取仍默认读取内容；显式候选 `--mode auto` 仅在 parts 或文本范围尚未决定读取方式时选择该命中窗口，普通事件引用没有命中时读取内容。不复用无效偏移。读取 part 的 `previous`／`next` 是完整输入对象，不同于 context 导航引用，应原样提交。冲突及准确坐标见[阅读与续读](../../skills/history-retrieval/references/reading.md)。

The dedicated HTTP interface accepts `POST /api/history/status`, `/observe`, `/search`, `/context`, `/read` and `/open` with a JSON request object. CLI structured input accepts inline `--input '<JSON>'`, UTF-8 `--input-file <path>`, or stdin through `--input-file -`. Choose one input source; it cannot duplicate fields supplied through flags. Repeated `--query` terms are OR alternatives, repeated `--exclude` terms are NOT, and structural filters are AND on the same event. `/open` accepts only `refs:[one event reference]` and optional `contextRef`; browser invocation is a CLI action. `/observe` accepts only `callerSessionId`, `maxFiles`, `limit`, `maxBytes`, `presentation`, `contextRef`. / 独立 HTTP 接口接受 `POST /api/history/status`、`/observe`、`/search`、`/context`、`/read`、`/open`，请求体为 JSON 对象。CLI 结构化输入支持内联 `--input '<JSON>'`、UTF-8 文件 `--input-file <path>` 或通过 `--input-file -` 读取 stdin。选择一个输入来源，不能与 flag 重复提供同一字段。重复 `--query` 为 OR 候选词，重复 `--exclude` 为 NOT，结构筛选在同一事件上 AND。open 仅接受单事件 refs 数组和可选 contextRef，浏览器启动由 CLI 执行。observe 仅接受上述六个字段。

Literal clue values may themselves be option names: `history search --query '--help'` searches for that text, while `history search --help` prints help. Text filters and exclusions follow the same value-position rule. Repeated `parts` selectors are folded into their first occurrence before reading or interpreting offsets, so `raw,raw` continues identically to `raw`. / 字面线索本身可以是选项名：`history search --query '--help'` 搜索该文本，`history search --help` 则显示帮助。文本筛选与排除项遵循同样的值位置规则。重复 `parts` 在读取及解释偏移前按首次出现去重，因此 `raw,raw` 的续读与 `raw` 一致。

To submit a returned read continuation on Windows PowerShell or PowerShell 7, write UTF-8 explicitly instead of relying on the shell's default file encoding. In this example `$read` is the parsed previous JSON response and the selected part has a non-null `next`. / 在 Windows PowerShell 或 PowerShell 7 提交返回的读取续读对象时，明确写为 UTF-8，不依赖 shell 默认文件编码。此例中 `$read` 是已解析的上一响应，选定 part 的 `next` 非 null。

```powershell
$json = $read.items[0].parts[0].next | ConvertTo-Json -Depth 30 -Compress
[IO.File]::WriteAllText('next-read.json', $json, [Text.UTF8Encoding]::new($false))
session-analyzer history read --endpoint 'http://127.0.0.1:17891' --input-file 'next-read.json'
```

POSIX shells can use the same file or `cat next-read.json | session-analyzer history read --endpoint http://127.0.0.1:17891 --input-file -`. A continuation carries its own refs and matching context; do not add the old parts, range or around-hit arguments. / POSIX shell 可使用同一文件，或执行上述管道命令。续读携带自身 refs 及匹配 context，不额外添加旧 parts、范围或命中附近参数。

The CLI and HTTP request limit is 256 KiB, including JSON encoding. If `CONTINUATION_TOO_LARGE` is returned when a search would need a larger continuation, shorten the query or reduce its terms and start a new search without the cursor. File and stdin input share this request limit. The response setting `maxBytes` controls a separate budget. / CLI 和 HTTP 的请求上限为 256 KiB，包含 JSON 编码。若搜索需要更大的续页请求而报 `CONTINUATION_TOO_LARGE`，请缩短查询或减少词条，从头搜索并省略游标。文件和 stdin 输入共用此请求上限。响应的 `maxBytes` 是独立预算。

Search defaults to `--order diverse`, which interleaves sessions so a verbose session does not occupy the entire first page. Use `--order session` for the earlier grouped order. To investigate one candidate's Session, search again with `--session '<returned-sessionId>'`; the query keeps its other filters and an unknown ID fails explicitly. JSON uses `order` and `session`. `scan.matchedSessions` and `scan.scopedSessions` separate matching sessions from the allowed query scope; changing order/scope requires a fresh cursor, while changing `--limit` or `--max-bytes` does not. / 搜索默认 `--order diverse`，交错会话，避免冗长会话占满首页。`--order session` 使用此前的会话分组顺序。深入某个候选的会话时，以 `--session '<返回的 sessionId>'` 重新搜索，保留其他筛选；未知 ID 明确失败。JSON 字段为 `order` 和 `session`。`scan.matchedSessions` 与 `scan.scopedSessions` 区分匹配会话和允许查询范围；改变排序／范围需重新获取游标，改变 `--limit` 或 `--max-bytes` 则不需要。

For example, `{"queries":["eventHasSearchHit","countMatches"],"exclude":["unrelated-example"],"limit":8,"maxBytes":24000}` is a search object; `{"refs":["<evidenceRef>"],"parts":["projection"],"length":2000}` is a read object. Errors use JSON `error.code` and `error.message`; CLI errors exit nonzero. The endpoint is constrained to `http://127.0.0.1:<port>`. / 例如，`{"queries":["eventHasSearchHit","countMatches"],"exclude":["unrelated-example"],"limit":8,"maxBytes":24000}` 是搜索对象；`{"refs":["<evidenceRef>"],"parts":["projection"],"length":2000}` 是读取对象。错误使用 JSON `error.code` 和 `error.message`；CLI 错误以非零退出。Endpoint 限于 `http://127.0.0.1:<port>`。

Indexing is a snapshot: restart deliberately when you need later history. See operation help for pagination, range and filter options. / `context` 锚点是命中周围邻近消息，不是模型摘要。通过返回的内部间隙引用和前后游标查看省略操作或后续纠正。`read` 选择证据部分；重复 `--ref` 批量处理候选。原样保留引用。来源变化明确失败；重启后重新搜索以获取新 context，未变化来源的证据引用可重新核验。分页、范围及筛选参数见各操作 help。

This reduces direct echoes, not all later paraphrases. / 搜索默认 Main 及 `--retrieval-artifacts exclude`。使用 `include` 纳入可识别检索命令／结果，`only` 仅查看它们。含命令示例的文档、混合操作及不确定包装仍可搜索。这减少直接回声，不过滤所有后续转述。

`--max-bytes` controls serialized response size rather than exact model tokens. Inspect `truncated`, continuation and coverage before drawing conclusions. Pass a gap, `previous` or `next` event-range reference to `context --ref` to expand it. For batch pagination, submit top-level `next` unchanged, or repeat the original arguments plus `--cursor <nextCursor>`. ## Open a result for inspection / 打开结果供核对

Use the original history endpoint and pass a returned event reference unchanged. Choose `--no-browser` to prepare a citation link; omit it when the user asks to open the record. / 使用原检索 endpoint，原样传递返回的事件引用。准备引用链接时选择 no-browser；用户要求打开记录时省略该选项。

```sh
session-analyzer history open --endpoint http://127.0.0.1:17891 --ref "<evidenceRef>" --no-browser
session-analyzer history open --endpoint http://127.0.0.1:17891 --context "<contextRef>" --ref "<hr1-handle>"
```

`open` accepts one event. For a range, read context first and choose a returned event. It starts/reuses a viewer bound to that service's original snapshot without changing an ordinary Web instance. Copy the returned `url`; do not construct a port or decode a reference yourself. `targetVerified` confirms evidence validation, `viewerReady` confirms the URL is ready, and `browserOpenRequested` confirms a successful opener invocation. None confirms page-render completion. Browser failure returns exit code 1 with `browser.status=failed`, while preserving the ready URL; `--no-browser` returns `skipped`. / open 接受单事件，范围先读取 context 并选择返回事件。它启动／复用绑定原服务快照的查看页，不改变普通 Web 实例。复制返回 url，不自行猜端口或拆引用。三个布尔状态分别确认核验、URL 就绪和 opener 调用成功，均不等于页面完成渲染。浏览器失败返回退出码 1 及 failed 状态，仍保留就绪 URL；no-browser 返回 skipped。

Linux browser opening requires `gio` from GLib (Debian/Ubuntu package `libglib2.0-bin`) and a registered default HTTP browser. It returns after the launch request completes, even if the browser keeps running. If `gio` or a default handler is unavailable, use the preserved URL or `--no-browser`; preparing the link needs no desktop launcher. / Linux 打开浏览器要求 GLib 提供的 `gio`（Debian／Ubuntu 软件包 `libglib2.0-bin`）及已注册的默认 HTTP 浏览器。启动请求完成后即返回，即使浏览器仍在运行。若缺少 `gio` 或默认处理程序，可使用保留的 URL 或 `--no-browser`；准备链接不需要桌面启动器。

The page displays the exact record, actual hit excerpt and nearby excerpts. These excerpts are bounded search projections with explicit omissions, not Raw coordinates or a contiguous timeline segment. Keep the history service running while using its links. For file-backed sources, refresh revalidates source bytes; accepted-prefix appends can remain readable, while rewrite/deletion or a newly indexed snapshot can invalidate the reference. OpenCode instead reads immutable native snapshots: later live database changes do not alter that service's captured evidence. Its snapshot files must remain intact, and a reference from a changed revision must not silently resolve to new content. Restarting may choose another viewer port: call open again with the durable reference. Loopback URLs belong to the service environment; remote/container use needs a reachable local service or deliberate port forwarding. / 使用链接时保持检索服务运行。文件来源刷新时重新核验来源字节；已接受前缀的追加可继续读，改写／删除或重新索引快照可能使引用过期。OpenCode 则读取不可变原生快照：活动数据库后续变更不改变该服务已捕获的依据。其快照文件须保持完整，发生 revision 变更的引用不能静默指向新内容。重启可能使用另一查看端口，应以持久引用再次调用 open。回环 URL 属于服务环境，远端／容器使用需服务可达或明确端口转发。

## Group queries and read a known source position / 分组查询与读取已知来源位置

Use a JSON file for independent queries; repeated --query outside groups still means a single union query. Start with distinctive identifiers and keep broad fallback words separate. Inline --input JSON remains available when the shell preserves it exactly. / 使用 JSON 文件提交独立查询；groups 外重复 --query 仍表示一个取并集查询。先使用独特标识，宽泛回退词保持独立。Shell 能原样保留 JSON 时，仍可使用内联 --input。

```sh
session-analyzer history search --input '{"groups":[{"id":"commit","query":"abc1234","limit":3},{"id":"fallback","query":"CI","limit":2}],"maxBytes":16000}'
session-analyzer history read --input '{"source":{"sourcePath":"2026/09/01/rollout-example.jsonl","locator":{"type":"jsonl-line","line":12}}}'
session-analyzer history read --input '{"source":{"sourceRef":"<returned-sourceRef>","locator":{"type":"jsonl-line","line":12}}}'
```

The example path is illustrative: supply the exact admitted path spelling (or its exact indexed absolute alias), including platform separators. Source locators initially support only uncompressed Codex primary transcripts. Historical dependencies may still contribute searchable events without admitting their old path/line; use canonical search/context/read references to check evidence after `UNKNOWN_SOURCE`. Path-only reads explicitly cannot verify an old note's historical position. Inspect the Raw evidence and optionally follow `logicalRefs` through context/read. Submit the item's `logicalRefsNext` unchanged to continue its associations. It carries `source.logicalOffset` and the exact `source.rawRef`. Use top-level `next` to page across Raw items and a text part's `next` to continue that text. / 示例路径仅作示意；应提供精确准入路径写法（或精确索引绝对别名），包括平台分隔符。来源定位首版仅支持未压缩 Codex 主转录。历史依赖仍可贡献可搜索事件，但其旧路径／行号未必准入；遇到 `UNKNOWN_SOURCE` 时，应通过规范的搜索／上下文／读取引用核对证据。仅路径读取明确无法验证旧笔记的历史位置，应检查 Raw 证据，再按需沿 `logicalRefs` 进入 context/read。原样提交该项的 `logicalRefsNext` 以续读关联。对象含 `source.logicalOffset` 与准确的 `source.rawRef`。Raw 项批分页用顶层 `next`，文本续读用其 part 的 `next`。

Grouped state=complete can still have hasMore and nextCursor. Retry results_omitted with the original query and resumeCursor, omitting cursor when null; retry not_executed with the original query. These states are output/execution limits, not zero matches. Invalid groups fail the request; correct the reported input before retrying. / 分组 complete 仍可能有 hasMore 和 nextCursor。results_omitted 保持原查询与 resumeCursor 重试（null 时省略 cursor）；not_executed 保持原查询重试。这些是输出／执行限制，不是零命中。无效组使请求失败，应先修正报错输入再重试。

Grouped continuation must retain the original group `id`, query and filters. To retry one group, submit a one-element `groups` array, for example `{"groups":[{"id":"sha","query":"abc123","cursor":"<resumeCursor>"}]}`; omit cursor when resumeCursor is null. Do not transfer a group cursor to flat single-search input. The same rule applies to nextCursor. / 分组续读必须保留原组的 `id`、查询和筛选。单独重试时仍提交仅含该组的 `groups` 数组，如上述 JSON；resumeCursor 为 null 时省略 cursor。不得将组游标用于平面的单查询输入，nextCursor 同样遵循此规则。

For later-state questions, bounded checking may end in uncertainty. A later record quoting an older report is not a later state. The [state-resolution evaluation](../evals/history-state-resolution/README.md) keeps correctness separate from search/read counts. / 后续状态检查可以以不确定性结束；较晚记录引用旧报告不是较晚状态。[后续状态评估](../evals/history-state-resolution/README.md)将正确性与 search/read 次数分开。
