# Source switch frontend / 来源切换前端

## Objective / 目标

Add the Select project source switcher on top of the runtime `POST /api/source` backend: switch between Codex and Claude Code inside the chooser, optionally edit both home directories, keep last-selected repo storage scoped per source, and localize all new copy in English and Simplified Chinese. / 在运行期 `POST /api/source` 后端之上为 Select project 增加来源切换：在 chooser 内切换 Codex 与 Claude Code，可选编辑两个 home 目录，按来源区分“最后选择的仓库”存储，并用英文与简体中文本地化所有新文案。

## Scope / 范围

1. Add a source switch block under `#projectStatus` in `.projectChooserHeader`: current source and home summary, a switch action with inline two-step confirmation, and a collapsible custom-directories editor. The block is always visible in the chooser; the summary uses the “no projects? try switching” hint only after discovery finishes with an empty list. / 在 `.projectChooserHeader` 的 `#projectStatus` 下方新增来源切换区块：当前来源与 home 摘要、带行内两步确认的切换按钮，以及可折叠的自定义目录编辑器。区块在 chooser 中始终可见；只有发现完成后列表为空时，摘要才使用“没有找到想看的仓库？尝试切换”的提示。
2. Add `applySourceConfig()` as the single source-config sync entry, called from `/api/state` (`applyAppState`), `/api/projects` summary/full discovery, `/api/source` responses, and the 409 init fallback. / 新增 `applySourceConfig()` 作为唯一的来源配置同步入口，由 `/api/state`（`applyAppState`）、`/api/projects` summary/full 发现、`/api/source` 响应以及 init 的 409 回退统一调用。
3. Commit source changes through one `commitSourceConfig()` used by both source switching and home-directory apply. A backend reset (`projectSelected: false`) clears `state.repoRoot` and `projectReturning` so the topbar Return affordance disappears; an inactive-home-only change keeps them. The chooser accepts only non-empty absolute homes in the analyzer server's path syntax, revalidates the live draft at confirmation, and compares path equivalence with host-correct separator semantics. If a POST ends without an HTTP status, reconcile `/api/state` (including its 409 details) and accept the mutation only when the authoritative configuration matches the requested target. / 来源切换与目录应用共用 `commitSourceConfig()`。后端重置（`projectSelected: false`）时清空 `state.repoRoot` 与 `projectReturning`，使顶栏 Return 消失；仅 inactive home 变化时保留两者。Chooser 只接受采用 Analyzer 服务器路径语法的非空绝对 home，在确认时重新校验实时草稿，并按宿主机的正确分隔符语义比较路径等价性。若 POST 在没有 HTTP 状态的情况下结束，则通过 `/api/state`（包括其 409 details）对账，并且仅在权威配置与请求目标一致时把 mutation 视为成功。
4. Track `projectDiscoveryLoading` so the empty-state hint and “no transcript projects” notice never flash while summary/full discovery is still pending. Discovery 409s are treated as expected races, and every failure from an invalidated request is dropped silently via the chooser request-id guard. / 用 `projectDiscoveryLoading` 区分发现进行中，避免空态提示与“没有发现转录项目”通知在 summary/full 请求未完成时闪现。发现 409 按预期竞争处理；被作废请求产生的任何失败都通过 chooser request-id 守卫静默丢弃。
5. Replace the legacy `sessionAnalyzer.repoRoot` storage with per-source keys (`sessionAnalyzer.repoRoot.<sourceKind>`). The legacy key is read and migrated only for Codex and always removed after a Codex read, including when a namespaced value already exists; writes use the payload's `sourceKind`, never the possibly stale `state.sourceKind`. / 用按来源区分的 key（`sessionAnalyzer.repoRoot.<sourceKind>`）替换旧 `sessionAnalyzer.repoRoot`。旧 key 仅对 Codex 读取迁移，并在 Codex 读取后始终删除，包括 namespaced 值已存在的情况；写入使用 payload 的 `sourceKind`，绝不使用可能过期的 `state.sourceKind`。
6. Localize new UI copy and switch `projectActivityLoading`/`projectCandidates`/`noProjectCandidates` to the `{sourceHome}` placeholder; rename the empty notice to source-neutral `noTranscriptProjects`. / 本地化新 UI 文案，并把 `projectActivityLoading`/`projectCandidates`/`noProjectCandidates` 改用 `{sourceHome}` 占位符；空通知改为来源无关的 `noTranscriptProjects`。
7. Refine the source switch block into a cohesive settings card using the existing panel, accent, border, and monospace-path language: group source identity and actions, nest the custom-directory editor, keep long paths readable, preserve responsive stacking, and keep project-indexing progress above the source settings so ownership remains clear. / 使用现有的面板、强调色、边框与等宽路径语言，把来源切换区优化为内聚的设置卡：对来源身份和操作分组，内嵌自定义目录编辑器，保证长路径可读，保留响应式堆叠，并把项目索引进度置于来源设置上方以明确其归属。
8. Serialize source mutation against chooser exit, project selection, and home editing: while a source POST is in flight, Return, project rows, and home inputs are disabled; their action handlers reject programmatic or stale click delivery; and the dirty flag is cleared only when the live inputs still match the submitted draft. / 将来源 mutation 与 chooser 退出、项目选择及 home 编辑串行化：来源 POST 进行期间禁用 Return、项目行与 home 输入；对应 action handler 会拒绝程序化或过期的点击投递；只有实时输入仍与已提交草稿一致时才清除 dirty 标记。

## Validation / 验证

- New e2e helper opens a server without a prebuilt index and drives the chooser through source switches, legacy storage migration, and home-directory edits. / 新增 e2e helper 以无预建索引的服务器打开 chooser，覆盖来源切换、旧存储迁移与目录编辑。
- Eleven new browser tests cover the eight earlier scenarios plus: source switching carries unapplied home-directory edits; inactive-home apply starts a successor discovery when a scan is in flight; and a 202 indexing-job state applies the source configuration immediately. / 十一个新增浏览器用例覆盖此前八个场景，另加：来源切换携带未应用的目录草稿；扫描进行中应用 inactive home 会启动后继发现；202 索引 job 状态会立即应用来源配置。
- Review follow-ups: `commitSourceConfig` re-renders controls after clearing the busy flag; home inputs are preserved through a dirty-edit flag instead of focus-only; `resolveSourceMutation` bumps `sourceRevision` for any configuration change so stale discovery is rejected; and the product spec documents runtime switching. / 评审后续：`commitSourceConfig` 在清除 busy 后重新渲染控件；home 输入通过 dirty 编辑标记而非仅焦点判断来保留；`resolveSourceMutation` 在任何配置变化时递增 `sourceRevision`，使过期发现被拒绝；产品 spec 已补充运行期切换说明。
- Second review follow-ups: `projectDiscoveryLoading` is cleared on discovery failure or invalidation (without clobbering a successor request), and home-change confirmation compares normalized path forms so Windows-equivalent inputs do not prompt a spurious reset confirmation. / 第二轮评审后续：`projectDiscoveryLoading` 在发现失败或被作废时复位（且不会覆盖后继请求的状态）；home 修改确认改用归一化路径比较，Windows 下等价输入不再弹出多余的确认。
- Third review follow-up: the empty-state hint now sets `data-empty="true"` explicitly so the emphasis styling applies, with an e2e assertion on the computed font weight. / 第三轮评审后续：空态提示改为显式设置 `data-empty="true"`，使强调样式生效，并新增对计算后 font-weight 的 e2e 断言。
- Fourth review follow-ups: source switch consumes the unapplied home draft (and cancel no longer discards it), any successful home mutation re-runs project discovery as the successor of a stale scan, and `init()` applies source configuration immediately for the 202 job envelope. / 第四轮评审后续：来源切换携带未应用的 home 草稿（取消不再丢弃草稿）；任何成功的 home 修改都会重新执行项目发现，作为过期扫描的后继；`init()` 对 202 job envelope 立即应用来源配置。
- Fifth review follow-ups: source confirmation validates the home draft before invalidating discovery, so a failed validation never strands the project list, and the duplicate Full-gates line was removed. / 第五轮评审后续：来源确认在作废 discovery 之前先校验 home 草稿，因此校验失败不会让项目列表滞留；同时删除了重复的 Full gates 行。
- Sixth review follow-up: when the source commit itself fails after discovery was invalidated, the chooser runs a best-effort successor discovery so the list converges to the authoritative source after an explicit mutation failure. / 第六轮评审后续：当来源提交在 discovery 被作废后失败时，chooser 会执行尽力而为的后继发现，使列表在明确的 mutation 失败后收敛到权威来源。
- Seventh review follow-ups: a source POST whose response is lost reconciles `/api/state`, including project-selection state, before deciding whether the requested mutation succeeded; and a non-409 error from invalidated full discovery is dropped without overwriting the successor chooser state. Browser coverage exercises lost responses for both inactive-home apply and source switching, plus an obsolete discovery that fails after its successor succeeds. / 第七轮评审后续：来源 POST 的响应丢失时，会先通过 `/api/state` 对账（包括项目选择状态），再判断请求的 mutation 是否成功；被作废的完整 discovery 即使返回非 409 错误，也会静默丢弃而不覆盖后继 chooser 状态。浏览器用例覆盖 inactive-home 应用与来源切换的响应丢失，以及后继请求成功后旧 discovery 才失败的场景。
- Eighth review follow-ups: source mutation disables project rows and gates `selectProject()` until the commit settles; custom-home validation rejects relative or host-mismatched path syntax before invalidating discovery or posting a mutation. Browser coverage holds a source POST open while delivering a synthetic project-row click and exercises both empty and relative validation failures. / 第八轮评审后续：来源 mutation 会禁用项目行并在提交结束前阻止 `selectProject()`；自定义 home 校验会在作废 discovery 或提交 mutation 前拒绝相对路径以及与宿主不匹配的路径语法。浏览器用例会保持来源 POST 未完成并投递合成项目行点击，同时覆盖空路径与相对路径校验失败。
- Ninth review follow-ups: the same source-mutation lock covers Return and both home inputs, the topbar handler rejects synthetic delivery, and a late unsent home draft survives commit completion. Codex storage reads remove a stale legacy key even when the namespaced key wins. Browser coverage extends the delayed-POST and storage-migration scenarios without adding a separate fixture. / 第九轮评审后续：同一来源 mutation 锁会覆盖 Return 与两个 home 输入，topbar handler 会拒绝合成事件投递，提交期间产生的未发送 home 草稿会在提交结束后保留。即使最终采用 namespaced key，Codex storage 读取也会删除过期 legacy key。浏览器覆盖在既有延迟 POST 与 storage migration 场景上扩展，无需新增独立 fixture。
- Tenth review follow-ups: home confirmation revalidates the current editable draft before posting, and POSIX home comparison preserves backslashes as literal characters while Windows still accepts both separator forms. Browser coverage mutates a confirmed draft to a relative path and injects POSIX source configuration to prove a trailing backslash still requires confirmation. / 第十轮评审后续：home 确认会在提交前重新校验当前可编辑草稿；POSIX home 比较会把反斜杠保留为普通字符，而 Windows 仍接受两种分隔符形式。浏览器覆盖会把已进入确认状态的草稿改为相对路径，并注入 POSIX 来源配置，以证明尾随反斜杠仍会触发确认。
- UI polish follow-up: the source switcher now uses a compact identity card, grouped source actions, a visually nested directory editor, full-width path fields, and pending-action emphasis while retaining the existing controls and localized copy. / UI 打磨后续：来源切换器现在使用紧凑的身份卡、分组后的来源操作、视觉上内嵌的目录编辑器、全宽路径输入以及待确认操作强调，同时保留原有控件与本地化文案。
- Full gates: 395 Node tests, 102 browser tests, `npm run build:check`, and `git diff --check` pass. / 完整门槛：395 项 Node 测试、102 项浏览器测试、`npm run build:check` 与 `git diff --check` 均通过。
