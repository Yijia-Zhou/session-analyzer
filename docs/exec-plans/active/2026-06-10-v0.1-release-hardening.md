## Goal / 目标

Prepare the first public release as a Codex-first, adapter-ready local transcript viewer. The release should keep current Codex workflows reliable while preventing the event model, raw references, browser flows, i18n, and packaging from locking the project to Codex JSONL implementation details.

将第一个公开版本准备成 Codex 优先、但为后续 adapter 预留空间的本地 transcript 查看器。该版本应保持现有 Codex 工作流可靠，同时避免 event model、raw reference、浏览器流程、i18n 和打包方式被 Codex JSONL 实现细节锁死。

## Non-goals / 非目标

- Full Claude Code, opencode, Crush, or Hermes import support before v0.1. / v0.1 前不实现完整 Claude Code、opencode、Crush 或 Hermes 导入支持。
- A broad rewrite of `src/codex.js`, `public/app.js`, or `server.js`. / 不对 `src/codex.js`、`public/app.js` 或 `server.js` 做大范围重写。
- Exhaustive field-level rendering for every unobserved Codex protocol family. / 不为每个尚未观察到的 Codex 协议族实现穷尽的字段级渲染。
- A persistent index or generic deferred loader unless measurements show a release-blocking issue. / 除非测量显示存在发布阻塞问题，否则不实现持久索引或通用延迟加载器。

## Invariants / 不变量

- Keep the existing server API behavior stable unless an explicit milestone says otherwise. / 除非里程碑明确要求，否则保持现有 server API 行为稳定。
- Unknown transcript records must remain visible through protocol/raw fallback. / 未知 transcript 记录必须继续通过 protocol/raw 兜底可见。
- Stable machine identifiers such as `kind`, `subtype`, `layer`, `status`, and condition IDs must not be localized. / `kind`、`subtype`、`layer`、`status` 和 condition ID 等稳定机器标识不得本地化。
- Public fixtures must be synthetic or strongly minimized and sanitized; real `.codex/sessions` data must not be committed. / 公开 fixture 必须是合成数据，或经过强最小化与脱敏；不得提交真实 `.codex/sessions` 数据。
- Large payload work must preserve source-backed raw drill-down and avoid eager duplication. / 大 payload 相关工作必须保留基于源数据的 raw 下钻，并避免 eager 复制。

## P0 release scope / P0 发布范围

- Add replay/golden coverage for current fixture behavior. / 为当前 fixture 行为增加 replay/golden 覆盖。
- Freeze a minimal canonical envelope before broad fixture expansion. / 在大范围扩展 fixture 前冻结最小 canonical envelope。
- Extract stable source/logical/detail boundaries incrementally behind current APIs. / 在当前 API 后渐进提取 source、logical、detail 边界。
- Cover Codex missing-event P0 behavior: fallback visibility, lifecycle labels, status/severity, and raw traceability. / 覆盖 Codex 缺失事件的 P0 行为：兜底可见性、生命周期 label、status/severity 和 raw 可追踪性。
- Add browser automation for the highest-risk search, inspector, folding, and navigation flows before i18n and packaging. / 在 i18n 和打包前，为最高风险的搜索、inspector、folding 和导航流程增加浏览器自动化。
- Package v0.1 as a local npm/Node CLI that explicitly supports Codex transcripts. / 将 v0.1 打包为本地 npm/Node CLI，并明确支持范围是 Codex transcripts。

## P1 follow-up scope / P1 后续范围

- Field-specific detail renderers for every unobserved event family. / 为每个尚未观察到的事件族实现字段级 detail 渲染。
- Full external source adapters. / 完整外部 source adapter。
- Persistent indexing, generic section-level deferred loading, or desktop distribution. / 持久索引、通用 section 级延迟加载或桌面分发。

### Decision record / 决策记录

- v0.1 remains Codex-first. External tools are used as schema pressure tests, not as release-blocking importer targets. / v0.1 保持 Codex 优先。外部工具只作为 schema 压力测试，不作为发布阻塞的 importer 目标。
- Adapter-ready means preserving future source boundaries, locators, raw drill-down, lazy detail options, tests, and i18n/storage stability; it does not mean adding many optional fields eagerly. / Adapter-ready 指保留未来 source 边界、locator、raw 下钻、lazy detail 可能性、测试和 i18n/storage 稳定性；不表示提前加入大量可选字段。
- Minimal canonical envelope must be designed before broad missing-event fixture work so expected DTOs do not churn later. / 最小 canonical envelope 必须先于大范围缺失事件 fixture 工作设计，避免 expected DTO 后续大面积返工。
- `schemaVersion` and `sourceKind` belong on raw, logical, and detail DTOs so each returned DTO is independently interpretable; `sourceSchemaVersion` stays optional and must not be invented when the source does not provide a trustworthy version. / `schemaVersion` 和 `sourceKind` 属于 raw、logical 和 detail DTO，使每个返回 DTO 都能独立解释；`sourceSchemaVersion` 保持可选，来源未提供可信版本时不得编造。
- `sourceLocator` uses typed locator objects. Codex keeps legacy `source`, `rawRefs[].file`, `rawRefs[].line`, and `rawRefs[].rawId` during compatibility migration, while new code should not assume future locators are file+line rows. / `sourceLocator` 使用 typed locator 对象。兼容迁移期间 Codex 保留 legacy `source`、`rawRefs[].file`、`rawRefs[].line` 和 `rawRefs[].rawId`，但新代码不应假设未来 locator 都是 file+line 行。
- `sourceRecordType` and `sourceEventType` use refs-only semantics: raw DTOs may expose precise row types, while logical/detail DTOs rely on per-entry `rawRefs[]` types instead of top-level aggregate type fields. / `sourceRecordType` 和 `sourceEventType` 采用 refs-only 语义：raw DTO 可以暴露精确行类型，而 logical/detail DTO 依赖每个 `rawRefs[]` 条目的类型，不使用顶层聚合类型字段。
- Codex missing-event P0 work validates the event model; it is not just UI polish. / Codex 缺失事件 P0 工作用于验证 event model，不只是 UI polish。
- Browser automation must precede i18n and packaging because parser tests cannot catch composed DOM, scrolling, localStorage, and inspector regressions. / 浏览器自动化必须早于 i18n 和打包，因为 parser 测试无法捕获组合 DOM、滚动、localStorage 和 inspector 回归。
- i18n must localize display text only; API/filter/storage identifiers remain stable machine IDs. / i18n 只本地化展示文本；API/filter/storage 标识保持稳定机器 ID。
- Large payload handling must avoid eager duplication and preserve source-backed raw access. / 大 payload 处理必须避免 eager 复制，并保留基于源数据的 raw 访问。
- New shared browser-and-Node domain modules need an ownership strategy before adding another `public/folding.js`-style shared asset. / 新的 browser-and-Node 共享领域模块在新增前需要先确定归属策略，避免继续扩大 `public/folding.js` 式共享资产模式。
