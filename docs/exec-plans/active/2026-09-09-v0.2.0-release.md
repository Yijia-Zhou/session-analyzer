## Frozen scope and non-goals / 冻结范围与非目标

- Included: the accepted baseline's Codex, Claude Code, DeepSeek Harness,
  Timeline/Trajectory, source selection, materialization, package-reading,
  diagnostics, documentation, and generated assets.
- Included release preparation: package/lock identity, bilingual changelog,
  package metadata assertions, README and online-guide convergence, release
  evidence, and only release-blocking validation corrections.
- Excluded: new product behavior, performance experiments, architecture
  redesign, unrelated cleanup, and non-blocking technical debt. Existing debt
  remains open unless the runbook requires a release-specific record.
- No real transcripts, credentials, tokens, OTPs, recovery codes, or personal
  absolute paths may enter the plan, package, or public evidence.

- [x] Create this active plan from the accepted baseline.
- [x] Update `package.json`, both `package-lock.json` identity locations, and
  package metadata version assertions to `0.2.0`.
- [x] Close the bilingual `Unreleased` changelog into the dated `0.2.0`

- [x] Converge both READMEs and the online usage/development guides on the

- [x] Update only relevant current product/design version boundaries; do not
  rewrite historical completed plans or close unrelated debt.
- [x] Recheck package allowlist, third-party notices, dependency placement,
  `publishConfig`, `devEngines`, and lockfile install-script coverage.
- [x] Record the frozen metadata diff and confirm no production feature edit.

### Phase 2 — Candidate gates / 阶段 2：候选 gate

- [x] Bootstrap/verify the exact toolchain from outside the checkout, using the
  explicit official registry on every npm command.
- [x] Run clean strict install, pending install-script check, `release:check`,
  browser tests, both audits, whitespace check, and final clean-tree check.
- [x] Generate and inspect a candidate outside the worktree; verify manifest,
  allowlist, notices, sensitive paths, hashes, installed CLI, and packaged
  server behavior. Do not pass the inspection tarball to publish.
- [x] Run the guarded directory `npm publish --dry-run` with no positional
  package/tarball argument and observe `prepublishOnly`/`release:check`.

### Phase 3 — Exact `main` source / 阶段 3：精确 `main` 来源

- [ ] Use the normal review path to get the frozen change onto `main`.
- [ ] Record the pushed exact `main` SHA and required CI run URL/results.
- [ ] Stop if local source, pushed `main`, CI, metadata, registry, or manifest
  differs from this approved plan.

### Phase 4 — Trusted Publishing handoff / 阶段 4：Trusted Publishing 交接

- [ ] Run `npm run release:preflight -- '0.2.0'` with the explicit official
  registry configuration and require the sole GO result.
- [ ] Stop before dispatch. Workflow dispatch, GitHub Environment approval,
  staged artifact review, and WebAuthn/2FA approval are maintainer-owned.
- [ ] Do not use the manual fallback unless staged publishing is unavailable,
  the reason is recorded here, and the maintainer explicitly authorizes it.

### Phase 5 — Public verification and closeout / 阶段 5：公共验证与收尾

- [ ] After maintainer approval, require the read-only Ubuntu/Windows public
  verification evidence before any tag or GitHub Release.
- [ ] Stop before remote tag creation and GitHub Release publication; both are
  maintainer-owned external release gates.
- [ ] Archive this plan only after all runbook-required publication, public
  verification, tag, and GitHub Release evidence is complete.

## Mandatory STOP conditions / 强制 STOP 条件

Stop immediately and report without improvising a workaround when any of the
following occurs: / 遇到以下任一情况立即停止并报告，不得自行发明 workaround：

- Any package, lockfile, changelog, metadata assertion, intended tag, plan,
  source SHA, or manifest disagreement.
- Any npm command is not explicitly pinned to
  `https://registry.npmjs.org/`, or the response is not an explicit expected
  result (including an ambiguous/network version-slot response).
- Dirty worktree at a required clean boundary, missing/failed/incomplete CI,
  unsupported Node/npm, pending install scripts, failed audit, stale generated
  asset, or failed package/browser smoke.
- A candidate contains an unapproved file, source map, fixture, plan,
  credential, transcript, log, personal path, or incomplete third-party notice.
- A release workflow, source, dependency, generated asset, or metadata changes
  after a recorded gate without returning to the invalidated phase.
- Any request to fix non-blocking technical debt or add product scope during
  this freeze.
- Any maintainer-owned action: workflow dispatch, Environment approval, staged
  approve/reject, npm authentication or registry mutation outside the exact
  authorized workflow, dist-tag mutation, remote tag, or GitHub Release.
