# Search navigation state convergence / 搜索导航状态收敛

## Goal / 目标

Make free-text previous/next navigation operate on stable semantic targets while preserving the current ability to reveal unloaded timeline content and inspector matches. Keep the search-assist dialog reliably reopenable after navigation, without letting programmatic scrolling or presentation-only inline text steal the user's search-input interaction. / 让自由文本的上一个/下一个导航基于稳定的语义目标运行，同时保留当前揭示未加载 timeline 内容和 Inspector 命中的能力。确保导航后搜索辅助面板仍可可靠地重新打开，并避免程序化滚动或仅用于展示的内联文本抢走用户与搜索框的交互。

## Confirmed failures and root cause / 已确认问题与根因

- [x] The displayed jump-target denominator can shrink or oscillate while repeatedly navigating the same unchanged query. In one browser reproduction, the initial `1 / 18` consisted of 16 timeline marks and two detail marks; opening a search-transient inspector changed the detail marks to one and the count to `2 / 17`, and further forward/backward navigation replayed the `17 / 18` denominator changes in reverse. At the materialization boundary, `18 / 18` became `17 / 33` while timeline marks grew from 16 to 32. Growth caused by newly materialized timeline content is valid, but removal or replacement caused only by an inspector redraw, or current-position regression caused by mutable indexing, is not. / 对同一个未变化的查询反复导航时，界面显示的可跳目标分母会缩小或来回波动。一次浏览器复现中，初始 `1 / 18` 由 16 个 timeline mark 和两个 detail mark 组成；打开搜索临时 Inspector 后，detail mark 变成一个，计数变为 `2 / 17`，继续向前/向后导航还会严格反向重放 `17 / 18` 的分母变化。到物化边界时，timeline mark 从 16 增至 32，而计数从 `18 / 18` 变成 `17 / 33`。因新 timeline 内容物化而增长是合法的，仅因 Inspector 重绘而删除或替换目标，或因可变索引导致当前位置倒退，则不是。
- [x] `refreshSearchHighlights()` rebuilds `state.searchHighlight.marks` from the session list, timeline, and detail roots, and `setActiveSearchMark()` tracks only a numeric index. `showInspector()` and timeline materialization redraw those roots during navigation, so navigation mutates its own registry and can revisit, skip, or renumber semantic targets. / `refreshSearchHighlights()` 会从 session list、timeline 和 detail 三个根节点重建 `state.searchHighlight.marks`，而 `setActiveSearchMark()` 只追踪数值索引。`showInspector()` 和 timeline 物化会在导航过程中重绘这些根节点，因此导航会修改自身的注册表，并可能重复、跳过或重新编号语义目标。
- [x] Search-button and Enter handlers launch `navigateSearchMatch()` without a navigation lock. Rapid repeated actions can therefore overlap asynchronous page loading, expansion, inspector rendering, highlight refresh, and active-target updates against the same mutable state. / 搜索按钮和 Enter handler 在没有导航锁的情况下启动 `navigateSearchMatch()`。因此，快速连续操作可能让异步分页加载、展开、Inspector 渲染、高亮刷新和活动目标更新在同一可变状态上互相重叠。
- [x] Search navigation uses smooth scrolling, while the timeline scroll handler unconditionally hides the search assist. Instrumented events showed focus opening the assist and a residual programmatic scroll closing it about 8 ms later while the input remained focused; later clicks do not emit another focus event. / 搜索导航使用平滑滚动，而 timeline scroll handler 会无条件隐藏搜索辅助面板。事件记录显示，focus 打开辅助面板后，残留的程序化滚动约 8 ms 后又将其关闭，同时输入框仍保持焦点；后续点击不会再次产生 focus 事件。
- [x] The absolutely positioned inline match summary overlaps a substantial part of the input and receives pointer hits outside the actual previous/next buttons. In the reproduced layout, the input was about 293 px wide and the overlay about 170 px wide, so the input center hit `.searchInlineCount`; the fixed `padding-right: 10rem` is also not a reliable geometry contract for dynamically sized, unabridged counts. / 绝对定位的内联命中摘要覆盖了搜索框的较大区域，并会在真正的上一个/下一个按钮之外接收指针命中。在复现布局中，输入框约 293 px 宽、覆盖层约 170 px 宽，因此输入框中心实际命中 `.searchInlineCount`；固定的 `padding-right: 10rem` 也无法作为动态且不缩写计数的可靠几何契约。
- [x] Existing browser coverage verifies loading later pages, transient expansion, and reacquiring a live mark after redraw. The test around `e2e/browser.test.js:600` deliberately includes detail marks while checking unmaterialized hits, but it does not assert a stable denominator, semantic target identity/order, serialized rapid navigation, input hit testing, or assist reopening during residual scroll. / 现有浏览器覆盖验证了加载后续页面、临时展开，以及重绘后重新获取实时 mark。`e2e/browser.test.js:600` 附近的测试会在检查未物化命中时有意包含 detail mark，但没有断言稳定分母、语义目标身份/顺序、快速导航串行化、输入框点击命中，或残留滚动期间重新打开辅助面板。

## Decisions / 已定决策

- DOM `<mark>` nodes are disposable rendering artifacts, not the authoritative navigation registry, active-position identity, or denominator source. / DOM `<mark>` 节点是可丢弃的渲染产物，不再作为权威导航注册表、活动位置身份或分母来源。
- A target descriptor is scoped by the complete search target key and identifies its surface, owning session/event, and occurrence within that owner. The active target is stored by descriptor identity. / 目标 descriptor 由完整搜索目标 key 限定，并标识其 surface、所属 session/event，以及该 owner 内的命中序号。活动目标按 descriptor 身份保存。
- A registry for one unchanged search key is non-shrinking. DOM refresh may rebind existing targets and materialization may append newly discovered targets; transient inspector replacement must not remove prior targets. Returning to an inspector target rematerializes its owner before resolving the concrete mark. / 对一个未变化搜索 key 的注册表只增不减。DOM 刷新可以重新绑定已有目标，物化可以追加新发现的目标；临时 Inspector 替换不得删除先前目标。返回 Inspector 目标时，应先重新物化其 owner，再解析具体 mark。
- Only searchable content regions contribute targets. Search controls, folding-strategy controls, result summaries, and other UI chrome may contain highlighted-looking text only if explicitly intended, but they never participate in global previous/next counts. / 只有可搜索内容区贡献目标。搜索控件、折叠策略控件、结果摘要和其它 UI chrome 只有在明确需要时才可显示类似高亮的文本，但绝不参与全局上一个/下一个计数。
- Previous/next navigation is serialized as one asynchronous transition at a time. The UI must prevent overlapping materialization, inspector redraw, highlight refresh, and scroll transitions. / 上一个/下一个导航必须按一次一个异步转换串行执行。UI 必须防止目标物化、Inspector 重绘、高亮刷新和滚动转换互相重叠。
- Search input focus or click wins over navigation-driven scrolling. Clicking an already-focused input reopens the assist; programmatic search scrolling does not close it; non-button inline summary text does not own pointer events. / 搜索框 focus 或 click 的优先级高于导航驱动的滚动。点击已经聚焦的输入框会重新打开辅助面板；程序化搜索滚动不会关闭它；非按钮的内联摘要文本不拥有指针事件。
- The backend full-text count remains separate secondary context. This plan changes frontend target identity and interaction state, not the `/timeline` response contract or full-text count semantics. / 后端全文命中计数继续作为独立的次级上下文。本计划修改前端目标身份和交互状态，不改变 `/timeline` 响应契约或全文计数语义。

## Phase 1: stable target registry / 第一阶段：稳定目标注册表

- [ ] Introduce a search-target descriptor and registry separate from `state.searchHighlight.marks`. Include the complete search key, surface, owner ID, and stable occurrence key needed to resolve the rendered match again. / 引入与 `state.searchHighlight.marks` 分离的搜索目标 descriptor 和注册表。包含完整搜索 key、surface、owner ID，以及再次解析已渲染命中所需的稳定 occurrence key。
- [ ] Restrict registry discovery to searchable session-row, timeline-event, and selected-event-inspector content; explicitly exclude UI chrome and the empty-detail folding editor. / 将注册表发现限制在可搜索的 session row、timeline event 和 selected-event Inspector 内容；明确排除 UI chrome 和空详情态的折叠编辑器。
- [ ] Preserve `activeTargetId` across highlight refreshes and root rerenders. Rebind descriptors to live nodes without deriving membership or position solely from the newest flat DOM scan. / 跨高亮刷新和根节点重绘保留 `activeTargetId`。把 descriptor 重新绑定到实时节点，而不是仅从最新的扁平 DOM 扫描推导成员集合或位置。
- [ ] Reset the registry only when the semantic search key changes, including session, layer, free text, kind, status, file, or another structured boundary that changes the search result context. / 只在语义搜索 key 变化时重置注册表，包括 session、layer、自由文本、kind、status、file，或其它会改变搜索结果上下文的结构化边界。

## Phase 2: serialized materialization and navigation / 第二阶段：串行物化与导航

- [ ] Make one previous/next action own the complete load-expand-render-refresh-resolve-open-scroll transition. Disable or queue further navigation consistently until it settles; do not allow fire-and-forget handlers to overlap transitions. / 让一次上一个/下一个操作拥有完整的加载、展开、渲染、刷新、解析、打开和滚动转换。转换结束前以一致方式禁用或排队后续导航；不允许 fire-and-forget handler 造成转换重叠。
- [ ] When a target's old DOM node is gone, resolve it from its descriptor. For inspector targets, reopen the owning event with search-transient provenance, open supplemental `<details>` ancestors, then resolve and scroll to the concrete occurrence. / 当目标的旧 DOM 节点已消失时，从 descriptor 重新解析。对于 Inspector 目标，用搜索临时来源重新打开所属事件，展开补充 `<details>` 祖先，再解析并滚动到具体 occurrence。
- [ ] Keep explicit timeline pagination and transient event expansion monotonic for the active search key. Newly discovered descriptors may extend the denominator, but a completed transition must leave the active descriptor selected and must not reduce the known target set. / 对当前搜索 key 保持明确 timeline 分页和临时事件展开的单调性。新发现的 descriptor 可以扩大分母，但一次完成的转换必须保留活动 descriptor，且不能缩小已知目标集合。
- [ ] Define wrapping only after the filtered timeline is exhausted and all descriptors discoverable by the current transition have been registered. / 只有在筛选后的 timeline 已耗尽，且当前转换可发现的 descriptor 都已注册后，才允许循环回绕。

## Phase 3: search-assist interaction state / 第三阶段：搜索辅助交互状态

- [ ] Add an input click path that opens the assist even when focus did not change. Keep focus and input paths as equivalent open intents. / 增加搜索框 click 打开路径，即使焦点没有变化也能打开辅助面板。让 focus 与 input 路径表达等价的打开意图。
- [ ] Prevent navigation-driven smooth scroll from closing the assist while the search input is focused. Scope timeline-scroll dismissal to user navigation outside the focused search field, with an explicit programmatic-scroll guard where needed. / 防止导航驱动的平滑滚动在搜索框已聚焦时关闭辅助面板。将 timeline scroll 关闭行为限定为焦点已离开搜索框的用户导航场景，并在需要时增加明确的程序化滚动 guard。
- [ ] Make the inline count container and text pointer-transparent while preserving pointer events and accessible names on the actual previous/next buttons. Do not treat pointer transparency alone as the layout fix: replace the fixed `10rem` assumption with measured/responsive space reservation or responsive relocation, so dynamic localized counts remain fully visible and cannot overlap typed input or create an unclickable input region. / 让内联计数容器和文本对指针透明，同时保留真正上一个/下一个按钮的指针事件和无障碍名称。不要把指针穿透本身当作布局修复：用测量后或响应式的空间预留，或响应式重新安置，替代固定 `10rem` 假设，使动态本地化计数保持完整可见，并且不会覆盖已输入文本或制造无法点击的输入框区域。
