# v0.1.4 freeze and release / v0.1.4 冻结与发布

## Objective / 目标

Freeze the implemented v0.1.4 increment as `session-analyzer@0.1.4`, take it through the normal pull-request and CI path, and release the exact verified `main` commit through the repository's staged OIDC workflow. The increment includes runtime Codex/Claude Code source switching, source-neutral runtime ownership cleanup, compact Codex resident indexing with source-backed detail hydration and freshness protection, and the associated capacity/reliability documentation. Complete staged-artifact review, maintainer approval, anonymous public verification, and only then create `v0.1.4` and the GitHub Release. / 将已经实现的 v0.1.4 增量冻结为 `session-analyzer@0.1.4`，通过正常 pull request 与 CI 流程，并通过仓库的 staged OIDC workflow 发布精确验证过的 `main` commit。本增量包括 Codex／Claude Code 运行期来源切换、来源中立运行时 ownership 清理、带来源支撑详情 hydration 与 freshness 保护的 Codex 紧凑常驻索引，以及配套的容量／可靠性文档。完成 staged 制品审查、维护者审批、匿名公共验证后，才创建 `v0.1.4` 与 GitHub Release。

## Frozen release decisions / 已冻结的发布决策

1. `0.1.4` is now in feature freeze. Only release metadata, documentation convergence, package-contract tests, validation fixes, and evidence recording remain in scope; no new user-facing feature is added during release preparation. / `0.1.4` 现在进入功能冻结。发布准备期间只允许修改 release metadata、文档收敛、package-contract 测试、验证修复与证据记录；不再增加面向用户的新功能。

## Version-specific risks / 版本特有风险

### Large Codex index reliability / Codex 大型索引可靠性

The compact resident index must keep source JSONL as the lossless source of truth, avoid a reachable full parsed-record graph, and preserve source-backed detail hydration, Raw readback, image preview, exact transcript fingerprinting, append-only handling, and stale-source/reindex correctness. The completed memory/reliability plans provide the implementation evidence; this release must rerun the relevant gates on the exact release commit. / 紧凑常驻索引必须继续以来源 JSONL 作为无损事实来源，避免可到达的完整 parsed-record 对象图，并保持来源支撑的详情 hydration、Raw 回读、图片预览、精确 transcript 指纹、append-only 处理以及过期来源／重建索引正确性。已完成的内存／可靠性计划提供实现证据；本次发布仍必须在精确 release commit 上重跑相关门禁。

The 800 MiB candidate-byte warning is advisory and non-blocking. Release notes should communicate the material resident-memory and freshness benefit without copying local benchmark values or sensitive corpus details. / 800 MiB candidate-byte warning 是提示性的、非阻断的。Release note 应传达常驻内存与 freshness 的实质收益，但不复制本地 benchmark 数字或敏感语料细节。

### Runtime source switching and stale discovery / 运行期来源切换与过期发现

The active source can change without restarting the server, and source configuration/ownership must remain registry-driven and source-neutral. Stale discovery responses must not commit an old source or old project selection. Existing browser coverage exercises invalidated discovery failures and source transitions; the remaining tracked case is the successful stale full-scan response after summary selection, including the old auto-restore path. / 当前来源可以在不重启 server 的情况下切换，来源配置／ownership 必须继续由 registry 驱动并保持来源中立。过期发现响应不得提交旧来源或旧项目选择。现有 browser coverage 已覆盖失效 discovery failure 与 source transition；剩余跟踪 case 是 summary 选择之后成功返回的过期 full-scan 响应，包括旧 auto-restore 路径。

### Package and cross-platform contract / Package 与跨平台契约

The package manifest, generated browser asset, Codex and Claude installed-package smoke paths, strict npm 12 install-script policy, and Linux/Windows CI must remain aligned. Any package allowlist or generated-asset change invalidates candidate hashes and requires fresh inspection. / Package manifest、生成的 browser asset、Codex 与 Claude 安装后 package smoke、npm 12 strict install-script policy，以及 Linux／Windows CI 必须保持一致。任何 package allowlist 或生成资产变化都会使候选哈希失效，并要求重新检查。
