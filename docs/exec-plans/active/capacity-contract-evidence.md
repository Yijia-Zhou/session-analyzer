- Dependency **entry count** is currently fixed: Codex creates two entries in `buildCodexMaterializationState`, Claude creates one in `createClaudeMaterializationState`, and DeepSeek creates one in `buildDeepSeekIndex`. The old 65,536-entry ceiling is **not a demonstrated current production failure for these sources**. No claim of 65,537 production dependencies is made. / 依赖**项数**当前固定：Codex 两项，Claude 与 DeepSeek 各一项，对应生产函数如上。因此旧 65,536 项上限**不是这三个来源已证实的生产故障**，不声称已验证 65,537 个生产依赖。
- Codex copies untruncated `session_index.jsonl.thread_name` into dependency metadata, including the original copied source entry. A valid Unicode title exceeds both the old 64 KiB scalar and 4 MiB dependency encoding ceilings. / Codex 将未经截断的 `session_index.jsonl.thread_name` 复制进依赖元数据（包括源条目副本）；有效 Unicode 标题可超过旧 64 KiB 字符串及 4 MiB 依赖编码上限。
- Claude copies all distinct observed cwd values into `cwdSet` and descriptor `projection.cwdSet`. One valid transcript with 16,385 distinct cwd values exceeds the old cwd count, payload structural count, and 512 KiB descriptor limits. / Claude 将所有不同 cwd 复制到 `cwdSet` 和描述符 `projection.cwdSet`；含 16,385 个不同 cwd 的有效转录超过旧 cwd 项数、payload 结构项数及 512 KiB 描述符预算。
- Codex and Claude accumulate all distinct modified files in `analysis.patchedFiles`; at 200,001 `{file,count}` entries this alone exceeds the old one-million structural-entry accounting. DeepSeek currently emits an empty patched-files collection; that particular counterexample is not applicable to DeepSeek. / Codex 和 Claude 累积全部不同改动路径到 `analysis.patchedFiles`；200,001 个 `{file,count}` 条目已超过旧一百万结构项计数。DeepSeek 当前该集合为空，此反例不适用于 DeepSeek。

## Implementation / 实现

Natural breadth and scalar text size no longer define corruption for cwd evidence, descriptors, dependency evidence, or materialized analysis. Validation still checks finite numbers, plain data, dense arrays, data properties, cycle freedom, exact top-level fields, source ownership, copied-fact equality, and adapter-owned path/snapshot/digest consistency. Structural depth remains 8 for descriptors/evidence and 32 for analysis; summary budgets remain separate. / cwd 证据、描述符、依赖证据及物化分析不再用自然增长宽度和文本大小判断损坏；仍检查有限数值、普通数据、稠密数组、数据属性、无环、精确顶层字段、来源归属、复制事实相等及 adapter 的路径／快照／摘要一致性。描述符／证据深度仍为 8，分析为 32；摘要预算保持独立。

`plain-value-stream.js` encodes JSON incrementally in at most 64 Ki UTF-16-code-unit output chunks, with bounded scalar escaping pieces. All three materialization identity hashers consume these chunks; dependency accounting no longer allocates whole serialized sets. Encoding matches historical `JSON.stringify` bytes, including Unicode, escaped strings and surrogate pairs, so snapshot/cache identities remain compatible. Validation no longer builds a descriptor Map for every array element. Existing in-memory canonical objects and reflective array key lists still consume resources proportional to their contents; this is not a claim of unlimited or disk-backed materialization. / 新模块按最多 64 Ki UTF-16 代码单元的块编码 JSON，字符串转义也分段；三来源物化身份哈希消费这些块，依赖计数不再构造完整序列化副本。字节与历史 `JSON.stringify` 相同（覆盖 Unicode、转义、代理对），保持快照／缓存身份兼容。数组验证不再为每项建立 descriptor Map。规范对象和反射数组键表仍按内容占用内存，不承诺无限容量或磁盘物化。
