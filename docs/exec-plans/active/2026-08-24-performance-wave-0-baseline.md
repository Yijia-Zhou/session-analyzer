- Focused tests must build through `getSourceAdapter('codex').buildIndex()`, run `validateIndexOwnershipForCommit()`, assert that strict Indexed Session objects omit every forbidden resident event field and pass strict canonical validation, materialize through `materializeSessionForIndex()`, and verify exactly 1,800 Main events plus the hit at ordinal 1,650. ## Private real-corpus snapshot policy / 私有真实语料 snapshot 策略

1. Create one repository-external physical copy containing only the transcript source root needed by the selected adapter and the repository association needed for the run. Reject symlinks, junctions, reparse points, or any other entry that resolves back to live mutable data. The copy must never be the live transcript directory. / 创建一个仓库外 physical copy，只包含所选 adapter 所需 transcript source root 与运行所需 repository association。拒绝 symlink、junction、reparse point 或任何会解析回活跃可变数据的 entry。该 copy 绝不能是活跃 transcript 目录。
2. Seal the copy before run 1 with read-only filesystem permissions or equivalent ACL. Record only a boolean read-only attestation in the access-controlled manifest; do not record its path. ACL／read-only attestation is supplementary defense, not the sole immutability proof. / 在第 1 次运行前使用只读文件系统权限或等价 ACL 密封该 copy。受访问控制 manifest 只记录 read-only attestation boolean，不记录其 path。ACL／read-only attestation 只是补充防御，不是唯一的不可变性证明。
3. Use this same external copy for every independent process. Do not re-copy between repetitions, and do not let the adapter's default live home substitute for an omitted `--source-home`. / 每个独立进程使用同一个外部 copy。重复运行之间不得重新 copy，也不得因遗漏 `--source-home` 而回退到 adapter 默认活跃 home。
4. Compute one deterministic aggregate SHA-256 over the copy. Canonically traverse normalized relative entry names in UTF-8 ordinal order; reject unsupported entry types; and feed a version tag plus each regular file's normalized relative name, byte length, and exact bytes through length-delimited records. The external root path is never an input. The reference digest remains only in a repository-external, access-controlled proof-state file and is never emitted by a worker. / 对该 copy 计算一个确定性的聚合 SHA-256。按 UTF-8 ordinal 顺序 canonical 遍历 normalized 相对 entry name；拒绝不支持的 entry type；通过带长度分隔的 record 输入 version tag，以及每个 regular file 的 normalized 相对名称、byte length 与精确 byte。外部 root path 绝不作为输入。Reference digest 只保留在仓库外、受访问控制的 proof-state file 中，worker 绝不输出该值。
5. Recompute and compare the aggregate SHA-256 before run 1, immediately before and after every repetition, and once after the whole repetition group. This supplies before, during, and after evidence and detects residual append or any other mutation. Any mismatch invalidates the whole group; after diagnosis, create and seal a new copy with a new opaque group label and restart all repetitions. / 在第 1 次运行前、每次 repetition 紧邻的前后，以及整个 repetition group 之后各重新计算并比较聚合 SHA-256。这同时提供 before／during／after 证据，并检测 residual append 或任何其它 mutation。任何 mismatch 都会使整个 group 无效；诊断后必须创建并密封新 copy，使用新的 opaque group label，并从头运行全部 repetition。
6. The `snapshotProof` section in access-controlled raw artifacts/manifests contains only `proofVersion`, `algorithm: "SHA-256"`, an opaque group label, checkpoint count, and proof-match verdicts; it never contains the reference/current digest. Console/progress logs and repository progress entries are narrower and contain only the public profiled tree hash, opaque group label, repeat count, and aggregate proof-match verdict. Published evidence states only equality, never a private digest or checksum. / 受访问控制 raw artifact／manifest 中的 `snapshotProof` section 只包含 `proofVersion`、`algorithm: "SHA-256"`、opaque group label、checkpoint count 与 proof-match verdict；绝不包含 reference／current digest。Console／progress log 与仓库 progress entry 更窄，只包含 public profiled tree hash、opaque group label、repeat count 与聚合 proof-match verdict。发布的证据只说明相等，绝不包含 private digest 或 checksum。
7. Do not commit or publish transcript content, prompts, responses, commands, query strings derived from transcripts, source paths, repository paths, source-home paths, Session IDs, Analyzer Session identities, per-Session source digests, dependency-set IDs, or per-Session selection facts. / 不得 commit 或发布 transcript 内容、prompt、response、command、从 transcript 派生的 query string、来源 path、repository path、source-home path、Session ID、Analyzer Session identity、逐 Session source digest、dependency-set ID 或逐 Session selection fact。
8. Allowed aggregate corpus facts are source kind, Session count, Main/Protocol/Raw row counts, total candidate/indexed/logical source bytes, aggregate dependency counts, query-store accounted bytes, total accounted Index bytes, and redacted selection ordinals with source/row counts. / 允许的聚合语料 fact 包括 source kind、Session count、Main／Protocol／Raw row count、候选／已索引／逻辑 source byte 总数、聚合 dependency count、query-store accounted bytes、Index total accounted bytes，以及只含 source／row count 的脱敏选择 ordinal。
9. Do not run browser scenarios, capture screenshots, or save HTML against the private corpus in Wave 0. The real corpus is used for server domains 1–4 only; domains 5–6 use the synthetic fixture. / Wave 0 不在私有语料上运行 browser scenario、截图或保存 HTML。真实语料只用于服务端成本域 1 至 4；成本域 5 至 6 使用合成 fixture。

- The private-corpus runner must reject an output directory inside the Git repository. It must also reject an absent output directory rather than falling back to a repository-relative location. / 私有语料 runner 必须拒绝 Git 仓库内的输出目录；也必须拒绝缺失 output directory，不能回退到仓库相对位置。

It never contains arguments, paths, shell text, environment values, or free-form strings. Private paths may be used by the child process but never serialized. / 用 `invocationTemplate` 替换 `command` metadata。其唯一允许的 field／value 是 `worker: "timeline" | "project-query"`、`runtime: "node" | "node-expose-gc"`、`inputRole: "external-synthetic-fixture" | "external-private-copy"` 与 `outputRole: "external-artifact-directory"`；未知 field／value 会使校验失败。它绝不包含 argument、path、shell text、environment value 或自由文本。Private path 可以被 child process 使用，但绝不能序列化。
- Raw JSON, stdout/stderr captures, heap diagnostic files, and failure traces remain outside the repository or in access-controlled CI artifacts. Only a manually reviewed bilingual aggregate summary may enter repository documentation. / Raw JSON、stdout／stderr capture、heap diagnostic file 与 failure trace 保留在仓库外或受访问控制 CI artifact 中。只有经过人工评审的双语聚合摘要可以进入仓库文档。

No ratio may imply that accounted bytes equal retained heap or RSS. / Accounted／logical bytes 与 process memory 必须分开标注。`projectQueryStore.accountedBytes`、metadata／dependency／catalog／legacy-owner accounted bytes及其总和描述逻辑编码 ownership；`heapUsed`、`external`、`arrayBuffers`、heap limit、采样 RSS 与 process maximum RSS 描述 runtime memory。任何 ratio 都不得暗示 accounted bytes 等于 retained heap 或 RSS。

## Repeatability protocol / 可重复性协议

### Process isolation / 进程隔离

- Synthetic browser baseline: five valid independent Node processes. Each process creates a new fixture directory, builds/validates one strict Index, creates fresh server owner(s), launches a new Chromium process, runs the scenarios, closes servers/browser, and removes its fixture. / 合成浏览器基线：五个有效独立 Node 进程。每个进程创建新的 fixture 目录、构建／校验一个 strict Index、创建 fresh server owner、启动新的 Chromium 进程、运行场景、关闭 server／browser 并移除 fixture。
- Private real-corpus baseline: at least three valid independent `node --expose-gc` processes against the same sealed repository-external copy. Each process performs one cold source build and one commit validation; within-process query scans remain three repeats unless the reviewer approves another fixed count. / 私有真实语料基线：至少三个有效独立 `node --expose-gc` 进程，均针对同一密封仓库外 copy。每个进程执行一次冷来源构建和一次 commit validation；进程内 query scan 保持三次 repeat，除非 reviewer 批准另一固定 count。
- A failed, leaked, ref-mismatched, fixture/snapshot-mismatched, or structurally invalid process does not count toward N and is never silently replaced in the summary. Record the invalid attempt and reason in the access-controlled manifest, then rerun only after diagnosis. / Failed、leak、ref mismatch、fixture／snapshot mismatch 或结构无效的进程不计入 N，也不得在摘要中被静默替换。在受访问控制 manifest 中记录无效 attempt 与原因，诊断后再重跑。
- Do not alternate implementation variants, source roots, Node heap limits, browser modes, or machine power conditions within one baseline group. / 同一 baseline group 内不得交替使用 implementation variant、source root、Node heap limit、browser mode 或机器电源条件。

### Warm and cold control / Warm 与 cold 控制

- Warm browser suite owner: after server start, load the primary Session's first page and wait for network idle plus two animation frames. Confirm exactly one primary adapter call occurred, then reset browser/request/materialization counters. Every warm scenario must observe zero new adapter calls. / Warm browser suite owner：server 启动后加载 primary Session 第一页，等待 network idle 与两个 animation frame。确认 primary adapter 精确调用一次，再 reset browser／request／materialization counter。每个 warm scenario 必须观测到零新增 adapter 调用。
- Cold switch owner: create a second `createServer(prebuiltIndex, …)` instance from the same immutable strict Index, with its own fresh revision owner and `sessionPrewarm: false`. Warm only primary, assert secondary call count/cache history is zero, reset, then perform the switch. / Cold switch owner：从同一 immutable strict Index 创建第二个 `createServer(prebuiltIndex, …)` instance，使其具有自己的 fresh revision owner，并设置 `sessionPrewarm: false`。只 warm primary，断言 secondary call count／cache history 为零，reset 后再执行切换。
- Server materialization warm hits: after one cold admission, perform three same-owner gets and require the exact same object every time with no new adapter call. Record all three timings plus median/min/max. / Server 物化 warm hit：一次 cold admission 后，在同一 owner 上执行三次 get，要求每次都是精确同一 object，且没有新增 adapter 调用。记录三次 timing 及 median／min／max。

### Three repeatability classes / 三类可重复性指标

1. **Hard exact invariants.** These are pass/fail in every accepted repetition and are summarized with the expected value plus `distinctValueCount`: schema/identity metadata; semantic fixture proof or private snapshot proof-match verdict; final functional state/digest; source-build count 1; commit-validation count 1; project-job count 0; prewarm disabled; owner count; materializer calls by role; exact warm identity; timeline offsets/limits/page counts within each timeline stream; no residual append; cleanup/privacy verdicts; and the context-reveal zero-work contract (zero timeline request, zero full render/card-generation/highlight/discovery work, zero materializer calls, exactly one envelope request, and at most one detail request). Functional canonical card/mark/loaded/context-row counts are exact state, distinct from work-performed counters. / **Hard exact invariant。** 每次 accepted repetition 都必须 pass／fail，并以 expected value 加 `distinctValueCount` 汇总：schema／identity metadata；semantic fixture proof 或 private snapshot proof-match verdict；最终功能状态／digest；source-build count 1；commit-validation count 1；project-job count 0；prewarm disabled；owner count；按 role 统计的 materializer call；精确 warm identity；每条 timeline stream 内精确的 offset／limit／page count；无 residual append；cleanup／privacy verdict；以及 context-reveal 零工作契约（零 timeline request、零 full render／card-generation／highlight／discovery work、零 materializer call、精确一次 envelope request、最多一次 detail request）。功能性的 canonical card／mark／loaded／context-row count 属于精确状态，与 work-performed counter 不同。
2. **Causal partial-order request constraints.** Each scenario declares a closed set of required happens-before edges and forbidden stale-commit edges. Examples include action/reset before its dependent requests, increasing timeline offsets within one dependent paging chain, Session selection before secondary requests, envelope before an optional dependent detail request, and no superseded primary response committing after secondary selection. The raw artifact may retain observed sequence numbers, but acceptance compares constraint satisfaction, family/count/offset invariants, and outcomes—not a total sequence. In particular, no relative total order is required among logically concurrent `analysis`, `timeline`, and `fileSuggestions` requests. / **因果 partial-order request constraint。** 每个场景声明封闭的必需 happens-before edge 与禁止 stale-commit edge 集合。例如：action／reset 先于其依赖 request；同一依赖 paging chain 内 timeline offset 递增；Session selection 先于 secondary request；envelope 先于可选的依赖 detail request；secondary selection 后不得 commit 被取代的 primary response。Raw artifact 可以保留观测到的 sequence number，但验收比较的是 constraint satisfaction、family／count／offset invariant 与 outcome，而不是 total sequence。尤其不得要求逻辑并发的 `analysis`、`timeline` 与 `fileSuggestions` request 之间存在相对 total order。
3. **Observational work/timing metrics.** Timing, memory, Long Tasks, Resource Timing, observed sibling-request ordering, completion-versus-intentional-abort outcomes for superseded work, transient cold-switch work, and any render/card-generation/highlight/discovery counter not frozen by calibration are distributions. Numeric metrics report `repeatCount`, median, minimum, and maximum; categorical outcomes report counts. Per-run values stay in access-controlled raw artifacts. These observations can diagnose variance but cannot fail a run unless they violate a hard invariant or causal constraint. / **Observational work／timing metric。** Timing、memory、Long Task、Resource Timing、观测到的 sibling-request 顺序、被取代工作 completion／intentional-abort outcome、cold-switch transient work，以及任何未通过 calibration 冻结的 render／card-generation／highlight／discovery counter 都作为 distribution。数值 metric 报告 `repeatCount`、median、minimum 与 maximum；分类 outcome 报告 count。逐 run value 只保留在受访问控制 raw artifact 中。这些观测可用于诊断 variance，但除非违反 hard invariant 或 causal constraint，否则不能使运行失败。

### Short pre-baseline counter calibration / 基线前短 counter 校准

After the M5 smoke and before the five-run baseline, execute three fresh synthetic child processes that exercise each scenario once under the fixed environment. These calibration runs do not count toward the five baseline repetitions and do not use private data. For each scenario, classify only render, card-generation, highlight, and discovery counters: a counter may enter the frozen `exactCounterSet` only when all three values match and the result is consistent with the scenario contract. Context-reveal zero-work counters remain hard exact regardless of calibration. Freeze and review the per-scenario `exactCounterSet` before M6; do not add/remove a counter after seeing baseline results. Any eligible counter that varies stays observational; any frozen counter that later varies invalidates that repetition group and requires diagnosis plus a new calibration/baseline group. / 在 M5 smoke 之后、五次 baseline 之前，执行三个 fresh 合成 child process，在固定环境下各运行每个场景一次。这些 calibration run 不计入五次 baseline repetition，也不使用 private data。对每个场景只分类 render、card-generation、highlight 与 discovery counter：只有三次 value 全部相同且结果符合场景契约时，该 counter 才能进入冻结的 `exactCounterSet`。Context-reveal 零工作 counter 不受 calibration 影响，始终属于 hard exact。M6 前冻结并评审逐场景 `exactCounterSet`；不得在看到 baseline 结果后增删 counter。任何不稳定的 eligible counter 保持 observational；任何冻结 counter 后续发生变化都会使该 repetition group 无效，并要求诊断后重新 calibration／baseline。

Do not discard outliers merely because they are slow. Mark a run invalid only for a documented structural/environment breach, hard-invariant failure, or causal-constraint failure; otherwise retain it in the observational summaries and diagnose separately. / 不得仅因运行较慢而丢弃 outlier。只有存在已记录的结构／环境 breach、hard invariant 失败或 causal constraint 失败时，才能把运行标记为 invalid；否则必须保留在 observational 摘要中，并另行诊断。
