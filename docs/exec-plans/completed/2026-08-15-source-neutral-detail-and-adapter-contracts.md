# Source-neutral detail and adapter contracts / 来源中立详情与适配器契约

## Objective / 目标

Establish the normative structured-detail and source-adapter boundaries that future Transcript Sources must implement before any additional source harness is built. Codex and Claude Code are reference implementations, not specifications. Preserve the deliberately small canonical Index, Session, Logical Event, and raw-record DTO contract while keeping parsing, storage, locators, correlation, structured-detail interpretation, and Raw evidence source-owned. / 在实现任何额外转录来源 harness 之前，建立未来转录来源必须实现的规范化结构详情与来源适配器边界。Codex 与 Claude Code 是参考实现，而不是规格。保留刻意保持精简的 canonical Index、Session、Logical Event 与原始记录 DTO 契约，同时让解析、存储、locator、关联、结构详情解释与 Raw 证据继续由来源拥有。

## Guardrails / 护栏

1. Source-specific evidence is interpreted by the owning adapter. Shared code validates and presents the adapter result; it does not reverse-engineer source semantics from labels, renderer types, or source payloads. / 来源专属证据由所属 adapter 解释。共享代码校验并呈现 adapter 结果；不得根据 label、renderer type 或来源 payload 反向猜测来源语义。
2. Detail Purpose is a response-time presentation semantic. It is not added to the canonical Logical Event, Raw Record, index, search, metrics, folding, or ownership contract. / 详情用途属于响应期呈现语义，不进入 canonical Logical Event、Raw Record、index、搜索、指标、折叠或 ownership 契约。
3. `rawRefs` and adapter-owned locators remain the authority for source evidence. Structured detail is bounded, sanitized, derived, and replaceable; it never becomes a lossless payload store. / `rawRefs` 与 adapter-owned locator 继续作为来源证据的权威。结构详情是有界、已脱敏、派生且可替换的展示，不会成为无损 payload 存储。
4. Unknown, malformed, ambiguous, or unsupported source material remains traceable through Protocol and/or Raw fallback. A renderer or Detail Purpose must not upgrade uncertain material into canonical meaning. / 未知、畸形、有歧义或不受支持的来源材料继续通过 Protocol 和／或 Raw fallback 保持可追溯。Renderer 或详情用途不得把不确定材料提升为 canonical 语义。
5. Checkpoint gates are real stop points. No M2 implementation starts until M1 blocking architecture feedback is resolved; no M4 implementation starts until the M3 implementation review is accepted. / 检查点是真实停点。M1 的阻断性架构反馈解决前不开始 M2；M3 实现评审通过前不开始 M4。

### Proposed semantic contract at the checkpoint / 检查点提交的语义契约提案

Every structured section on a Main- or Protocol-layer Event Detail carries exactly one required machine `purpose`. The vocabulary is closed and source-neutral: / Main 或 Protocol 层 Event Detail 中的每个结构化 section 都必须携带一个必需且唯一的机器字段 `purpose`。该词汇表封闭且来源中立：

| Purpose / 用途 | Meaning / 含义 | Representative current material / 当前代表材料 |
| --- | --- | --- |
| `content` | A coherent event-specific body meant to be read as one unit and not usefully separated into request/result stages. / 应作为一个整体阅读、且不适合拆成 request/result 阶段的事件专属正文。 | messages, reasoning, plan bodies, user-input interactions, collaboration cards / 消息、推理、计划正文、用户输入交互、协作卡片 |
| `request` | What an operation was asked or declared to do, without claiming that it ran or succeeded. / 某次操作被请求或声明要做什么，不声称已经执行或成功。 | command, patch input, tool arguments, declared Code Mode request / 命令、patch 输入、工具参数、已声明 Code Mode request |
| `result` | An observed output, response, completion, or outcome owned by the selected event. / 所选事件拥有的已观测输出、响应、完成事实或结果。 | stdout/stderr, tool response, applied diff, lifecycle completion / stdout/stderr、工具响应、已应用 diff、生命周期完成事实 |
| `context` | Event-specific supporting facts needed to interpret content, request, or result, excluding common envelope metadata. / 理解 content、request 或 result 所需的事件专属辅助事实，不包括通用 envelope metadata。 | run context, usage, files, lifecycle launch state, source-owned options / 运行上下文、用量、文件、生命周期启动状态、来源专属选项 |
| `traceability` | How the analyzer related or projected evidence, or a relation to another canonical event; it explains interpretation but is not the source evidence itself. / Analyzer 如何关联或投影证据，或与另一 canonical event 的关系；它解释解释过程，但不是来源证据本身。 | projection evidence, execution trace, observed nested event links / 投影证据、执行 trace、已观测嵌套事件链接 |
| `fallback` | Bounded, sanitized material whose semantic role cannot safely be identified as `content`, `request`, `result`, `context`, or `traceability`. / 无法安全识别为 `content`、`request`、`result`、`context` 或 `traceability` 的有界、已脱敏材料。 | unclassified logical fragment, bounded logical Raw JSON for an already admitted event / 未分类 logical fragment、已接纳事件的有界 logical Raw JSON |

`purpose` says what a section means. `type` remains the closed renderer discriminant that says how its payload is rendered. `title`, localized copy, `hideTitle`, and source-owned titles remain display data. Producer order is only a within-purpose narrative tie-breaker; it does not establish semantic ownership. Rendering genericness and modeling specificity are not purpose axes: a generic JSON or code summary that the adapter knows is a request or result must use `request` or `result`, never `fallback`. / `purpose` 表示 section 的含义；`type` 继续作为封闭的 renderer 判别字段，说明 payload 如何绘制。`title`、本地化文案、`hideTitle` 与来源拥有的标题继续只是显示数据。Producer 顺序只作为同一 purpose 内的叙事顺序 tie-breaker，不建立语义 ownership。渲染是否通用、建模是否具体都不是 purpose 轴：adapter 已知属于 request 或 result 的通用 JSON／code 摘要必须使用 `request` 或 `result`，绝不能使用 `fallback`。

A top-level or nested composite section that must remain atomic uses outer `content`. That outer purpose controls the composite's global M4 placement. Nested child sections still carry purposes for renderer-local meaning and ordering, but the shared Inspector never hoists, splits, or reorders those children across top-level purpose groups. Scalar evidence badges embedded by a composite renderer are display fields of that atomic content; a standalone projection-evidence section uses `traceability`. / 必须保持原子性的顶层或嵌套 composite section 使用外层 `content`；该外层 purpose 决定 composite 在 M4 全局排序中的位置。嵌套子 section 仍携带 purpose，供 renderer 局部表达含义和排序，但共享 Inspector 绝不会把这些子 section 提升、拆分或跨顶层 purpose 分组重排。Composite renderer 内嵌的标量证据 badge 属于该原子 content 的显示字段；独立的投影证据 section 使用 `traceability`。

The contract initially governs structured logical detail (`main` and `protocol`). Raw-layer detail remains a source-evidence view and is not an M3 semantic-migration target. `timelineSections[]` and `inspectorSections[]` remain response surfaces during migration so existing presentation can be preserved; purpose is orthogonal to that placement. / 该契约首期约束结构化 logical detail（`main` 与 `protocol`）。Raw 层详情继续是来源证据视图，不是 M3 语义迁移目标。迁移期间 `timelineSections[]` 与 `inspectorSections[]` 继续作为响应 surface，以尽量保持现有呈现；purpose 与该 placement 正交。

### Ownership boundary / Ownership 边界

| Owner / 所有者 | Owns / 负责 | Must not own / 不得负责 |
| --- | --- | --- |
| Canonical data / Canonical 数据 | Event identity, layer, kind, status/severity, metrics/search facts, source ownership, and complete `rawRefs`. / Event identity、layer、kind、status/severity、指标／搜索事实、来源 ownership 与完整 `rawRefs`。 | Renderer type, localized section title, Detail Purpose, Inspector order. / Renderer type、本地化 section title、详情用途、Inspector 顺序。 |
| Source adapter / 来源 adapter | Source parsing/correlation, detail hydration, event-specific extraction, section purpose, renderer payload, source-owned strings, and initial timeline/inspector placement. / 来源解析／关联、详情 hydration、事件专属提取、section purpose、renderer payload、来源拥有字符串及初始 timeline/inspector placement。 | Shared UI ordering, inference from another adapter, canonical expansion for presentation convenience, or lossless payload retention in detail. / 共享 UI 排序、根据另一 adapter 推断、为呈现便利扩张 canonical contract，或在 detail 中保留无损 payload。 |
| Shared detail boundary / 共享详情边界 | Exact immutable envelope／Raw-reference equality, closed-purpose and renderer validation, bounded recursive and type-specific shape validation, shape-preserving sanitization, final emitted-shape validation, and clear contract errors. / 精确不可变 envelope／Raw-reference 等值校验、封闭 purpose 与 renderer 校验、有界递归且按 type 的 shape 校验、保持 shape 的脱敏、最终输出 shape 校验与清晰契约错误。 | Source-specific parsing, title-based semantic inference, silent coercion of unknown purposes/types, mutation of canonical identity/evidence fields, or generic plugin capabilities. / 来源专属解析、基于 title 的语义推断、静默强制转换未知 purpose/type、改变 canonical identity／evidence 字段，或通用插件 capability。 |
| Shared browser / 共享浏览器 | Renderer selection from `type`, stable grouping and order from `purpose`, common metadata placement, duplication reduction, localization chrome, and the stable Raw References affordance. / 根据 `type` 选 renderer、根据 `purpose` 稳定归组与排序、通用 metadata placement、减少重复、本地化 chrome 与稳定 Raw References 入口。 | Recovering purpose from `type`, title, array position, source kind, or tool name; changing canonical meaning. / 根据 `type`、title、数组位置、source kind 或 tool name 恢复 purpose；改变 canonical 语义。 |
| Raw References / 原始引用 | Exact evidence identity and adapter-validated lazy readback through the indexed Session and source locator. / 精确证据 identity，以及通过已索引 Session 与 source locator 执行的 adapter 校验惰性回读。 | Acting as an ordinary detail section, being reordered by purpose, or being replaced by cached raw payloads. / 充当普通 detail section、按 purpose 重排，或被缓存 raw payload 替代。 |

M3 freezes the shared consumption pipeline in this order: (1) resolve canonical Index → Session → Logical Event ownership and every referenced Raw Record; (2) let the owning adapter hydrate structured detail; (3) compare immutable response fields exactly with the selected canonical event and expected request envelope—`id`, `schemaVersion`, `sourceKind`, `kind`, `subtype`, `layer`, `sourceLocator`, and the ordered, deep `rawRefs`; (4) validate bounded recursion, plain containers, closed purpose／renderer discriminants, and type-specific shapes, then apply type-aware sanitization; and (5) validate the final emitted shape. `rawRefs` equality is complete, ordered, and deep; the adapter may not omit, add, reorder, or rewrite them. / M3 将共享消费流水线固定为以下顺序：（1）解析 canonical Index → Session → Logical Event ownership 及其引用的每条 Raw Record；（2）由所属 adapter hydrate 结构化详情；（3）把不可变响应字段与所选 canonical event 及预期请求 envelope 做精确比较，包括 `id`、`schemaVersion`、`sourceKind`、`kind`、`subtype`、`layer`、`sourceLocator` 与有序、深度相等的 `rawRefs`；（4）校验有界递归、plain container、封闭 purpose／renderer discriminant 与按 type 的 shape，再执行 type-aware 脱敏；（5）校验最终输出 shape。`rawRefs` 必须完整、有序且深度相等；adapter 不得遗漏、增加、重排或重写。

The type-aware sanitizer may redact or truncate leaf strings and omit optional excess only in schema-defined ways, including schema-defined omission markers. It must never change a section purpose, renderer type, required container kind, immutable envelope field, Raw Reference, or source locator. Accessors, cycles, unknown discriminants, and over-budget containers fail before sanitization; sanitization is not a repair mechanism for malformed DTOs. / Type-aware sanitizer 只能脱敏或截断叶子字符串，并且只能按 schema 定义的方式省略可选超量内容，包括 schema 定义的 omission marker。它绝不能改变 section purpose、renderer type、必需 container kind、不可变 envelope 字段、Raw Reference 或 source locator。Accessor、cycle、未知 discriminant 与超预算 container 必须在脱敏前失败；脱敏不能用来修复畸形 DTO。

### M4 ordering target established by M1 / M1 确立的 M4 排序目标

The selected-event Inspector uses the total precedence `content` → `request` → `result` → `context` → `traceability` → `fallback`. Producer order is preserved only within the same purpose. An atomic composite is placed once by its outer `content` purpose; its nested child ordering remains renderer-owned and is never split into the global order. Common canonical metadata is a separate browser-owned block placed after event-specific information unless a compact high-value fact belongs in existing header/chip presentation. Raw References remains one source-neutral, always available escape hatch outside the section arrays. Exact layout and duplication rules are implemented and browser-validated only in M4. / 选中事件 Inspector 使用全序 `content` → `request` → `result` → `context` → `traceability` → `fallback`。Producer 顺序只在同一 purpose 内保留。原子 composite 只按其外层 `content` purpose 放置一次；其嵌套子项顺序由 renderer 拥有，绝不拆入全局顺序。通用 canonical metadata 是独立、由浏览器拥有的区域，位于事件专属信息之后；已有 header/chip 中适合紧凑展示的高价值事实除外。Raw References 作为 section 数组之外、始终可用的单一来源中立逃生口。精确布局与去重规则只在 M4 实现并做浏览器验证。

### Pressure scenarios / 压力场景

- A Codex patch can use the same `patch` renderer with `request` purpose for requested input or `result` purpose for an applied result diff; the renderer type no longer decides meaning. / Codex patch 可以让同一 `patch` renderer 在请求输入时使用 `request`，在已应用结果 diff 时使用 `result`；renderer type 不再决定含义。
- Claude `TaskCreate`／`TaskUpdate`, user input, and collaboration cards may remain atomic `content` when splitting would damage their coherent interaction; result-only supplements still use `result`. / Claude `TaskCreate`／`TaskUpdate`、用户输入与协作卡片在拆分会破坏连贯交互时可以保持为原子 `content`；仅结果 supplement 仍使用 `result`。
- A Code Mode composite remains one outer `content` section; child request/result sections keep their local purposes, embedded scalar evidence badges remain display fields, and only standalone projection evidence or event-link sections use `traceability`. Outer source or run facts use `context`; declared calls remain `request` and never become execution evidence. / Code Mode composite 保持为一个外层 `content` section；子 request／result section 保留局部 purpose，内嵌标量 evidence badge 仍是显示字段，只有独立的投影证据或 event-link section 使用 `traceability`。Outer source 或运行事实使用 `context`；声明调用保持为 `request`，绝不会变成执行证据。
- An OpenCode-style database row, message part, or event cursor changes the adapter-owned locator and Raw readback, not the Detail Purpose vocabulary or canonical event envelope. / OpenCode 风格的数据库 row、message part 或 event cursor 会改变 adapter-owned locator 与 Raw 回读，而不会改变详情用途词汇表或 canonical event envelope。
- Unknown future source shapes remain Protocol/Raw. If an already admitted Logical Event includes bounded material whose semantic role cannot safely be identified, that fragment uses `fallback` and remains traceable through the event's complete Raw References. / 未知未来来源形态继续进入 Protocol／Raw。若已接纳 Logical Event 包含无法安全识别语义角色的有界材料，该 fragment 使用 `fallback`，并继续通过事件的完整 Raw References 保持可追溯。
