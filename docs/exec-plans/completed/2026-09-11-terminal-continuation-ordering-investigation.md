## Decision and correction / 决策与纠正

Source reviewed: Codex commit `624ccf794703e2d84e748fc3ef547d6191a8c0a4`, normal LocalThreadStore recorder plus direct model-tool execution. This is an audited source profile, not a claim about every Codex release, storage backend, export, or mixed execution mode. A future implementation must map supported producer versions/formats to this profile rather than assume the current Phase A coverage implies relation eligibility. / 核验来源：上述固定 Codex commit 的正常 LocalThreadStore recorder 与模型 direct-tool 执行路径。这是已核验的 source profile，不推广到所有 Codex release、存储后端、导出或混合执行模式。未来实现须明确生产版本／格式与该 profile 的对应关系，不能因 Phase A 支持某条记录就自动准入 relation。

Withdraw the earlier counterexample that an ordinary temporary rollout I/O failure can silently remove both E2 request/output while a later W request/output becomes durable through the same healthy/recovering recorder. The upper layer logs persistence failures, but that alone says nothing about the recorder's buffered items: the recorder preserves the unwritten suffix and drains it before subsequent items. / 撤回此前反例：普通暂时 rollout I/O 失败可令 E2 request／output 整组无痕消失，而后续 W request／output 仍通过同一正常／恢复中的 recorder 落盘。上层仅记录 persistence error 并不能说明 recorder 丢弃了缓冲项；recorder 保留未写后缀，并先于后续项写出。

The product trusts supported transcripts normally produced by Codex. It does not demand cryptographic proof against external deletion, replacement, or fabrication. Detected corruption, duplicates, identity conflicts, unsupported boundaries and missing records still fail closed. This is an ordered-prefix property under the supported runtime/writer behavior, not an exactly-once or power-loss durability claim. / 产品信任 Codex 正常产生的受支持 transcript，不要求以密码学方式证明外部程序从未删除、替换或伪造记录。已检测的损坏、重复、identity 冲突、不支持边界及记录缺失仍须 fail closed。这里证明的是受支持 runtime／writer 行为下的有序前缀性质，不声称 exactly-once 或断电持久性。

## Admission algorithm / 准入算法

Inputs: full physical Raw Record order in one accepted source snapshot; exact source/session and supported execution-segment membership; unique call/output pairing; existing Logical Event IDs; validated request arguments and direct-tool response headers. Never run this over timestamp-sorted Logical Events, a filtered timeline, or a browser page. / 输入：单一 accepted source snapshot 的完整物理 Raw Record 顺序、准确 source／session 与受支持 execution segment 归属、唯一 call／output 配对、既有 Logical Event ID、经校验的 request arguments 与 direct-tool response header。不得使用按 timestamp 排序的 Logical Events、过滤后的 timeline 或浏览器单页作为扫描输入。

1. **Establish the boundary.** Admit only the audited native local/direct profile. Respect known resume, inherited/fork, replacement/revert, discontinuity and unsupported storage/execution boundaries. Do not invent runtime continuity from a filename, session ID or turn ID. Segment recognition must use verified source/adapter evidence; an unrecognizable boundary is ineligible. / **确定边界。** 仅准入已核验的 native local／direct profile。遵守已知 resume、inherited／fork、replacement／revert、discontinuity 及不支持 storage／execution 边界。不从文件名、session ID 或 turn ID 捏造 runtime 连续性。Segment 识别须使用已核验的 source／adapter 证据，无法识别则不准入。
2. **Pair before associating.** Inventory supported requests and their unique outputs across the segment, keeping physical call/output positions and unresolved spans. Reject malformed/duplicate/ambiguous pairs; do not use the logical builder's first matching row as a uniqueness proof. Relevant unknown prior producers cannot be erased by simply starting a new scan at E. / **先配对再关联。** 在 segment 内盘点受支持 request 与唯一 output，保留物理位置和未解决 span。拒绝 malformed／重复／歧义配对；不能将 logical builder 的首个匹配行当作唯一性证明。不能通过从 E 重新扫描来抹去此前未知 producer。
3. **Select an origin candidate.** E must be a direct `exec_command` with a unique valid request/output; its trusted response metadata reports running N. Require `E.request < E.output < W.request < W.output`. W is a direct `write_stdin` with valid arguments and the same i32 ID N. Reject conflicting header fields. / **选择候选 origin。** E 必须是 direct `exec_command`，request／output 唯一有效，可信 response metadata 报告 running N。要求上述严格物理次序；W 必须是有效 direct `write_stdin`，参数中为相同 i32 ID N。冲突 header 字段拒绝。
4. **Exclude competing creation over the closed interval I = [E.request, W.output].** Any other `exec_command` request inside I rejects the candidate regardless of its eventual ID or success. Also reject any earlier creating request whose output is missing or whose call/output span overlaps I. Do not shorten I to W.request: a later request in W's response can execute before W and must be seen before W.output. / **在闭区间 I = [E.request, W.output] 排除竞争创建。** I 内任何其他 `exec_command` request 均否决候选，不因其最终 ID 不同或失败而放行。E 之前已发出但 output 缺失、或 call／output span 与 I 相交的创建请求也否决。I 不能止于 W.request：W 所在 response 后续 request 可能先于 W 执行，且必定出现在 W.output 前。
5. **Reject opaque execution.** Initially whitelist direct terminal requests plus understood non-tool records only. Any other tool path requires an explicit proof that it cannot create unified-exec processes; otherwise it is a barrier. Code Mode/unsupported mixed execution in I, or a prior opaque producer not proven quiescent, rejects association. Completion of an outer Code Mode tool alone is not proof that all callbacks/cells have stopped. / **拒绝不透明执行。** 首版仅放行 direct terminal requests 与已理解的非工具记录。其他工具路径必须明确证明不会创建 unified-exec process，否则作为 barrier。I 内 Code Mode／不支持混合执行，或此前未证明静止的不透明 producer 均拒绝关联；外层 Code Mode tool 返回本身不能证明所有 callback／cell 已结束。
6. **Require W access evidence.** W must have a trusted, fully recognized direct-tool response proving process access: running N, or the supported terminal-exit receipt without a conflicting running ID. Nonzero process exit still proves access, not input success. Request-only, unknown-process, rejection, write error, malformed/unsupported result or contradictory metadata yields no relation. Parse only the source formatter's header before `Output:`; command body lookalikes or arbitrary nested `session_id` do not count. / **要求 W 访问证据。** W 须有完全识别、可信的 direct-tool response，证明访问 process：running N，或受支持且不含冲突 running ID 的 terminal-exit receipt。非零 process exit 仍可证明访问，但不证明输入成功。仅 request、unknown-process、拒绝、写入错误、malformed／不支持结果或矛盾 metadata 均不关联。仅解析来源 formatter 在 `Output:` 前的 header；正文伪 header 或任意嵌套 `session_id` 不算证据。
7. **Reject lifecycle contradiction.** An earlier unambiguous terminal/unknown-process receipt for the proposed epoch invalidates later W association until a fresh E supplies a new origin. For the first implementation, overlapping same-ID write_stdin spans may conservatively reject association rather than reconstruct interaction-lock order. / **拒绝 lifecycle 矛盾。** 候选 epoch 较早的明确 terminal／unknown-process receipt 否决后续 W 关联，直到新的 E 提供新 origin。首版对重叠的同 ID write_stdin span 可保守拒绝，不重建 interaction-lock 次序。
8. **Require uniqueness and project only.** Exactly one candidate must pass all gates. Emit only `W.eventId → E.eventId` as a presentation/index relation. Keep epoch identity tied to E, never a transcript-wide numeric-ID map. Sequential W requests can each point to E; a fresh E with a reused N starts a distinct epoch without rewriting prior edges. No match or multiple matches means no suffix. / **要求唯一且只投影。** 恰好一个候选通过全部条件才输出 presentation／index relation `W.eventId → E.eventId`。Epoch identity 绑定 E，不使用 transcript-wide 数字 ID map。顺序 W 可分别指向 E；新 E 复用 N 时开启新 epoch，不改写旧 edge。零个或多个候选均不显示后缀。

Proof sketch: in this profile an E receipt follows E's process creation and precedes W dispatch. The writer cannot skip a failed queued creator and later persist W through ordinary recovery. Direct cycle ordering exposes every same-cycle creating request before W.output; the prior-span check excludes creators already in flight at E. With opaque producers/boundaries excluded, no admitted creation can replace N between E and W. W's access receipt therefore identifies the process created by E. This proves contextual association only, never successful stdin delivery or a combined execution. / 证明概要：在该 profile 内，E receipt 位于 E process 创建之后、W dispatch 之前。Writer 不能在普通恢复中跳过已入队但写失败的 creator 而随后持久化 W；direct cycle 顺序使同 cycle 创建请求均在 W.output 前可见；此前 span 检查排除 E 时已在途的 creator。再排除不透明 producer／边界后，没有被准入的创建活动可在 E 与 W 间替换 N，因此 W 的访问 receipt 对应 E 创建的 process。这里只证明上下文关联，不证明 stdin 成功送达，也不合并执行。
