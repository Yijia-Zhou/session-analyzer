# Query storage capacity evidence / 查询存储容量证据

Baseline / 基线: `6e84bb09876561ced0b060e68f3ee5da173614a5`; local Node / 本地 Node: `24.18.1`.

- Baseline reproduction: loaded the exact baseline `src/project-query-store.js` through `git show`; a synthetic one-event Main record with 4 MiB + 1 ASCII search bytes throws `PROJECT_QUERY_STORE_CONTRACT_VIOLATION: single main text row exceeds 4 MiB`. The same valid event is accepted by the adaptive store. / 基线复现：通过 `git show` 加载精确基线模块；合成的单个 Main 事件包含 4 MiB + 1 ASCII 搜索字节时，旧版本抛所列契约错误；自适应存储接受相同合法事件。
- Focused integration: `test/query-disk-capacity.test.js` covers UTF-8 frame sizes one byte below / at / above 4 MiB, three-layer oversized-event project search with stable IDs and counts, Unicode and long whitespace crossing text-read boundaries, memory-to-disk migration, unchanged filters and digests, cancellation during build/commit/query, injected `ENOSPC`, finished-store preservation and private-directory cleanup. Six tests passed including a GC-enabled run. / 聚焦集成：六个测试覆盖 UTF-8 frame 比 4 MiB 少一字节／相等／多一字节，三层超大事件的项目搜索及稳定 ID／计数，Unicode 与长空白跨文本读取边界，内存迁移到磁盘，既有筛选与摘要，构建／提交验证／查询取消，注入 ENOSPC，已完成存储保全与私有目录清理；包括启用 GC 的运行均通过。
- Matcher: `test/search-text-stream.test.js` preserves the existing plain-phrase JS case-insensitive, non-overlapping count semantics, with 500 deterministic randomized segmented comparisons against the original regex; 4 Mi-character whitespace run, Unicode/surrogate boundaries, bounded snippets and 1 MiB cancellation checkpoints are covered. Snippets normalize whitespace before taking context; event occurrence count remains `max(preview, searchText)` and preview takes snippet priority. / 匹配器：保留既有普通短语的 JS 不区分大小写、非重叠计数语义，500 次确定性随机分段与原 regex 对照；覆盖 4 Mi 字符空白 run、Unicode／代理项边界、有界摘要及 1 MiB 取消检查。摘要先折叠空白再截取上下文；事件出现计数仍为两个文本域最大值，摘要优先 preview。
- Reproducible isolated tool: `node scripts/query-capacity-profile.js --rows=<rows> --text-bytes=<ASCII search bytes per row> --batch-rows=3000`. It builds bounded batches, verifies the committed projection, scans all layers cold/warm, measures cancellation and cleanup, and reports sampled RSS/heap/external memory, disk bytes and process maximum RSS. These are synthetic reader/store observations, not source parser or UI benchmarks. / 可复现独立工具：按所列命令运行；有界批次构建后验证已提交投影，冷／暖扫描全部层，测量取消和清理，并报告采样 RSS／堆／external、磁盘字节及进程最高 RSS。这是合成 reader／store 观察，不是来源解析或 UI benchmark。
- Ordinary sample, 3,000 rows × 64 search bytes: schema 2, encoded 557,868 bytes, build 48 ms, verify 30 ms, cold 6.5 ms, warm 4.9 ms, cancellation 2.1 ms; sampled RSS 68,210,688 bytes and heap 13,482,920 bytes; no remaining temporary directories. / 普通样本：3,000 行、每行 64 搜索字节，schema 2、编码 557,868 字节，构建 48 ms、验证 30 ms、冷 6.5 ms、暖 4.9 ms、取消 2.1 ms；采样 RSS 68,210,688 字节、堆 13,482,920 字节，无临时目录遗留。
- First 5,000,001-row experiment failed after build and commit verification, before the first cold query: disk-manifest reserialization was not stable across V8 internal value representations. This was a new implementation regression, not a source-change or user-capacity failure. The manifest now hashes stable JSON chunks; a regression mutates internal number/string representations without changing values, forces GC when available, and verifies/searches successfully. A separate review found repeated full manifest hashing on every shard scan would cost O(session-count²); the query validation cache was corrected before the scale rerun. / 首次 5,000,001 行实验在构建与提交验证后、首次冷查询前失败：磁盘 manifest 的重序列化受 V8 内部值表示影响而不稳定。这是新实现回归，不是来源变化或用户容量错误。现改用稳定 JSON 分块哈希；回归测试改变数字／字符串内部表示但保持值不变，在可用时强制 GC，验证与查询均成功。另查出每次 shard 扫描重算全部 manifest 会造成 O(会话数²)；已在规模重跑前修正查询验证缓存。

“Cold” here means the first query invocation after build/verification; the OS file cache is not flushed, so these are not cold-disk latency claims. / 此处“冷”指构建／验证后的首次查询调用；没有清空操作系统文件缓存，因此不宣称是冷磁盘延迟。

This is direct evidence beyond the old total-row bound, not an 8-GiB claim. / 修复后独立 5,000,001 行重跑通过构建、完整投影验证、冷／暖全文扫描、取消与清理。每次扫描在 Main／Protocol／Raw 累计精确访问并命中 5,000,001 行。来源搜索文本总计 320,000,064 字节，编码及实际磁盘均为 2,786,493,028 字节。构建 158,746 ms、验证 125,344 ms、冷查询 87,217 ms、暖查询 86,768 ms、取消 12.2 ms。采样 RSS 381,341,696 字节、堆 210,293,256 字节、external 24,189,618 字节、进程最高 RSS 374,524 KiB；临时目录遗留为零。这是越过旧总行数上限的直接证据，不宣称 8 GiB 验证。

This is a resource-exhaustion/cleanup observation, not a successful 8-GiB test. The rerun uses `--temp-root=G:\vibe\session-analyzer` on the workspace drive with 215.9 GB free. / 首次超过 8 GiB 文本实验写入时真实触发 `ENOSPC`，准确呈现为 `PROJECT_QUERY_STORAGE_RESOURCE_EXHAUSTED` 并清理全部实验目录。`os.tmpdir()` 实际位于 D 盘，清理后仅有 8.20 GB 空间；C 盘的 36.7 GB 空间不适用于该路径。这是资源耗尽／清理观察，不是 8 GiB 成功验证。重跑通过所列 temp-root 参数使用具有 215.9 GB 可用空间的工作区 G 盘。

These runs demonstrate bounded query-storage working sets at the tested scales, with exact counts and cleanup; they do not assert unlimited capacity or set timing gates from single samples.
