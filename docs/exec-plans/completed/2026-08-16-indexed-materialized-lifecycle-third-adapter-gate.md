## Objective / 目标

Close the remaining architecture gates before a third strict source adapter begins production work: make the bounded request-time materialization boundary declarative and source-neutral, prove exact ProjectQueryStore-to-Materialized projection parity, reduce Claude request-time dependencies to inputs that reconstruct the selected body, avoid full text hydration for metadata-only project filters, and make final projection admission cancellable and exception-safe. Preserve the accepted Codex/Claude lifecycle, revision owner, Detail/Raw responsibilities, source freshness, and no-eviction stop point. / 在第三个 strict 来源 adapter 开始 production 工作前关闭剩余架构门槛：把 request-time 有界物化边界变为声明式且来源中立；证明 ProjectQueryStore 到 Materialized projection 的精确等价；把 Claude request-time dependency 缩小为重建所选 body 的输入；避免 metadata-only 项目过滤完整 hydration 文本；并让最终 projection admission 可取消且异常安全。保持已接受的 Codex／Claude 生命周期、revision owner、Detail／Raw 职责、来源 freshness 与 no-eviction 停点。

## Accepted findings / 已接受 finding

1. The repository-owned Codex/Claude function-identity whitelist makes a future strict adapter fall back to repeated whole-Index fingerprints. Replace it with a closed descriptor declaration for bounded string context fields; every strict adapter receives only source ownership, repository root, declared context, the selected Indexed Session, and its selected DependencySet. / 仓库拥有的 Codex／Claude function-identity 白名单会使未来 strict adapter 回退到反复执行整 Index fingerprint。以 descriptor 中封闭的有界 string context field 声明替代；每个 strict adapter 只接收来源 ownership、repository root、已声明 context、所选 Indexed Session 与其所选 DependencySet。
2. Claude currently copies same-container siblings and directory/sidecar relationship evidence into every Session dependency closure. Request-time dependency sets must contain only files actually read to reconstruct that Session body; relationship, sidecar, and tree evidence remains authoritative at reindex time and copied relationship facts remain authoritative for the old revision. / Claude 当前把同 container sibling 与 directory／sidecar 关系证据复制到每个 Session dependency closure。Request-time dependency set 只包含实际用于重建该 Session body 的文件；关系、sidecar 与 tree 证据继续由 reindex-time snapshot 管理，旧 revision 继续以 copied relationship fact 为权威。
3. Counts alone do not close ProjectQueryStore-to-Materialized identity. Add one canonical digest over ordered query rows and fail materialization before cache commit when IDs, ordinals, structured facts, files, presentation facts, preview, or search text drift. / 仅靠 count 无法关闭 ProjectQueryStore 到 Materialized identity。对有序 query row 增加一个 canonical digest；当 ID、ordinal、结构化 fact、file、presentation fact、preview 或 search text 漂移时，在 cache commit 前让物化失败。
4. Metadata-only project filters should scan packed metadata first and hydrate only the latest matching preview per matching Session; they must not decode search text. / 仅 metadata 的项目过滤应先扫描 packed metadata，并且每个匹配 Session 只 hydration 最新匹配 preview；不得解码 search text。
5. Final ProjectQueryStore commit verification and Materialized query-projection verification must yield between bounded chunks, observe the active `AbortSignal`, and perform one final abort check before Index or cache admission. A cancellation queued while synchronous structural validation is running may wait for the next event-loop handoff, but it must still prevent admission. / 最终 ProjectQueryStore commit verification 与 Materialized query-projection verification 必须在有界 chunk 之间让出 event loop、观测 active `AbortSignal`，并在 Index 或 cache admission 前执行最后一次 abort 检查。在同步结构校验运行期间排队的取消可以等到下一次 event-loop handoff，但仍必须阻止 admission。
6. Fingerprint capture and recheck failures are adapter contract failures, including revoked Proxy or other unverifiable graphs. They must surface as `MATERIALIZATION_CONTRACT_VIOLATION`; mutation remains dominant over a simultaneous adapter rejection and retains that rejection as the cause. / Fingerprint capture 与 recheck 失败属于 adapter contract failure，包括 revoked Proxy 或其它不可验证 graph。它们必须以 `MATERIALIZATION_CONTRACT_VIOLATION` 暴露；mutation 与 adapter rejection 同时发生时仍由 mutation 优先，并保留 rejection 作为 cause。
