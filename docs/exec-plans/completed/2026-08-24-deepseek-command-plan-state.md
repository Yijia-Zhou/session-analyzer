## Delivered behavior / 已交付行为

1. One structurally valid child-owned `command/run` and exactly one valid later `command/done` form one Protocol lifecycle only when their non-empty `commandId` is globally unique among command endpoints. Duplicate, partial, malformed, reversed, or inherited-crossing evidence stays row-level generic Protocol/Raw. / 一个结构有效的 child-owned `command/run` 与恰好一个有效且更晚的 `command/done`，只有在非空 `commandId` 对全部 command 端点均唯一时才形成一条 Protocol lifecycle。重复、不完整、畸形、反序或跨 inherited 边界的证据保持逐 row generic Protocol／Raw。
2. The lifecycle owns exactly its run/done Raw rows and exposes command name, exact recorded args, source kind, settlement/result, endpoint seqs, and optional source-backed `sourceEventSeq`. It is labeled as DSH UI/application control rather than model tool work and adds zero Main activity. / Lifecycle 恰好拥有自身 run／done Raw row，并暴露 command 名称、精确记录的 args、source kind、settlement／result、端点 seq 及可选来源支撑的 `sourceEventSeq`。它明确呈现为 DSH UI／application control，而非模型工具工作，并且 Main 影响为零。
3. Every exact child-owned `plan/mode { active: boolean }` row remains one independently owned Protocol state boundary with one Raw row and structured enabled/disabled Detail. It creates no canonical plan event, artifact, counter, or Session field. / 每条精确 child-owned `plan/mode { active: boolean }` row 保持为独立 ownership 的 Protocol 状态边界，拥有一条 Raw row 与结构化 enabled／disabled Detail。不创建 canonical plan event、artifact、counter 或 Session 字段。
4. No command-to-plan metadata, Raw transfer, or `event_refs` is created. Immediate Batch A adjacency, queued/non-adjacent synthetic shape, disagreeing args/state, command name, timing, and optional `sourceEventSeq` remain independent facts. / 不创建 command-to-plan metadata、Raw 转移或 `event_refs`。Batch A immediate adjacency、合成 queued／non-adjacent shape、相互不一致的 args／state、command 名称、时间及可选 `sourceEventSeq` 均保持独立事实。

## Architecture conclusion / 架构结论

`commandId` is sufficient durable identity for a strict unique and causal DSH command pair, but not for a domain transition. Command lifecycle is Protocol application control rather than Main model activity. `plan/mode` is durable source state rather than a Main plan artifact. Batch A adjacency demonstrates only the between-turn immediate-commit writer path; current upstream also permits a later accepted pre-step commit for an open turn. Current evidence therefore justifies neither command-to-plan provenance nor shared/canonical expansion. / `commandId` 足以作为严格、唯一且具因果顺序的 DSH command pair 持久 identity，但不足以证明领域 transition。Command lifecycle 是 Protocol application control，而非 Main 模型活动。`plan/mode` 是持久来源状态，而非 Main plan artifact。Batch A adjacency 只展示 between-turn immediate-commit writer path；当前上游也允许 open turn 的较晚 accepted pre-step commit。因此当前证据既不支持 command-to-plan provenance，也不支持 shared／canonical 扩张。
