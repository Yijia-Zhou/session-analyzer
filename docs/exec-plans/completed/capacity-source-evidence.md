## Group 7 — solved old boundary, runtime JSON memory remains / 第七组：旧边界已解决，仍受运行时 JSON 内存约束

Plain first lines now read progressively through newline. Zstd discovery scans exactly one frame with fixed headers and at most 64 KiB payload reads, feeding a backpressured decoder. It no longer repeatedly concatenates/scans the compressed prefix and no longer conflates 4 MiB compressed bytes with complete-header availability. UTF-8 uses `StringDecoder`; decoded text joins once for `JSON.parse`. / 普通首行渐进读至换行；Zstd discovery 用固定帧头和至多 64 KiB payload 读取精确扫描首帧，向解码器按背压供给，不再反复拼接／扫描压缩前缀，也不把 4 MiB 压缩字节预算与头部是否完整混淆。UTF-8 使用 `StringDecoder`；解码文本只在 `JSON.parse` 前拼接一次。

Artifact diagnostics distinguish `DEEPSEEK_STORAGE_EMPTY`, `DEEPSEEK_HEADER_UNCOMMITTED`, `DEEPSEEK_STORAGE_INVALID`, unsupported format, and `DEEPSEEK_HEADER_RESOURCE_EXHAUSTED`. The remaining limit is Node's `buffer.constants.MAX_STRING_LENGTH` **UTF-16 code units of decoded JSON**, scoped to one header, with a small injectable test seam. Cancellable reads close handles; resource errors isolate that artifact and keep healthy neighbors. Retrying after committing the header or with sufficient resources is supported. Full JSON parsing and full-artifact materialization still need source-sized memory; this work does not claim streaming every DeepSeek record or recovery from a process-fatal V8 OOM. / 工件诊断分别表示空文件、未提交首记录、损坏、不支持格式及头部资源耗尽。剩余限制是 Node 运行时单个解码 JSON 字符串的 `MAX_STRING_LENGTH`（UTF-16 code unit），测试可注入小阈值；可取消读取关闭句柄，资源失败仅隔离该工件、保留健康邻居。头部提交或资源足够后可重试。完整 JSON 解析和完整工件物化仍需与来源大小相关的内存；本改动不声称所有 DeepSeek 记录流式处理，也不保证从 V8 进程级 OOM 恢复。

Regression evidence: real plain and raw-block Zstd headers exceeding 4 MiB, with valid v0 opaque extension data, pass discovery and indexing. Plain 4 MiB−1 / exact / +1, split UTF-8, independently compressed/decoded sizes, empty/torn/corrupt, cancellation during I/O, handle closure and healthy-artifact isolation are covered. / 回归使用合法 v0 扩展字段使普通及 raw-block Zstd 首记录真实超过 4 MiB，通过发现与索引；覆盖普通旧边界前／等于／后、跨块 UTF-8、压缩／解压独立单位、空／未提交／损坏、I/O 中取消、句柄关闭与健康工件隔离。
