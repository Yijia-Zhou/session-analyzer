# Timeline transition safety and profiling / 时间线转换安全与性能基线

## Goal-ready objective / 可直接用于 `/goal` 的目标

Make long-transcript timeline context transitions intentional, cancellable, and measurable before changing the renderer architecture. Freeze the 1,800-event reproduction in a repeatable profiling harness; prevent residual scroll state from silently appending pages after query/filter/Session/Layer transitions; add explicit request ownership and cancellation while retaining request-generation and context guards; and preserve current search counts, canonical targets, paging, folding, detail provenance, project drill-down, and user-scroll behavior. This plan is complete only when deterministic browser tests prove that no transition performs pagination without a qualifying user or navigation intent, intentional aborts cannot commit or surface as errors, all affected pending/loading states settle, and before/after profiling evidence is recorded. / 在改变 renderer 架构前，让长转录时间线 context 转换变得有意图、可取消、可测量。把 1,800 事件复现固化为可重复的 profiling harness；防止残留滚动状态在 query、筛选、会话或事件层转换后静默追加分页；增加显式请求 ownership 与取消，同时保留请求 generation 和 context guard；并保持当前搜索计数、canonical target、分页、折叠、详情来源、项目下钻与用户滚动行为。只有确定性浏览器测试证明任何转换都不会在缺少合格用户或导航意图时分页、intentional abort 无法提交或显示为错误、所有受影响 pending/loading 状态都能收束，并记录前后 profiling 证据时，本计划才算完成。

## Confirmed baseline / 已确认基线

The 2026-07-17 Chromium profile used a temporary synthetic Session Transcript with 1,800 Main Timeline Logical Events, about 3.7 KiB of searchable text per event, and a hit near event 1,650. It reproduced main-thread starvation rather than a permanent deadlock: / 2026-07-17 Chromium profile 使用临时合成会话转录，其中包含 1,800 个主时间线逻辑事件、每个事件约 3.7 KiB 可搜索文本，并在约第 1,650 个事件处放置命中。它复现的是主线程饥饿，而不是永久死锁：

| Interaction / 交互 | End-to-end / 端到端 | Main thread / 主线程 | Timeline network / 时间线网络 |
| --- | ---: | ---: | ---: |
| Search and bounded preload to 600 events / 搜索并有限预加载到 600 个事件 | 1.73 s | 1.45 s Long Tasks | Not dominant / 非主因 |
| Jump to the hit near event 1,650 / 跳到约第 1,650 个事件处的命中 | 8.22 s | 8.17 s Long Tasks | Eight requests total about 0.33 s / 8 次请求合计约 0.33 s |
| Edit query and immediately switch Session / 修改 query 后立即切换会话 | 6.30 s | 5.52 s main task / 主任务 5.52 s | Five requests total about 0.71 s / 5 次请求合计约 0.71 s |
| Change a filter from a deep position with a common term / 深位置下以常见词改变筛选 | 12.35 s | 12.23 s Long Tasks | Two measured requests about 0.21 s / 两次已测请求约 0.21 s |

The filter case exposed one deterministic multiplier: structural refresh calls `loadTimeline(false, { keepScroll: true })`; after the deep prefix is replaced by page zero, the old `scrollTop` can be clamped near the new bottom, causing the ordinary bottom-pagination handler to request `offset=150` without new user scroll input. / 筛选场景暴露了一个确定性放大器：结构化刷新调用 `loadTimeline(false, { keepScroll: true })`；深层前缀被第零页替换后，旧 `scrollTop` 可能被 clamp 到新内容底部附近，使普通底部分页 handler 在没有新用户滚动输入时请求 `offset=150`。

Request IDs and context keys already prevent many obsolete responses from committing. They do not cancel fetch, response decoding, synchronous server scans, or browser work already queued before the stale check. / 请求 ID 与 context key 已经能阻止许多过期响应提交，但不会取消 fetch、响应解码、同步服务端扫描，或 stale check 前已经排队的浏览器工作。

## Fixed behavior decisions / 固定行为决策

1. Current-session free text remains a find aid. Query-only edits and clearing only free text retain the already materialized prefix instead of returning to page zero. / 当前会话自由文本继续作为查找辅助。只修改 query 或只清除自由文本时，保留已物化前缀，不返回第零页。
2. A Session switch resets the new Session to its first page and normal top position. No state from the preceding Session authorizes pagination. / 切换会话时，新会话重置为第一页和正常顶部位置。前一会话的任何状态都不能授权分页。
3. Programmatic search navigation remains unable to trigger ordinary auto-pagination. Search navigation itself explicitly decides when to load a page. / 程序化搜索导航继续不能触发普通自动分页；是否加载分页由搜索导航本身显式决定。
4. Real downward wheel, touch/pointer scroll movement proved by a positive timeline `scrollTop` delta, unmodified downward scrolling-key input, explicit Load more, and explicit search or selected-event navigation remain qualifying intents and can load required pages. Input alone is only a short candidate; reverse or zero movement and inappropriate modifiers cannot load a page. / 真实向下 wheel、由时间线 `scrollTop` 正向 delta 证明的 touch/pointer 滚动、未带修饰键的向下滚动键输入、显式加载更多，以及显式搜索或所选事件导航继续属于合格意图，可以加载所需分页。输入本身只是短暂候选；反向或零移动及不适用修饰键不能加载分页。
5. Layer switches, `Read from here`, project-result drill-down, and focus restoration keep their existing explicit anchor-loading behavior. Their deliberate calls may materialize a deep prefix; a residual scroll event may not add another page. / 事件层切换、“从此处阅读”、项目结果下钻与焦点恢复保持既有显式锚点加载行为。它们的有意调用可以物化深层前缀；残留滚动事件不得再增加分页。
6. A structured-filter replacement may not silently append a page. The exact post-filter viewport policy must pass the Phase 1 checkpoint before implementation; the default is to preserve an already selected event only when it is present in the newly committed page, otherwise reset to a deterministic top position rather than deep-load solely for scroll preservation. / 结构化筛选替换不得静默追加分页。精确的筛选后视口策略必须在实现前通过第一阶段 checkpoint；默认方案是只在已选事件存在于新提交分页时保留它，否则回到确定性顶部位置，而不是仅为保持滚动而深层加载。
7. Exact structural totals, matching-event totals, occurrence totals, result order, and project aggregates do not change. Initial `loaded` and discovered-target counts may remain smaller because accidental pages are no longer materialized. / 精确结构总数、命中事件总数、occurrence 总数、结果顺序与项目聚合不变。由于不再物化意外分页，初始 `loaded` 与已发现 target 数可以保持更小。
8. An intentional abort is control flow, not an error and not a zero-result commit. It produces no error toast, cannot clear a newer result, and must release the owning loading/pending state. / Intentional abort 属于控制流，不是错误，也不是零结果提交。它不产生错误 toast，不能清空更新的结果，并且必须释放所属 loading/pending 状态。
9. Request generation and context keys remain mandatory even after cancellation. Cancellation reduces wasted work; it does not replace stale-response correctness checks. / 即使增加取消，请求 generation 与 context key 仍然必需。取消用于减少浪费工作，不能取代过期响应正确性检查。
10. Profiling instrumentation is opt-in or test-observable and adds no normal product panel, persistent transcript data, or user tracking. / Profiling instrumentation 为 opt-in 或测试可观察，不增加普通产品面板、持久转录数据或用户跟踪。

## Non-negotiable invariants / 不可妥协的不变量

### Timeline and paging / 时间线与分页

- A committed normal timeline remains an ordered, duplicate-free contiguous prefix for this plan: `offset === currentEvents.length <= timelineTotal`. / 本计划中已提交普通时间线继续是有序、无重复的连续前缀：`offset === currentEvents.length <= timelineTotal`。
- Only a qualifying intent captured for the current timeline context may start an append. A scroll position or scroll event inherited from a replaced context is not intent. / 只有为当前时间线 context 捕获的合格意图才能启动追加。继承自被替换 context 的滚动位置或滚动事件不属于意图。
- A user-input candidate becomes eligible only after a subsequent positive timeline `scrollTop` movement in the same sequence. Reverse or zero movement revokes or cannot consume it; a current-context page-zero replacement failure instead exposes an explicit offset-zero retry and never masquerades as an append. / 用户输入候选只有在同一序列中随后出现时间线 `scrollTop` 正向移动后才具备资格。反向或零移动会撤销它或不能消费它；当前 context 的第零页替换失败则显示明确的 offset-zero 重试，绝不伪装成追加。
- One intent cannot start the same page twice. Existing append serialization and target-navigation serialization remain intact. / 一个意图不能启动同一分页两次。既有追加串行化与 target 导航串行化保持不变。
- The explicit Load more button and genuine bottom scrolling continue to function when more events exist. / 存在更多事件时，显式加载更多按钮与真实底部滚动继续正常。

### Search and detail / 搜索与详情

- Canonical target identity remains `[completeSemanticSearchKey, logicalEventId]`; DOM marks stay disposable bindings. / Canonical target identity 继续保持 `[完整语义搜索 key, 逻辑事件 ID]`；DOM mark 继续是可丢弃 binding。
- Query-only refresh preserves loaded depth, target ordering, selected-event behavior, and user-confirmed Inspector/Raw Reference provenance. / Query-only 刷新保持已加载深度、target 顺序、所选事件行为，以及用户确认的检查器/原始引用来源。
- Manual folds remain authoritative; search-transient expansion remains non-persistent. / 手动折叠保持权威；搜索临时展开继续不持久化。
- Aborted detail requests cannot populate cache, error state, or a new detail surface after their owner context is obsolete. A still-needed same-key detail request remains deduplicated or is deliberately restarted. / 已取消详情请求在 owner context 过期后不能填充 cache、错误状态或新详情 surface。仍需要的同 key 详情请求继续去重，或被有意重启。

### Concurrency and UI settlement / 并发与 UI 收束

- Every request owner has exactly one current controller or a documented per-key controller map. Starting a superseding request aborts only work owned by the superseded intent. / 每个请求 owner 恰有一个当前 controller，或使用有文档说明的逐 key controller map。启动取代请求时，只取消由被取代意图拥有的工作。
- Abort cleanup is identity-safe: an old request's `finally` cannot clear the loading state or controller belonging to a newer request. / Abort cleanup 必须 identity-safe：旧请求的 `finally` 不能清除新请求所属的 loading 状态或 controller。
- Intentional aborts are filtered by type rather than message text and never enter the ordinary `showError` path. / Intentional abort 按类型过滤，而不是按 message 文本过滤，并且绝不进入普通 `showError` 路径。
- Latest-intent pending, disabled, and searching UI eventually settles after success, error, abort, or immediate retry. / Latest-intent 的 pending、disabled 与 searching UI 在成功、错误、abort 或立即重试后最终都能收束。
- Synchronous server computation may finish even after the client disconnects. This plan does not claim server CPU preemption; its guarantee is browser ownership, no stale commit, and no obsolete response/render work. / 即使客户端断开，同步服务端计算仍可能完成。本计划不声称能抢占服务端 CPU；其保证是浏览器 ownership、无过期提交，以及无过期响应/render 工作。

## Execution phases / 执行阶段

### Phase 0: profiling harness and observability / 第零阶段：Profiling harness 与可观察性

- Extract or extend a deterministic synthetic transcript helper with configurable event count, searchable text size, hit positions, common-term density, and detail-heavy events. Do not commit real Session Transcripts. / 提取或扩展确定性合成转录 helper，可配置事件数、可搜索文本大小、命中位置、常见词密度与详情密集事件。不得提交真实会话转录。
- Add an opt-in command, preferably `npm run profile:timeline`, that starts an isolated server, drives Chromium through the baseline interactions, gathers CDP/PerformanceObserver Long Tasks and Resource Timing, and cleans up generated data and processes. / 增加 opt-in 命令，优先使用 `npm run profile:timeline`；它启动隔离 server、驱动 Chromium 执行基线交互、采集 CDP/PerformanceObserver Long Task 与 Resource Timing，并清理生成数据和进程。
- Record deterministic counters for timeline API requests by context/offset/limit, full `renderTimeline` calls, card generations, highlighted owners and marks, mounted DOM nodes, and detail requests. Timing stays diagnostic; deterministic counters are suitable for regression assertions. / 记录按 context/offset/limit 统计的时间线 API 请求数、完整 `renderTimeline` 调用、卡片生成、高亮 owner 与 mark、已挂载 DOM 节点和详情请求。时长作为诊断；确定性计数适合回归断言。
- Store concise summary output only. Raw traces remain temporary unless an implementation investigation explicitly needs them. / 只保存简洁摘要输出。Raw trace 保持临时，除非实现调查明确需要。
- Re-run the current baseline before runtime changes and record environment, fixture parameters, and results in the progress log. / 在运行时改动前重新运行当前基线，并在进度日志记录环境、fixture 参数与结果。

### Phase 1: transition-intent and anchor checkpoint / 第一阶段：转换意图与锚点 checkpoint

- Enumerate every source of timeline scrolling and pagination: pane scroll, wheel, touch, pointer, keyboard, explicit Load more, search target preload/navigation, selected-event navigation, focus restoration, project drill-down, Session replacement, Layer replacement, query refresh, and structured refresh. / 枚举所有时间线滚动与分页来源：pane scroll、wheel、touch、pointer、keyboard、显式加载更多、搜索 target 预加载/导航、所选事件导航、焦点恢复、项目下钻、会话替换、事件层替换、query 刷新与结构化刷新。
- Define a small state machine or monotonic epoch for replacement, programmatic scroll, user takeover, and pagination authorization. It must distinguish current-context intent from residual events without relying only on elapsed time. / 为替换、程序化滚动、用户接管与分页授权定义小型状态机或单调 epoch。它必须区分当前 context 意图与残留事件，不能只依赖经过时间。
- Freeze the structured-filter viewport behavior in a browser test before implementing the guard. Default: exact selected event only if present in the newly committed page; otherwise deterministic top. If repository evidence requires another policy, update this plan and bilingual product/design docs before coding it. / 在实现 guard 前，用浏览器测试冻结结构化筛选后的视口行为。默认：只有精确所选事件存在于新提交分页时才保留，否则回到确定性顶部。如果仓库证据要求其它策略，应先更新本计划与双语产品/设计文档，再编码。
- Preserve existing explicit Layer/`Read from here` focus restoration and prove that the residual-scroll guard does not suppress their deliberate page loads. / 保留既有显式事件层/“从此处阅读”焦点恢复，并证明残留滚动 guard 不会抑制其有意分页加载。

### Phase 2: request cancellation ownership / 第二阶段：请求取消 ownership

- Extend `api()` to accept and preserve `AbortSignal`, and add a narrow intentional-abort classifier. Do not infer abort from localized or browser-dependent message text. / 扩展 `api()` 以接收并保留 `AbortSignal`，并增加窄化 intentional-abort classifier。不得通过本地化或浏览器相关 message 文本推断 abort。
- Introduce controller ownership according to the matrix, retaining existing request IDs and context comparisons. / 按 ownership 矩阵引入 controller，同时保留既有请求 ID 与 context 比较。
- Make all success, failure, abort, and `finally` mutations conditional on current owner identity. / 让所有成功、失败、abort 与 `finally` 状态修改都以当前 owner identity 为条件。
- Ensure an aborted append, preload, navigation scan, detail, or project result does not leave serialized queues, `timelineLoading`, target preload pending, navigation pending, disabled controls, or Searching UI stuck. / 确保被取消的追加、预加载、导航扫描、详情或项目结果不会让串行队列、`timelineLoading`、target preload pending、navigation pending、disabled 控件或“搜索中”UI 卡住。
- Preserve retry behavior after real errors and after intentional abort. / 保留真实错误与 intentional abort 之后的重试行为。

## Acceptance criteria / 验收标准

1. The profiling command reproduces all four baseline interactions from deterministic temporary data, cleans up after itself, and records comparable environment and metric summaries. / Profiling 命令从确定性临时数据复现四个基线交互、自动清理，并记录可比较的环境与指标摘要。
2. A structural refresh from a deep position produces no ordinary append request until a new qualifying intent occurs. / 深位置结构化刷新在出现新的合格意图前，不产生普通追加请求。
3. Genuine bottom scrolling, explicit Load more, search navigation, selected-event navigation, project drill-down, Layer focus restoration, and `Read from here` retain their required loading behavior. / 真实底部滚动、显式加载更多、搜索导航、所选事件导航、项目下钻、事件层焦点恢复与“从此处阅读”保持所需加载行为。
4. Query-only changes and clearing only query preserve the already loaded timeline range. / 只修改 query 或只清除 query 时，保留已加载时间线范围。
5. Every implemented request owner aborts superseded work, retains stale-generation/context guards, and settles current loading/pending state on success, real error, abort, and retry. / 每个已实现请求 owner 都会取消被取代工作、保留过期 generation/context guard，并在成功、真实错误、abort 与重试时收束当前 loading/pending 状态。
6. Intentional aborts do not show error UI, commit zero results, mutate canonical targets, populate obsolete caches, or clear newer state. / Intentional abort 不显示错误 UI、不提交零结果、不修改 canonical target、不填充过期 cache，也不清除更新状态。
7. Exact result counts, event order, canonical target identity, user-confirmed detail provenance, manual folds, and Raw Reference evidence remain unchanged. / 精确结果计数、事件顺序、canonical target identity、用户确认详情来源、手动折叠与原始引用证据保持不变。
8. The filter pressure reproduction no longer contains the extra residual `offset=150` request or its resulting extra full render/highlight pass. / 筛选压力复现不再包含额外残留 `offset=150` 请求，也不再包含由此产生的额外完整 render/highlight pass。
9. Profiling evidence honestly records the remaining full-render and full-highlight cost as input to the next active plan. / Profiling 证据如实记录仍存在的完整 render 与完整高亮成本，作为下一份 active plan 的输入。
10. English and Simplified Chinese product/design/plan text remain aligned for every accepted visible behavior. / 每项已接受可见行为的英文与简体中文产品/设计/计划文本保持一致。

## Risks and prohibited shortcuts / 风险与禁止捷径

- **Prohibited:** disable bottom auto-pagination globally or require the Load more button for every page. / **禁止：**全局禁用底部自动分页，或要求每个分页都必须点击加载更多按钮。
- **Prohibited:** reset every query/filter/Layer transition to the top merely to avoid scroll events. / **禁止：**仅为避免滚动事件而把每次 query/筛选/事件层转换都重置到顶部。
- **Prohibited:** treat any scroll event after replacement as user intent. Residual and programmatic scroll must remain distinguishable from real takeover input. / **禁止：**把替换后的任意 scroll event 当作用户意图。残留和程序化滚动必须继续可与真实接管输入区分。
- **Prohibited:** remove request IDs or context checks after adding AbortController. / **禁止：**增加 AbortController 后移除请求 ID 或 context check。
- **Prohibited:** swallow real network, HTTP, parsing, or server errors as if they were aborts. / **禁止：**把真实网络、HTTP、解析或服务端错误当作 abort 吞掉。
- **Prohibited:** introduce timing assertions into the default CI suite as the only performance regression evidence. / **禁止：**把时长断言作为默认 CI suite 中唯一的性能回归证据。
- **Prohibited:** claim that client abort stops synchronous `getTimeline` server scans. / **禁止：**声称客户端 abort 会停止同步 `getTimeline` 服务端扫描。
- **Prohibited:** begin incremental rendering, virtualization, cursor, cache, or count-semantics work under this plan to make the profile look better. / **禁止：**为了让 profile 看起来更好而在本计划中开始增量渲染、虚拟化、cursor、cache 或计数语义工作。
- **Risk:** an over-broad controller can cancel same-context work still needed by another consumer, especially per-event detail and search navigation. Keep ownership narrow. / **风险：**过宽 controller 可能取消同 context 中其它消费者仍需要的工作，尤其是逐事件详情与搜索导航。应保持 ownership 收窄。
- **Risk:** guarding only the scroll handler may miss a queued animation-frame pagination check. The epoch/intent check must occur at the final append authorization point. / **风险：**只 guard scroll handler 可能漏掉已排队的 animation-frame 分页检查。Epoch/intent check 必须位于最终追加授权点。
- **Risk:** anchor restoration can itself load a deep prefix and recreate the measured freeze. This plan preserves already-required explicit restoration but does not add new deep restoration for structured filters by default. / **风险：**锚点恢复本身可能加载深层前缀并重新造成已测卡顿。本计划保留既有必需显式恢复，但默认不为结构化筛选新增深层恢复。
