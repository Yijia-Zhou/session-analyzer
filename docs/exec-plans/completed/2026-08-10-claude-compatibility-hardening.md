## Stable contracts / 稳定契约

1. Preserve every admitted source record in Raw and preserve every Logical Event's complete relevant Raw References. Unknown, malformed, ambiguous, or unmodeled material remains visible through Protocol and/or Raw rather than being dropped or guessed. / 在 Raw 中保留每条已接纳的来源记录，并保留每个 Logical Event 的完整相关 Raw References。未知、畸形、有歧义或尚未建模的材料继续通过 Protocol 和／或 Raw 可见，不得丢弃或猜测。
2. Preserve normal Claude subagent Analyzer identities and relationship semantics. New derived relationship kinds use collision-safe, component-encoded identities with an explicit kind component; they must not reinterpret existing `:agent:` identities. / 保留普通 Claude subagent 的 Analyzer identity 与关系语义。新的派生关系种类使用 collision-safe、按组件编码并带显式 kind component 的 identity；不得重新解释现有 `:agent:` identity。
3. Relationship and lifecycle inference fails closed on missing, duplicated, stale, contradictory, escaped, reused, or ambiguous evidence. Human-readable assistant prose is never authority when source facts exist. / 当证据缺失、重复、过期、矛盾、逃逸、复用或有歧义时，关系与生命周期推断保持 fail closed。存在来源事实时，人类可读的 assistant prose 绝不作为权威。
4. Discovery remains layout-aware. Do not replace explicit primary, normal-subagent, forked-skill, and workflow-agent layout rules with recursive JSONL discovery. Lexical and physical real-path containment are required before reads and Raw readback. / 发现流程继续感知布局。不得用递归 JSONL 发现替代显式的 primary、普通 subagent、forked-skill 与 workflow-agent 布局规则。读取及 Raw readback 前必须同时满足词法与物理 real-path containment。
5. Incremental reuse depends on every transcript, sidecar, marker, journal, and relationship input that can change an accepted session or relationship. Counts, totals, progress, identity resolution, hierarchy, search, detail, and Raw APIs must agree after cold and reused indexing. / 增量复用必须依赖所有可能改变已接纳 session 或关系的 transcript、sidecar、marker、journal 与关系输入。冷索引与复用索引后的计数、总量、进度、identity resolution、层级、搜索、详情与 Raw API 必须一致。
6. Machine identifiers and schema keys remain stable and unlocalized. Bilingual documentation changes English and Chinese together only when the corresponding contract changes. / 机器标识与 schema key 保持稳定且不本地化。只有对应 contract 实际改变时才更新双语文档，并在同一次变更中同步英文与中文。

## Milestone 1 — semantic lifecycle correctness / 里程碑 1——语义生命周期正确性

### Evidence and fixtures / 证据与 fixture

- Add minimal sanitized fixtures for valid `/loop` and `/simplify` envelopes with observed tag order variants; malformed, duplicate-tag, mixed ordinary-text, and unrelated XML-like negatives; successful and failed Workflow terminal facts; and duplicate, mismatched, contradictory, or otherwise ambiguous notifications. / 为以下情况添加最小脱敏 fixture：采用已观察 tag 顺序变体的有效 `/loop` 与 `/simplify` envelope；畸形、重复 tag、混入普通文本及无关 XML-like 反例；Workflow 成功与失败终态事实；重复、不匹配、矛盾或其他有歧义的 notification。
- Prove fixture Raw line counts and Protocol fallback before changing projection behavior. / 在改变投影行为前，先证明 fixture 的 Raw 行数与 Protocol fallback。

### Implementation contract / 实现契约

- Replace the order-sensitive slash-command envelope check with a strict tag-set parser that accepts exactly one required `command-name` plus at most one each of the admitted optional tags, regardless of order. Reject nesting, duplicate/malformed tags, unknown sibling tags, non-whitespace outside the envelope, mixed ordinary user text, and unrelated XML-like content. / 将顺序敏感的 slash-command envelope 检查替换为严格 tag-set parser：无论顺序如何，只接受恰好一个必需的 `command-name`，以及每种最多一个的允许 optional tag。拒绝嵌套、重复／畸形 tag、未知同级 tag、envelope 外非空白文本、混入的普通用户文本及无关 XML-like 内容。
- Extend `buildAsyncLifecycleCorrelation()` and its launch classification instead of adding a parallel lifecycle mechanism. Recognize only the observed, structurally exact `local_workflow` launch receipt and correlate terminal evidence through one unique launch owner plus exact `taskId + tool-use-id`, in causal order. / 扩展 `buildAsyncLifecycleCorrelation()` 及其 launch 分类，不新增并行生命周期机制。只识别已观察、结构精确的 `local_workflow` launch receipt，并通过唯一 launch owner、精确 `taskId + tool-use-id` 及因果顺序关联终态证据。
- Terminal source status determines success, failure, declined, or incomplete outcome. Preserve duration, token usage, tool-use and agent-activity statistics, terminal/result facts, and every contributing Raw Reference. Contradictory terminal facts do not use a “last record wins” guess. / 最终的来源 status 决定 success、failure、declined 或 incomplete。保留 duration、token usage、tool-use 与 agent-activity 统计、terminal／result 事实及每条贡献证据的 Raw Reference。互相矛盾的终态事实不得使用“最后一条获胜”的猜测。
- Do not redesign background Bash or existing async Agent lifecycle unless a shared defect is demonstrated by a focused regression test. / 除非聚焦回归测试证明存在共享缺陷，否则不重设计 background Bash 或现有 async Agent 生命周期。

### Gate / 门槛

- Run focused fixture, Claude logical, lifecycle negative-case, Raw-reference, and Claude reindex tests. Do not advance while any ambiguous case produces a semantic success or loses Raw. / 运行聚焦 fixture、Claude logical、生命周期反例、Raw-reference 与 Claude reindex 测试。有歧义的情况若产生语义 success 或丢失 Raw，则不得进入下一 milestone。

## Milestone 2 — derived session storage and relationships / 里程碑 2——派生会话存储与关系

### Evidence model / 证据模型

- Forked-skill children require an exact parent `<forked-skill-launch>` record plus the observed bounded sidecar/marker evidence. Workflow agents require the explicit `subagents/workflows/<runId>/agent-*.jsonl` layout plus exact workflow sidecar/journal evidence that proves parent run and child ownership. / Forked-skill child 必须具有精确的父 `<forked-skill-launch>` 记录以及已观察到的有界 sidecar／marker 证据。Workflow agent 必须位于显式的 `subagents/workflows/<runId>/agent-*.jsonl` 布局中，并具有能证明父 run 与 child ownership 的精确 workflow sidecar／journal 证据。
- Missing, malformed, duplicated, stale, escaped, reused, contradictory, or ambiguous relationship evidence rejects only the unsupported derived relationship/session; it does not poison unrelated valid primary or normal-subagent sessions. Every safe discovered source record still remains available through an appropriate independent or fallback path when the existing storage contract permits it. / 关系证据缺失、畸形、重复、过期、逃逸、复用、矛盾或有歧义时，只拒绝缺乏支持的派生关系／session，不影响无关的有效 primary 或普通 subagent session。在现有存储 contract 允许时，每条安全发现的来源记录仍通过适当的独立路径或 fallback 保留。

### Implementation contract / 实现契约

- Extend the existing candidate, context, identity, session construction, and relationship-evidence abstractions. Use explicit collision-safe derived identity helpers such as kind-separated encoded components while leaving `analyzerSubagentSessionId(parentSourceSessionId, agentId)` unchanged. / 扩展现有 candidate、context、identity、session construction 与 relationship-evidence 抽象。为新 kind 使用显式且 collision-safe 的派生 identity helper，例如按 kind 分隔的编码组件，同时保持 `analyzerSubagentSessionId(parentSourceSessionId, agentId)` 不变。
- Extend discovery, project association, containment, Raw readback, hierarchy metadata, totals/progress, identity conflict propagation, and search/detail visibility together. / 同步扩展 discovery、project association、containment、Raw readback、层级 metadata、总量／进度、identity conflict 传播以及搜索／详情可见性。

## Milestone 4 — Loop and Ultracode presentation / 里程碑 4——Loop 与 Ultracode 呈现

### Evidence-first decision / Evidence-first 决策

- Model dynamic loop execution and fixed cron lifecycle as distinct state machines in fixtures before changing presentation. `ScheduleWakeup(stop:true)` is a wakeup/stop fact, not deletion; only exact `CronDelete` evidence establishes cron deletion. / 在改变 presentation 前，先在 fixture 中把动态 loop execution 与固定 cron lifecycle 建模为不同 state machine。`ScheduleWakeup(stop:true)` 是 wakeup／stop 事实而非删除；只有精确的 `CronDelete` 证据才能证明 cron 已删除。
- Preserve the underlying `CronCreate`, `CronList`, `ScheduleWakeup`, and `CronDelete` source operations and their Raw traceability. Promote them into a composite Loop event only if fixtures demonstrate one unambiguous causal owner, the composite adds user value, and search/detail can still reach the underlying operations. / 保留底层 `CronCreate`、`CronList`、`ScheduleWakeup` 与 `CronDelete` 来源操作及其 Raw 可追溯性。只有当 fixture 证明存在唯一无歧义的因果 owner、组合事件确有用户价值且搜索／详情仍能到达底层 operation 时，才将其提升为复合 Loop event。
- Treat `ultra_effort_enter` full/sparse presentation, session badges, and repeated sparse-reminder folding as lower-priority refinement. Reuse existing model/effort fields and `attributionSkill` provenance; do not add another mode model without evidence that existing facts cannot represent the source. / 将 `ultra_effort_enter` full／sparse presentation、session badge 与重复 sparse reminder folding 视为较低优先级优化。复用现有 model／effort 字段与 `attributionSkill` provenance；除非证据表明现有事实无法表达来源，否则不新增 mode model。

### Fixtures and gate / Fixture 与门槛

Record the decision to add or defer composite/badge/folding behavior. / 分别添加 dynamic-loop、cron-lifecycle、wakeup-without-delete、explicit-delete、ambiguous-owner、Ultracode full／sparse 与 repeated-sparse fixture。记录新增或延期 composite／badge／folding 行为的决定。
