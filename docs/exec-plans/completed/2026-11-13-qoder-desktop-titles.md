## Findings and evidence limits / 发现与依据边界

The current mapper in `src/qoder-logical.js` selects the latest nonempty `custom-title.customTitle`, then eligible user text, then a session-ID fallback. `src/qoder.js` reads no desktop database; the browser displays the resulting `session.title`. The missing desktop title is an ingestion gap. / 当前 mapper 依次选择最后一个非空 custom-title、符合条件的用户文本、会话 ID 兜底；adapter 不读取桌面数据库，浏览器直接显示所得 session.title。问题在于未接入桌面标题元数据。

Read-only inspection of the selected Qoder CN Windows corpus found 110 transcripts: 50 primary and 60 child sessions. Only three primary transcripts contain custom-title records; no ai-title records were observed. The desktop `chat_sessions` table has 53 rows, with an exact session-ID and recorded-cwd match for all 50 primary transcripts; all 50 matches have nonempty titles. Current displayed titles equal the database title in only one case. / 对选定 Qoder CN Windows 语料的只读检查发现 110 份转录，含 50 个主会话、60 个子会话；仅三个主会话保存 custom-title，未观察到 ai-title。桌面 chat_sessions 表有 53 行，50 个主会话均有 session ID 与记录 cwd 精确对应的非空标题；当前显示标题仅一例与数据库相同。

Of these 50 rows, 15 report `titleSource: ai`, four `fallback`, two `custom`, and 29 lack that field. The 21 rows with provenance also report `titleResolved: true`. All three JSONL custom titles disagree with their corresponding desktop title. These observations do not establish which conflicting title is newer or authoritative, nor whether the 29 unlabelled titles were generated by AI. / 50 行中，15 行标记 ai、四行 fallback、两行 custom、29 行缺少来源字段；有来源的 21 行同时标记 titleResolved 为 true。三个 JSONL 自定义标题均与对应桌面标题不同。仅凭这些观察不能判断冲突标题的新旧或权威性，也不能将 29 个无来源标题称为 AI 标题。

Observed desktop profile: Qoder CN desktop `0.4.9`; Windows roaming directory `com.qodercn.app.stable/main.sqlite`; relevant table `chat_sessions`. The database and WAL measured approximately 196.83 MiB and 3.93 MiB. This is distinct from the Qoder IDE's storage and from an unverified global-edition layout. Keep real paths, IDs, titles and database contents out of committed fixtures. / 已观察桌面形态为 Qoder CN 0.4.9、所列 Windows roaming 目录及表；主库与 WAL 分别约 196.83、3.93 MiB。它不同于 Qoder IDE 存储，亦不代表已验证全球版布局。真实路径、ID、标题和数据库内容不得进入提交的 fixture。

Existing production SQLite readers are OpenCode native storage, Codex current-rollout pointers, and optional WorkBuddy desktop origin metadata. Node's built-in SQLite is already used; no new npm SQLite package is needed. WorkBuddy's stable private DB/WAL copy and `copied_value` dependency provide the closest reference. / 当前生产代码的 SQLite 读取分别用于 OpenCode 原生存储、Codex 当前 rollout 指针及可选 WorkBuddy 桌面来源元数据；已有 Node 内置 SQLite，不需新增 npm SQLite 包。WorkBuddy 的私有稳定 DB/WAL 副本与 copied_value 依赖最接近本任务。

## Accepted decisions / 接纳决策

1. Make the desktop database an optional, explicitly configured Qoder input. Initial implementation should use `--qoder-desktop-db <file>` and the corresponding Qoder source-config field, with matching History CLI support. Resolve relative configuration paths against the config file. Avoid inferring a Windows profile from a WSL username or combining unrelated installations. Automatic location detection and a new browser path editor are separate follow-ups. / 将桌面数据库作为可选且显式配置的 Qoder 输入；初版使用所列 CLI 参数及对应 Qoder source-config 字段，并同步 History CLI。配置相对路径以配置文件为基准，不从 WSL 用户名猜测 Windows 用户目录，也不混合不同安装。自动定位及新增浏览器路径编辑器另列后续。
2. Bind this setting to the configured Qoder home. Preserve it across switches to other sources and back; when that home changes without an explicit matching database setting, clear the association. Include metadata-setting changes in source revision/cache invalidation. Existing source configurations without the field retain their behavior. / 将该设置绑定到配置的 Qoder home；切换其他来源再返回时保留，改变 home 且未显式提供匹配数据库时清除关联。元数据设置变化参与来源 revision／缓存失效；不含新字段的既有配置保持原行为。
3. Read once per project index build, after identifying candidate main transcripts. Do not open the database for project-list statistics, each Session, Detail, Raw or browser refresh. Query only bounded identity, title and provenance fields needed by the candidates. / 在识别候选主转录后，每次项目索引只读一次；项目列表统计、每个会话、Detail、Raw 和普通浏览器刷新均不另行打开数据库。只查询候选会话所需、有长度限制的身份、标题及来源字段。
4. Match a unique native primary-session ID and verified recorded cwd under the shared path policy; detect duplicate physical transcript identities. Never assign a parent desktop title to a child or infer ownership from title text. Ambiguous matches fall back with diagnostics. / 按共享路径策略核对唯一原生主会话 ID 与记录 cwd，并检测物理转录身份重复；不把父桌面标题分配给子会话，也不从标题文本推断归属。歧义匹配以诊断和回退处理。
5. Preserve an explicit JSONL custom title unless evidence establishes a later authoritative desktop rename. Admit a resolved desktop title before user-text fallback only under the M0 provenance rule. Provisional, unlabelled and conflicting values need an explicit accepted rule; do not use database file mtime as rename order. / 除非有依据证明桌面后续重命名更具权威性，否则保留 JSONL 显式自定义标题。仅按 M0 确认的来源规则，将已确定桌面标题置于用户文本兜底之前。临时、无来源及冲突值必须有明确接纳规则；不得用数据库文件 mtime 排序重命名。
6. Copy the admitted title, identity and minimal provenance into a validated `copied_value` dependency. Apply it both while building Indexed Sessions and during materialization. A later desktop rename or database deletion does not mutate an accepted index; project reindex captures new metadata. Store a provenance digest for the copied fact, not a requirement that the entire live database remain unchanged. / 将接纳的标题、身份及最小来源事实保存为经过验证的 copied_value 依赖，索引与物化均应用该值。后续桌面重命名或数据库删除不改变已有索引，由项目重建索引读取新值。摘要绑定复制事实，不要求整个实时数据库始终不变。
7. Keep the live database and side files untouched. Prototype a bounded stable DB/WAL copy with identity/change checks, cancellation and unconditional temporary-file cleanup; reject active rollback journals and unsafe paths. Open only the private copy using read-only SQLite, disabled extensions and a bounded query. Missing, busy, corrupt, oversized, unsupported-schema or unavailable-SQLite cases return JSONL titles with an appropriate diagnostic. Cancellation remains cancellation. / 不改动实时数据库及 side file。以有界稳定 DB/WAL 副本为原型，加入身份／变化检查、取消和无条件临时文件清理，拒绝活跃 rollback journal 及不安全路径。仅对私有副本使用只读 SQLite，禁止扩展并限制查询。缺失、繁忙、损坏、超预算、不支持的 schema 或缺少 SQLite 能力时诊断并退回 JSONL 标题；取消仍按取消处理。

## Milestones / 里程碑

### M0 — Establish title authority / 确认标题权威性

- Inspect the pinned installed desktop writer or controlled rename evidence for `title`, `titleSource`, `titleResolved`, `titleRevision` and `provisionalTitle`; distinguish a current title from an import or fallback. Resolve the three observed conflicts without storing private strings. / 检查固定版本桌面 writer 或可控重命名证据，确认所列字段含义，区分当前标题、导入和兜底；处理三个已观察冲突，不保存私人标题字符串。
- Publish a precedence table covering JSONL custom, desktop custom, resolved AI, fallback, missing provenance, provisional and malformed values. If a case remains unproven, retain JSONL fallback and name that limitation. / 明确 JSONL 自定义、桌面自定义、已确定 AI、兜底、无来源、临时及异常值的优先级表；仍未证实的情况保持 JSONL 回退并注明限制。
- Measure one stable copy and candidate query against the selected approximately 201 MiB input. Record elapsed time, temporary bytes, peak RSS, busy/cancel behavior and unchanged source-side files. Set explicit file, returned-string and query-work budgets before implementation acceptance. / 针对约 201 MiB 输入测量一次稳定复制与候选查询，记录耗时、临时字节、峰值 RSS、繁忙／取消行为及源 side file 未变证据；验收前固定文件、返回字符串及查询工作预算。

### M1 — Optional capture and configuration / 可选采集与配置

- Add a focused `src/qoder-desktop-titles.js`; reuse a small stable-copy helper only if its extraction leaves WorkBuddy behavior unchanged and tested. Do not build a generic SQLite adapter framework. / 新增职责集中的所列模块；仅当小型稳定复制 helper 的抽取能保持 WorkBuddy 行为且有测试时复用，不建设通用 SQLite adapter 框架。
- Thread the optional setting through CLI, History CLI, source configs, server revision changes and Qoder index context; extend validation only for the Qoder field. Add the new packaged module to the package allowlist. / 将可选设置接入 CLI、History CLI、来源配置、服务端 revision 变化及 Qoder 索引上下文；仅为 Qoder 扩展所需字段校验。把新模块加入打包清单。
- Exercise schema, identity, WAL, path and capacity failures before connecting successful capture to titles. / 在将成功采集接入标题前，先验证 schema、身份、WAL、路径及容量失败。

### M2 — Indexed title replay / 索引标题回放

- Extend the Qoder dependency validator, snapshot identity and materialization replay. Keep the primary transcript dependency independent of optional title metadata. Apply one resolver in index and materialization; cover search/list metadata as well as Session headers. / 扩展 Qoder 依赖校验、快照身份及物化回放；主转录依赖与可选标题元数据独立。索引与物化共用标题决策逻辑，同时覆盖搜索／列表元数据与会话标题。
- Update the product spec, Qoder design and usage/configuration documentation in English and Chinese. Preserve event counts, Raw references, source fingerprints, child identities and native bytes. / 同步更新双语产品规格、Qoder 设计及使用／配置文档，保持事件计数、Raw 引用、源 fingerprint、子会话身份及原生字节不变。

### M3 — Validation and acceptance / 验证与验收

- Use synthetic SQLite/JSONL fixtures for precedence, missing provenance, duplicate IDs, cwd mismatch, child exclusion, empty/oversized titles, malformed JSON, unsupported schemas and optional-reader failures. / 使用合成 SQLite／JSONL fixture 覆盖优先级、无来源、重复 ID、cwd 不符、子会话排除、空／超长标题、异常 JSON、不支持 schema 及可选 reader 失败。
- Prove WAL-only updates are captured, source DB/WAL/SHM/journal remain unchanged, repeated/cancelled scans clean up, and title changes/deletion are invisible until reindex. Verify wrong-home metadata is not reused after source configuration changes. / 证明能捕获仅在 WAL 中的更新、源 DB／WAL／SHM／journal 不变、重复／取消扫描完成清理，以及标题变化／删除在重建索引前不影响旧值；验证改变来源配置后不复用错误 home 的元数据。
- Run affected Qoder, WorkBuddy-helper, lifecycle/conformance, source-switch, CLI/History CLI and package tests. Build assets, verify title display/reindex and repeated source switching in the browser, then restore generated assets before ordinary commits. / 执行受影响 Qoder、WorkBuddy helper、生命周期／conformance、来源切换、CLI／History CLI 及打包测试；构建资产，在浏览器验证标题显示／重建索引及反复来源切换，普通提交前恢复生成资产。
- Repeat the real-corpus comparison and report titles by admitted provenance, fallback and conflict categories; 50/50 title equality is not an acceptance target while authority conflicts remain. Before each commit obtain a fresh independent review of the exact diff; report local checks and final-SHA CI separately. / 重做真实语料对照，按接纳来源、回退与冲突类别报告；权威性冲突未解决时，不将 50/50 标题相同作为目标。每次提交前对精确 diff 做 fresh 独立审查，区分本地检查与最终 SHA CI。

## Completion criteria and maintenance scope / 完成标准与维护范围

The selected supported desktop titles appear after indexing and remain stable through materialization. Optional failures preserve readable JSONL sessions with explicit diagnostics. No database access is added to Detail/Raw or project-list discovery. Source files remain unchanged, configuration survives intended switches, and no unproven title source is labelled AI. / 已支持的桌面标题在索引后显示，物化时保持稳定；可选读取失败仍可读取 JSONL 会话并有明确诊断。Detail／Raw 和项目列表发现不新增数据库访问，源文件不变，配置按预期跨切换保留，未证明的标题来源不标记 AI。

Expected maintenance is one optional schema reader plus configuration and snapshot tests. The recurring costs are desktop schema/provenance changes, platform location policy and stable-copy I/O. A wholesale shared SQLite abstraction, other adapters' title changes, Qoder IDE/global-edition discovery, and automatic database migration are outside this plan. / 预计维护对象为一个可选 schema reader 以及配置／快照测试；持续成本主要来自桌面 schema／来源语义变化、平台定位策略及稳定复制 I/O。通用 SQLite 重构、其他 adapter 标题修改、Qoder IDE／全球版发现及自动数据库迁移均不在本计划内。
