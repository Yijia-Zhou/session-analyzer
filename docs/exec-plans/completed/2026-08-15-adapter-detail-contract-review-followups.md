## Accepted architecture / 已接受架构

1. Structured Detail has two orthogonal semantic axes. `purpose` states what a section means; Detail Responsibility states whether it is Primary Detail or Supplemental Detail. / 结构化详情具有两条正交语义轴。`purpose` 表示区段是什么；详情职责表示它属于主体详情还是补充详情。
2. Responsibility is encoded by the existing containers without a duplicate section field: `timelineSections[]` normatively contains Primary Detail, and `inspectorSections[]` normatively contains Supplemental Detail. The current names remain for compatibility. / 详情职责由既有容器编码，不新增重复 section 字段：`timelineSections[]` 规范地包含主体详情，`inspectorSections[]` 规范地包含补充详情。当前命名为兼容性继续保留。
3. The owning adapter assigns purpose, responsibility, and renderer payload from source semantics. The shared contract validates the assignment and never infers it from renderer type, title, source kind, or producer order. The browser consumes the two containers without reclassification. / 所属 adapter 根据来源语义分配 purpose、responsibility 与 renderer payload。共享契约验证该分配，绝不根据 renderer type、title、source kind 或 producer 顺序推断。浏览器消费两个容器，不再重新分类。
4. Primary Detail makes a Logical Event intelligible in chronological work history without opening the Inspector. Supplemental Detail supports inspection, verification, provenance, debugging, or deeper understanding. Purpose does not determine responsibility: command request／output may be primary, while full arguments or a structured output projection may be supplemental. / 主体详情使逻辑事件无需打开 Inspector 即可在时间顺序工作历史中被理解。补充详情用于检查、核验、来源追溯、调试或深入理解。Purpose 不决定责任：command request／output 可以是主体，而完整参数或结构化输出投影可以是补充。
5. Canonical Raw References are authoritative source evidence and become shared Inspector chrome in a stable action area. Inline `raw_json` is only an optional, collapsed, bounded and sanitized logical fallback; in Main／Protocol detail it requires `purpose: fallback` and cannot duplicate source payload merely for convenience. / 规范 Raw References 是权威来源证据，并成为固定操作区中的共享 Inspector chrome。Inline `raw_json` 仅是可选、默认折叠、有界且已脱敏的 logical fallback；在 Main／Protocol detail 中必须使用 `purpose: fallback`，不得仅为方便而复制来源 payload。

## Required invariants / 必需不变量

- Equivalent responsibility cannot change because an adapter chose another renderer type, localized title, or producer order. / Adapter 选择不同 renderer type、本地化 title 或 producer 顺序时，等价责任不得变化。
- Browser code never promotes or demotes a section between Primary and Supplemental Detail. / 浏览器代码绝不在主体详情与补充详情之间提升或降级 section。
- `sectionIsInspectorSupplement()` may remain only as an explicitly bounded migration helper while producers become responsibility-explicit; it is not a future-adapter precedent. / `sectionIsInspectorSupplement()` 只能在 producer 迁移为显式职责期间作为范围明确的迁移 helper 保留；它不是未来 adapter 的先例。
- Main／Protocol `raw_json` must be `fallback`, collapsed, conditional, and traceable through complete canonical Raw References. Raw-layer detail remains a separate exact source-evidence presentation. / Main／Protocol 的 `raw_json` 必须是 `fallback`、默认折叠、条件式出现，并通过完整规范 Raw References 保持可追溯。Raw 层详情继续作为独立的精确来源证据呈现。
- Metadata deduplication requires matching typed semantic facts, never an untyped scalar collision. / Metadata 去重必须匹配 typed semantic fact，绝不接受无类型 scalar 碰撞。
- Specialized Code Mode renderer validation remains statically invoked by the shared closed renderer contract but is owned by a focused module; no dynamic registration is introduced. / 专用 Code Mode renderer validation 继续由共享封闭 renderer 契约静态调用，但由聚焦模块拥有；不引入动态 registration。
- Detail schema validation uses one canonical expected version source rather than a literal fallback hidden in the validator. / Detail schema 校验使用唯一 canonical expected version 来源，而不是藏在 validator 中的 literal fallback。

## Validation strategy / 验证策略

1. Focused contract tests for responsibility-container semantics, forbidden Raw JSON combinations, schema version mismatch, and typed-dedup collisions. / 对职责容器语义、禁止的 Raw JSON 组合、schema version mismatch 与 typed-dedup 碰撞运行聚焦契约测试。
2. One source-neutral conformance matrix over representative Codex and Claude message, command／tool, plan, protocol fallback, and Raw readback scenarios. / 对代表性的 Codex／Claude message、command／tool、plan、protocol fallback 与 Raw 回读场景运行一套来源中立 conformance matrix。
3. Browser checks for primary expanded bodies, supplemental Inspector ordering, a fixed Raw action with exact lazy readback, and both locales. / 对主体展开正文、补充 Inspector 排序、固定 Raw 操作与精确惰性回读，以及两种 locale 运行 browser 检查。
4. Full Node, browser, generated-asset, and package validation before archiving this plan. / 归档本计划前运行完整 Node、browser、生成资产与 package 验证。

## Completion criteria / 完成标准

The new-adapter gate is restored only when the two-axis contract is normative and tested; Codex and Claude no longer establish responsibility through renderer／title heuristics or unconditional logical Raw dumps; Raw access is stable shared chrome backed by exact lazy readback; the P2 collision, validator-ownership, and schema-version issues are closed; and all validation plus final review have no unresolved blocking findings. / 只有当二维契约已经成为规范并有测试、Codex 与 Claude 不再通过 renderer／title heuristic 或无条件 logical Raw dump 建立职责、Raw 入口成为由精确惰性回读支撑的固定共享 chrome、P2 碰撞／validator ownership／schema-version 问题均已关闭，并且所有验证与最终评审没有未解决阻断 finding 时，新增 adapter 门槛才恢复。
