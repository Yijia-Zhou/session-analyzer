## Objective / 目标

Replace revision-long unbounded retention of complete Materialized Sessions with one source-neutral weighted LRU working-set cache backed only by the authoritative transcript files. The cache combines deterministic estimated byte weight, a Session-count cap, recency, and foreground-versus-speculative admission priority while preserving cold-open fingerprint reuse, bounded idle prewarm, exact revision ownership, same-Session coalescing, cancellation/failure exclusion, and adapter contracts. No derived disk cache is introduced. / 用一个来源中立的加权 LRU working-set cache 取代 complete Materialized Session 在整个 revision 生命周期内的无界保留；权重缓存只以权威 transcript 文件为后端。Cache 同时使用确定性的估算 byte weight、Session 数量上限、recency 与 foreground／speculative admission 优先级，并保持冷开 fingerprint 复用、有界 idle prewarm、精确 revision ownership、同 Session 合并、取消／失败排除以及 adapter contract。不引入派生 disk cache。

## Frozen boundaries / 冻结边界

1. `indexed-materialized-v1`, adapter descriptors and signatures, `materializationContextFields`, DependencySet semantics, ProjectQueryStore parity, source freshness, Q↔M validation, canonical Materialized Session shape, Detail Purpose／Responsibility, and Raw Reference ownership remain unchanged. / `indexed-materialized-v1`、adapter descriptor 与 signature、`materializationContextFields`、DependencySet 语义、ProjectQueryStore 等价、来源 freshness、Q↔M 校验、规范 Materialized Session 形态、详情用途／职责以及 Raw Reference ownership 均保持不变。
2. The policy uses only canonical Indexed Session facts and revision-owner cache state. Shared code must not inspect Codex-, Claude-, or DeepSeek-specific fields. / 策略只使用规范 Indexed Session facts 与 revision owner cache state；共享代码不得检查 Codex、Claude 或 DeepSeek 特有字段。
3. The cache budget bounds retained estimated cache weight, not V8 heap, RSS, transient parsing memory, ProjectQueryStore external memory, temporary projection/fingerprint allocations, or an evicted object still referenced by an in-flight request. / Cache budget 限制的是保留的估算 cache weight，不是 V8 heap、RSS、瞬时解析内存、ProjectQueryStore external memory、临时 projection／fingerprint 分配，或被淘汰但仍由 in-flight request 引用的 object。
4. Cache eviction never targets active materialization jobs. Same-ID coalescing, active speculative-job foreground promotion, foreground preemption, the process-global active-one scheduler, and bounded FIFO admission remain unchanged. / Cache eviction 绝不以 active materialization job 为目标。同 ID 合并、active speculative job 的 foreground promotion、foreground 抢占、进程级 active-one scheduler 与有界 FIFO admission 均保持不变。

No persistent or derived disk cache, database, mmap store, process-memory admission key, reference-counted lease, partial Session reconstruction, parser continuation, concurrency increase, hard RSS limit, or browser virtualization is introduced. / 不引入持久或派生 disk cache、数据库、mmap store、基于进程内存的 admission key、引用计数 lease、局部 Session 重建、parser continuation、并发提升、硬 RSS 限制或 browser virtualization。

## M0 design checkpoint / M0 设计检查点

The v1 defaults are confirmed as `maxEstimatedMaterializedBytes = 256 MiB` and `maxCachedSessions = 12`. The measured recent sequence makes the count cap dominant first and reaches the byte cap at ordinal 21; the accepted largest estimate remains 127,923,725 bytes, so the byte bound can retain roughly two observed largest-class entries without becoming an RSS promise. The independent cap protects numerous small Sessions, while the stricter 96-MiB／48-MiB prewarm envelope continues to limit speculation. No adjustment is justified by M0 evidence. / v1 默认值确认为 `maxEstimatedMaterializedBytes = 256 MiB` 与 `maxCachedSessions = 12`。已量测近期序列先由 count cap 主导，并在第 21 项触发 byte cap；已接受最大 estimate 仍为 127,923,725 bytes，因此 byte bound 大致可保留两个已观测最大级别 entry，同时不会成为 RSS 承诺。独立 count cap 会保护大量小 Session；更严格的 96-MiB／48-MiB prewarm envelope 继续限制 speculation。M0 证据不支持调整默认值。

Selected policy invariants: / 已选策略不变量：

1. Cache metadata uses a monotonic access sequence and current origin (`foreground` or `speculative`); an O(N) victim scan is acceptable at the small cap. / Cache metadata 使用单调 access sequence 与当前 origin（`foreground` 或 `speculative`）；在小容量上限下允许 O(N) victim scan。
2. Foreground hit touches MRU and promotes speculative origin to foreground. / Foreground hit 会 touch MRU，并把 speculative origin promote 为 foreground。
3. Foreground admission evicts oldest speculative entries before oldest foreground entries, then admits as foreground MRU. / Foreground admission 先淘汰最旧 speculative entry，再淘汰最旧 foreground entry，随后作为 foreground MRU 准入。
4. Speculative admission may evict only speculative entries; if fitting would require foreground eviction, the completed value is not retained and no user-visible error is produced. / Speculative admission 只能淘汰 speculative entry；若要腾出空间必须淘汰 foreground，则完成的 value 不予保留，且不产生用户可见错误。
5. A foreground entry larger than the entire byte budget evicts all residents and becomes the sole cached value; speculative work never receives this exception. / 大于整个 byte budget 的 foreground entry 会淘汰全部 resident 并成为唯一 cached value；speculative work 不享有该例外。
6. Eviction removes owner retention only. An in-flight request that already captured the object may finish through its ordinary local JavaScript reference, without acquire/release leases. / Eviction 只移除 owner retention；已捕获 object 的 in-flight request 可通过普通局部 JavaScript reference 正常完成，无需 acquire／release lease。
7. Ordinary state obeys both byte and count limits; the only allowed violation is exactly one oversize foreground resident. / 普通状态同时遵守 byte 与 count 限制；唯一允许的例外是恰好一个 oversize foreground resident。
