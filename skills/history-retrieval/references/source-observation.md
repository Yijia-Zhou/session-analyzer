# Observe source changes without chasing the caller / 观察来源变化，不追赶调用方日志

Use `observe` only when the question needs information about changes outside the service's fixed snapshot and `status.capabilities.operations` lists it. Ordinary `status`, search, context and reads do not trigger this check. A successful old evidence read and an observation of source changes answer different questions; report them separately. / 仅在问题需要了解服务固定快照之外的来源变化，且 `status.capabilities.operations` 列出 `observe` 时使用。普通 `status`、搜索、上下文和读取不触发此检查。旧证据读取成功与来源变化观察回答不同问题，应分别报告。

```sh
session-analyzer history observe --endpoint http://127.0.0.1:17891
session-analyzer history observe --endpoint http://127.0.0.1:17891 --caller-session "<known-caller-sessionId>" --max-files 10000 --limit 8 --max-bytes 24000
```

`--caller-session` is optional and asserts the caller's known Session ID. Do not guess from the newest Session, a filename or matching text. Omit it when the identity is unknown. An ID absent from the old index is accepted with `caller.indexedSessionMatched:false`; this is unresolved association, not a request to rebuild. Exact indexed matches separate caller-associated and other file counts. They do not exclude the Session, authenticate the actor or classify its new content as retrieval echoes. Shared dependencies can also affect other Sessions; `unattributed` files may belong to the caller or another project. / `--caller-session` 可省略，用于声明已知的调用方会话 ID。不要从最新会话、文件名或匹配文本猜测；身份未知时省略。旧索引中没有该 ID 时仍接受，返回 `caller.indexedSessionMatched:false`，表示关联未确认，不要求重建。精确匹配索引后，调用方关联文件与其他文件分别计数；不排除会话、不认证主体，也不把新增内容分类为检索回声。共享依赖还可能影响其他会话；`unattributed` 文件可能属于调用方或其他项目。

The observation compares physical file metadata with the captured baseline. Read its scope, baseline and check intervals, partial status, gaps, omitted items and unchecked controls before interpreting differences. Candidate discovery includes files outside the project's admitted evidence; new candidates have unknown project membership. Missing or incomplete baseline coverage leaves prior existence unknown. Unchanged metadata does not prove unchanged content, and growth does not prove append-only history. Compressed physical bytes and accepted decoded bytes are different measures. / 观察将物理文件 metadata 与捕获的基线比较。解释差异前，阅读范围、基线及检查时段、部分完成状态、缺口、省略项和未检查的控制来源。候选发现包含项目准入证据之外的文件；新候选的项目归属未知。基线缺失或覆盖不完整时，原先是否存在未知。metadata 未变不证明内容未变，增长不证明历史仅追加。压缩物理字节与接纳的解压字节是不同度量。

Continuous writing by the active caller is normal, including the tools used for this task. Preserve the task's evidence cutoff, read enough evidence to answer, and state the observed changes or remaining uncertainty. There is no refresh-required signal. Do not repeat observe → rebuild → observe until the caller stops growing; the check and its response may themselves become new log records. / 活动调用方持续写入是正常情形，包括本任务使用的工具。保持本轮证据截止点，读取足以回答问题的依据，并说明观察到的变化或仍未知之处。报告不提供“必须刷新”信号。不要反复观察 → 重建 → 观察，等待调用方停止增长；检查及其响应本身也可能成为新日志记录。

If later evidence is necessary, explicitly start a new history service snapshot and search/read again. A separate port can keep the old reader service reachable while the new snapshot is built. Old refs, cursors and URLs retain their original scope; stopping or restarting their service does not preserve an old version behind the same link. Obtain and verify new entries from the new service. / 若确需后续证据，明确启动新的 history service 快照，再搜索／读取。使用另一端口可以在建立新快照时保留旧阅读服务可达。旧引用、游标和 URL 仍属于原范围；停止或重启其服务，不会在同一链接后保留旧版本。应从新服务取得并核验新入口。

`maxFiles` bounds observation work, while `limit` and `maxBytes` bound returned detail. Supported ranges are 1–100000 files, 1–100 items and 4096–1048576 serialized bytes; defaults are 10000, 8 and 24000. An omitted or unexamined item is not an unchanged item. Observation has no cursor: another call starts a new observation against the original baseline, not the next page. Increase a bound only when the missing information matters and the task budget permits; repeated checks cannot repair an incomplete original baseline. After cancellation, retain uncertainty or make one deliberate new check when useful. / `maxFiles` 限制观察工作量，`limit` 与 `maxBytes` 限制返回细节。支持范围分别为 1–100000 个文件、1–100 项及 4096–1048576 个序列化字节，默认 10000、8、24000。省略或未检查不等于未变。观察没有游标：再次调用是对原基线重新观察，不是下一页。仅在缺失信息影响问题且任务预算允许时提高上限；重复检查不能修复不完整的原基线。取消后保留不确定性，或在确有帮助时主动重新检查一次。
